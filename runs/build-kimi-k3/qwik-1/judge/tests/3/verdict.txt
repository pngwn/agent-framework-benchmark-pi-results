## Review: test quality

**Measured facts, confirmed by inspection:** `app/` contains zero test files. There is no `test` script in `app/package.json:6-12`, no test runner among the devDependencies (`@builder.io/qwik`, `@builder.io/qwik-city`, `@types/node`, `typescript`, `undici`, `vite`, `vite-tsconfig-paths` only), and a grep for `vitest|playwright|jest|@testing-library|node:test` across `app/` returns nothing. Every guard this app has is the acceptance suite the harness runs from `tests/`, which is outside `app/` and will not protect a refactor of the app's own logic.

That's a real gap, because this app is unusually testable: its riskiest behaviour lives in pure functions and pure data transformations that could be covered with Vitest and a fixture API client, with no browser at all.

The untested hot spots, in order of the damage a regression would cause:

- **Home filtering + pagination pipeline** — `app/src/routes/index.tsx:66-107`. Search-substring matching, type/generation filtering, `Math.max(1, Math.ceil(total / 48))`, page clamping, and the `slice((page-1)*48, page*48)` window are all inline in one `routeLoader$`. An off-by-one in the slice, swapping `q` matching to the raw API name, or forgetting to clamp `page` against a shrunken result set all ship silently. This is the single most regression-prone code in the app and the easiest to unit-test if it were extracted to a pure function.
- **Moves-table sort comparator** — `app/src/components/moves-table.tsx:34-50`. "Missing values sort last in both directions" is implemented by null-checking *before* applying `dir`. The classic refactor mistake — multiplying by `dir` first — makes nulls sort first when descending, which is exactly the kind of silent spec violation nothing here would catch. It's a five-line pure function begging for a parameterized test.
- **Species mapping for reference lists** — `app/src/lib/data.ts:73-110`. The `pokemonId >= 10000` alternate-form cutoff, dedupe by species id, and the defensive resolve-through-`/pokemon/<id>/` fallback govern "Learned by" / "Pokémon" counts and card ordering on every move, ability and type page. The acceptance fixtures happen to include forms-bearing cases, but a refactor here (moving the dedupe before the fallback, or keying by Pokémon name instead of species id) would corrupt dozens of pages with no failing test in `app/`.
- **Move-table construction** — `app/src/routes/pokemon/[name]/index.tsx:86-112`. The dedupe key `${m.move.name}|${level}` merges same-move-different-level rows within a version group (arguably dropping legitimate rows, e.g. a move relearned at two levels across versions inside one group), and the default game selection relies on `vgRecords[length-1]` being the highest `order`. Neither behaviour is pinned by anything.
- **URL-state round trip** — `app/src/lib/urls.ts:12-21` against the loaders at `app/src/routes/index.tsx:88-101` and the `onInput$`/`onChange$` handlers at `app/src/routes/index.tsx:118-160`. Omitting defaults, resetting to page 1 when a filter changes, and round-tripping `q` containing spaces or `&` are exactly the behaviours a URL-state refactor breaks; `homeUrl` is pure and trivially testable, but isn't.
- **API client semantics** — `app/src/lib/api.ts:29-60`. The promise-caching with rejected-promise eviction, `404 → null` vs. `throw` on other statuses, and the regex-based `idFromUrl`/`apiPathOf` (a URL without a trailing slash silently yields `NaN` and drops the species) are untested. The module is also not injectable — `API_BASE` and `cache` are module-level constants — which is part of *why* it's untested.
- **Error paths** — `apiFetch` throws on any non-404 failure and no loader catches (`app/src/routes/moves/[name]/index.tsx:19` is representative), so an API hiccup surfaces as an unhandled server error. The 404 → `NotFound` path (`app/src/routes/[...all]/index.tsx:6-8`, and each `[name]` loader) is likewise unpinned.
- **Concurrency limiter** — `app/src/lib/api.ts:15-27`: the waiter-queue ordering is subtle and unexercised; a refactor that shifts a waiter before decrementing `active` would deadlock bulk fan-outs.

Cheap wins left on the table: `app/src/lib/format.ts` (humanize, dexNumber padding, whitespace collapse, English-name selection) and `homeUrl` are pure, dependency-free, and would take an afternoon to cover — the absence of even these suggests tests were never attempted rather than deliberately skipped.
