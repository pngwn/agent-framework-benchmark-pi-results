## What I found

**The app source contains zero experimental, preview, RC, or canary APIs.** Every API in `app/src/` is long-stable Qwik/Qwik City v1 surface:

- City: `routeLoader$`, `useNavigate`, `useDocumentHead`, `DocumentHead`, `RequestHandler`, `QwikCityProvider`, `RouterOutlet` (`app/src/routes/index.tsx:1-2`, `app/src/components/router-head.tsx:1-2`, `app/src/routes/[...all]/index.tsx:1-2`)
- Node adapter: `createQwikCity` from `@builder.io/qwik-city/middleware/node`, the `@qwik-city-plan`/`@qwik-client-manifest` virtual modules, and `nodeServerAdapter` + `extendConfig` (`app/src/entry.node-server.ts:1-6`, `app/adapters/node-server/vite.config.ts:1-10`) — all of which match the official node-server starter adapter output verbatim.
- Vite config uses only default plugin options — no `experimental*` flags anywhere (`app/vite.config.ts:9-10`).

The single "experimental" marker in the measured facts (`server/q-BrBSDCN_.js:15`) is **not app code reaching for an experimental API**: it's a minified Qwik core chunk — the serializer's dev-mode "Trying to serialize…" warning string that references the QRL docs — bundled into the committed build output. I confirmed this by reading the chunk.

**Version currency:** `app/package.json:11-12` pins `^1.20.3` of both Qwik packages. Per the GitHub releases page (published 2026-10-25), `@builder.io/qwik@1.20.3` is the latest stable v1 release; Qwik v2 (`@qwik.dev/core`) is in beta/RC. The app correctly stays on the stable v1 line and does not touch any v2 preview material.

The only borderline-new APIs I could find are the `(event, target)` event-handler signature (`app/src/routes/index.tsx:102,115,133`, `app/src/routes/pokemon/[name]/index.tsx:298`) and the `status()` helper on the loader requestEvent (`app/src/routes/pokemon/[name]/index.tsx:32`) — both stable since Qwik 1.5/1.6 (2024), i.e., nearly two years stable, not "recently-stable" and certainly not experimental.

Two hygiene notes (not experimentalness risks, but worth flagging): committed build artifacts in `app/server/` and `app/dist/` that the analyzer evidently counted as source, and `undici` pinned as a **dev**Dependency even though the production server bundle statically imports it (`app/server/entry.node-server.js:1`) — it resolves today only because `@builder.io/qwik-city` itself depends on `undici` (confirmed in `app/package-lock.json:50`).
