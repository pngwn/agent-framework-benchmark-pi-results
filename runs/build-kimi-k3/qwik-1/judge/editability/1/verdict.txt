## Review: Pokédex app (Qwik + Qwik City 1.20.3)

**Framework currency check:** `package.json` pins `@builder.io/qwik@^1.20.3` / `@builder.io/qwik-city@^1.20.3`, which matches the current stable line as of 2026-10 (v2 is still at RC). The APIs used — `routeLoader$` with `status(404)`, `DocumentHead` with `resolveValue` (`app/src/routes/pokemon/[name]/index.tsx:319`), `useNavigate` + debounced `onInput$` (`app/src/routes/index.tsx:103-110`), `useStyles$` with `?inline` CSS, the `nodeServerAdapter` + custom `entry.node-server.ts` (`app/src/entry.node-server.ts`) — are all current, idiomatic 1.x patterns. Nothing deprecated.

**Structure:** 4 route directories under `app/src/routes/` mirroring URLs, shared presentational components (`card-grid.tsx`, `moves-table.tsx`, `moves-table.tsx` sorting is fully self-contained client-side), shared data/format helpers in `app/src/lib/` (one `api.ts` owns base URL, cache, and sprite URL). This is textbook Qwik City layout.

**What I traced for each scenario:**

1. *Remove Abilities* — delete `app/src/routes/abilities/`, then one contiguous JSX section + one loader mapping in `app/src/routes/pokemon/[name]/index.tsx:174` and `:270-281`. No nav link, no shared state, no other importers. Nearly ideal.
2. *Sprite bug (Deoxys)* — the "card sprite = front sprite of Pokémon ID" decision is made in **two producers**: `app/src/lib/data.ts:104` (`cardsForPokemonRefs`, covers move/ability/type lists) and `app/src/routes/index.tsx:67` (home). The URL pattern itself is one place (`app/src/lib/api.ts:56-59`), but a fix that resolves the default Pokémon's actual sprite must land twice, and the two card shapes are even typed twice (`CardData` in `data.ts:70` vs `CardItem` in `card-grid.tsx:5`).
3. *Sort cards by name* — every card list renders through `CardGrid` (`app/src/components/card-grid.tsx:11`), so it's a single chokepoint; the wrinkle is that dex-order is baked into both producers (`data.ts:108`, home preserves API order), so producers carry a hidden invariant.
4. *Items section* — all plumbing (`apiFetch`, `englishName`/`humanize`, `cardsForPokemonRefs`, `CardGrid`, `NotFound`, CSS classes) is reusable; the route pages themselves are bespoke and get copy-adapted from `moves/[name]/index.tsx` (~110 lines including the repeated 404/head boilerplate), plus a one-line nav link in `layout.tsx:15`.
5. *Data source* — base URL (`api.ts:6`), the promise cache (`api.ts:8`), the concurrency limiter, and 404 semantics all live in `app/src/lib/api.ts` alone. One file, one obvious place.

**Other notes:** `typeEn` map construction is repeated in three loaders (`pokemon/[name]/index.tsx:48`, `moves/[name]/index.tsx:22`, `types/[name]/index.tsx:20`); the `status(404)` / `NotFound` / head-ternary trio is repeated in four routes; API records are `any` throughout (no interfaces to lean on); `server/` and `dist/` build artifacts sit in the tree with only `/data/` gitignored; the app ships zero of its own tests.
