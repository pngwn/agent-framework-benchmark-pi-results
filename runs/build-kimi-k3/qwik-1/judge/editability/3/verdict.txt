I've reviewed the whole app (`app/src` routes, components, lib, server entry, packaging) against the spec and current Qwik stable (1.20.x, current as of 2026-10; 2.0 is still RC — the app pins `^1.20.3`, which is correct).

## Scenario walkthrough

1. **Remove Abilities**: delete `app/src/routes/abilities/` and the Abilities section on the Pokémon page (`app/src/routes/pokemon/[name]/index.tsx:270-279` + the loader mapping at `:174-179`), plus the now-dead `.hidden-note` rule in `app/src/global.css:449`. Grep confirms no other inbound links (the nav in `layout.tsx` doesn't link abilities). Difficulty **5**.
2. **Sprite fix**: the sprite URL is centralized in `spriteUrl` (`app/src/lib/api.ts:62`) but card *construction* is duplicated — `cardsForPokemonRefs` uses the ref's Pokémon id (`app/src/lib/data.ts:104`) while the home loader uses the species id (`app/src/routes/index.tsx:67`), with a third derivation on the Pokémon page artwork fallback (`.../pokemon/[name]/index.tsx:158`). One fix in `data.ts` covers the move/ability/type lists, but the home list and artwork need separate edits, and the maintainer must first discover that three sites exist and that they don't agree on which ID they use. Difficulty **3**.
3. **Sort cards by name**: one edit in `cardsForPokemonRefs` (`app/src/lib/data.ts:108` already centralizes the by-dex sort) covers 3 of 4 lists; the home loader's `all` mapping (`app/src/routes/index.tsx:46-56`) needs its own sort. `CardGrid` itself is untouched. Difficulty **4**.
4. **Items section**: `CardGrid`, `cardsForPokemonRefs`, `apiFetch`, `format.ts` helpers and `NotFound` all reuse directly; `getTypes` (`app/src/lib/data.ts:24-38`) is a 15-line template for `getItems`. But the Moves detail page is a single route file with no shared "resource page" abstraction, so `/items/:name` is copy-adapt of `app/src/routes/moves/[name]/index.tsx`, and nothing of the move-table grouping logic is extractable (it's inlined in the Pokémon loader). Difficulty **4**.
5. **API base/caching change**: everything lives in `app/src/lib/api.ts` — base URL `:6`, promise cache `:8`, concurrency pool `:11-30`, `apiFetch` `:32`, media prefix derived from the same constant `:62`. One file. Difficulty **5**.

## Scores

- **removability 5** — routes map 1:1 to features; abilities touches only its own directory, one consumer section, and one CSS rule.
- **changeability 3** — data fixes mostly land in `lib/`, but card construction is duplicated (`app/src/lib/data.ts:80-110` vs `app/src/routes/index.tsx:63-72`), the type-name map is rebuilt in three loaders (`routes/moves/[name]/index.tsx:22`, `routes/types/[name]/index.tsx:20`, `routes/pokemon/[name]/index.tsx:48`), and URL building is only half-centralized (`lib/urls.ts` has `homeUrl` only; `/pokemon/…` links are inlined at `components/card-grid.tsx:14`, `components/moves-table.tsx:98`, `routes/pokemon/[name]/index.tsx:299`).
- **coupling 4** — clean layering (lib → route loaders → presentational components), all fetching in `routeLoader$`s with client state limited to sort signals and filter nav; docked for the duplicated `CardData` type (`lib/data.ts:66`) vs `CardItem` (`components/card-grid.tsx:3`) and API-shape knowledge living in the home route loader (`routes/index.tsx:37-47`) rather than `lib/data.ts`.
- **abstraction_design 3** — `CardGrid`/`MovesTable`/`NotFound` are small, prop-driven, and own their concerns (sort state lives inside `MovesTable`), but optional-flag creep (`showLevel`, `types?`, `hidden?`) is at the limit, the Pokémon loader is a 140-line monolith (`routes/pokemon/[name]/index.tsx:32-170`) that can't be reused, and page skeletons are copy-paste ×4.
- **overall 4** — well-factored for its size; I'd approve with comments.
