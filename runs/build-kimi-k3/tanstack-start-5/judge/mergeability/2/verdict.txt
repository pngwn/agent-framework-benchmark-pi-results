## Review summary

The app is built on the **current stable TanStack Start** (Vite 8 + `tanstackStart()` + `nitro()` from `nitro/vite` at `app/vite.config.ts:1-16` — matches the post-1.169 hosting docs; `.validator()` (not the removed `inputValidator()`) at `app/src/lib/server.ts:16,20,24,30`; server functions called from route loaders; `head`/meta per route; `notFound()` thrown from loaders with a root `notFoundComponent`). Routing conventions (`createFileRoute`, `__root.tsx`, `$param.tsx`, `routeTree.gen.ts`), `validateSearch`/`loaderDeps` for URL-driven filter state, and `?url` CSS import are all as documented. Data lives on the server behind server functions with a single low-level fetch layer; the client only sees serializable DTOs.

The warts: a process-lifetime promise cache that permanently caches *rejections* (`pokeapi.ts:23`), a god data module that mixes server-only builders with client-shared types (docs recommend `.functions.ts`/`.server.ts` naming), pervasive `any` for API records, a `useEffect`-based `<title>` workaround for unmatched 404s, and a magic-150 ms `scrollIntoView` hack. Nothing structural blocks merge; I'd ask for the cache fix and a naming/typing pass.
