## Review summary

**Verification of statuses (as of 2026-10-31):**

- **TanStack Start 1.0 was declared stable on 2026-10-13** (tanstack.com/blog/tanstack-start-1-0; PR TanStack/router#8696 merged 2026-10-12). The app pins `@tanstack/react-start` **1.169.4** in its lockfile — an RC-era build from just *before* the stable announcement. The APIs used (`createServerFn().handler()/.validator()`, `tanstackStart()` plugin, `HeadContent`/`Scripts` root document) are exactly the ones documented as stable in the current "Build from Scratch" guide, with no experimental-status caveats.
- **Nitro v3 is still a Release Candidate** — `v3.0.261029-rc` released 2026-10-29, two days ago (github.com/nitrojs/nitro releases; nitro.build/docs/migration says "check back regularly until Nitro v3 is stable"). The app uses the `nitro()` Vite plugin (`app/vite.config.ts:3,10`) and serves the Nitro-built `.output/server/index.mjs`. However, this is the *officially documented* path: TanStack's own `examples/react/start-basic/vite.config.ts` and Nitro's `vite-ssr-tss-react` example both include `nitro()` from `nitro/vite` with the same dependency versions.
- **Vite 8** has been stable since 2026-03-12 (vite.dev/blog/announcing-vite8) — ~7.5 months, past the "recently-stable" window; `@vitejs/plugin-react` 6.1.2 is the current stable release. **React 19.3** and all `@tanstack/react-router` APIs (`createFileRoute`, `validateSearch`, `loaderDeps`, `notFound`, `useNavigate`, `head`) are long-stable.
- Static scan of all 14 source files: **zero** `unstable_`/`experimental_` names, zero experimental config flags, no RSC, no React Compiler, no canary features. The transitive `@tanstack/react-start-rsc@0.1.65` (a 0.x experimental package) appears only inside react-start's own dependency tree, never imported by app code.

**Scoring rationale:** `reach` 3 — the app's whole server layer rests on a framework that's been stable for only 18 days plus one still-RC bundler, but the framework was spec-mandated and nothing riskier was layered on top. `containment` 5 — Nitro appears in exactly one config line and `createServerFn` in one wrapper module (`app/src/lib/server.ts`); every route consumes plain typed functions, so a breaking change has a one-file blast radius. `justification` 5 — Nitro is the only deployment target that yields the self-contained node server the spec's `npm start` requires, Start itself is required, and there is no novelty-seeking anywhere.
