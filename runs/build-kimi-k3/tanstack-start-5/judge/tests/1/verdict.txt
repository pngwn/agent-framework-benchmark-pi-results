I've reviewed the spec, the acceptance-test harness, and all of `app/`'s source. The verdict on this dimension is short and stark: **the app contains no tests of its own whatsoever** — no test script in `app/package.json`, no runner in devDependencies (`app/package.json:18-27`), no spec/test files anywhere under `app/` (confirmed by the measured facts: `tests.files: 0`). The interesting work, then, is enumerating what the acceptance suite won't guard once it stops being the only line of defense.

What I found while reading the risky code:

- **Pure helpers in `app/src/lib/format.ts`** — `humanize`, `dexNumber`, `idFromUrl`, `latestEnglishFlavor`, `englishName` are the app's entire naming/display contract (the acceptance tests only sample a few names). `latestEnglishFlavor` (`format.ts:33-41`) dereferences `entries[i].language.name` without a guard; `idFromUrl` returns `NaN` for odd URLs, which callers filter — a behavior worth pinning.
- **Filtering/sorting/pagination in `app/src/routes/index.tsx:36-46`** — search matching (against humanized label, lowercased), type/generation filters, `Math.ceil/PAGE_SIZE` slicing, page clamping (`index.tsx:52-54`) and URL param omission (`buildSearch`, `index.tsx:32-38`). A refactor of `validateSearch` (`index.tsx:14-27`) or the clamping logic could silently break `/?q=char&page=99` behavior.
- **Card construction in `app/src/lib/data.ts:48-73`** — alt-form exclusion via `id > MAX_ALT_FORM_ID`, per-species dedupe, species-map resolution. The acceptance tests check a handful of pages; a regression in `seen`/`speciesMap` logic would mis-list forms everywhere at once.
- **Move grouping/ordering in `data.ts:186-236`** — the `METHOD_ORDER` comparator, "default game = highest `order`" (`data.ts:175`), level-then-name sorting. This is fiddly comparator code with several near-miss edge cases.
- **`MovesTable.tsx:42-61`** — missing-values-last in both directions and `aria-sort` toggling. The acceptance suite only checks the initial sort.
- **`pokeapi.ts:17-31`** — the cache stores the *promise*, including rejected ones: a single transient network error is cached for the process lifetime, which would be caught instantly by one mock-failure test.
- **Not-found plumbing** — `buildX` returning `null` → `throw notFound()` (`routes/pokemon/$name.tsx:16-21`), plus the `head` fallback title and `__root.tsx:23-33`'s `useEffect`-based title patch.
- **Sprite URL fabrication** (`data.ts:41-43`) constructs `/media/sprites/pokemon/<id>.png` instead of using the API-provided sprite URL; if the overlay data ships a species whose front sprite is `null`, the app renders a broken image — exactly the class of change the harness warns about, and nothing in `app/` would catch it.

None of this has any regression net inside `app/` beyond the acceptance suite, which samples by URL and won't exercise edge inputs (empty search, out-of-range page, `?game=` for a game the Pokémon doesn't learn in, unshipped sprites, malformed entries).
