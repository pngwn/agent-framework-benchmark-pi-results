## Review summary — dimension: test quality

The app contains **zero tests of its own**: no test runner, no test files, no `test` script (`app/package.json:6-9` defines only `dev`, `build`, `start`), and static analysis confirms 0 test files/cases/assertions. All verification was delegated to the acceptance suite in `tests/` (which the agent didn't write). The instruction set explicitly permits this outcome, so I score `coverage_of_risk` and `regression_power` on what would be caught — which is essentially nothing once a refactor touches any of the logic the acceptance specs don't pin down.

What's notably unguarded:

- **Data transformation layer** — `app/src/lib/data.ts` is 400+ lines of pure, fetch-free-in-spirit transformation logic that is ideal unit-test material but entirely untested: alternate-form exclusion and dedup (`data.ts:76-90`), species↔pokemon ID mapping, version-group ordering and default-game selection (`data.ts:225-240`), method-table grouping and ordering (`data.ts:242-296`), stat total (`data.ts:300`), evolution tree parsing (`data.ts:198-207`).
- **Client-side sort** — the comparator in `app/src/lib/MovesTable.tsx:53-71` implements several spec-tricky rules (missing-values-last in *both* directions, mixed number/string compare, three-state toggle). A one-line "fix" to `return dir * cmp` would silently sort nulls first on descending and no test would fail.
- **URL/search state** — `app/src/routes/index.tsx:24-41` (`validateSearch` page coercion, `page > 1` omission) and the page clamp at `index.tsx:75` (`Math.min(page, totalPages)`); `app/src/routes/pokemon/$name.tsx:8-11` game param validation. Pagination edge cases (page beyond total, `page` = 1 being stripped from the URL) are classic silent regressions.
- **Formatting helpers** — `app/src/lib/format.ts` (`humanize:10-16`, `idFromUrl:35-39` with its NaN path, `latestEnglishFlavor:40-48` whitespace collapse) are the app's most-reused primitives; they currently look correct but nothing locks them in.
- **API/error paths** — `app/src/lib/pokeapi.ts:16-28` caches 404s as `null` for process lifetime and throws on non-ok; the cache-hit-on-rejected-promise path (a rejected promise stays cached, poisoning the process) is untested and is a real production hazard.

The `__root.tsx` not-found wiring, `notFound()` throwing in loaders (`app/src/routes/pokemon/$name.tsx:13-17`), and the head/title logic are likewise only guarded by the acceptance suite.
