I've read the whole app (14 source files) and verified the current TanStack Start stable-release idioms (the app pins `@tanstack/react-start` 1.169.4 — the first stable release — and correctly uses `.validator()` on server functions and `nitro/vite`, matching the official migration guide; nothing here is deprecated API). Here's my review.

## Structure

The app is layered cleanly: `lib/pokeapi.ts` (transport + cache) → `lib/data.ts` (per-page data builders, server-only) → `lib/server.ts` (six thin `createServerFn` wrappers) → `routes/*` (thin view components). `lib/format.ts` and `lib/components.tsx` are shared client-safe helpers. `MovesTable.tsx` isolates the only interactive client state.

## Scenario walkthroughs

1. **Remove Abilities** — delete `routes/abilities/`, then `buildAbilityPage` (app/src/lib/data.ts:369), `getAbilityPage` (app/src/lib/server.ts:23), and the Abilities `<Section>` on the Pokémon page (app/src/routes/pokemon/$name.tsx:129). Nav in `__root.tsx` has no Abilities link, so no header edit. But the hidden-ability plumbing — the `extras`/`hidden` parameter chain in `cardsFromPokemonRefs` (data.ts:66-96), `CardData.hidden`, the `card.hidden` span (components.tsx:73) and `.card-hidden` (styles.css:302) — exists *only* for abilities and would silently become dead code. A handful of scattered but greppable edits; the dead-code trap keeps this from being trivial.

2. **Deoxys sprite bug** — the single seam is `spriteUrl()` (app/src/lib/data.ts:50-52), used by `cardsFromPokemonRefs` (data.ts:83) and `buildHomeData` (data.ts:153). All four card lists (home, move, ability, type) render cards whose sprites come from those two call sites in one file, and `cardsFromPokemonRefs` already centralizes the pokemon-ref → species resolution. One fix covers every list. The only duplication: `HomeSpecies` and `CardData` are two parallel card shapes built with the same `humanize`/`spriteUrl` logic, so a fix in card *construction* (not URL) would land twice.

3. **Sort by name on every card list** — all four lists render through `CardList`/`PokemonCard` (app/src/lib/components.tsx:48-75), so a sort inside `CardList` covers move/ability/type in one edit. The home list is paginated before `CardList` receives it (app/src/routes/index.tsx:74-76), so home's sort must move into the `filtered` memo before the slice — a second, still-obvious file.

4. **Add Items like Moves** — you'd copy the route/loader/head/notFound triple into a new `routes/items/$name.tsx`, add a builder to `data.ts` and a wrapper to `server.ts`. `Section`, `CardList`, `TypeBadgeLink`, `format.ts` helpers and `apiFetch`/`apiList` all stretch to the new resource unchanged. What's copied rather than reused: the ~12-line loader boilerplate that already appears identically in four `$name.tsx` routes, and a per-resource builder (each is ~15 lines and genuinely resource-specific, so some duplication is honest). Note Moves has no `/moves` index route, so `/items`' list page has no in-repo analogue to copy.

5. **Data source / caching change** — one file. `apiBase()` is the only reader of `API_BASE_URL` and the only URL builder (app/src/lib/pokeapi.ts:4-6), and the module-level `cache` Map inside `apiFetch` (pokeapi.ts:14-27) is the only caching layer for API data; `apiList` goes through `apiFetch`. Every endpoint string (`/api/v2/...`) lives in `data.ts`, and sprite URLs route through `spriteUrl` → `apiBase`. The only other caches are router `staleTime` flags in two route files, which is a distinct concern.

## Scores

- **removability: 3** — exactly the "handful of scattered edits" anchor: route dir + data builder + server fn + Pokémon-page section, plus hidden-ability plumbing that would be left dead across three layers.
- **changeability: 4** — sprite and data-source fixes land in one obvious helper; the HomeSpecies/CardData twin is the one place a fix could land twice.
- **coupling: 5** — narrow, explicit seams: transport (pokeapi.ts) vs builders (data.ts, server-only by construction — imported only from `server.ts`) vs DTO-consuming views; client state isolated in `MovesTable` and the home page's URL-driven filters.
- **abstraction_design: 4** — `cardsFromPokemonRefs`, `Section`, `CardList`, `MovesTable` are shaped around real variation (alt-form exclusion, hidden flag, `hasLevel`); the route-loader boilerplate ×4 and duplicated card shape are the copy-paste residue.
- **overall: 4** — a small, well-layered codebase a teammate could safely extend; the friction is duplicated boilerplate, not tangles.
