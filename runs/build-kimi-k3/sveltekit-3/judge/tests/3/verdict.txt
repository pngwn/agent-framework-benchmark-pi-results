## Review — Dimension: test quality

**No tests exist in `app/` at all.** `app/package.json` has no `test` script and no test runner among its five devDependencies (`app/package.json:6-19`), and `grep` for `vitest|playwright|describe(|test(|it(` across `app/src` matches nothing — the only hits are inside `app/build/` build artifacts. The measured facts confirm: 0 test files, 0 cases, 0 assertions. The acceptance suite in `tests/` (not the agent's work) is the only guard, so every finding below is about what will slip through the moment someone refactors.

The app has a substantial amount of genuinely risky, easily-testable logic that is completely unguarded:

- **URL state / filtering / pagination** — `app/src/routes/+page.svelte:19-58`: query parsing with parseInt fallback, page clamping (`shownPage` vs `currentPage`), `updateFilters` dropping `page` on every filter change, `pageHref` re-building params, a 150 ms debounce. This code leans on the new `goto(..., { shallow: true, replace: true })` / `page.shallow.url` API (current idiomatic SvelteKit, verified against the docs), which is exactly the kind of subtle behavior that breaks silently on framework upgrades.
- **Table sorting** — `app/src/lib/components/MovesTable.svelte:37-61`: missing-values-last in both directions, direction flip, stable tie-breaking, and `aria-sort` on the right header (`MovesTable.svelte:66`). Classic regression territory, zero coverage.
- **Move/method grouping** — `app/src/routes/pokemon/[name]/+page.server.js:49-96`: version-group intersection, "default = highest order" via `games.at(-1)`, the `METHOD_ORDER`-vs-alphabetical comparator, per-method row assembly with one row per `(move, version group, method)` detail — note a move learned at two different levels within one version group yields two rows (`+page.server.js:66-78`), a latent correctness question nobody would notice in a refactor.
- **Card building / alternate-form exclusion** — `app/src/lib/server/api.js:113-142` (`speciesCardsFromRefs`: dedupe, `id >= 10000` cutoff, species mapping, hidden flag) and `api.js:104-141` (`getSpeciesMeta`: types reconstructed from *type* records in slot order — a non-obvious derivation).
- **Pure helpers** — `app/src/lib/utils.js:1-35`: `humanize`, `englishName`, `latestEnglishFlavor`, `dexNumber`, `idFromUrl`. These are the cheapest possible unit tests and none exist.
- **Caching** — `api.js:9-30`: 404s cached permanently as `null`, failures evicted on rejection. Untested.
- **Error path** — `app/src/routes/+error.svelte:1-5` renders "Not found" unconditionally, so a 500 would masquerade as a 404; nothing would catch that.

On the criteria as anchored for a no-test submission: `coverage_of_risk` and `regression_power` at 1, `behaviour_not_implementation` at 1 (no tests), `signal_to_noise` at 3 per the anchor.
