## Review — test quality

The measured facts are unambiguous and my exploration confirms them: `app/` contains **zero test files**. `app/package.json:6-9` defines only `dev`, `build`, and `start` scripts; there is no `test` script, no `vitest`/`playwright` in devDependencies (`app/package.json:11-17`), and grep for test idioms only hits build artifacts in `app/build/` and `app/.svelte-kit/`. The app passes because it satisfies the harness-owned suite in `tests/` (Playwright specs for home, layout, pokemon, details), but nothing in `app/` itself would catch a regression the day someone refactors the data layer.

That's a real loss here, because this app is dense with exactly the kind of logic unit tests are good at: a pure data-shaping layer (`app/src/lib/server/api.js`), pure helpers (`app/src/lib/utils.js`), and interactive sorting/filtering (`app/src/routes/+page.svelte`, `app/src/lib/components/MovesTable.svelte`). Notably, the async cache/promises in `api.js` and the pure functions in `utils.js` are trivially testable with no DOM and minimal mocking — the barrier was near zero.

Latent bugs that a small suite would catch, found while reading the untested code:

- **500 rendered as "Not found"**: `app/src/routes/+error.svelte:1-6` hardcodes the title and `h1` as "Not found" regardless of status, so when `api()` throws (`app/src/lib/server/api.js:21` — network failure → 500), the user sees "Not found". No test exercises the API-down path.
- **Default game depends on a sort elsewhere**: `app/src/routes/pokemon/[name]/+page.server.js:43` picks `games.at(-1)` as the default, which is only "highest `order`" because `getVersionGroups` (`api.js:76-87`) sorts ascending. Reorder or sort by id and the wrong game is silently selected.
- **Missing-values-last sorting is fragile**: `MovesTable.svelte:46-53` handles nulls correctly today, but this is the classic spot where a refactor (e.g. applying direction to the missing check, or comparing stringified numbers) flips it; also `aria-sort` on the non-active headers depends on the `undefined` vs `"none"` nuance (`MovesTable.svelte:62`).
- **Shallow-navigation filter sync**: `app/src/routes/+page.svelte:21` reads `page.shallow?.url ?? page.url` and `:52` uses `goto(..., { shallow: true, replace: true })` — a newer Kit API whose semantics (does `page.url` update? does `updateFilters` still reset to page 1?) are completely unguarded. Any change to the debounce (`:59-63`, and the un-cleared timer on destroy) or the param-omission logic in `pageHref` (`:71-77`) would pass silently.

There is also good news worth stating: the riskiest logic is nicely *separable* — pure functions (`humanize`, `idFromUrl`, `latestEnglishFlavor`, `dexNumber` at `utils.js:6-37`) and pure-ish builders (`speciesCardsFromRefs`, `getSpeciesMeta` maps) mean a refactor-friendly unit suite could be added cheaply. The agent chose not to.
