# Review — forward-thinking

## What this code is

A SvelteKit 3 Pokédex: server `load` functions pull from PokeAPI behind one module, Svelte 5 runes + snippets in the templates, plain CSS, zero runtime dependencies. All claims verified against the current (Oct 2026) SvelteKit docs and release notes.

## Current-API verification (sources cited)

- **`goto(..., { shallow: true, replace: true })` + `page.shallow`** — added in SvelteKit 3 (`sveltejs/kit` PR #16449, merged 2026-07; `3.0.0-next.13` notes; documented at svelte.dev/docs/kit/shallow-routing). This is the *replacement* for the now-deprecated `pushState`/`replaceState` and the deprecated `replaceState` option. The app uses the new spelling, not the deprecated one.
- **`defineEnvVars` from `@sveltejs/kit/env` + `$app/env/private`** — the documented current way (svelte.dev/docs/kit/environment-variables: "The `$env/*` modules ... were deprecated in SvelteKit 3 ... in favour of explicit environment variables"). The app does not touch any `$env/*` module.
- **Vite-plugin config** — `sveltekit({ adapter: ... })` in `vite.config.js` is required in SvelteKit 3 (`svelte.config.js` "is no longer supported", svelte.dev/docs/kit/migrating-to-sveltekit-3). Correct, with no leftover `svelte.config.js`.
- **`error(404, 'Not found')`** — the `error(status, message)` signature; `error(status, {...})` was deprecated in SvelteKit 3 (release notes `3.0.0-next.13`). App uses the current form.
- **`page` from `$app/state`** — current since 2.12; runes (`$props`, `$state`, `$derived`, `{#snippet}`/`{@render}`) are the Svelte 5 model.

## Scoring

**`latest_apis` — 5.** This is not just "current for my training data", it's current for *today*: `app/src/routes/+page.svelte:11` reads `page.shallow?.url` and `app/src/routes/+page.svelte:64` does `goto(..., { shallow: true, replace: true })` — an API three months old, used exactly as its release notes prescribe (filters update the URL without re-running `load`). `app/src/env.js:1-14` is the new `defineEnvVars` setup (and correctly `static: false` so `API_BASE_URL` is read at runtime, not inlined at build — a newer and easily-missed subtlety), consumed via `$app/env/private` at `app/src/lib/server/api.js:2`. `app/vite.config.js:7-9` places the adapter in the Vite plugin per the SvelteKit 3 migration; `app/src/routes/pokemon/[name]/+page.server.js:15` uses the new `error(status, message)` signature. No deprecated fallbacks anywhere.

**`platform` — 5.** Platform-first throughout: native `fetch` with a memoized-promise cache (`app/src/lib/server/api.js:15-30`), `URLSearchParams` for all query building (`app/src/routes/+page.svelte:62-70, 84-91`), `Map`/`Set` and `??=` (`app/src/lib/server/api.js:13, 61`), `Array.prototype.at(-1)` (`app/src/routes/pokemon/[name]/+page.server.js:36`), `localeCompare` (`app/src/lib/components/MovesTable.svelte:54`), CSS custom properties for the whole design token set plus intrinsic responsive layout via `repeat(auto-fill, minmax(...))` grids instead of media queries (`app/src/app.css:249, 191` — no `@media` anywhere). `scrollIntoView` rather than manual math (`app/src/routes/pokemon/[name]/+page.svelte:10`). The only hand-rolled bits are a 10-line debounce and the hash-scroll, both trivial.

**`dependencies` — 5.** Zero `dependencies` and exactly the five devDependencies SvelteKit 3 itself mandates: `@sveltejs/kit@3.1.1`, `svelte@^5.57.3` (3.x requires ≥5.57.1), `vite@^8.3.5` (3.x requires Vite 8), `@sveltejs/vite-plugin-svelte@^7.3.1`, `@sveltejs/adapter-node@^6` — confirmed current in the lockfile (`app/package-lock.json:390`). No CSS framework, no state library, no Lodash: filtering/pagination/sorting are ~30 lines of runes. Nothing to remove.

**`churn_resistance` — 4.** Strong architecture: all API access and cache live behind one module (`app/src/lib/server/api.js`) that every route consumes; naming/shape helpers centralised in `app/src/lib/utils.js`; env vars defined in one file (`app/src/env.js`); `#lib` subpath imports (`app/package.json:4-7`) decouple route files from `../..` paths; load functions return small view-model objects (e.g. `app/src/routes/pokemon/[name]/+page.server.js:121-141`) so components won't churn with the API. Two gaps keep it from a 5: there is **not a single type annotation or JSDoc typedef in the codebase** (measured `typeLines: 0`) — the raw PokeAPI shapes are destructure-guessed at call sites, so an upstream shape change fails silently at runtime rather than at build; and the raw-species decoding is split between `api.js` and the route's `load` (`pokemon/[name]/+page.server.js:29-114`), so a second consumer would copy it.

## Findings

1. **medium** — `app/src/lib/server/api.js:20` (and all `load`s) — the PokeAPI boundary is entirely untyped; `api()` returns raw parsed JSON whose shape is implicit in destructuring. Suggestion: JSDoc `@typedef`s (or TS) for species/pokemon/move records — `defineEnvVars` already supports `schema` validation, and the same idea applied to the fetch layer would move breakage from runtime to build time.
2. **low** — `app/src/routes/+page.svelte:66-70` — the 150 ms debounce timer is never cleared on component destruction; a keystroke immediately before navigating away fires `goto` against a stale URL. Use `$effect` cleanup or `$effect(() => () => clearTimeout(searchTimer))`.
3. **low** — `app/src/routes/pokemon/[name]/+page.svelte:7-11` — `onMount` hash-scrolling re-implements router behaviour SvelteKit already handles (svelte.dev/docs/kit/$app-navigation: hash navigations scroll and focus the target; `disableScrollHandling` exists for opting out). This is the one place the app works *against* the framework.
4. **low** — `app/src/lib/components/MovesTable.svelte:82` — `{#each sorted as row (row)}` keys by object identity; fragile if rows are ever rebuilt (e.g. server-sorting later). Key by `row.moveName` + `row.level`.
5. **low** — `app/src/lib/server/api.js:15` — server-side `fetch` has no `AbortSignal.timeout()`; a hung upstream stalls the request indefinitely and the in-flight promise stays in the cache. `fetch(url, { signal: AbortSignal.timeout(10_000) })` is one line.
6. **low** — `app/src/routes/pokemon/[name]/+page.svelte:75-86` — the stat-bar width formula is duplicated inline for stats and the total row; a tiny helper (or a `StatBar` component) would keep the /255 normalisation in one place.
7. **low** — `app/` — no `.gitignore`; `build/` and `.svelte-kit/` artifacts appear to live in the repo alongside `package-lock.json`. Standard SvelteKit template ships one; regenerate with `npx sv create` hygiene.

## Summary

This codebase reads like it was written from the current SvelteKit 3 manual: shallow routing, `defineEnvVars`, Vite-plugin config and the new `error()` signature, with zero runtime dependencies and a clean single-module data layer — upgrades would touch almost nothing. The only meaningful forward-looking gap is the total absence of types at the API boundary, which is the one thing that would make future data-shape changes painful instead of mechanical.
