**Latest APIs — this is genuinely current-generation SvelteKit 3.** Everything the training-data era would call "modern" (and one generation past it):

- Config lives in `app/vite.config.js:1-12` as Kit 3 plugin options with no `svelte.config.js` — the post-2.62 style now mandatory in Kit 3.
- `#lib` subpath imports declared in `app/package.json:6-7` (Kit 3's replacement for the removed `$lib` alias).
- Env vars via `defineEnvVars` in `app/src/env.js:3-9` consumed through `$app/env/private` (`app/src/lib/server/api.js:3`) — the current pattern; `$env/*` is deprecated for removal in Kit 4. Crucially `static: false` is set, so the built artifact reads the env at runtime — exactly what the spec's build-then-run-against-changed-API harness demands.
- Shallow routing uses the *current* API: `goto(..., { shallow: true, replace: true })` at `app/src/routes/+page.svelte:40` (Kit 3 deprecated `pushState`/`replaceState`), and filter state is read from `page.shallow?.url ?? page.url` at `app/src/routes/+page.svelte:12` — this is verbatim the documented shallow-routing pattern. Pagination stays real `<a href>` links, so back/forward still work.
- Runes throughout (`$props`, `$state`, `$derived`, `$derived.by` at `app/src/lib/components/MovesTable.svelte:7,29`), snippets + `{@render}` for the recursive evolution tree (`app/src/routes/pokemon/[name]/+page.svelte:119-130`), `onclick`/`onchange` attributes, no stores, no `on:` directives, no `export let`, no `<slot>` anywhere (grep confirmed).
- `error(404, ...)` called without `throw` in every `+page.server.js` — correct, since it never returns.

The only legacy-flavored spots are the `onMount` hash-scroll hack (`app/src/routes/pokemon/[name]/+page.svelte:9-13`) — SvelteKit's `goto` already scrolls to the URL's `#hash` per the `reset`/hash behavior documented in the routing docs — and a `querySelector` poke in the form submit handler (`app/src/routes/+page.svelte:74`).

**Platform:** solid. Native `fetch` in the server data layer, `URLSearchParams` for all query handling (`app/src/routes/+page.svelte:41,59-65`), native form controls, `Array.prototype.at(-1)` (`app/src/lib/utils.js:32`), `padStart`, `??=`, `Promise.all`, CSS custom properties throughout `app/src/app.css`, CSS grid/flex, logical properties (`padding-inline`, `padding-block`, `app/src/app.css:122-125,155`). No polyfills or libraries covering anything the platform does.

**Dependencies:** zero runtime dependencies; five devDependencies all at the majors Kit 3 requires (kit 3.1.1, svelte ≥5.57.1 → 5.57.3, vite ≥8.0.12 → 8.3.5, vite-plugin-svelte 7, adapter-node 6). Perfectly lean.

**Churn resistance:** data access is confined to `app/src/lib/server/api.js` (caching, list/record fetching, view-model shaping), and every component consumes pre-shaped props, so API-shape changes stay in server files.
