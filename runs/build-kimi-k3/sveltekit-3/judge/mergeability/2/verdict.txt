# Review: Pokédex app (SvelteKit)

## What this app is doing right (and it's a lot)

This codebase is written against **SvelteKit 3 / Svelte 5.57 / Vite 8** — the current stable stack as of today — and it uses the *new* idioms correctly, not the ones from my training data:

- **Config in the Vite plugin, no `svelte.config.js`** — correct for SvelteKit 3 (`app/vite.config.js:6-9` uses `sveltekit({ adapter: adapter() })`, matching the v3 migration guide; `svelte.config.js` is no longer supported).
- **`#lib` subpath imports** (`app/package.json:6-8`, used throughout) — this is the *replacement* for `$lib` announced in the SvelteKit 3 release notes, via standard package `imports` field. Not a home-grown alias.
- **Explicit env vars** (`app/src/env.js` uses `defineEnvVars` from `@sveltejs/kit/env`; consumed via `$app/env/private` at `app/src/lib/server/api.js:2`) — the current recommended replacement for the deprecated `$env/*` modules, with `static: false` correctly chosen so the base URL is read at runtime, which matters because the harness builds once and runs against a changed API.
- **Shallow routing** (`app/src/routes/+page.svelte:45`) — `goto(url, { shallow: true, replace: true })` with `page.shallow?.url` (`:11`) is exactly the pattern the current docs prescribe for URL-driven local state without re-running `load`; the app even knows the documented subtlety that `page.url` is not updated by shallow navigations (comment at `:9-10`).
- **Svelte 5 runes everywhere**: `$props`, `$derived`/`$derived.by`, snippets with `{@render}`, `onclick`, keyed each-blocks, `style:` directive — no legacy syntax at all. Recursive snippet for the evolution tree (`app/src/routes/pokemon/[name]/+page.svelte:118-128`) is idiomatic and neat.
- **Data loading is server `load` + `error(404)`**, with a clean server-only data layer in `#lib/server/api.js` — the directory whose imports SvelteKit blocks from client code, so the server/client boundary is enforced, not just conventional.

## Issues

The one genuine bug class I found is the **unowned debounce timer** (`app/src/routes/+page.svelte:48-52`): typing in search and then clicking a card within the 150 ms window fires `goto('/?q=…', { shallow: true, replace: true })` *after* the app has navigated to the Pokémon page — a shallow URL rewrite behind a different page, with no cleanup on destroy. In Svelte 5 this should be a `$effect` teardown or timer scoped to the component. Everything else is polish: the `+error.svelte` claims "Not found" even for a 500 (API down), the whole 500-line stylesheet is global while its markup lives in components, and pagination uses plain anchors so the ~1025-item species payload is re-serialized on every page click.

No tests in `app/` (0 test files), but the acceptance suite is external per the task setup.
