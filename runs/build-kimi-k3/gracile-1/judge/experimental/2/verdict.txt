I've verified everything I need against the framework's current docs and source. Here's my review of the **experimentalness** dimension.

## Context

Gracile's current stable release is **0.11.0** (published ~6 months ago; `0.11.1-next.2` is the preview channel, per npm/socket). The framework self-describes as **alpha** (docs caution at gracile.js.org/docs/), and genuinely experimental surfaces exist: the CSR add-on ("under an experimental phase", output-modes docs), `@gracile-labs/client-router` ("Experimental. This is not well tested…"), route "premises" (`pages.premises.expose`), and Lit hydration layers. This app touches **none** of those.

## What the app actually uses

- `defineRoute` with `handler`/`document`/`template` — the documented core API (`app/src/routes/index.ts:31-160`, `app/src/routes/pokemon/[name].ts:99-230`). Docs: defining-routes page.
- `handler` context `{ url, params, responseInit }` and `responseInit.status = 404` (`app/src/routes/pokemon/[name].ts:101,110`) — public typed context; confirmed against the framework's own test fixture `packages/engine/__fixtures__/server-express/src/routes/response-init.ts` (sets `responseInit.status`).
- `html` from `@gracile/gracile/server-html` + `<route-template-outlet>` in `app/src/document.ts:1,24` — exactly the documented document shape.
- `gracile.nodeAdapter(handler)` / `gracile.getClientBuildPath(import.meta.url)` in `app/server.js:5,10-11` — verbatim the documented Express pattern (output-modes docs / `minimal-server-express` starter).
- `gracile({ output: 'server' })` in `app/vite.config.ts:5` — documented option.
- Client scripts are **plain vanilla DOM** (`app/src/routes/index.client.ts:16-38`, `app/src/routes/pokemon/[name].client.ts:9-46`) — no hydration, no client router, no islands. The most conservative posture Gracile offers.
- Deps (`app/package.json:6-9`): gracile 0.11.0 (latest stable), lit ^3.3.3 and vite ^8.3.5 — both inside `@gracile/engine@0.12.0`'s declared peer ranges (`vite: ^7.0.0 || ^8.0.0`, `lit: ^3.3.2`). Vite 8.0 went stable 2026-03-12 (>6 months ago), so this is current-stable, not recently-stable.

## The one unstable reliance

`url.hostname === 'gracile-static'` appears in **five handlers** (`app/src/routes/index.ts:35`, `pokemon/[name].ts:104`, `abilities/[name].ts:19`, `types/[name].ts:24`, `moves/[name].ts:28`). This is the internal base URL Gracile's engine uses when it invokes route handlers *at build time* — I confirmed it in the exact released 0.11.0 source (`packages/engine/src/routes/render.ts`, commit cd52d7e: `new URL(pathnameWithParameters, 'http://gracile-static')`) and on current `main`. It is **undocumented** — no mention anywhere on gracile.js.org or in llms.txt. The use is justified: Gracile calls handlers during `vite build` even in server mode, and the spec forbids build-time API fetches, so stubbing is necessary and no documented alternative exists. But it's a private contract duplicated verbatim in five files, and `app/src/routes/types/index.ts:10` has *no* guard at all, so that handler does perform a build-time network fetch (harmless for correctness in server output — build-time props are discarded unless `prerender`/premises are set — but inconsistent and would break under `output: 'static'`).
