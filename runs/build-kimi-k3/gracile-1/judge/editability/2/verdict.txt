I've read the whole app, the spec, the Gracile docs (route definitions, output modes, Express adapter) and the framework engine source (which confirms the `http://gracile-static` build-time handler invocation that the app's stub guards work around). Here's my review.

## Scenario walkthrough

**1. Remove Abilities** — delete `app/src/routes/abilities/` (one file, no sibling client script), and delete the `Abilities` section block in `app/src/routes/pokemon/[name].ts:316-339`. The nav in `app/src/document.ts:16-19` never linked to it. Only residue: `.abilities-list` in `app/public/styles/global.css:402`. Essentially free.

**2. Sprite bug (Deoxys)** — the sprite rule lives in `app/src/lib/species-cards.ts:41` (covers the Moves/Abilities/Types lists) but the home page builds its own `CardData` with its own sprite line at `app/src/routes/index.ts:125`. One bug, two fixes; a maintainer who only fixes `speciesCards` leaves half the lists broken. This is the clearest duplication in the app.

**3. Sort every card list by name** — `species-cards.ts:45` and `index.ts:75` each own an ordering; both are one-line changes, and `cardList` in `app/src/lib/components.ts:46` is a natural single seam if you'd rather do it once. Reasonable.

**4. Items section shaped like Moves** — `app/src/routes/moves/[name].ts` is a self-contained route reusing `api`, `speciesCards`, `section`, `cardList`, `format` and `document`. You'd copy the ~20-line route skeleton (stub guard, 404 try/catch, document wrapper) twice and reuse everything else. The boilerplate that *is* copied is not factored out, but it's small.

**5. API base URL / caching** — everything funnels through `app/src/lib/api.ts`: base at `:8`, concurrency at `:26-48`, cache at `:66-83`. Routes never build raw URLs except via `api(...)`. Best case.

## Notable strengths

- `app/src/lib/species-cards.ts:24` is a genuinely good abstraction: it absorbs three different entry shapes (`move.learned_by_pokemon` bare refs vs. `type.pokemon`/`ability.pokemon` wrapped refs), dedupes per species, drops alternate forms, and passes the raw `entry` through typed so the ability page can read `is_hidden` (`app/src/routes/abilities/[name].ts:30`) without the helper knowing about abilities.
- `app/src/lib/format.ts` is exactly the right size — every display rule the spec names is one named function with a JSDoc example.
- The `gracile-static` guards (`app/src/routes/index.ts:35`, `:19` in the others) look odd but are correct and necessary: Gracile's build invokes every handler with `http://gracile-static` to extract props, and the spec forbids fetching API data at build time. Verified against `packages/engine/src/routes/render.ts` upstream.
- `app/server.js` and `app/vite.config.ts` match the documented Express/server-mode patterns almost verbatim.

## Main deductions

- The home page bypasses the card abstraction and re-implements sprite/types extraction inline (`app/src/routes/index.ts:120-133`).
- All 10 `document`/`template` functions cast `context.props.GET as any` (e.g. `app/src/routes/moves/[name].ts:50,58`), discarding the prop typing `defineRoute` would otherwise infer — rename a handler field and nothing warns.
- The route skeleton (stub guard + 404 try/catch + document wrapper + `englishName` h1) is copy-pasted across all five routes rather than shared.
- `CardData` has grown page-specific optional flags with comments like "home page only" / "ability page only" (`app/src/lib/components.ts:11-22`).
