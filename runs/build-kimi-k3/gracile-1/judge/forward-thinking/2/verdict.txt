I've read the whole app, verified Gracile's current APIs against the 0.11.0 package (npm's latest stable, published ~6 months ago) and the `@gracile/engine` sources, and confirmed the official "Minimal server (Express)" starter. Here's my review.

## Review notes

**What's current.** `app/server.js` is a near-verbatim match for the official `minimal-server-express` starter (`gracile.getClientBuildPath` + `gracile.nodeAdapter`, confirmed against `@gracile/gracile@0.11.0/dist/node.d.ts` and `starter-projects/templates/minimal-server-express/server.js`). Route modules use the current `defineRoute({ handler, document, template })` shape with `responseInit.status` for 404s — exactly the pattern in the docs' annotated example. `@gracile/gracile/server-html` for the document vs `lit` for route templates matches the docs too. Deps are all at the latest stable: Vite 8.3.5 (current, Mar 2026), Lit 3.3.3 (current, May 2026), Express 5.3.0 (current). Four runtime deps, zero extras.

**The one framework-internal coupling.** Five route handlers guard build-time probe renders with `url.hostname === 'gracile-static'`. I traced this to `packages/engine/src/routes/render.ts` in the Gracile repo: `renderRoutes()` invokes `handler.GET` with `new URL(pattern, 'http://gracile-static')` at build time even in server mode (to collect page assets), and the file is marked `@internal`. The public `constants` (`@gracile/engine/server/constants`) do not export this sentinel, and no docs mention it — so it's reverse-engineered behaviour, and it's duplicated across five files rather than centralized.

**Inconsistency.** `/types/` (`app/src/routes/types/index.ts:14`) has no such guard, so `vite build` performs a live `/type/` fetch — a build-time API dependency the spec explicitly discourages, and the one route that behaves differently from its five siblings.

**Typing.** `context.props.GET as any` appears in 8 places (plus `let species: any` etc.), defeating the type inference `defineRoute` is designed to provide — largely because handlers return two shapes (stub + real) so the inferred union can't be narrowed. And there's no `tsconfig.json`, no `typescript` devDependency and no check script in `app/package.json`, so the `.ts` sources are only ever transpiled by Vite, never checked.
