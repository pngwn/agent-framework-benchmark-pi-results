## Review

**Structure & framework use.** This is a clean App Router app: server components fetch data directly, interactivity lives in three small `'use client'` islands (`Controls`, `MovesTable`, `GameSelect`), and `params`/`searchParams` are correctly `await`ed (Next 15+/16 requirement) — `app/app/page.js:13`, `app/app/pokemon/[name]/page.js:122`. `export const dynamic = 'force-dynamic'` on every route is the right call here: it guarantees no build-time prerendering of API data, which the spec explicitly forbids, and remains the documented approach in Next 16 when `cacheComponents` is not enabled. Metadata uses the template API correctly (`app/app/layout.js:5`), 404s go through `notFound()` so status codes and the `not-found.js` route both work. URL-as-state is done properly: server reads `searchParams`, client pushes with `router.replace` from `next/navigation`.

**Data layer.** `lib/api.js` is a single cohesive module: promise-caching with failure eviction (`lib/api.js:53-60`), a bounded concurrency limiter, 404→null semantics, and a genuinely clever derivation of the Pokémon→types map from the 18 type records instead of 1025 per-Pokémon fetches (`lib/api.js:105-121`). The cache on `globalThis` is unbounded in principle but bounded in practice by the fixed API snapshot, and the spec explicitly allows runtime memory caching.

**Risks found.** No error boundary anywhere, so a non-404 API failure (`lib/api.js:36` throws) becomes Next's default error page. Invalid `?type=`/`?generation=` values are silently ignored rather than 404'd (`app/app/page.js:52-63`) — defensible given spec ambiguity but worth a decision. `PokemonCard` builds sprite URLs from a pattern constant instead of the API-provided URLs (`app/components/PokemonCard.js:20`), coupling presentation to the media server's URL layout. Small duplication: the type-label fallback appears in four files, and filter query-string building is duplicated between `app/page.js:69` and `app/Controls.js:21`. `getPokemon` (`lib/api.js:67`) is dead code. `prefetch={false}` is applied to card/detail links but not to the header nav links — inconsistent policy, though the intent (avoid prefetching expensive dynamic pages) is sound.

I'd approve this with nits.
