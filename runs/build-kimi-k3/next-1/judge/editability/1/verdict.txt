## Editability review — Pokédex app (Next.js 16.4.3 / React 19.3.1)

The app is a textbook App Router layout: server components per route, three small `'use client'` leaf components (`Controls.js`, `pokemon/[name]/GameSelect.js`, `pokemon/[name]/MovesTable.js`), all HTTP/caching knowledge in one data-layer module (`lib/api.js`), pure format helpers in `lib/format.js`, and three shared UI primitives. Async `params`/`searchParams` are awaited correctly for the current release. The main softness is mild copy-paste at the page level (the "count + CardGrid + cards" block, the facts `<dl>`, the `typeLabel` lambda, a re-declared `MISSING`) and per-page repetition of route-segment config.

Scenario walkthroughs:

1. **Remove Abilities**: delete `app/abilities/`; remove the Abilities `Section` from `app/pokemon/[name]/page.js:216-226`; delete `getAbility` at `app/lib/api.js:69`. Nav never links to abilities. Essentially the 5-on-the-anchor case. Difficulty 5.
2. **Sprite bug**: the URL is built in exactly one place, `app/components/PokemonCard.js:18`, and all four lists (home, moves, ability, type) render `PokemonCard`, so one fix covers all of them — though if the fix needs default-variety data beyond the species id, `mapToSpecies`/`getSpeciesIndex` in `lib/api.js` must pass it through. Difficulty 4.
3. **Sort by name**: `mapToSpecies` hardcodes dex order at `app/lib/api.js:143`, so either a flag/param there plus a separate change in `app/page.js:67-71`, or four per-page sorts — no shared list component absorbs it. Difficulty 3.
4. **Items section**: the `resource` factory (`app/lib/api.js:64`) makes `getItem` a one-liner; `Section`, `PokemonCard`/`CardGrid` and `lib/format` all reuse cleanly, but the move page's facts `<dl>` and detail-page scaffolding are inline and would be copied. Difficulty 4.
5. **Data source/caching**: `API_BASE_URL`, `MEDIA_BASE_URL`, the cache `store` and `cached()` all live in `app/lib/api.js:7-8,14,54-62` — one file. But Next-level rendering policy is repeated as `export const dynamic = 'force-dynamic'` in all six page files, and `prefetch={false}` is sprinkled across 7 files. Difficulty 4.

One framework note verified against the current release: Next.js 16.4 (current LTS, 16.4.3, Oct 2026) now recommends Cache Components for every app; `dynamic = 'force-dynamic'` still works in the legacy model and isn't wrong, but a future migration to the recommended model touches every page file.
