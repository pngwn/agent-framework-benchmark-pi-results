All source reviewed. The app runs on Next.js 16.4.3 (current stable line) and React 19.3.1, and its entire surface — App Router pages/layouts, async `params`/`searchParams` (mandatory in Next 16), `export const dynamic = 'force-dynamic'`, `generateMetadata`, `notFound()`, `next/navigation#useRouter`, `next/link` with `prefetch={false}` — is made of long-stable APIs. Notably, it deliberately avoids the new stuff in its own release: no `cacheComponents`/`use cache` (confirmed off by default in `app/.next/required-server-files.json:110` showing `cacheComponents: false`, with a hand-rolled in-memory Map cache in `app/lib/api.js:14` instead), no `proxy.ts`, no experimental route handlers, no React experimental hooks. Verified against the Next.js 16 release blog (nextjs.org/blog/next-16), which labels Cache Components as the new opt-in model while Turbopack/App Router async params are stable.
