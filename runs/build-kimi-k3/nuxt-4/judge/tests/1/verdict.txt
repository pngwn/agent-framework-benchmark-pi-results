## Review — test quality

The app contains **zero tests of its own**. Confirmed by search: no `*.spec.*`/`*.test.*` under `app/`, no test runner in `app/package.json` (only `dev`/`build`/`start`), no `vitest`/`@nuxt/test-utils` dependency (devDependencies is empty), and no test config. The only green suite is the repo's Playwright acceptance tests, which the agent didn't write and was told to pass.

That's a real gap because the current Nuxt stable line (4.x, which `app/package.json:6` targets) makes this cheap to do well: `@nuxt/test-utils` (now v4, Vitest v4) provides a Nuxt runtime environment for component tests, and — more importantly for this codebase — the entire data layer (`app/app/lib/pokeapi.ts`) is **pure, framework-free TypeScript** that plain Vitest can exercise with a stubbed `fetch`. The highest-risk logic in the app is exactly there, and none of it is guarded.

### Where bugs would hide

- **Hand-rolled concurrency limiter** — `app/app/lib/pokeapi.ts:49-66`. A manual waiter queue (`waiters.shift()?.()` inside `finally`) gates *every* API call. A refactor that breaks the `finally` release, or swaps `shift` for `pop`, silently hangs SSR or floods the API with 1025+ parallel fetches. No test pins "max 24 in flight, all resolve".
- **Rejected promises cached forever** — `app/app/lib/pokeapi.ts:73-86` (same pattern in `getTypes`/`getIndex`). The promise is memoized *before* it settles, with no eviction on rejection, so one transient 500 permanently poisons that resource (and `getIndex`, which 10 pages depend on) until process restart. No test of the non-404 error path; this latent bug is invisible to the happy-path acceptance suite.
- **Silent-ID extraction** — `app/app/lib/pokeapi.ts:20-23`. `idFromUrl` returns `NaN` on a URL-shape change, which then keys `speciesById` lookups; a data-format drift would render as *missing cards*, not an error. Untested.
- **Index cross-join** — `app/app/lib/pokeapi.ts:132-197`. `buildIndex` joins species ↔ type records ↔ generations for 1025 species, with slot dedupe, slot sorting, and implicit alternate-form exclusion via the `speciesById` lookup. This is the single most refactor-hostile function in the app; any permutation bug shows up wrong-but-plausible.
- **Duplicate card-mapping logic** — `app/app/lib/pokeapi.ts:217-228` and copy-pasted inline in `app/app/pages/abilities/[name].vue:15-24`. Dedupe, form-drop, sort-by-dex; a divergence between the two copies would only be caught by eyeballing pages.
- **URL state on the home page** — `app/app/pages/index.vue:23-27` accepts `page=2abc` as page 2 (`Number.parseInt`), `:38-41` clamps overflow, `:60-68` debounces `q` and syncs it back from `route.query.q`. Pagination/reset/feedback-loop behaviors are classic regression bait, untested.
- **Move-table transformation** — `app/app/pages/pokemon/[name].vue:74-96`: filtering rows by selected version group, deduping move refs, per-method sort orders, `METHOD_ORDER` ranking. Rich in boundary conditions (0 games, level ties, unknown method names).
- **Pure-string helpers** — `app/app/lib/pokeapi.ts:13-18` (`humanize`: `ho-oh`→"Ho Oh", `porygon2`), `:26-37` (`latestEnFlavor`: `\f` collapsing, "last English entry") — one-line test cases each; their absence is the clearest sign tests were never considered.

The acceptance suite does give reasonable coverage of rendered output (roles, headings, counts), so short-term risk is moderate — but the spec explicitly warns the data can change at runtime, and the moment anyone refactors `pokeapi.ts`, nothing in `app/` will catch the breakage.
