I've read the spec, all of `app/`'s source, and confirmed the measured facts on the ground: `app/` contains **zero tests** — no test files, no runner/devDependencies (`app/package.json` has only `dev`, `build`, `start` scripts and `nuxt`/`vue`/`vue-router` deps), and `testLoc: 0`. So this review is about what the acceptance suite won't catch.

**What's at risk, given the code's shape**

- The whole data layer lives in one module, `app/app/lib/pokeapi.ts`, full of pure, easily-testable transformation logic that has no tests: `humanize` (:13), `idFromUrl` (:24), `latestEnFlavor` (:38), `buildIndex` (:155 — type-slot ordering/dedup, generation mapping, alternate-form exclusion via `speciesById`), `speciesCardsForRefs` (:217 — dedup + dex sort + form exclusion). These are exactly the functions someone "refactoring the data layer" would touch.
- The riskiest UI logic: filtering/pagination/URL-state in `app/app/pages/index.vue` (`filtered` :31, `currentPage` clamp :41, `buildQuery` default-omission :44, and the 200 ms debounce watcher at :59-65), and the sortable-table comparator with "missing values last in both directions" semantics in `app/app/components/MoveTable.vue:61-77`. Neither has a single regression guard; a comparator sign flip or a broken clamp would pass green CI forever.
- The Pokémon page aggregator `app/app/pages/pokemon/[name].vue:19-121` encodes many spec rules in code (default version group = highest `order`, `?game` validation, `METHOD_ORDER` then alphabetical, stat `Total`, height/weight ÷ 10) — all untested.
- Notably, `api()` (`pokeapi.ts:67-83`) caches the *promise*, not the result: `cache.set(url, hit)` happens before the fetch resolves, so a transient API failure is cached permanently and every later request for that resource fails until restart. Same pattern in `getIndex` (:147) and `getTypes`. No error-path test would ever have caught this, and there is none.
- 404 handling (`api` returning `null` on 404 :73, per-page `setResponseStatus` in `[...slug].vue` and the three detail pages) is also untested.
- Minor: the ability page reimplements the species-card mapping (`abilities/[name].vue:14-30`) instead of reusing `speciesCardsForRefs`, so divergent bugs between the two paths are invisible without tests.
