## Review

This is a clean, small Nuxt 4 app with a real data-access seam (`app/app/lib/pokeapi.ts`) and component abstractions (`PokemonCard`, `MoveTable`, `EvoNode`, `NotFound`) that cover the app's actual variation. Structure follows current Nuxt conventions: `app/` srcDir (`app/app/…`), `useAsyncData` with route watches, runtime config for `API_BASE_URL`. The main editability costs are copy-paste at the page level: the 404/load/title boilerplate is repeated verbatim in five page files, the type-badge markup is inlined in five templates, and the ability page reimplements a helper that already exists in the data layer.

**Scenario walkthroughs**

1. **Remove Abilities** — delete `app/app/pages/abilities/[name].vue` (a single-file route, no nav link exists at `app/app/layouts/default.vue:8-9`); then strip the links in the Abilities section of `app/app/pages/pokemon/[name].vue:192-199`. Two files, one of which is a deletion. Residual: page-specific CSS blocks in the shared `main.css` would survive.

2. **Sprite bug (Deoxys-style species)** — the sprite URL is derived in exactly one live place, `app/app/components/PokemonCard.vue:23`, and all four card lists render this component, so one fix covers every list. If the fix needs the default variety's data, `SpeciesRef` in `app/app/lib/pokeapi.ts:131` grows a field; callers spread it (`{...species}`) so they ripple automatically — except the trap of `spriteUrl` at `app/app/lib/pokeapi.ts:82`, a dead export that duplicates the URL logic and could tempt a partial fix.

3. **Sort every card list by name** — ordering lives in three places: `speciesCardsForRefs` (moves, types pages; `app/app/lib/pokeapi.ts:203`), the ability page's own inline dedupe+sort (`app/app/pages/abilities/[name].vue:13-21`), and the home page's `pageItems` slice (`app/app/pages/index.vue:47`). Three files, and the ability-page duplication is the reason it isn't two.

4. **Items section shaped like Moves** — high reuse: `api()`, `getIndex`/`speciesCardsForRefs`, `PokemonCard`, `NotFound`, `englishName`/`humanize`/`collapse`, and the shared `.panel`/`.detail-list`/`.card-grid` CSS all transfer. What gets copied is the ~15-line per-page boilerplate (`useAsyncData` + `watch` + `setResponseStatus` + `useHead`, cf. `app/app/pages/moves/[name].vue:29-36`) which was never extracted into a composable.

5. **Change API base / caching** — base URL is centralized in `app/nuxt.config.ts:12-14` + `app/app/composables/useApiBase.ts`; caching (in-memory promise cache + concurrency limiter + three keyed caches) is entirely inside `app/app/lib/pokeapi.ts:52-90`. Changing base is config-only; changing URL *shape* (`/api/v2`, `/media/…`) touches `pokeapi.ts` plus the inline media URL in `PokemonCard.vue:23`. The `base: string` parameter threading through every function and every page is verbose but explicit and greppable.
