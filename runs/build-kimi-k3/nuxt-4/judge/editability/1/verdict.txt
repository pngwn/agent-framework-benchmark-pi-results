## Review: `app/` (Nuxt 4.6.3 — current stable; structure uses the Nuxt 4 `app/` srcDir convention correctly)

**What's here.** A data-access layer (`app/app/lib/pokeapi.ts`), one composable (`app/app/composables/useApiBase.ts`), four components, six route files, one global stylesheet. Layering is clean: pages → `lib/pokeapi.ts` → `fetch` with in-memory caching; components are presentational with narrow props.

### Scenario walkthroughs

1. **Remove Abilities**: delete `app/app/pages/abilities/` (self-contained), then edit `app/app/pages/pokemon/[name].vue` (data mapping ~:89-95 and the Abilities section in template ~:168-176), drop the now-dead `hidden` prop (`app/app/components/PokemonCard.vue:28`), and prune orphaned CSS (`app/app/assets/css/main.css:199`). No nav link exists to remove — a handful of scattered edits.
2. **Sprite bug (Deoxys)**: the sprite URL is built in exactly one place, `app/app/components/PokemonCard.vue:19`, and every card list on every page renders through `PokemonCard`, so one fix covers all lists. The trap: `app/app/lib/pokeapi.ts:83` has an *unused* `spriteUrl` helper that encodes the same knowledge — a fixer who greps for "sprite" could edit the dead helper and ship nothing.
3. **Sort all card lists by name**: three sort sites by dex id — `app/app/lib/pokeapi.ts:203` (index build), `app/app/lib/pokeapi.ts:226` (`speciesCardsForRefs`), and a fork of that logic at `app/app/pages/abilities/[name].vue:21`. No shared "card list" abstraction, so the change is made three times.
4. **Add Items section**: `lib/pokeapi.ts` helpers (`api`, `englishName`, `humanize`, `speciesCardsForRefs`) and `PokemonCard` are directly reusable; but the detail-page skeleton — `load()` + 404 handling + `useHead` title pattern — is copy-pasted verbatim in `moves`, `abilities`, `types` and `pokemon` (`setResponseStatus` incantation at 5 locations), so an Items page is mostly a fresh copy of `app/app/pages/moves/[name].vue`.
5. **Change API base/caching**: caching and the concurrency limiter live entirely in `api()` at `app/app/lib/pokeapi.ts:55-80` (cache is even keyed by base URL, so live-data swaps are safe). Base resolution is `useApiBase.ts` + the `runtimeConfig` default in `app/nuxt.config.ts`. But the media origin is known in two places (inline `PokemonCard.vue:19` and the dead helper), and `base` is threaded as a string through ~10 function signatures and every page.

### Criterion scores

- **removability: 3** — route directories are self-contained and there's no cross-linking nav, but features leak props and CSS into shared files (`PokemonCard.vue:28`, `main.css:199`, the Pokémon page's Abilities section).
- **changeability: 3** — the single-riskiest logic (sprite URL, fetching, caching, move-table sorting) is centralized; but card ordering is triplicated and 404 handling is in five files.
- **coupling: 4** — narrow prop interfaces (`MoveTable` takes `label/rows/showLevel`; `PokemonCard` takes scalars), a single explicit base resolver, server-side fetching confined to `lib/pokeapi.ts`; the global stylesheet and the pervasive `base`/`any` threading are the only tangles.
- **abstraction_design: 3** — `PokemonCard`, `MoveTable`, `EvoNode` are genuinely well-shaped, but `speciesCardsForRefs` couldn't stretch to carry the `hidden` flag and was forked, and the page skeleton is copied rather than shared; adding a fifth resource type is a copy-paste exercise.
