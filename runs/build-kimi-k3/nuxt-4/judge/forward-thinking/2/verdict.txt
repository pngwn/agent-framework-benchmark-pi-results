I've reviewed the app against the spec, the Nuxt 4.6.3 docs/release notes (the current stable — released 2026-10-27, three days ago), and the h3 v2 migration guide. Here's my review.

## Review

**What ages well:**
- The app is on the **latest stable Nuxt** (`^4.6.3`, `app/package.json:8`) and uses the Nuxt 4 project layout (`app/app/app.vue`, `app/app/pages/…`, `app/app/layouts/default.vue`) that matches the framework's current `srcDir` default — not the Nuxt 3-era root layout that would churn on upgrade.
- Current data-loading primitive everywhere: `await useAsyncData(key, handler, { watch: [...] })` with param-reactive keys (`app/app/pages/pokemon/[name].vue:116`, `app/app/pages/moves/[name].vue:26`), exactly the documented pattern for reactive route params.
- All data access is behind one module, `app/app/lib/pokeapi.ts` (fetching, caching, normalization, humanize/englishName helpers), with the API origin resolved in a single composable (`app/app/composables/useApiBase.ts`). Changing the API or its base URL touches one or two files.
- Platform-first: native `fetch` (`app/app/lib/pokeapi.ts:112`), `Map`/`Set`/`Promise`-based caching and concurrency limiting, CSS custom properties from tokens plus logical properties (`padding-inline`, `margin-inline`, `app/app/assets/css/main.css:42`) and `grid-template-columns: repeat(auto-fill, minmax(...))` (`main.css:129`) — no CSS framework, per spec.
- Dependency surface is 3 runtime deps, zero dev fluff.

**What will churn:**
- The 404/`setResponseStatus`/`useRequestEvent`/`useHead` block is copy-pasted across five pages (`app/app/pages/[...slug].vue:6-7`, `pokemon/[name].vue:120-128`, `moves/[name].vue:31-38`, `abilities/[name].vue:36-43`, `types/[name].vue:45-52`). One composable would make the h3 v2 change (`setResponseStatus` → `event.res.status`, per https://h3.dev/migration) and any error-page redesign a one-file change.
- The API boundary is untyped: `api(): Promise<any>` (`app/app/lib/pokeapi.ts:112`) with `any` casts throughout the loaders (`pokemon/[name].vue:57`, `rec: any` at :68); `MoveRow` is defined only in the component (`app/app/components/MoveTable.vue:2`) while the page constructs rows untyped. If PokeAPI's shape moves, TS can't catch it.
- The `useAsyncData` handlers ignore the `(_nuxtApp, { signal })` signature the current Nuxt 4 docs show (`https://nuxt.com/docs/4.x/api/composables/use-async-data/`) — in-flight client refetches aren't aborted.
- `vue-router` as a direct dependency is redundant; Nuxt resolves it itself.
- Minor: `idFromUrl` regex-parses URLs (`app/app/lib/pokeapi.ts:24`) instead of using the `URL` API.
