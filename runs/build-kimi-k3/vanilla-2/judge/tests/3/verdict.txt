Confirmed facts: `app/` contains **zero test files** (no test runner in devDependencies, no `test` script in `app/package.json:5-8`, no spec/assert/test imports anywhere in `app/src`). The app is a server-rendered vanilla-JS site with a genuinely testable architecture — pure, side-effect-free helpers in `app/src/shared/` (`format.js`, `home-view.js`, `router.js`, `components.js`) deliberately shared between SSR and client — but not one of them has a unit test, and all protection comes from the harness-owned `tests/` suite.

## Review notes

**What exists.** The one smart decision from a testability standpoint is the `shared/` layer: filtering, pagination, URL-state parsing and all formatting helpers are pure functions usable in Node with no DOM or network (`app/src/shared/home-view.js:8,19,29,38`, `app/src/shared/format.js:3-40`). Writing tests for these would have cost minutes and caught real regressions; the agent wrote none.

**The highest-risk untested logic** (what breaks once someone refactors the data layer):

- **Home filtering/pagination/URL state** — `filterSummaries`/`homeResultsHtml`/`parseHomeState`/`homeQueryString` (`app/src/shared/home-view.js:8-59`). The `slice((page-1)*48, page*48)` off-by-one, `Math.ceil` total-pages, the clamp at `home-view.js:44` (a URL with `?page=999` renders page 1's content but keeps `page=999` in the query — an inconsistency no test pins down), `q` values containing `&`/`+`/`#`, and default-param omission would all regress silently.
- **Client-side table sorting** (`app/src/client/main.js:73-102`) — numeric-vs-text dispatch, missing-values-sort-last in *both* directions, direction flip, and `aria-sort` housekeeping. Any of the three acceptance tests touching sorting covers only one happy path; a refactor of this comparator would pass on the cases the suite samples while breaking missing-value ordering or descending numeric sorts.
- **Species↔Pokémon mapping and alternate-form exclusion** (`app/src/server/api.js:138-155`) — the `id >= 10000` threshold, and the fallback branch at `api.js:144-147` (Pokémon id with no matching species id) which is effectively dead in the shipped data — precisely the kind of path a data-layer refactor breaks with no signal.
- **Hidden-ability marker mismatch** (`app/src/server/pages.js:335-342`) — the map is keyed by **Pokémon id** (`idFromUrl(entry.pokemon.url)`) but looked up by **species id** (`hiddenBySpecies.get(species.id)`). These coincide only because of the default-variety convention; on the fallback path in `speciesForPokemonRef` (where `species.id` comes from `pokemon.species.url`) the "Hidden ability" marker silently disappears. No test would catch this.
- **Route matching** (`app/src/shared/router.js:7`) — `decodeURIComponent` throws `URIError` on malformed escapes (`/pokemon/%`), which escapes to the 500 handler in `app/server/server.mjs:85-88` instead of the 404 page. Not-found handling is tested only for well-formed names.
- **Debounce ↔ popstate race** (`app/src/client/main.js:36-59`) — type "cha", immediately hit Back: the pending 200 ms debounce fires after the `popstate` render and re-renders with the stale query while the URL shows the previous state. Timing-sensitive and completely unguarded.
- **Cache/eviction logic** (`app/src/server/api.js:15-40,72-76`) — the `promise.catch(() => cache.delete(path))` retry-on-failure pattern and the `summariesPromise` reset are exactly the lines a refactor of `getJson` would drop (leaving a permanently rejected cached promise), with no test to notice.
- **API-failure paths** — every render failure collapses to a bare `text/plain` 500 (`app/server/server.mjs:87`). Nothing exercises what a user sees when the API is down or returns 500s.
- **Text/number formatting** (`app/src/shared/format.js:8-40`) — `collapseWhitespace` on `\f`, `latestEnglishFlavor` mixed-language ordering, `formatMeters` rounding, `dexNumber` padding: all trivially fuzzable, all untested.
