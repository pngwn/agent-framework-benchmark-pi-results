## Review: test quality

**Confirmed:** `app/` contains zero tests — no test files, no runner in `devDependencies` (only `vite`, app/package.json:12), no `test` script (app/package.json:6-9). Static facts agree (`tests.files: 0`). The agent relied entirely on the acceptance suite in `tests/` (which it did not write and which lives outside `app/`).

The app is unusually testable for a vanilla-JS project — most of its logic lives in pure modules (`src/shared/format.js`, `src/shared/home-view.js`, `src/shared/router.js`, `src/shared/components.js`) that were clearly extracted *for* SSR/client reuse, yet none of them got a single unit test. That's a missed opportunity, not an accident of architecture: these functions have no DOM or network dependencies and would have cost a `vitest` install plus an afternoon.

The riskiest untested code:

- **Home filtering/pagination/URL round-trip** (`app/src/shared/home-view.js:7-56`): case-insensitive humanized-name search, type/generation filters, page clamping (`Math.min(Math.max(1, state.page), totalPages)`), and `homeQueryString` default-param omission. A refactor that drops the `humanize()` inside `filterSummaries`, or stops clamping `page`, passes type checks and breaks silently at runtime.
- **Species summary build & alternate-form exclusion** (`app/src/server/api.js:78-131`): generation back-mapping, the `id >= 10000` alternate-form cutoff (`api.js:117`), dedupe-by-species-id in `speciesCardsForPokemonRefs` (`api.js:139-147`), and sort by dex id. This is exactly the layer the "live data overlay" acceptance test guards — once that fixture is gone, nothing catches a broken cutoff or dedupe.
- **Moves section** (`app/src/server/pages.js:123-199`): method ordering (`Level Up, Machine, Egg, Tutor, then alpha`), default game = highest `order`, level-up sort by level-then-name, missing-value rendering. Pure ordering logic, zero coverage.
- **Client DOM sorting** (`app/src/client/main.js:84-110`): sorts by parsing rendered cell text (`Number(text)`, `'—' → null`), so it silently couples to markup; a template change breaks ordering with no test to notice.
- **XSS guards** (`app/src/shared/format.js:31-40`): `escapeHtml`/`escapeJsonForHtml` protect every interpolated value; a refactor that skips one creates an injection hole nothing would catch.
- **Error paths**: `renderPage` only catches `NotFoundError` (`app/src/server/pages.js:400-405`); a species with empty `varieties` throws a raw `TypeError` at `pages.js:216` and surfaces as a bare 500 (`app/server/server.mjs:89-95`). Untested today, plausibly a live bug tomorrow.
- **Cache semantics** (`app/src/server/api.js:23-31`): promise caching with delete-on-rejection is correct-looking but subtle; a refactor could easily cache a rejected promise forever.
