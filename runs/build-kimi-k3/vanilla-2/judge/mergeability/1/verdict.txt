## Review

**Architecture:** SSR by a small Node `http` server that string-templates HTML from live API fetches, plus a thin Vite client bundle for home filtering, table sorting and the game selector. The `src/shared/` layer (`format.js`, `components.js`, `home-view.js`, `router.js`) is genuinely shared between server and client, which eliminates the classic SSR/CSR markup-mismatch risk — the client re-renders the home list with the *same* functions the server used (`app/src/client/main.js:24-26`, `app/src/shared/home-view.js`). That's the strongest design decision here.

**Idiom:** Correct, current Vite (8.3.5, matching npm `latest`); manifest-based backend integration is exactly what the docs prescribe; `fetch`/`URL`/`URLSearchParams`/native form controls/delegated events throughout; no build-time data fetching (spec constraint honored); escaping discipline is consistent. The one non-idiomatic choice: `npm run dev` bypasses Vite's dev server and hand-serves raw sources — which breaks, because `app/src/client/main.js:2` does `import './styles.css'` and browsers reject a `text/css` module. In dev the whole client script fails, killing filtering/sorting/game-select on that path. Production (`build` + `start`) is unaffected.

**Correctness:** Production path is solid: single-flight promise caches with failure-eviction (`app/src/server/api.js:15-32`), bounded parallelism (`mapLimit`), 404 → `NotFoundError` → 404 page, path-traversal guard in the static handler, `escapeJsonForHtml` correctly defuses `</script>`. Minor rough edges: `page` param stays out-of-range in the URL while content clamps; HEAD returns a body; empty `varieties` would 500; the home page inlines the entire 1025-species summary JSON in every response with `Cache-Control: no-cache`.

**Abstractions:** Boundaries are clean (server-only `api.js`; pure shared template/format layer; client imports nothing server-side). The repeated promise-memoization idiom appears four times with slight variations in `api.js` — a `memoize(fn)` helper would collapse them. `pages.js` is one 460-line module holding all five page renderers; well-sectioned, but worth splitting per page as it grows. The DOM-id contract between the SSR template and the client script (`species-data`, `filter-*`, `game-select`) is a magic-string coupling with no shared constants.
