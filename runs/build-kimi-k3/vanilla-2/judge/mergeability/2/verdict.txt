I've reviewed the app thoroughly against the spec, the current Vite 8 docs (Vite 8.3.5 is the current stable, and the app uses it correctly — `build.manifest` + reading `dist/.vite/manifest.json` is the documented backend-integration pattern), and the code itself. This is a well-structured vanilla-JS SSR app: `src/server/` (data + pages + layout), `src/shared/` (pure helpers reused by browser bundle), `src/client/` (progressive enhancement only), served by a small Node HTTP server that reads the Vite manifest for hashed assets.

Notable issues found while reading:

- **Dev mode is broken**: `app/src/client/main.js:2` does `import './styles.css'`, which only works after Vite transforms it — but `npm run dev` (`app/server/server.mjs`) serves raw source files directly instead of running Vite's dev server. The CSS import fails as a JS module, killing the whole module graph, so search, selects and sortable tables are dead in dev. The Vite docs' recommended pattern for this architecture is to mount Vite's dev server middleware in dev.
- **Production leaks server source**: `app/server/server.mjs:46` serves any path under `/src/` unconditionally (not just in the dev fallback), so `GET /src/server/api.js` returns server-side source in production.
- **`decodeURIComponent` in `app/src/shared/router.js:8` can throw `URIError`** on `/pokemon/%`, which the server turns into a 500 instead of a 404.
- Smaller things: the full species dataset is embedded as JSON in every home-page response (`app/src/server/pages.js:66`); `speciesCardsForPokemonRefs` awaits serially in a loop (`app/src/server/api.js:138`); the search debounce timer isn't cleared on `popstate` (`app/src/client/main.js:40`); HEAD requests get the full body computed and written (`app/server/server.mjs:88`).

On the plus side: consistent `escapeHtml`/`escapeJsonForHtml` usage everywhere data touches templates, bounded concurrency via `mapLimit`, failed cache entries evicted so retries work (`app/src/server/api.js:31`), path-traversal-safe static serving, real 404 statuses, and a genuinely good abstraction in `src/shared/home-view.js` that guarantees server and client render identical markup for the home page.
