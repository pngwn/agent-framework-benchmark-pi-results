I've now reviewed the whole app and verified every framework API against Gracile's current release and docs. Here's my assessment for the **experimentalness** dimension.

## What I verified

**Framework channel and version.** `@gracile/gracile` in `app/package.json:5` is `^0.11.0`, which is exactly npm's `latest` dist-tag (0.11.0, published ~Apr 2026); the lockfile (`app/package-lock.json:506`) pins 0.11.0 exactly. The app does **not** use the `next` channel (0.11.1-next.2). Caret on 0.x only admits 0.11.x, so it won't drift into breaking 0.12 minors.

**Every imported API is current and documented, none experimental:**
- `defineRoute` from `@gracile/gracile/route` (`app/src/routes/index.js:1`, all route files) — matches the framework's annotated example verbatim.
- `html` from `@gracile/gracile/server-html` (`app/src/document.js:1`, `views.js:1`) — same, re-exported from `@lit-labs/ssr`.
- `nodeAdapter` / `getClientBuildPath` / `printUrls` from `@gracile/gracile/node` (`app/server.js:3,10,13`) — confirmed present in `packages/gracile/src/node.ts` on the framework's main branch.
- `gracile({ output: 'server' })` vite plugin (`app/vite.config.js:3`) — the documented standard SSR option; no experimental flags anywhere.
- `context.responseInit.status` (`app/src/routes/pokemon/[name].js:90`, etc.), `<route-template-outlet>` (`app/src/document.js:26`), and the `*.client.js` route-adjacent bundle convention (`app/src/routes/index.client.js`) all match the official annotated example.
- The measured facts' `experimental` array is empty; no `unstable_`/`experimental_` names exist in the repo.

**The one systemic caveat:** Gracile's own docs state "This project is in an **alpha** state" — it's a 0.x framework (since May 2024), so every page rests on pre-1.0 API surface. That was mandated by the assignment, not an agent choice, and the agent took the most conservative path available: plain SSR + **vanilla** progressive enhancement (`fetch`/`DOMParser`/`history.pushState` in `index.client.js:29-53` and `pokemon/[name].client.js:10-25`) instead of Gracile's newer, riskier features (client-side routing, Lit hydration/islands, JSX templates, the `@gracile/markdown` add-on which is explicitly marked "API subject to changes"). Domain logic (`lib/api.js`, `lib/data.js`, `lib/util.js`) has zero framework imports, so it survives framework churn.

**Other deps:** lit 3.3.3 (current latest), vite 7.3.7 (latest major is 8.3.5, but Gracile's own peer range is `^7.0.0 || ^8.0.0`, so this is a supported stable line), express 4.22.3 (the maintained `latest-4` line). All stable, mildly conservative — nothing experimental.
