## Review: forward-thinking

**Framework version & APIs.** The app pins `@gracile/gracile@^0.11.0`, which the npm registry confirms is the current `latest` dist-tag (next is `0.11.1-next.2`). Every Gracile API used matches the current docs and official starter: `defineRoute` with `handler`/`document`/`template` (docs "Defining routes"), `context.responseInit.status` and `context.props.GET` (docs "Handle forms" recipe), `html` from `@gracile/gracile/server-html` (routes-and-documents reference), and `server.js` is a near-verbatim copy of the current `templates/minimal-server-express` starter, including `gracile.nodeAdapter`, `getClientBuildPath`, `printUrls` and `gracile({ output: 'server' })` in the Vite plugin. File conventions (`[name].js`, `[name].client.js`, `index.js`, `404.js`) are all current; the official starter itself ships `src/routes/404.ts`.

**Platform.** Server data access uses native `fetch` with a promise-caching `Map`; the client scripts use `fetch`, `URLSearchParams`, `URL`, `history.pushState`/`popstate`, `DOMParser`, event delegation, and the filter form works without JS via native GET. CSS is plain custom-properties + grid. The one hand-rolled choice where a platform primitive exists: a `requestId` counter guards stale responses instead of `AbortController`, so in-flight requests are never cancelled.

**Dependencies.** Two majors behind current: `express ^4.21.2` (current 5.2.1; the Gracile starter uses `express ^5.0.1`) and `vite ^7.1.0` (current 8.2.2, and `@gracile/gracile@0.11.0` already peers with `^7.0.0 || ^8.0.0`). `lit ^3.3.2` is declared but never imported — the app uses only server-html templates and no custom elements, so it's starter leftover.

**Churn resistance.** Data access is fully behind `src/lib/api.js`/`src/lib/data.js`, the API base URL lives in one place, and no framework internals are touched — an upgrade would touch `server.js` only because the starter changes. Weak spots: zero types (no TS, no JSDoc) on the large handler→template props boundary where `defineRoute` would otherwise give inference; a `typeNames` Map→object→Map round-trip repeated in all five routes; and built `dist/` present in the working tree with no `.gitignore` covering it.
