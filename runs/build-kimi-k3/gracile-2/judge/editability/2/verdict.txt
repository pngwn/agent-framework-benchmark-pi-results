## Review: editability of `app/` (Gracile 0.11 + Lit)

I read `SPEC.md`, all 15 source files in `app/src/`, the API data for the Deoxys case, and verified against the current Gracile stable release (0.11.0, published ~6 months ago — the app pins `^0.11.0`, and its `defineRoute({handler, document, template})`, `[param].js` / `[param].client.js` / `index.js` route conventions, `@gracile/gracile/server-html#html` and the Express node adapter in `app/server.js:1-17` are all current-stable idioms, so nothing here is judged against an outdated Gracile).

### Scenario walkthroughs

1. **Remove Abilities** — delete `app/src/routes/abilities/` (one file); the only remaining inbound links are the Abilities section in `app/src/routes/pokemon/[name].js:291-300` (template) and its data at `:199-205` (handler). Nav (`app/src/document.js:15-18`) only links Pokémon/Types, so no nav edit. Two edits in one extra file, all intrinsic to the feature. Difficulty 5.
2. **Sprite bug (Deoxys-class)** — every card list renders through `pokemonCard` (`app/src/lib/views.js:12-54`), so the render fix is one seam. But the sprite is *constructed from a URL pattern* (`views.js:6-7`, used at `:24`) rather than taken from the default Pokémon's `sprites.front_default`; the full Pokémon resource is already fetched inside `pokemonRefsToSpecies` (`app/src/lib/data.js:60-70`) and discarded, so threading the real URL through touches `data.js` + `views.js` (the home list in `app/src/routes/index.js:149-153` would keep the pattern unless it also fetches Pokémon). Notably the Pokémon page already does it right for artwork (`pokemon/[name].js:103-105`). One conceptual fix, 2–3 files. Difficulty 4.
3. **Sort all card lists by name** — there is no shared "render a species list" helper; the `cardList(arr.map(s => pokemonCard(...)))` expression is repeated in four routes (`routes/index.js:149`, `routes/moves/[name].js:118`, `routes/abilities/[name].js:83`, `routes/types/[name].js:84`), and ordering lives in `data.js:53` and `data.js:77`. You'd edit all four call sites (or first extract a helper). Difficulty 3.
4. **Items section like Moves** — the lib layer (`api.js`, `util.js` pure formatters, `views.js` cards/not-found, `data.js` `pokemonRefsToSpecies` with its `extraOf` callback) is fully reusable; but Moves has no generic "resource page" abstraction — the handler/404/document boilerplate (`moves/[name].js:35-38, 66-68`) and domain-specific dl/tables must be re-written/copied into two new route files. Difficulty 3.
5. **Change API base / caching** — base URL (`api.js:6-8`), the cache Map and its eviction-on-error (`api.js:10, 16-20, 30-38`), and list pagination (`api.js:26-28`) are all in one file; `views.js:6-7` correctly imports `apiBase` from it rather than re-reading the env var. Difficulty 5.

### What's good
- Genuine, purposeful abstractions: `pokemonRefsToSpecies(refs, extraOf)` (alt-form exclusion, dedupe, dex ordering, caller payload) serves three pages; `pokemonCard`'s `options.types`/`options.note` (`views.js:15-17`) models the real variation (type badges on home, "Hidden ability" note) without flag creep; `util.js` is all pure one-liners.
- Clean server/client split: `.client.js` files are pure DOM progressive enhancement over element IDs, sharing no state with the server templates.

### What costs you
- Duplicated boilerplate across routes: the `typeNames` Map→`Object.fromEntries`→`new Map(Object.entries(...))` dance appears in all five routes (e.g. `routes/moves/[name].js:58` and `:69`); the 404/`document` wiring block is copied in four routes; `option()` is defined twice (`routes/index.js:15-18`, `pokemon/[name].js:30-33`); the client `refresh()` fetch/DOMParser/replace helper is near-identical in `routes/index.client.js:20-32` and `pokemon/[name].client.js:12-25`.
- `app/src/routes/pokemon/[name].js` is a ~330-line route mixing five concerns (summary, stats, abilities, evolution, version-group/moves logic at `:122-196`), so targeted edits require navigating a large handler.
- Minor dead code: unused `apiBase` import (`pokemon/[name].js:5`).
