I've reviewed the app against Gracile 0.11 (current stable, published Apr 2026 — its `defineRoute` / `handler` / `document` / `template` / `route-template-outlet` / express `nodeAdapter` APIs all match what the app uses, so the framework usage is idiomatic and current). Here's my assessment focused on editability.

## Review notes

**Structure**: Clean file-based routing (`routes/index.js`, `routes/[name].js`, `routes/[name].client.js`, `routes/404.js`), a shared `document.js` layout, and four small lib modules (`api.js` fetch+cache, `data.js` domain queries, `util.js` formatters, `views.js` shared fragments). All four Pokémon-card lists (home, moves, abilities, types) render through one `pokemonCard` helper (`app/src/lib/views.js`), and all "Pokémon refs → species" resolution goes through one `pokemonRefsToSpecies` helper (`app/src/lib/data.js:47`–73). These are the right seams.

**Where change gets harder**: every route handler fetches `getTypeNames()` and flattens the Map to `Object.fromEntries`, then every template rebuilds `new Map(Object.entries(...))` — 10 occurrences across 5 route files; `option()` is defined twice; the 404 flow (`context.responseInit.status = 404` + `{notFound: true}` + template guard) is repeated in 4 routes; the fetch/DOMParser/replaceWith refresh routine exists in both client scripts; the moves/abilities/types detail pages are structurally near-identical (~140 lines each) with no shared page-level helper, so an Items section would be mostly a copy of `moves/[name].js`.

## Scores

**removability — 4**: Abilities is a route directory plus one section on the Pokémon page and one shared-CSS edit. No nav link, no data-layer references. `app/src/routes/abilities/[name].js` is fully self-contained; `app/src/routes/pokemon/[name].js:197`–204 (handler) and `:291`–302 (template section) need deleting; `app/public/styles/app.css:387`–394 shares selectors with `.evolution-tree`, so it's an edit, not a delete. Near the "delete a dir and a link" ideal, minus the shared CSS.

**changeability — 4**: Sprite fix lands in one render site (`app/src/lib/views.js:6`–7 `spriteUrl`, used by `pokemonCard` at `views.js:14`, which all four card lists call). Caveat: the card only receives `{speciesId, speciesName}`, so a data-driven fix (use `pokemon.sprites.front_default`) would also touch `app/src/lib/data.js:52`–57 (which already fetches each Pokémon but discards sprites) and the home page's data path, since `app/src/routes/index.js:75` never fetches per-Pokémon data — three files, though the markup edit is still one place. Minor dings: duplicate `option()` (`app/src/routes/index.js:17`, `app/src/routes/pokemon/[name].js:30`), duplicate client refresh (`app/src/routes/index.client.js:24`–36` vs `app/src/routes/pokemon/[name].client.js:18`–30).

**coupling — 4**: Narrow, explicit interfaces: routes import only `api`/`data`/`util`/`views`; server/client split is clean (client scripts are pure progressive enhancement over full GET navigation, no shared state); the props boundary is respected. Tangles: `views.js:3` imports `apiBase` from the API client (template layer knows the media host — defensible for absolute sprite URLs, but it's a cross-layer import), the typeNames Map→object→Map dance repeated in every route (`app/src/routes/moves/[name].js:58`/`69`, `abilities/[name].js:46`/`57`, `types/[name].js:64`/`75`, `index.js:86`/`99`, `pokemon/[name].js:209`/`220`), and `app/src/routes/pokemon/[name].js:5` imports `apiBase` unused.

**abstraction_design — 3**: The component-level abstractions stretch well — `pokemonCard` grew `types`/`note` via an options object rather than flags (`app/src/lib/views.js:14`–44), and `pokemonRefsToSpecies(refs, extraOf)` adapts to three consumers (`app/src/lib/data.js:47`). But route-level structure didn't get abstracted: the moves/abilities/types pages duplicate the fetch→404→props→facts-`dl`→sections→card-grid shape (`app/src/routes/moves/[name].js` vs `app/src/routes/abilities/[name].js`), the 404 sequence repeats 4×, and card-list *ordering* lives in two separate data paths (`data.js:46`, `data.js:73`). Adding an Items section means copying a route, not reusing one — real copy-paste, the anchor for a 3.
