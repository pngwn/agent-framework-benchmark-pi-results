## Review — test quality

The app ships **zero tests of its own**. `app/package.json` has no `test` script, no test runner in devDependencies (`app/package.json:6-15`), and there are no test or spec files anywhere under `app/` (confirmed by `find` and the measured `tests: {files: 0, cases: 0}`). All verification came from leaning on the acceptance suite in `tests/`, which the agent doesn't own.

That's a missed opportunity because the riskiest logic here is remarkably testable. The codebase is a clean split of pure data functions (`app/src/api.js`) and route handlers on a plain `Hono` app, and Hono's own current guidance (skill doc, `hono/testing` `testClient`, and the noted `app.request()` — "no server startup needed") means every route could be exercised in-process with `node:test` and a stubbed `apiFetch`, no browser required. The pure helpers (`humanize`, `latestEnglishFlavor`, `toSpeciesList`, `sortedRows`, pagination math) need no mocks at all.

Specific untested risks I traced:

- **`app/src/app.js:153-167` (`sortedRows`)** — the null-handling ("missing values sort last in both directions") plus `sign * cmp` over mixed number/string keys is exactly the kind of comparator that silently breaks on refactor. Descending string sort via negated `localeCompare` and the `va == null` short-circuit ordering are both easy to get wrong.
- **`app/src/app.js:196-202`** — the ability hidden-flag merge (`existing.hidden && entry.is_hidden`) implements "a non-hidden entry wins when a species appears twice". It's correct today but subtle; a refactor to "last entry wins" would flip `Hidden ability` badges with no failing test in `app/`.
- **`app/src/api.js:97-135` (`buildIndex`)** — type/generation enrichment keyed on `idFromUrl`, alternate-form exclusion via the `byId` species map, and slot-order type sorting. A regression here (e.g. dropping the `slot` sort, or matching by name instead of id) corrupts *every* list page at once.
- **`app/src/api.js:140-151` (`toSpeciesList`)** — dedupe-by-id plus dex-number sort; the acceptance tests only spot-check a few pages, so a broken dedupe would show up as duplicated cards on large moves/types pages only.
- **`app/src/app.js:59-66` + `app/src/views.js:145-160`** — page parsing (`parseInt`, clamp to `[1, totalPages]`) and the `pageUrl` builder that must omit default/empty params. Edge inputs (`page=abc`, `page=999`, `page=0`) have no guard tests.
- **`app/public/app.js:3-7`** — the `htmx:configRequest` hook that strips empty form params is the only thing keeping pushed URLs free of `type=&q=`; it's one small client file with disproportionate URL-state impact and no test (a Playwright-level check exists in the acceptance suite, but nothing in `app/`).
- **`app/src/api.js:19-25`** — cache stores the promise and deletes on rejection; a refactor that cached rejected promises (or forgot the delete) would poison every subsequent request for that resource. Also a tiny race: a concurrent `apiFetch` for the same URL in the same tick can still receive the rejected entry before the `.catch` microtask deletes it.
- **`app/src/app.js:143-150`** — the `/pokemon/:name/moves-table` fragment route returns the full not-found *document* as the table swap body when `method` doesn't match; the error path of an htmx endpoint is untested and visibly broken if hit.
- **`app/src/app.js:180-182`** — the effect fallback chain (`short_effect` → flavor → `—`) for moves; a reordering here changes rendered text with no local test.
