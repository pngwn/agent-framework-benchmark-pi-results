# Review: `app/` (editability)

A tidy, idiomatic SvelteKit 2 / Svelte 5 runes app: all fetching lives in `+page.server.js` files backed by two server modules (`lib/server/api.js` for transport+caching, `lib/server/data.js` for assembly), shared components (`Section`, `CardGrid`, `PokemonCard`, `MoveTable`, `EvolutionNode`) are small and prop-driven, and SvelteKit's file conventions do the routing work. It's the kind of code I'd accept in a PR with small comments.

**Scenario walkthroughs** (all verified against the data and routes):

1. **Remove Abilities** — delete `app/src/routes/abilities/`, then remove the Abilities section (`app/src/routes/pokemon/[name]/+page.svelte:82-90`) and its data assembly (`app/src/routes/pokemon/[name]/+page.server.js:43-49`). No nav link, no shared helper becomes dead. Two edits + one directory delete.
2. **Sprite bug (Deoxys)** — the wrong sprite comes from `speciesFromPokemonRefs`: whichever alternate form resolves first donates its `front_default` (e.g. `10002.png` for `deoxys-defense`, which *is* shipped in `data/media/sprites/pokemon/10002.png`) to the species card (`app/src/lib/server/data.js:57` via `spriteFor`, `data.js:29-31`). All three ref-based lists (moves, abilities, types) funnel through this one function, so one fix covers them; the home list (`+page.server.js:57`) uses the default-Pokémon record and is already correct. The fix is central, but you must understand `spriteFor`'s mixed record+id contract not to break the null-sprite fallback.
3. **Sort by name** — the ref-based lists all sort in one place (`data.js:64`), but home sorts elsewhere (`data.js:11`, consumed by pagination in `+page.server.js`), so a cross-app sort means edits in `data.js` + home server/page (for URL state), or a client-side sort in `CardGrid` that only fixes 3 of 4 lists (and sorts only the current page at home).
4. **Items like Moves** — Moves has no index route; the shape is one `+page.server.js`/`+page.svelte` pair. The genuinely reusable parts (`api`/`apiList`, `utils`, `Section`, `CardGrid`) are already extracted; the ~70-line page shell would be copied, which is the idiomatic SvelteKit cost of the pattern.
5. **API base URL + caching** — one file knows both: `app/src/lib/server/api.js:6` (base) and `api.js:44-52` (cache Map). `apiBase` is the only leak, and it flows through one export.

Deductions: the Pokémon-card object shape is assembled in two places (home `+page.server.js:52-66` vs `data.js:51-59`), the type-pill markup (`class="pill" style:--pill-bg="var(--type-{name}, ...)"`) is copy-pasted in five files, and the "N Pokémon" count line in four. None are severe, but each adds a "fix it N times" risk.
