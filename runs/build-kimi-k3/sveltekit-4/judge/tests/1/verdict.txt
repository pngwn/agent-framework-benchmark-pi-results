I've reviewed the full app. It's a clean, idiomatic SvelteKit/Svelte 5 codebase — but the test dimension is straightforward: **the agent wrote zero tests**. No test files, no runner in `package.json` (`app/package.json:6-11` has only dev/build/start scripts), no `vitest`/`playwright` dependencies, and no test config. The measured facts confirm: `tests.files: 0, cases: 0`.

What makes this costly is where the untested logic lives. The app is not just markup: there is a real data layer with the exact kind of fragile, branchy code that unit tests exist for:

- **Sorting** (`app/src/lib/components/MoveTable.svelte:75-96`): the comparator handles missing-values-last in both directions, numeric vs. string comparison, a three-way tiebreak, and direction flipping. A one-character change (`return 1` vs `return -1` for nulls, or forgetting `* dir` on the tiebreak) would pass review and silently mis-order tables.
- **Filtering/pagination** (`app/src/routes/+page.server.js:16-57`): search is a substring match against humanized names lowercased; the type filter derives species ids from `/type/` and drops ids ≥ 10000; page parsing clamps `Math.max(1, parseInt(...)||1)` and `Math.min(pageParam, totalPages)`. Edge cases (`?page=0`, `?page=999`, `?type=stellar`, `q` with whitespace) are all hand-rolled.
- **Species resolution** (`app/src/lib/server/data.js:48-75`): `speciesFromPokemonRefs` dedupes by species id, drops alternate forms (`pokemonId >= 10000`), preserves card order via a Map keyed by species id, and threads an `augment` callback whose correctness depends on the index alignment with `entries` (used for hidden-ability flags in `app/src/routes/abilities/[name]/+page.server.js:21-24`). This is the single most refactor-hostile function in the app.
- **Pure helpers** (`app/src/lib/utils.js`): `humanize`, `latestFlavor` (last English entry, whitespace collapse), `idFromUrl` (trailing-slash-optional regex), `dexNumber` — all trivially unit-testable, all untested.
- **Move aggregation** (`app/src/routes/pokemon/[name]/+page.server.js:83-107`): a dedup key of `method|move|level`, the `METHOD_ORDER` comparator with its `indexOf(-1)` handling, and the selected-game fallback to highest `order`.
- **URL/typing interaction** (`app/src/routes/+page.svelte:29-53`): debounce at 250 ms with `replaceState`, a `typed` override cleared by `afterNavigate`. Svelte's SvelteKit-recommended testing story (vitest + @testing-library/svelte) would cover this; nothing does.
- **Cache behavior** (`app/src/lib/server/api.js:44-54`): 404s are deliberately *not* cached (each not-found lookup refetches), while successes are cached forever — a decision a refactor could flip without any failing signal.

All of this is currently guarded only by the acceptance suite in `tests/` (not the agent's, and not shipped with the app). If anyone refactors the data layer — the most likely first change — nothing in `app/` would fail.
