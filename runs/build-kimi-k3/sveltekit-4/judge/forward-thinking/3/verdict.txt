## Review: `app/` (SvelteKit Pokédex) — forward-thinking

**Framework currency.** This app is on the current generation across the board, which is notable because SvelteKit 3 went stable on 2026-10-01 — a month before today — and it adopted the post-3.0 conventions correctly:

- Configuration lives in `app/vite.config.js:8` with `sveltekit({ adapter: adapter() })` — exactly the Kit 3 shape (SvelteKit 3 removed `svelte.config.js` support per the migration guide; `sv create` now generates this).
- `goto(..., { reset: false, replace: true })` at `app/src/routes/+page.svelte:33` uses the *renamed* Kit 3 options (`reset` replacing `keepFocus`/`noScroll`, `replace` replacing `replaceState`) — these were only introduced in the 3.0 cycle.
- `page` imported from `$app/state` (`app/src/routes/+error.svelte:2`) — `$app/stores` was removed in Kit 3, so this is correct.
- `error(404, ...)` called without `throw` (`app/src/routes/types/[name]/+page.server.js:7`) — the current Kit 2+ idiom.
- Svelte 5 runes throughout: `$props`, `$derived`/`$derived.by`, `$state`, snippets via `children` + `{@render}` (`app/src/routes/+layout.svelte:14`), self-import recursion instead of `<svelte:self>` (`app/src/lib/components/EvolutionNode.svelte:2`), keyed each blocks everywhere, `style:` custom properties. No legacy `on:`, `export let`, stores, or slots anywhere.
- The app never used `$lib` (grep confirms zero matches), so it is unaffected by the Kit 3 `$lib`→`#lib` removal — though it also didn't adopt the new `#lib` subpath-import convention, using deep relative imports (`../../../lib/server/api.js`) instead.

**Platform.** Reaches for the platform consistently: native `fetch` with a small concurrency limiter (`app/src/lib/server/api.js:26`), `URL` parsing for URL rewrites (`api.js:35`), `URLSearchParams` for query building (`app/src/routes/+page.svelte:18`), `Map`/`Set` for dedupe, CSS custom properties as theming and component API (`style:--pill-bg="var(--type-fire, ...)"` in `app/src/lib/components/PokemonCard.svelte:15`), logical properties (`margin-inline` in `app/src/app.css:31`), `aspect-ratio` (`app/src/routes/pokemon/[name]/+page.svelte` styles), `:focus-visible`. Zero polyfills, zero hand-rolled routing/history hacks.

**Dependencies.** Zero runtime dependencies; five devDependencies that are each required and pinned at exactly the majors SvelteKit 3 requires (Svelte ≥5.57, Vite ≥8.0.12, vite-plugin-svelte v7, adapter-node 6 for the `node build` start script). Nothing to trim.

**Churn.** All PokeAPI access is behind two modules (`app/src/lib/server/api.js`, `data.js`) and shared helpers in `app/src/lib/utils.js`; an API shape change touches the load functions, not the components. Config is in exactly one file. The two soft spots: `process.env.API_BASE_URL` at `app/src/lib/server/api.js:6` bypasses the framework's env mechanism (Kit 3 deprecated `$env/*` in favour of `src/env.js` + `$app/env/private`; `process.env` couples the code to Node adapters), and the project is plain JS with no types at the load-function boundaries, so there's nothing checking the data contract between `+page.server.js` and components.
