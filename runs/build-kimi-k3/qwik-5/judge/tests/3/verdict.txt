The only tests in the repo are the provided acceptance suite in `tests/`, which is not the agent's work. Meanwhile the app contains a large amount of dense, pure, easily-testable logic — exactly the kind of code that unit tests pay off on.

What's unguarded (with locations):

- **`app/src/lib/format.ts:8-47`** — `humanize`, `dexNumber`, `englishName`, `collapseWhitespace`, `latestEnglishFlavorText`, `orDash`. Pure functions with spec-exact outputs (`mr-mime` → `Mr Mime`, `#0025`, `—` for missing, `\n`/`\f` collapsing). Zero-cost to test; a one-character regex change would go unnoticed.
- **`app/src/routes/index.tsx:39-71`** — the combination of search/type/generation filters, the 48-per-page slice, page clamping (`if (page > totalPages) page = totalPages`) and the "no matches → `No Pokémon found`" branch. Off-by-one pagination or a broken filter intersection would only be caught if the acceptance suite happens to hit that exact URL.
- **`app/src/routes/index.tsx:99-107`** — debounced search input. The timer is never cleared on unmount, so a stale debounce can call `nav()` after the user navigated away; a race like that is precisely what a focused test would catch.
- **`app/src/routes/pokemon/[name]/index.tsx:74-137`** — the densest logic in the app: game-version collection, default-game selection (highest `order`), the `move::method` dedupe keeping the *minimum* level, method ordering (`METHOD_ORDER` then alphabetical), and the level-up vs alphabetical default sorts. All untested.
- **`app/src/components/moves-table.tsx:36-52, 86-96`** — client-side sorting with "missing sorts last in both directions" and the ascending/descending flip plus `aria-sort`. The comparator is correct today; any refactor of `compareValues` (e.g. dropping the null special-case) would silently pass.
- **`app/src/lib/api.ts:14-33, 80-135`** — the in-memory promise cache (successes cached forever, 404s/failures evicted) and the type/generation index builders (alternate-form filtering via `isDefaultPokemonId`, slot ordering). A regression here silently corrupts *every* list page.
- **404 paths** — `app/src/routes/[...all]/index.tsx:3-5` and the `status(404); return null` branches in each route loader; the not-found page is only protected by one acceptance case (`/pokemon/missingno`).
- **Latent bug found while reading** — `app/src/routes/abilities/[name]/index.tsx:29-33`: `if (!byId.has(id)) byId.set(id, !!entry.is_hidden)` is first-wins, so a Pokémon listed with an ability both normally *and* hidden would lose its `Hidden ability` note. Nothing would catch this today.
- **Evolution recursion** — `app/src/routes/pokemon/[name]/index.tsx:139-143` (`EvoNode`/`toNode`) handles branching chains (Eevee) untested.

The code itself is well-factored for testability — pure helpers isolated in `lib/`, heavy logic hoisted into `routeLoader$` bodies that could be extracted and tested without a browser — which makes the complete absence of tests more of a choice than an obstacle.
