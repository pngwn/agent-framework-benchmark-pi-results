I've read the full app (`app/src` routes, components, lib, entries, configs) and verified framework currency: the app pins `@builder.io/qwik`/`@builder.io/qwik-city` **1.20.3**, which is the latest v1 stable release (published 2026‑10‑25; v2 is still RC), so nothing here is stale relative to the current stable line.

## Review

**Structure.** A textbook Qwik City layout: `src/routes/*` with per-route `routeLoader$`, a root `layout.tsx` for banner/nav/footer, three presentational components (`pokemon-cards.tsx`, `moves-table.tsx`, `not-found.tsx`, `router-head.tsx`), and a server-only data layer `src/lib/api.ts` plus pure helpers in `src/lib/format.ts`. Server entry (`entry.node-server.tsx`) follows the node-server adapter template. This is a small app with real seams.

**Removability.** The Abilities feature is one directory plus one inbound section: delete `app/src/routes/abilities/[name]/index.tsx`, then remove the loader field (`pokemon/[name]/index.tsx:165-172`) and the JSX section (`:259-268`). No nav link exists (nav is only Pokémon/Types, `layout.tsx:15-19`), and the CSS is generic (`.card-section`, `.link-list`) so nothing in `global.css` becomes dead. The only nit is that the removal touches two disjoint spots in the Pokémon route file.

**Changeability.** The strongest part of this app is `lib/api.ts`: `BASE`/`API` (`:5-6`), the single in-memory cache (`:10-24`), `spriteUrl` (`:41-43`), `isDefaultPokemonId` (`:46`) and the id→species map (`:67`) are each the only place that knows those facts. Every Pokémon-card list (home `index.tsx:60-64`, moves `moves/[name]/index.tsx:26-34`, abilities `abilities/[name]/index.tsx:22-37`, types `types/[name]/index.tsx:52-61`) builds cards through `spriteUrl`, so the Deoxys-style sprite bug fixes in one function. `format.ts` centralizes humanize/dex-number/flavor-text rules. Offsetting dings: `EXCLUDED_TYPES` is defined twice (`api.ts:83` and `types/[name]/index.tsx:22`), the loader logic is `any`-typed throughout (`moves/[name]/index.tsx:18`, `pokemon/[name]/index.tsx:89,138,159`), and the "cards from pokemon ids" mapping is pasted into three loaders with a silent `.filter(id => speciesById.has(id))` drop — a card that doesn't resolve disappears without any signal.

**Coupling.** Components are prop-driven with typed seams (`CardData` in `pokemon-cards.tsx:9-20`, `MoveRow`/`MoveTableData` in `moves-table.tsx:6-26`); `format.ts` is pure; only `api.ts` knows the wire protocol; server/client split is enforced by `routeLoader$` per route. Two things lower this: all styling lives in one 594-line `global.css` (components' class names are coupled to a distant file — Qwik's `useStylesScoped$`/`useStyles$` is the idiomatic per-component home), and internal navigation is inconsistent: `layout.tsx` and `not-found.tsx` use `Link`, while every card, badge, move link and pagination link uses raw `<a>` (`pokemon-cards.tsx:35`, `index.tsx:144`, `types/[name]/index.tsx:103`), which in Qwik City means a full page reload. On the home page, filter changes go through `useNavigate` (SPA nav) while pagination is a raw anchor (MPA reload) — a mixed navigation model in one component that a maintainer would have to reconcile.

**Abstraction design.** The variation is handled honestly: `CardData.types`/`note` optional fields (not flags) cover the home-page types and the ability "Hidden ability" note; `MovesTable` generalizes columns and sorting (`moves-table.tsx:38-70`) and is the single place the sortable-table behavior lives. What's missing: the "count Pokémon + cards" section markup is duplicated three times (`moves/[name]/index.tsx:100-101`, `abilities/[name]/index.tsx:62-63`, `types/[name]/index.tsx:108-109`), and the loader scaffolding (not-found → `status(404)` → `resolveValue` head with a duplicated `'Not found – Pokédex'` literal in four files) is pasted per route. An Items section would reuse `PokemonCards`, `NotFound`, `format` and `apiGet` wholesale, but would copy the detail-page scaffolding rather than extend anything.
