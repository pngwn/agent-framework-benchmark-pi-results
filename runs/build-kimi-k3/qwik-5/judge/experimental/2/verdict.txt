## Review: experimentalness

**Source API surface.** Every framework API in `app/src/` is from Qwik/Qwik City's long-stable 1.x core, and every usage matches the official starter templates:

- `component$`, `$`, `useSignal`, `Slot` (`@builder.io/qwik`) — stable since Qwik 1.0 (2023). e.g. `app/src/routes/index.tsx:1`, `app/src/routes/layout.tsx:1`.
- `routeLoader$`, `useNavigate`, `DocumentHead`, `Link`, `useDocumentHead`, `useLocation`, `QwikCityProvider`, `RouterOutlet` — stable since Qwik City 1.0. e.g. `app/src/routes/pokemon/[name]/index.tsx:2`, `app/src/root.tsx:2-7`, `app/src/components/router-head.tsx:2`.
- `renderToStream` from `@builder.io/qwik/server` + `@qwik-client-manifest` (`app/src/entry.ssr.tsx:1-2`) — the exact SSR entry the official starter generates.
- `createQwikCity` from `@builder.io/qwik-city/middleware/node` (`app/src/entry.node-server.tsx:1`) plus `nodeServerAdapter`/`extendConfig` (`app/adapters/node-server/vite.config.ts:1-6`) — the current stable node deployment path (confirmed against `qwik.dev/api/qwik-city-middleware-node/`; the `createQwikCity → createQwikRouter` / `@qwik.dev/router` rename is marked obsolete only in the **2.0** docs, not the 1.x line this app pins).
- `qwikCity({ trailingSlash: false })` (`app/vite.config.ts:6`) — a documented, stable plugin option (also used by the official `qwind` starter).
- No `useVisibleTask$`, `useTask$`, `server$`, `unstable_*`, `experimental_*`, preview flags, canary channels, or `vitePreload`/SSG flags anywhere in `app/src/` (grep across `app/src` returns nothing).

**The one "experimental" marker in the facts is not app code.** `server/q-BzUpVKqY.js:9` is Qwik's bundled runtime *error-message text* about QRL serialization inside a committed build artifact. Likewise the scary-looking ambient names (`Http2ServerRequest`, `undici#fetch`, `node:stream/web`, `ssrPreloads`, `clientConn`) all come from Qwik's own bundled middleware in `app/server/` and `app/dist/` — build output, not authored source.

**Version recency.** `app/package.json:6-7` exact-pins `@builder.io/qwik` / `@builder.io/qwik-city` at `1.20.3`, which is the current stable (published 2026-10-25, five days before this review). All APIs used are 3+ years old on that line, so nothing qualifies as "recently stable"; the only near-term churn risk is that Qwik 2.0 RCs are already shipping on a parallel line (`@builder.io/qwik-city/middleware/node`'s successor names exist there), which would be a major-version migration, not a break within the pinned line.

No experimental, preview, RC or canary APIs are used, so `count` is 0.
