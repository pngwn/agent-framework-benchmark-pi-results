I've reviewed the whole app source. Everything checks out as long-stable Qwik City API surface; the one flagged "experimental" marker in the measured facts is a false positive. Here's my review.

## What the app actually uses

- `app/src/root.tsx:1-18` — `component$`, `QwikCityProvider`, `RouterOutlet`, `Slot` (via RouterHead): the stock starter root, stable since Qwik 1.0 (2023).
- `app/src/entry.ssr.tsx:1-14` — `renderToStream` + `@qwik-client-manifest` virtual module: the canonical SSR entry, stable for years.
- `app/src/entry.node-server.tsx:1-41` and `app/adapters/node-server/vite.config.ts:1-18` — the official `nodeServerAdapter` scaffold from `npm create qwik`'s "adapt to node-server" flow, using `createQwikCity` from `@builder.io/qwik-city/middleware/node`. Documented, stable.
- Route files (`app/src/routes/index.tsx:9`, `app/src/routes/pokemon/[name]/index.tsx:38`, `app/src/routes/[...all]/index.tsx:5`, `app/src/routes/types/[name]/index.tsx:26`, etc.) — `routeLoader$`, `DocumentHead`, `useNavigate`, `useLocation`, `useDocumentHead`: all core, non-experimental Qwik City APIs.
- `app/src/components/moves-table.tsx:62-63` — `useSignal` for client-side sort state; `app/src/components/router-head.tsx:5-6` — `useDocumentHead`/`useLocation`. Both stable.
- No `experimental_`/`unstable_` names, no preview/beta flags, no canary imports anywhere in `app/src` (grep for `experimental|unstable|preview|beta|server$|inline$|useVisibleTask` returned nothing).

## The measured "experimental" marker is a false positive

The flagged string (`"Trying to serialize ... check out https://qwik.dev/docs/advanced/qrl/"`) lives in `app/server/q-BzUpVKqY.js:9` — that's the **minified Qwik core runtime chunk**, part of a committed build output, and the string is Qwik's own QRL-serialization `console.error` message. It is not an API the app calls. The same goes for the ambient names that look exotic (`Http2ServerRequest`, `PROTOCOL_HEADER`, `clientConn`, `ssrPreloads`, `undici#*`): they all come from the compiled Qwik City node middleware in `app/server/entry.node-server.js` and `app/server/@qwik-city-plan.js`, not from app source.

## Version currency

The app pins `@builder.io/qwik`/`@builder.io/qwik-city` to `1.20.3` (`app/package.json:12-13`). Per the QwikDev GitHub releases page, 1.20.3 was published 2026-10-25 — five days before today — and is the current stable patch of the 1.x line. Notably, Qwik 2.0 is in RC (`create-qwik@2.0.0-rc.4`, `eslint-plugin-qwik@2.0.0-rc.4` in the same releases feed), so 1.20.3 is the right thing to be on: the app stays on the stable line rather than the RC. The APIs it exercises have been stable since well before 1.10; nothing here is "recently stable".
