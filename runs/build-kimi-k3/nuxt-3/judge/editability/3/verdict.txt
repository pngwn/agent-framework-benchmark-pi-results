## Review — editability of the Nuxt Pokédex app

**Framework currency**: the app pins `nuxt@4.6.3` (`app/package.json:9`), which is the current stable release (shipped 2026‑10‑27). The layout follows Nuxt 4 conventions exactly: `app/` srcDir with `app/app/{pages,components,utils,plugins}`, auto-imported `utils/`, keyed `useAsyncData`, `runtimeConfig` + `defineNuxtPlugin` for the API base. Nothing here is legacy-framework noise; everything I judge below is against current idioms.

**How it's built**: one data layer (`app/app/utils/poke.ts`, ~260 lines) holds fetch+cache, indexes, pure helpers, and a card-model builder; four detail pages each do `fetchRecord` → model-mapping in `useAsyncData`; two small presentational components (`PokemonCard`, `MovesTable`) take typed props (`PokemonCardModel`, `MoveRow`); all page state lives in the URL query. That's a genuinely good skeleton. The main editability tax is copy-paste at the page level rather than tangles.

**Scenario walkthroughs**

1. **Remove Abilities**: delete `app/app/pages/abilities/[name].vue`, then strip the Abilities section from `app/app/pages/pokemon/[name].vue:92-94` (script) and `:248-256` (template). Nav (`app/app/app.vue`) has no Abilities link. If thorough, you'd also clean ability-specific leftovers baked into *shared* code: the `hidden` flag in `cardsFromPokemonRefs` (`app/app/utils/poke.ts:235,251`), the `card.hidden` branch (`app/app/components/PokemonCard.vue:19`), and the now-dead `.link-list` CSS (`app/app/assets/css/main.css:446`). Two mandatory files plus scattered traces → solid 3.
2. **Sprite bug (Deoxys-style)**: every card gets its sprite through one function, `spriteUrl` (`app/app/utils/poke.ts:90`), called from the shared card builder (`:250`) and the home page's local builder (`app/app/pages/index.vue:108`). One edit to `spriteUrl` covers every list — but only because the fix is expressible in terms of the id; if it needed default-variety data, the *duplicated card construction* (`cardOf` vs `cardsFromPokemonRefs`) would force two edits. The pokemon page's artwork path is separate and correct (`app/app/pages/pokemon/[name].vue:77`). Easy fix, mild duplication underneath.
3. **Sort all card lists by name**: one edit in `cardsFromPokemonRefs` (`app/app/utils/poke.ts:262` — final `sort by id`) covers moves, abilities and types pages; the home page needs its own edit in `filtered`/`pageItems` (`app/app/pages/index.vue:98`). Two places, both findable → 4.
4. **Add an Items section**: the reusable seams are real — `fetchRecord`, `cardsFromPokemonRefs`, `PokemonCard`, `humanize`/`englishName`, `panel`/`facts`/`card-grid` CSS. But there is no shared "resource detail page" composable: the `useAsyncData` → null → `useHead` title → 404-status snippet is copy-pasted identically in four pages (`app/app/pages/moves/[name].vue:36-37`, `abilities/[name].vue:31-32`, `types/[name].vue:45-46`, `pokemon/[name].vue:172-173`), and the "N Pokémon + card grid" section markup is triplicated (`moves/[name].vue:70-75`, `abilities/[name].vue:47-52`, `types/[name].vue:71-76`). So Items = copy `types/index.vue` + `moves/[name].vue` and adapt, mostly duplicated rather than reused.
5. **Change API base / caching**: the cache lives in exactly one place (`app/app/utils/poke.ts:63-79`), and the base URL flows through runtimeConfig → plugin (`app/app/plugins/api-base.ts:5`) → `setApiBase` — a clean seam. The only blemish is the default literal `'http://localhost:9000'` duplicated in `app/nuxt.config.ts:8` and `poke.ts:54`, so a default change touches two files (env-var-only change touches none). → 4.

**Criteria verdicts**: `changeability` and `coupling` are strong (typed card/row models, URL-driven state, one data layer, no server/client bleed); `removability` and `abstraction_design` are held back by the same pattern — page-level boilerplate and card-construction duplicated instead of extracted into the composable/component that is visibly begging to exist.
