The app itself is Nuxt 4.6.3 (current stable) with a dense, well-factored pure data layer (`app/app/utils/poke.ts`) — exactly the kind of code that's cheap to unit-test and easy to break during refactors.

Key untested risk areas I verified by reading:

- **Pure helpers** — `app/app/utils/poke.ts:26-48` (`humanize`, `dexNumber`, `idFromUrl`, `collapseWhitespace`), `:50-58` (`englishName`, `latestEnglishFlavorText`). The spec is picky here (e.g. `mr-mime` → `Mr Mime` vs the English name `Mr. Mime` used for h1 only; *last* English flavor entry; `\f` collapsing). A regression like taking the *first* English flavor entry or humanizing headings would pass silently.
- **Home filtering/pagination/URL state** — `app/app/pages/index.vue:39-91`: `pageParam` parsing (0/negative/non-numeric), `buildQuery` default-omission rules, filter-changes-reset-page, `currentPage` clamping when filters narrow results (`:89` clamps the display but leaves a stale `page` in the URL — an untested edge), `PAGE_SIZE` slicing off-by-one.
- **Card mapping** — `app/app/utils/poke.ts:194-227` (`cardsFromPokemonRefs`): the `id >= 10000` form-exclusion cutoff, dedupe, dex-order sort, and the `deoxys-normal` → species `deoxys` link mapping. Off-by-one or using the Pokémon name instead of the species name in `/pokemon/<species>` links is the classic bug here.
- **Type index** — `poke.ts:120-170`: `EXCLUDED_TYPES` filter (18 types), slot ordering/deduping, alternate-form skip.
- **Per-game moves transform** — `app/app/pages/pokemon/[name].vue:60-140`: default game = highest `order`, method ordering (`Level Up, Machine, Egg, Tutor`, then alphabetical), `name+level` dedupe, per-table sort with level-tiebreak.
- **Sortable table** — `app/app/components/MovesTable.vue:39-60`: missing-values-sort-last in *both* directions, asc-first toggle, `aria-sort`. A desc-order null-handling flip (`cmp * dir` interacting with the null short-circuit) is subtle and unguarded.
- **Error-vs-404 conflation** — `poke.ts:80-90` (`fetchRecord` swallows *all* errors into `null`) plus `app/app/pages/pokemon/[name].vue:148-150` etc.: a transient API 500/network error renders the "Not found" page with a 404 status; only distinguishable by logging.
- **Cache eviction & concurrency** — `poke.ts:62-77` (rejected-promise eviction guard) and `:93-104` (`mapLimit` worker-pool index assignment).
- **Serialization constraint** — handlers carefully avoid returning `Map`s from `useAsyncData` (e.g. `app/app/pages/pokemon/[name].vue:118` converts `enByName` to a plain object). Nothing would fail if a future refactor returned a `Map` directly — it would just break client hydration via devalue, a classic Nuxt pitfall worth a regression test.
