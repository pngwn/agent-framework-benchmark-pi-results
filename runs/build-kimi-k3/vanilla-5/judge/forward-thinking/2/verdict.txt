I've reviewed the whole app (`app/src/*`, `server.mjs`, `vite.config.ts`, configs) and verified the framework facts against current releases: **Vite 8** shipped stable 2026-03-12 with Rolldown (vite.dev/blog/announcing-vite8), and the app pins `vite ^8.3.5` with a fully current plugin API (`defineConfig`, `configureServer`, `server.middlewares` — unchanged in v8 per the migration guide). **TypeScript 7.0** (the native port) has been the stable major since Aug 2026, so `typescript ^5.9.3` is one major behind, though it's dev-only and low-risk.

**What ages well:** all HTTP access is behind one module (`app/src/api.ts` + `data.ts`, with a promise cache and error eviction), the runtime `API_BASE_URL` is injected via `/config.js` rather than baked at build time (so one build serves any environment), zero runtime dependencies, and a lean ~70-line `node:http` static server with a proper path-traversal guard. Platform usage is strong: `fetch`, `URL`/`URLSearchParams`, `Map`/`Set`, `??=`, `loading="lazy"`, `:focus-visible`, CSS custom properties.

**What will cause churn:** the API boundary is untyped (`any` everywhere in `data.ts`/`util.ts`), the moves-table sorting reconstructs typed rows by scraping rendered DOM text and regexing `href`s (a second source of truth for the column layout), no `AbortController` cancels in-flight requests on navigation, sprite URLs are hardcoded to the media layout instead of read from `pokemon.sprites`, and the `/config.js` serving logic is copy-pasted between `vite.config.ts` and `server.mjs`.
