# Review: `app/` — Editability

Vanilla TypeScript + Vite 8, no UI framework. The app is a string-template SPA: `api.ts` (fetch + in-memory cache) → `data.ts` (memoized aggregates) → `components.ts` (HTML atoms) → `pages/*` (one file per route) → `main.ts` (if/else router) with `nav.ts` as a tiny navigation bus. That layering is the code's best property; the weaknesses are a forked data helper and a sorting layer that re-parses its own rendered DOM.

## Scenario walkthroughs

1. **Remove Abilities** — delete `app/src/pages/ability.ts`, drop the import/branch at `app/src/main.ts:5,22`, remove the Abilities section at `app/src/pages/pokemon.ts:118-125` (and its use at `:139`). Nav never links abilities (`app/index.html:17-19`), so no dead links; only `.card-note` CSS (`app/src/style.css:201`) is orphaned, and it's generic. Clean: **difficulty 4**.
2. **Sprite bug (default Pokémon ≠ species name, e.g. Deoxys)** — the URL formula lives in exactly one place, `spriteUrl` (`app/src/api.ts:39`) consumed by `pokemonCard` (`app/src/components.ts:23`), which every list uses (`home.ts:130`, `move.ts:34`, `ability.ts:46`, `types.ts:57`), so a formula fix covers all lists. But `SpeciesRef.id` is produced inconsistently: species-id in `getSpeciesList` (`app/src/data.ts:30`) vs Pokémon-id in `speciesFromPokemonRefs` (`:105`) and the forked mapping in `app/src/pages/ability.ts:26-35`; they only coincide because the spec says default Pokémon ID == species ID. If the fix needs real Pokémon data, it lands in three producers. **difficulty 3**.
3. **Sort cards by name everywhere** — four call sites (`home.ts:118`, `move.ts:34`, `ability.ts:36-38`, `types.ts:37-38`) each hold the array before rendering, so sorting is easy per page, but `speciesFromPokemonRefs` hard-codes the dex sort *inside* the shared helper (`app/src/data.ts:110-112`), so three pages either re-sort after the call or the helper grows a flag. **difficulty 3**.
4. **Add Items shaped like Moves** — the plumbing (`apiJson`, `memo`, `section`, `typeBadge`, `humanize/enName/num`) is fully reusable; the page skeleton (fetch → `isNotFound` → `renderNotFound`, title, h1+sections) is *not* factored — `move.ts:10-16,31-35` duplicates the same boilerplate as `types.ts:26-33` and `ability.ts:8-16`, so a new section copies ~40 lines, plus a route branch in `main.ts:23` and optionally a nav link in `index.html`. **difficulty 4**.
5. **API base URL / caching change** — base URL: `app/src/api.ts:5` is the only consumer, injected via `/config.js` from `app/server.mjs:8,37-40` (and `vite.config.ts:13` for dev); but the default `http://localhost:9000` is written out in three files. Caching: two mechanisms — the promise cache (`api.ts:21-34`) and per-helper `memo` (`data.ts:15-18`) — so changing cache policy (e.g. TTL) touches both, and `memo` is replicated per helper rather than centralized. **difficulty 4**.

## Criteria

- **removability: 4** — features are one-page-plus-route-branch; nav is static and only links `/` and `/types` (`app/index.html:16-20`), so nothing dangles. Not 5 because section content is inlined in page templates and `section()`'s counter ids (`app/src/components.ts:35-42`) mean hand-built duplicates exist (see findings).
- **changeability: 3** — the card/sprite fix point is genuinely singular, but the Pokémon→species mapping exists twice (`app/src/data.ts:98-113` vs `app/src/pages/ability.ts:20-38`), and moves-table sorting re-derives `MoveRow` from rendered DOM text (`app/src/pages/pokemon.ts:279-305`) instead of keeping the data already computed in `movesSectionHtml` — markup changes silently break sorting.
- **coupling: 4** — clean one-way layering with narrow seams: pages never import each other, `nav.ts:9-14` decouples pages from history/router, `server.mjs` is fully separate from client code, and `window.__API_BASE_URL__` is an explicit config seam. Deductions: API records flow as untyped `any` everywhere (no narrow interfaces at the `data.ts` boundary), and `sectionCounter` is module-global mutable state (`app/src/components.ts:25`).
- **abstraction_design: 3** — `memo`, `speciesFromPokemonRefs`, `pokemonCard(opts)`, `section(title, inner, attrs)` are the right abstractions and stretch reasonably; but the helper hard-codes its sort (forcing the ability page to fork it), `section()` can't express the `id="moves"` anchor so the empty case is hand-built with a *different* heading-id scheme (`app/src/pages/pokemon.ts:153-154`), and per-resource page boilerplate is copy-pasted across four pages.

## Findings

1. **medium** — `app/src/pages/pokemon.ts:279-305`: sorting reconstructs `MoveRow` by scraping `textContent`/`href` of the just-rendered table, duplicating column-offset knowledge with `moveRowHtml` (`:225-236`). Suggestion: return the parsed `rows` from `movesSectionHtml` (module-level WeakMap keyed by `<table>`, or attach via a dataset/closure) and sort that.
2. **medium** — `app/src/pages/ability.ts:20-38` duplicates the Pokémon-ref→species mapping that `speciesFromPokemonRefs` (`app/src/data.ts:98-113`) already implements, differing only in carrying `is_hidden`. Suggestion: generalize the shared helper (e.g. return the raw entry alongside `SpeciesRef`) instead of forking it.
3. **medium** — `app/src/data.ts:6-9` / `app/src/data.ts:105`: `SpeciesRef.id` conflates species id and Pokémon id across producers; sprite/dex rendering relies on the spec's "default Pokémon ID == species ID" coincidence. Suggestion: make the distinction explicit (carry both ids, or fetch the default variety's Pokémon id where needed).
4. **low** — `app/src/api.ts:5`, `app/server.mjs:8`, `app/vite.config.ts:13`: default API URL duplicated in three files. Centralize (e.g. a shared constant or read it only from `__API_BASE_URL__` with a single fallback).
5. **low** — `app/src/data.ts:15-18` + `app/src/api.ts:21-34`: two independent caching mechanisms with no TTL/eviction seam. If "caching rules change", both must be edited; consider one cache layer with configurable policy.
6. **low** — `app/src/pages/pokemon.ts:153-154`: hand-built "empty moves" section with `moves-heading` id, diverging from `section()`'s counter ids (`app/src/components.ts:36-42`). Use `section('Moves', ..., 'id="moves"')` which already accepts attrs.
7. **low** — `app/src/pages/move.ts:10-16` (same in `types.ts`, `ability.ts`, `pokemon.ts`): fetch → `isNotFound` → `renderNotFound` → `document.title` boilerplate copy-pasted per page; factor a `loadResourceOr404` helper to make a future Items section cheap.
8. **low** — pervasive `any` for API records (`app/src/data.ts:29`, all of `pages/*.ts`): no compiler help when the API shape shifts, and refactors rely on grep. Declare the handful of record shapes actually consumed at the `data.ts` boundary.
