**What's good:** clean SSR data layer with a request-time fetch, in-memory promise cache, and a concurrency limiter (`app/src/lib/pokeapi.js:12-56`); proper `[name].astro` routing; 404 handling via `Astro.response.status = 404` on every dynamic route; race-guarded debounced search with a no-JS form fallback (`app/src/pages/index.astro:143-193`); well-named, commented, small components (`Section`, `PokemonCard`, `Layout`).

**Notable issues:** memoized module-level promises cache rejections forever (unlike `apiFetch`, which evicts failures) so one transient API error poisons every page for the process lifetime; the card-building helper is duplicated inline in the abilities page instead of parameterized; hand-rolled HTML string building with a manual `escapeHtml` for the evolution chain where a recursive component would be idiomatic; `is:inline` scripts bypass Astro's processed/bundled script pipeline; `app/dist/` and `app/.astro/` build artifacts aren't gitignored.
