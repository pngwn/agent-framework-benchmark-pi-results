I've reviewed the app against Astro 7.4 (current stable as of 2026-10-30 — `output: 'server'` with the standalone Node adapter is the current idiom, and the pinned `astro@^7.4.4` is up to date). Findings below are backed by specific locations.

**Structure:** 4 components (`Layout`, `Section`, `PokemonCard`, `NotFound`), one data module `src/lib/pokeapi.js`, and 6 route files. The data layer is a genuine seam: everything API-related goes through `apiFetch`/`apiFetchRef`, and display helpers (`humanize`, `enName`, `dexNumber`, `latestEnglishFlavor`) live in one file.

**Key editability observations:**

- Removing Abilities = delete `pages/abilities/` plus the Abilities section in `pages/pokemon/[name].astro:208-217` and the ability-specific `hidden` prop in `PokemonCard.astro:8,38`. Contained, but not a pure delete-and-nav-link.
- The sprite-fix scenario exposes real duplication: card-building logic exists in three places — `pokeapi.js:148` (`cardsFromPokemonRefs`, used by moves and types pages), `pages/index.astro:78`, and a hand-rolled copy in `pages/abilities/[name].astro:25-38` that re-implements `cardsFromPokemonRefs` just to add the `hidden` flag. One sprite fix does **not** cover every card list.
- Type-badge anchor markup is copy-pasted in four files (`PokemonCard.astro:30`, `pokemon/[name].astro:170,283`, `types/[name].astro:70`, `moves/[name].astro:61`).
- `pages/pokemon/[name].astro` is a 340-line monolith: moves-table data assembly, a recursive evolution tree built as an HTML string with manual `escapeHtml`, and two inline scripts in one file.
- Cache rules live in the `apiFetch` Map, but five module-level memo promises (`pokeapi.js:90-135`) bypass it, so a cache-TTL change touches several spots — all in one file, though.
