## Review: process dimension

**Narrative summary of the session.** The agent (117 turns, ~36 min, 143 tool calls) read the spec and the acceptance tests before writing anything, then verified the data layer empirically with small Node scripts against the live API before scaffolding Angular 22 via the CLI. It wrote the app in one large pass, ran the full suite, got 53/54, root-caused the single failure (resolvers not re-running on query-param change) by reading the router source in `node_modules`, fixed it with a one-line `runGuardsAndResolvers: 'paramsOrQueryParamsChange'` (confirmed present in `app/src/app/app.routes.ts:20`), and then did extensive visual verification against the reference screenshots at both widths. Its main stumbles were self-inflicted shell/process-management noise rather than conceptual problems.

**Circularity — 4.** Mostly steady: spec→tests→tokens→screenshots→data probes→scaffold→write→test. Three small loops, each self-recovered: a ~7-call hunt for `withHttpTransferCacheOptions`/`RESPONSE_INIT` in `node_modules` type defs (trace.md:340, Turn 23 → resolved Turn 32); a stale-server detour where a "wrong Game select" was chased as a hydration bug while the running server served 404'd JS chunks (trace.md:975, Turn 88 → resolved by console 404s at Turn 93–95); and `pkill -f "dist/app/server/server.mjs"` killing its own shell (exit 143) four times before switching to a PID file (trace.md:730, Turn 64 → trace.md:1138, Turn 106). No file re-reads, no edit reverts, no re-fixing the same test.

**Debugging — 5.** Every real failure was root-caused with evidence, never patched blindly. The failing test led to reading `shouldRunGuardsAndResolvers` in the router bundle and a precise route config fix (trace.md:818, Turn 71; trace.md:832, Turn 72–74). The SSR "Bad Request / host not allowed" was diagnosed by reading `@angular/ssr`'s validation chunk and fixed with `allowedHosts` (Turns 59–63). The select anomaly was pursued with SSR-HTML greps, `agent-browser eval`, a standalone Playwright repro, and a re-run of the specific test — which passed and became the clue pointing at environment staleness (Turns 88–95). The move-page blank sprites were first confirmed not-404 before removing `loading="lazy"` (trace.md:1088, Turn 99).

**Verification quality — 5.** Full suite ran 5×, including once with the complete install+build+overlay flow, and again after the last code edits (trace.md:1178, Turn 111 — 54/54, matching the measured "fullPassAfterLastEdit"). Beyond tests: raw SSR HTML inspected via curl (titles, `aria-sort`, caption "Train", 48 cards, 404 status on `/pokemon/missingno`), 11 own screenshots compared against 9 reference screenshots at desktop and mobile widths, ad-hoc Playwright scripts to probe hydration behavior, and pre-coding data-shape/count verification against the API (trace.md:262, Turn 18–19). It also cleaned up dev servers and committed a tidy tree.

**Tool use — 4.** 143 calls, 9 bash failures, zero failed edits (all 9 edit blocks applied first try), no invalid args. Good substitution behavior: used the `mcp__angular_cli__get_best_practices` call and both skills (Turns 7, 20), `npm view` for version check (Turn 9), and node_modules source reads instead of web search. Waste: the d.ts hunt above, `agent-browser viewport` misuse creating a stray `--full-page` file (Turn 82, cleaned up at Turn 114), and the four self-killing `pkill` invocations — one of which also killed the API server (`pkill -f "server.mjs"`, Turn 64→66) and produced a misleading ECONNREFUSED error.

**Planning — 5.** Understood the task up front and in the right order: spec, tests, tokens, all reference screenshots, API server semantics, live data probes (alternate-form filtering, counts, "train" learn method), version check, then scaffold and write (trace.md:306, Turn 21 onward). Rework was limited to template-syntax fixes from the first build (Turns 48–56) and one deliberate CSS tweak after visual comparison (trace.md:1127, Turn 104). No requirements were discovered late.

**Wasted turns:** roughly 15 of 117 — the pkill fumbling (~6), the stale-server detour (~6), and the d.ts search (~4) could all have been avoided with PID files, an immediate console-error check, and one targeted grep.
