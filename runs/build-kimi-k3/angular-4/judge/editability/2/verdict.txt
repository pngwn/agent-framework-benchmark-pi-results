## Review: `app/` — Editability

**Structure.** The app is a clean route → resolver → lazy component trio per page (`app/src/app/app.routes.ts`), with two narrow services — `Api` (transport + cache, `app/src/app/api.ts`) and `PokedexData` (derived datasets + card mapping, `app/src/app/pokedex-data.ts`) — and pure presentational components fed by typed inputs (`PokemonCards`, `TypePill`, `NotFoundView`). This is idiomatic Angular v22 (the app pins `^22.2.0`; `@Service()` is stable since v22, confirmed against release notes). The resolver pattern, `withComponentInputBinding`, and `RESPONSE_INIT` 404 handling all match current stable practice.

**Scenario walkthroughs.**

1. **Remove Abilities** — delete `ability-detail.ts` + `ability.resolver.ts` + the route in `app.routes.ts:28-31`; then the cross-link on the Pokémon page (`pokemon-detail.ts:93-102`), the `abilities` field in `pokemon.resolver.ts:44,181-187`, and the `Ability` model in `models.ts:64-69` (dead code otherwise). Six files, but every edit is obvious and greppable. Nav has no ability link (`app.html:11-13`). **Difficulty 4.**
2. **Sprite fix** — every card list except home funnels through `PokedexData.cardsFor` (`pokedex-data.ts:105-141`), which already maps `deoxys-normal`-style refs to species and dedupes; sprite URL derivation is centralized in `Api.spriteUrl` (`api.ts:47-49`) and consumed only by `PokemonCards` (`pokemon-cards.ts:42-44`). One fix in `cardsFor` covers all lists; the home page builds entries from species IDs directly (`home.ts:131-140`) so it can't have this bug. **Difficulty 5.**
3. **Sort by name** — either sort inside `PokemonCards` (one file, applies to all four lists, though home's pagination slices by dex order) or at the two `CardEntry` construction sites (`pokedex-data.ts:141`, `home.ts:131-140`). **Difficulty 4.**
4. **Items section** — copy the Moves trio: route + `item.resolver.ts` + `item-detail.ts` + model. Reusable as-is: `Api`, `cardsFor`/`PokemonCards`, `TypePill`, `NotFoundView`, `util` helpers, and the `.card`/`section` CSS. The cost is re-copying the ~15-line resolver boilerplate (try/catch + `Title` + `RESPONSE_INIT`, e.g. `move.resolver.ts:52-56`). **Difficulty 4.**
5. **API base URL / caching** — base URL lives in the `API_BASE_URL` token (`api.ts:10-18`, sole consumer `api.ts:23`), with server-side plumbing in `server.ts:26-33` + `index.html:8`. Caching spans three layers: per-request promise cache (`api.ts:24`), per-dataset memoization (`pokedex-data.ts:33-70`), and HTTP transfer cache (`app.config.ts:19`). Clear seams, but a TTL change touches all three. **Difficulty 3.**

**Main deduction**: the title/404 boilerplate is duplicated across four resolvers and three components — the `– Pokédex` suffix appears 10 times (`grep` above), and the identical `catch` block with `setTitle('Not found – Pokédex')` + 404 status appears in `pokemon.resolver.ts:191-196`, `move.resolver.ts:52-56`, `ability.resolver.ts:41-45`, `type.resolver.ts:53-57`. A `pageResolver()`/`setPageTitle()` helper would collapse that. Minor duplication also exists in type-name lookups (`typeNames.get(x) ?? humanize(x)` ×4) and move-field shaping (`pokemon.resolver.ts:105-112` vs `move.resolver.ts`'s dl fields).
