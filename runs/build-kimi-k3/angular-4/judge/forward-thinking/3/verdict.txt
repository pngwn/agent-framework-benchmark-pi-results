## Review — forward-thinking

**Verification notes.** Angular's current stable line is v22 (released 2026-06-04; app pins `^22.2.0`, `app/package.json:9`). I confirmed the modern APIs used here against current sources: `@Service` decorator is available as of v22.1 (angular.dev migration guide "Injectable to Service"), `BootstrapContext` was introduced for server bootstrapping in Sept 2025 (angular/angular commit 8bf80c9), `RESPONSE_INIT` is the current public core token (angular.dev/api/core/RESPONSE_INIT), and zoneless is the default since v21 (angular.dev/guide/zoneless) — the app has no `zone.js` dependency, which is correct for a v22 app. `resource()`/`httpResource()` became stable in v22; route resolvers remain a documented current pattern (skill reference `data-resolvers.md`, which labels `withComponentInputBinding` + `input()` the "modern" access path — this app does exactly that).

**What ages well.** The app is consistently on the newest generation: signals-only state (`signal`/`computed`/`effect`/`input.required`), native control flow (`@if/@for`), zoneless + OnPush-default, hydration with HTTP transfer cache, `provideHttpClient(withFetch())`, and the v21+ SSR stack (`mergeApplicationConfig`, `provideServerRendering(withRoutes)`, `BootstrapContext`, CLI-shaped `server.ts`). All data flows through one module (`api.ts` + `pokedex-data.ts`) with typed API shapes in `models.ts` — an upgrade or an API change touches few files.

**What will need touching.** The title-set + 404-status catch block is copy-pasted into five resolvers; runtime config travels through an untyped `window.__API_BASE_URL__` global plus a blocking script tag; `@angular/forms` is declared but never imported; and data loading ignores the now-stable `resource()`/`httpResource()` primitive (defensible, since resolvers guarantee data in the SSR HTML, but it's the current-gen primitive the app bypasses). None of these are blockers.
