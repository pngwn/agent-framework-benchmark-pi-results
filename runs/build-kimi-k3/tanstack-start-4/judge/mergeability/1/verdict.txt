## Review

**Framework fit.** This app is built against the actual current stable release of TanStack Start (1.169+, Vite 8, `nitro()` from `nitro/vite`, `createServerFn().validator()`, `shellComponent` root route). I verified each against the official migration/release notes: `vite.config.ts:1-15` uses exactly the plugins the 1.169 stable docs prescribe; `app/src/lib/server.ts:23` uses `.validator()`, the canonical method (the old `.inputValidator()` has been removed upstream); `app/src/routes/__root.tsx:14` uses `shellComponent` + `HeadContent`/`Scripts`, matching the framework's own examples. Loaders call server functions, throw `notFound()` for 404s, derive `head` from `loaderData`, and filter state lives in validated URL search. This is textbook current TanStack Start.

**Where it falls short of the framework's own examples:** there is no `errorComponent` anywhere (grep found none) — a non-404 API failure (server down, 500) hits the framework's default boundary, and the official starter ships a `DefaultCatchBoundary` on the root route. The router also omits `scrollRestoration: true`, which every official example sets.

**Correctness.** 404 handling is thorough and deliberate (`server.ts:15-24` maps `ApiError(404)` → `notFound()`; unmatched URLs fall through to `defaultNotFoundComponent` at `router.tsx:8`). The in-memory caches are failure-safe and self-invalidating (`api.ts:23`, `data.ts:26`), and the spec explicitly permits runtime caching. Minor risks: the controlled search input's value is derived from async router state (`index.tsx:66`), which can drop/revert fast keystrokes; and the not-found `<title>` is rendered in the body (`NotFoundPage.tsx:6`), working only via React 19's metadata hoisting.

**Abstractions and readability.** The layering is clean and one-directional: `api.ts` → `data.ts` (view models) → `server.ts` (server fns) → loaders → components, with the server/client split enforced by type-only imports. Two nits: view-model interfaces live in the server-only `data.ts` and are imported by client components, and `data.ts` is a ~470-line near-god module (well-sectioned, but it will keep growing). The whole data layer is `any`-typed (~30 occurrences) despite `"strict": true` in `tsconfig.json` — the one place types would have earned their keep.
