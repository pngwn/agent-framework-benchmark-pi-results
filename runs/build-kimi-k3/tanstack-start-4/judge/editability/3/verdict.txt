I've reviewed the app end to end. Structure summary before scoring:

- **Layers**: `routes/*` (thin route + render) → `lib/server.ts` (one `createServerFn` per page, shared `withNotFound`) → `lib/data.ts` (view-model builders) → `lib/api.ts` (base URL + in-flight cache) → `lib/format.ts` (isomorphic helpers). Shared UI in `lib/components.tsx` (`Section`, `TypeBadge`, `PokemonCard`, `CardList`) and `lib/MovesTable.tsx`.
- **Conventions check**: the app matches current TanStack Start (v1.17x) practice — `shellComponent` on the root route (`app/src/routes/__root.tsx:17`), `getRouter` export (`app/src/router.tsx:5`), `createServerFn({method}).validator().handler()` (`app/src/lib/server.ts:25-28`), `head()` per route. Nothing here is a dated pattern.

Working the five scenarios:

1. **Remove Abilities** — delete `routes/abilities.$name.tsx`; remove `getAbilityPageData` from `lib/server.ts:33` and `buildAbilityPageData` from `lib/data.ts:402`; delete the Abilities section in `routes/pokemon.$name.tsx:113-124` (the router's type-checked `Link to="/abilities/$name"` breaks at compile time once the route tree regenerates, so nothing is silently left); plus the `hidden`/`Hidden ability` vestiges in `lib/components.tsx:64` and `app.css:332`. Six files, but every edit is mechanical and compiler-guided.
2. **Sprite bug** — every card's sprite comes from one helper, `spriteUrl` (`lib/api.ts:33`), reached via `cardsForPokemonRefs` (`lib/data.ts:116`) for move/ability/type lists and the home catalog (`lib/data.ts:174`). One fix covers all four lists.
3. **Sort by name** — three of four lists funnel through `cardsForPokemonRefs`, whose sort is one line (`lib/data.ts:120`); the home page's card order is the catalog built in `buildHomeData` (`lib/data.ts:150-175`) — a second place, or a `sortBy` prop on `CardList` (which home also uses).
4. **Items section** — recipe is clear: new `routes/items.*.tsx`, one builder in `data.ts`, one server fn in `server.ts`; `apiGet`/`format.ts`/`Section`/`CardList`/`withNotFound` all reuse as-is. But there's no shared "resource detail page" scaffold, so the route file is a copy of `moves.$name.tsx`, and `data.ts` is already a 465-line module holding every builder.
5. **Data source change** — base URL lives in exactly one function (`lib/api.ts:3`) and the response cache in one Map (`lib/api.ts:12`). Caveat: caching rules actually live in three layers — that Map, five hand-rolled memo blocks in `data.ts:31-95`, and `staleTime: Infinity` in `routes/index.tsx:48`.

Other notes: server/client separation is clean (client components import only `type` from `data.ts`, e.g. `components.tsx:3`, `routes/index.tsx:4`); minor blemishes are the duplicated `EvoNode`/`EvoNodeVM` types (`routes/pokemon.$name.tsx:23` vs `lib/data.ts:206`), double not-found wiring (`__root.tsx:17` + `router.tsx:7`), a `<title>` rendered in the body of `NotFoundPage.tsx:6` (React 19 hoists it, but it's a second title mechanism alongside `head()`), the `englishName(...) ?? humanize(...)` fallback repeated 10× in `data.ts`, and `Section`'s hand-written `headingId` boilerplate.
