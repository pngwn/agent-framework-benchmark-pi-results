## Review: experimentalness

### What I found

**Measured markers:** zero `unstable_`/`experimental_` names and zero experimental config flags in `app/` (grep over the whole tree matches only the `nitro` prerelease version string). The facts list no experimental concepts, and the import surface is entirely the stable Router/Start API set (`createFileRoute`, `Link`, `HeadContent`, `Scripts`, `notFound`, `useNavigate`, `createServerFn`).

**But the stack is very young.** Verified against current docs and release notes:

- `@tanstack/react-start@1.169.4` (`app/package.json:14`) — TanStack Start **1.0 went stable on 2026-10-13** (official migration doc: "1.169 is the first stable release"; TanStack blog "TanStack Start 1.0 is Stable"). The app is on the exact latest stable, released 18 days before "today". The entire server layer rests on a framework that was an RC a month ago.
- `nitro@^3.0.260903-beta` (`app/package.json:22`, `nitro()` from `nitro/vite` at `app/vite.config.ts:6`) — **still a pre-release**. The `nitro` package's `latest` dist-tag is `3.0.261029-rc` (2026-10-30); the v3 line has been in public beta all year. However, this is the *officially mandated* path: TanStack Start's hosting docs direct node-server deployment through `nitro()` from `nitro/vite` ("still under active development"), the RC→stable migration table explicitly replaces `@tanstack/nitro-v2-vite-plugin` with `nitro()/vite`, and TanStack's own examples were bumped to nitro v3 beta (router PRs #6896, #6899). There is no stable alternative compatible with Start 1.169 (stable line is `nitropack@2` / h3 v1; Start ships h3 v2). The caret-prerelease range effectively pins the 3.0.260903 tuple, so installs won't drift.
- `vite@^8.0.14` (`app/package.json:13`, resolved 8.3.5) — stable since **2026-03-12** ("Vite 8.0 is out!"), but it's the Rolldown-rewritten major, and Start 1.0 *requires* Vite 8. `resolve.tsconfigPaths: true` (`app/vite.config.ts:9`) is a stable, documented Vite 8 option.
- The app's API usage within the framework is the *current stable* spelling, not RC-era leftovers: `.validator()` (not the deprecated/removed `.inputValidator()` — `app/src/lib/server.ts:19,25,30,35,45`), `shellComponent` on the root route (stable since router v1.122.0, 2025-06-27 — `app/src/routes/__root.tsx:18`), `createServerFn({ method: 'GET' })`, `validateSearch`/`loaderDeps`/`staleTime`/`head` (`app/src/routes/index.tsx:33-39`, `app/src/routes/pokemon.$name.tsx:6-11`), `notFound()` mapped from API 404s (`app/src/lib/server.ts:12`). Notably it does **not** use RSC (explicitly still experimental in Start 1.0), middleware, or devtools-in-prod.

### Scoring

- **reach: 3** — No experimental APIs *inside* the app code, but central features sit on recently-stable infrastructure (Start 1.0, 18 days old; Vite 8, ~7.5 months) plus one required pre-release (`nitro` v3 beta) powering the production build/serve.
- **containment: 5** — The only pre-release dependency touches exactly two files (`package.json:22`, `vite.config.ts:6`), matches the framework's documented recipe (one-line swap when nitro v3 goes stable), and all server functions are funneled through a single module (`app/src/lib/server.ts`).
- **justification: 5** — The nitro beta buys something no stable API can: a production node-server build for TanStack Start 1.0 (no stable bundler alternative exists for the node preset). The framework itself is mandated by SPEC.md. Everything else deliberately uses long-stable or canonical current APIs.
