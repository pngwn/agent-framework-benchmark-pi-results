## Review: test quality

The app contains **zero tests of its own**. The Angular scaffold set up the full Vitest toolchain (`@angular/build:unit-test` builder in `app/angular.json:68`, `tsconfig.spec.json`, `vitest` in `app/package.json:36`, a README section on unit tests), but not a single `*.spec.ts` exists anywhere under `app/src/`. Worse, `app/package.json:9` declares `"test": "ng test"`, which with no spec files will either error with "No test files found" or run an empty suite — a dead script someone will trip over the first time they try to run the app's own tests.

Everything the app does is guarded only by the acceptance suite in `tests/` (which it doesn't own), and there's a lot of high-risk pure logic that would be cheap to unit test: the entire data-shaping layer. Concretely untested, with the bugs that could hide:

- `app/src/app/util.ts:19` — `idFromUrl` returning `NaN` on a malformed URL silently produces species with no types and no generation (they just vanish from filters); `util.ts:29` — the "last **English** flavor entry + whitespace collapse" rule is easy to break by grabbing the last entry overall; `util.ts:10` — `humanize` edge cases (`nidoran-f`, `ho-oh`, empty segments).
- `app/src/app/catalog.service.ts:71-83` — the core derivation: types-in-slot-order reconstructed from type resources' `pokemon` lists, generation mapping, `id >= 10000` exclusion. A regression here scrambles type order or drops species with no visible error.
- `app/src/app/catalog.service.ts:127-160` — `pokemonRefsToCards`: dedupe, alternate-form exclusion, and the hidden-ability flag merge (`existing.hidden = true` only when a later ref carries it).
- `app/src/app/home.page.ts:44-66` — filtering, 48-per-page slicing, page clamp (`Math.min(requested, totalPages)`), and the parseInt fallback; classic off-by-one territory with zero coverage.
- `app/src/app/move-table.component.ts:22-30` — "missing values sort last in **both** directions" is implemented as an early return before the direction flip; a refactor that moves that check after the flip silently breaks descending sorts. Plus `aria-sort` toggling and the level/name secondary tiebreak (`move-table.component.ts:98-100`).
- `app/src/app/page-data.ts:120-127` — default game = highest `order`, and `page-data.ts:230-236` the level-up level-then-name sort; `page-data.ts:211-218` method table ordering (fixed four, then alphabetical).
- `app/src/app/pokeapi.service.ts:38-56` — promise cache with failure eviction and `normalize()` trailing-slash handling; a bug caches a rejected promise forever or misses the cache.
- Error paths: resolvers returning `null` (`page-data.ts:105-109` etc.) feeding `input.required<PokemonPageData | null>` and the SSR 404 via `RESPONSE_INIT` (`not-found.component.ts:12-15`).

The one mitigating factor is that this logic is factored into pure functions and resolvers (e.g. `catalog.service.ts` exports testable `pokemonRefsToCards`, `page-data.ts` exports resolvers taking `route`), so adding real tests would be straightforward — the agent just didn't. `home.page.ts:63-65` also has an uncleaned debounce timer (no `DestroyRef` cleanup), exactly the kind of leak a component test would surface.
