I've reviewed the app thoroughly. Before scoring, here's my assessment of what I found.

## Review notes

**Strengths.** This is a modern, idiomatic Angular 22 codebase: standalone components with `OnPush` everywhere, signal inputs + `computed` for filter/pagination/sorting state, `ResolveFn` resolvers feeding components via `withComponentInputBinding` (exactly the "modern" pattern in the official docs), `provideServerRendering(withRoutes(...))` with `RenderMode.Server` (the spec's "live data" requirement makes SSR-at-request-time the right call), `RESPONSE_INIT` for real 404s, TransferState for the API base, event replay, and the recursive evolution tree via `*ngTemplateOutlet`. The catalog design (deriving species→types/generations from the 18 type + 9 generation resources instead of 1,025 per-species fetches) is clever and well-bounded.

**What I verified before asserting.** The tsconfig without explicit `"strict": true` matches the current CLI 22 template (TS 6 defaults strict; `strictTemplates` defaults on) — not a finding. HTTP transfer cache is on by default with `provideClientHydration`, so resolver re-runs on the client don't refetch — also not a finding. Resolvers with `ResolveFn` + input binding are the documented approach, not legacy.

**Concerns.** (1) Every resolver's `catch { return null }` conflates 404 with any API failure — a transient 500 renders "Not found", and failures in the *secondary* fetches (evolution chain, move resources) reject the resolver with no `withNavigationErrorHandler`, so the SSR process 500s. (2) `page-data.ts` is a 400-line module holding all six resolvers plus every API resource and page-data interface — a merge hotspot. (3) The home page's debounce timer is never cleared on destroy; navigating away within 200 ms of typing yanks the user back to `/`. (4) The search input's `value="{{ q() }}"` attribute interpolation can clobber keystrokes made during the debounce window. (5) Small hygiene: duplicated title-setting effects in four components instead of route `title`/`TitleStrategy`, the `PokemonCardsComponent` injecting `PokeApi` just to build sprite URLs, scaffold boilerplate left in `server.ts` (default port 4000 vs spec's 3000), unused `@angular/forms`, and zero unit tests despite vitest being configured.
