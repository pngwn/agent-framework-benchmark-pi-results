## Review: forward-thinking

**Version check (verified):** Angular v22 is the current stable major (announced 2026-06-03; major releases now annual). v22 stabilized Signal Forms, `resource`/`httpResource`, and Angular Aria, made `OnPush` the default CD strategy, and introduced the `@Service()` decorator; zoneless is default since v21; Vitest is the default test runner since v21 (blog.angular.dev "Announcing Angular v22", angular.dev/events/v22, angularindepth.com v22 summary).

**What's current here (with sources):**
- All `@angular/*` at `^22.2.x`, no `zone.js` anywhere — correct for v21+ zoneless-by-default (app/package.json).
- Signals-only reactivity: `input()`, `signal()`, `computed()`, `effect()` — `app/src/app/home.page.ts:16`, `app/src/app/move-table.component.ts:83-85`.
- Resolvers + `withComponentInputBinding` — the skill's own `references/data-resolvers.md` labels input-bound resolved data "Modern"; appropriate for SSR where data must exist before render.
- Post-training-data APIs: `provideBrowserGlobalErrorListeners` (app/src/app/app.config.ts:2), `provideClientHydration(withEventReplay())` (app.config.ts:6), `BootstrapContext` (app/src/main.server.ts:3), `RESPONSE_INIT` 404 (app/src/app/not-found.component.ts:15), `RenderMode.Server` server routes (app/src/app/app.routes.server.ts:7), `@angular/build:unit-test` Vitest builder (app/angular.json).
- `server.ts` matches current CLI-generated boilerplate nearly verbatim.

**Issues found:**
- `app/tsconfig.json` omits `"strict": true` — the CLI default (verified: Angular CLI tsconfig has had `strict: true` since v12). Types get looser at boundaries than the framework's own baseline.
- `app/src/server.ts:22` uses `allowedHosts: ['*']`, directly contradicting the official SSR guidance ("Do not use a wildcard…", `.agents/skills/angular-developer/references/server-side-rendering.md:101`); `angular.json` security block is also left empty.
- `@angular/forms` is a declared dependency but never imported (grep for `FormsModule|ReactiveForms` across `app/src`: no matches).
- Four page components copy-paste the same `effect()` + `Title` boilerplate (pokemon.page.ts:29-32, move.page.ts:34-38, ability.page.ts:24-27, type.page.ts:68-71) instead of a route `title` resolver or a `TitleStrategy`.
- `idFromUrl` hand-rolls URL parsing with a regex (app/src/app/util.ts:18) where `new URL(url).pathname` is the platform tool.
- Mixed naming: new-style `app.ts`/`*.page.ts` alongside old-style `cards.component.ts`/`catalog.service.ts`, which the v20+ style guide dropped (skill `references/naming-conventions.md:10`).
- The `afterNextRender` → `ready` gate (home.page.ts:25-28, pokemon.page.ts:23) is a hydration-timing workaround duplicated in two components; coupling to a behavior `withEventReplay` already handles.
- Zero unit tests despite a fully wired Vitest/jsdom stack (testLoc = 0).
