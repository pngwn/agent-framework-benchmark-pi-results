## Review — forward-thinking

The app is a lean, SSR-first Angular 22 Pokédex. It is clearly written *against the current stable release* — signals-only reactivity, standalone components, control-flow templates, `withComponentInputBinding` + resolver data (the docs' "modern" access pattern), declarative `ServerRoute`/`RenderMode.Server` config, `RESPONSE_INIT` for the 404 status, `provideBrowserGlobalErrorListeners`, and no `zone.js` (zoneless by default). Against that high bar, there are a few v21-era leftovers: one deprecated call (`withFetch()`), one now-redundant call (`withEventReplay()`), and explicit `OnPush` everywhere that v22 makes the default.

**What's current and worth copying**
- `app/src/app/app.routes.server.ts:6` — `RenderMode.Server` via `ServerRoute[]`, matching the live-data requirement instead of prerendering.
- `app/src/app/pokeapi.service.ts:33-49` — one data-access module with typed resources, in-flight dedupe via a promise cache (spec-sanctioned), API origin through an `InjectionToken` + `TransferState` factory (`pokeapi.service.ts:18-31`).
- `app/src/app/not-found.component.ts:12-15` — `RESPONSE_INIT` for the 404 status, the current token.
- `app/src/app/home.page.ts:15-18` — filter state in URL inputs bound by `withComponentInputBinding`; derived pages via `computed`, no RxJS state.
- Native platform usage throughout: native `select`/`type="search"` controls (`home.page.html:5-29`), `loading="lazy"` + intrinsic `width`/`height` (`cards.component.ts:9`), CSS custom properties, no fonts/polyfills, `import.meta.dirname` (`server.ts:10`).

**What will age poorly**
- `app/src/app/app.config.ts:15` — `withFetch()` is **deprecated since v22** ("`FetchBackend` is the default `HttpBackend`", angular.dev/api/common/http/withFetch). On the exact version this app declares it should be a bare `provideHttpClient()`.
- `app/src/app/app.config.ts:16` — `withEventReplay()` is redundant in v22 (incremental hydration + event replay are defaults; the v22 CLI schematic was changed to drop it — angular/angular-cli#32996).
- `app/package.json:18` — `@angular/forms` is declared but never imported anywhere in `src/`.
- `app/src/server.ts:15` — `allowedHosts: ['*']` contradicts the current SSR guidance ("Do not use a wildcard… unless a trusted proxy validates forwarded headers"); the spec's proxy arguably justifies it, but it should be a deliberate, documented list.
- The `title.setTitle(...)` effect is copy-pasted in four components (`pokemon.page.ts:33`, `move.page.ts:86`, `ability.page.ts:47`, `type.page.ts:110`) while two routes use `route.title` — a custom `TitleStrategy` would put this in one place.
- `app/src/app/app.routes.ts:19` — `runGuardsAndResolvers: 'paramsOrQueryParamsChange'` re-runs the entire Pokémon resolver (species, evolution chain, all version groups, all move resources) whenever the `game` query param changes, though the tables are pure derivations of already-fetched data; a `computed`/`linkedSignal` off the query input would need no re-fetch.
- `app/src/app/home.page.ts:26-28` + `home.page.html:6` — controls are deliberately inert until `afterNextRender`, which fights v22's default event replay and leaves server-rendered users unable to interact until JS loads.
- `app/src/server.ts:18,54-57` — leftover CLI scaffold (example-API comment, PM2 check, default port 4000 where the spec says 3000).

Net: an upgrade to Angular 23 would touch `app.config.ts` (two lines), the redundant `OnPush` declarations, and `@angular/forms` in `package.json` — very little. Data access, display rules and config are all well-isolated.
