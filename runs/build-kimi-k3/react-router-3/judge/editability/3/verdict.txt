## Review notes

**Layering (strong).** The app has a clean three-layer structure that makes most edits predictable:
- `app/app/lib/pokeapi.server.ts` — all HTTP, caching, and API-shape knowledge, clearly marked server-only; caches are centralized (one `cache` Map at `:17` plus three memoized promises at `:70`, `:89`, `:126`).
- `app/app/lib/format.ts` — pure, shared display rules (`humanize`, `englishName`, `dexNumber`, `latestEnglishFlavor`) used by every route.
- `app/app/components/ui.tsx` — the shared `Section`/`TypeBadge`/`PokemonCard`/`PokemonCardList` primitives; all four card lists on the app (home `:126-130`, move `:90`, ability `:35`, type `:74`) render through `PokemonCardList`, so card-level changes have a single choke point.
- Loaders return plain serializable data; the client gets the API origin via the root loader (`app/app/root.tsx:7-8`) consumed through `useRouteLoaderData` (`app/app/lib/urls.ts:4-6`). Server/client separation is a genuine seam.

**Where it costs you an edit:**

1. **Sprite URL knowledge is duplicated and disconnected from API data.** There are two `spriteUrl` implementations (`app/app/lib/pokeapi.server.ts:46` — actually dead, never imported — and `app/app/lib/urls.ts:9`), both hard-coding the `/media/sprites/pokemon/<id>.png` pattern instead of using `sprites.front_default` from the API. `PokemonCard` reconstructs the URL from `card.id` (`app/app/components/ui.tsx:52`) rather than receiving it from the loader. The Deoxys-style sprite fix means changing `PokemonCardData` (`pokeapi.server.ts:170-176`), `pokemonRefsToCards`, `getIndex`'s `SpeciesEntry`, `CardData` (`ui.tsx:29-33`), and the render — and you'd have to remember the dead server copy exists. The fix *does* cover every list, but only because every list funnels through the same two functions.
2. **The root `ErrorBoundary` mislabels every error as "Not found"** (`app/app/root.tsx:65-74`): a thrown 500 from `apiGet` renders a 404-styled page, and it hand-duplicates the `NotFound` component markup (`ui.tsx:55-62`) plus the per-route `notFound` flag renders — three renderings of "not found" to keep in sync.
3. **Loader boilerplate repeated verbatim 4×**: `decodeURIComponent(params.name).toLowerCase()` + try/`isNotFound`/`data({notFound:true},{status:404})` + `meta` not-found title + `if ("notFound" in loaderData)` guard appear in `pokemon.tsx:62-68`, `move.tsx:9-15`, `ability.tsx:9-15`, `type.tsx:15-23`. Adding the Items section means copying this block a fifth time.
4. **Smaller copy-paste**: the type-badge markup is inlined again inside `type.tsx:70-80` instead of reusing `TypeBadge`; the em-dash `num()` helper exists twice (`move.tsx:41`, `pokemon.tsx:224`); the `API_BASE_URL` default + trailing-slash normalization is duplicated (`pokeapi.server.ts:5`, `root.tsx:7`).
5. **Type-blind loaders**: heavy `any` (`pokemon.tsx:80-160`, `move.tsx:9-20`) means edits lose type-guidance at exactly the layer that encodes the API shape.

On the plus side, removal is genuinely contained: deleting `ability.tsx`, the `routes.ts:7` line, and the Abilities section in `pokemon.tsx:357-368` does it — the only residue is the `hidden`/`is_hidden` plumbing (`pokeapi.server.ts:201-204`, `ui.tsx:62`) that would go dead. And `home.tsx:27-29`'s `shouldRevalidate = false` is a deliberate, commented tradeoff, idiomatic for a static index page.
