## Review

**Structure.** This is a clean, conventionally-layered React Router 8 (framework mode) app: `app/routes.ts` route config, per-route modules with generated `+types` types, a server-only data layer (`lib/pokeapi.server.ts`, `.server.ts` suffix keeps it out of the client bundle), a client-safe `lib/format.ts` / `lib/urls.ts` pair, and a small shared component file. Loaders produce serializable view-models; components stay presentational. That layering is the app's biggest editability asset — every one of the five scenarios lands in a bounded set of files.

**Scenarios worked through.**

1. *Remove Abilities*: delete `routes/ability.tsx` + one line in `routes.ts:7` + the Abilities section (`pokemon.tsx:358-366`) and its loader field (`pokemon.tsx:160-166`). The leak: "hidden ability" support is baked into the shared card (`ui.tsx:62`, `CardData.hidden` `ui.tsx:42`, `pokemonRefsToCards` `pokeapi.server.ts:212`, `.pokemon-card-hidden` CSS `app.css:213`), so a full cleanup touches 3 more files or leaves dead code.
2. *Sprite fix*: every card list renders through `PokemonCardList` → `PokemonCard` (`ui.tsx:79-93`, `ui.tsx:52`), which derives the sprite from `card.id` via `urls.ts:9`. One fix there covers all four lists; if the correct sprite needs API data, the change extends to `pokemonRefsToCards`/`CardData` — still contained. However the sprite pattern exists twice (`urls.ts:9` and the **unused** `pokeapi.server.ts:46`), so a pattern change touches two files.
3. *Sort by name*: one place covers move/ability/type lists (inside `PokemonCardList`), but home slices before rendering (`home.tsx:104-105`), so home must sort in its `filtered` computation — two files, and home must not break spec-required dex ordering.
4. *Items section*: `Section`, `PokemonCardList`, `pokemonRefsToCards`, and format helpers are directly reusable; the loader-try/catch→404 + meta + `NotFound` render boilerplate is duplicated per route (`move.tsx:14-21,39-41,45`, same in ability/type/pokemon) rather than a shared helper, so you copy ~10 lines. No `/moves` index route exists, so the "shaped like Moves" list page is genuinely new code.
5. *Data source change*: caching rules live in exactly one place (`pokeapi.server.ts:15-31` plus module memo promises). The base URL is known in two (`root.tsx:7` for the client, `pokeapi.server.ts:5` for the server) — duplicated env parsing that can drift.

**Notable frictions:** the type-color `var(--type-<name>)` rule is written inline three times instead of using the existing `TypeBadge` (`ui.tsx:32`, `types.tsx:24`, `type.tsx:69-72`); the `num`/em-dash formatter is duplicated (`move.tsx:46`, `pokemon.tsx:246`); the root `ErrorBoundary` (`root.tsx:65-77`) renders "Not found" for *any* error, including 500s, and re-inlines the `NotFound` markup from `ui.tsx:68-77`; `CardData` (client) and `PokemonCardData` (server) are two hand-maintained copies of the same shape plus the home route's inline mapping (`home.tsx:123`). None of these are severe; they're the kind of thing a PR comment would ask to tidy.
