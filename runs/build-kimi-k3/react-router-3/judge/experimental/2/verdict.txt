## Review: experimentalness

The app is maximally conservative. Verified against the current stable release — `react-router@8.5.1`, published 2026-10-27 (npm + reactrouter.com/changelog) — which is exactly what `app/package.json` pins.

**What the code uses (all long-stable):**
- `app/package.json:14-16` — `react-router`/`@react-router/dev`/`@react-router/serve` 8.5.1 = current stable line (v8.0.0 shipped 2026-06-17 per remix.run/blog/react-router-v8; v8.5.1 is the latest patch, 3 days old)
- `app/app/root.tsx:1` — `Links`, `Meta`, `Outlet`, `Scripts`, `ScrollRestoration`, `Link`: the standard root component exports, stable since v7
- `app/app/routes/not-found.tsx:1,6` — `data({}, { status: 404 })`: the `data()` utility, stable since v7.0
- `app/app/routes/home.tsx:16-18` — `shouldRevalidate` returning `false`: a stable, documented opt-out (deliberate and commented)
- `app/app/lib/urls.ts:2` — `useRouteLoaderData("root")`: stable since v6.x
- `app/app/routes.ts:1`, `app/react-router.config.ts:3` — `route`/`index` config and `ssr: true`: stable config surface
- `./+types/*` typegen (`Route.LoaderArgs`, `Route.MetaArgs`, `Route.ComponentProps` — used across all routes, e.g. `app/app/routes/move.tsx:7,35,42`): stable since v7
- React 19.3.1, Vite 7, isbot 5 — all stable tooling

**What it deliberately avoids:** no `unstable_`/`experimental_` names anywhere in source (grep clean), no RSC (`unstable_reactRouterRSC` per the framework-mode skill), no future flags in `react-router.config.ts`, and none of the v8.5.0 preview features (API-only mode, custom fetch metadata, application-controlled route discovery — all listed as *unstable* in the v8.5.0 changelog). It also sidesteps the view-transition APIs that v8.5.0 just deprecated. The only mild note: the exact `8.5.1` pin (no `^`) on a patch released three days before today means every `npm install` rides the newest patch — a hygiene nit, not an experimentalness risk.
