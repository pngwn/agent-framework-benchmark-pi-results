## Review — Test quality

The app is a well-factored React Router 8 framework-mode app (`app/app/routes.ts` with typed `Route` imports, server loaders in `app/app/lib/pokeapi.server.ts`), but **it shipped with zero tests of its own**: no test script in `app/package.json:6-10`, no test dependencies, no spec/test files anywhere under `app/app/` (verified with `ls`/`grep`; the only "test"-matching hits are compiled output in `app/build/` and a transitive dep name in `package-lock.json`). There is also no `typecheck`-adjacent guard beyond `npm run typecheck`, and no CI hook. Everything that protects this code today lives in `tests/`, which the harness owns and which the agent was told not to count on.

That's a real problem here specifically, because the riskiest code is exactly the kind that browser-level acceptance tests probe thinly:

- **The whole data layer is untested.** `pokemonRefsToCards` (`app/app/lib/pokeapi.server.ts:199-222`) does polymorphic input handling (`ref.pokemon ?? ref`), alternate-form exclusion at id ≥ 10000, dedupe, hidden-ability flag OR-merging, and id ordering — a refactor that drops the `is_hidden` merge on line 212-213 would silently unmark every "Hidden ability" card, and nothing in `app/` would fail. These functions are pure-ish and trivially unit-testable with fixture JSON.
- **`buildIndex`** (`app/app/lib/pokeapi.server.ts:133-184`) derives per-species types by scanning all 18 type records and generation membership from generation records, with silent fallbacks (`?? ""` on line 178 for missing generation). A species missing from type lists gets empty types and vanishes from every type filter with no error. The live-overlay test catches one specific instance of staleness, but none of the derivation logic.
- **URL-state logic on the home page** (`app/app/routes/home.tsx:29-77`): filter composition, page clamping (line 46 silently clamps a stale `page` while leaving it in the URL), and — a genuinely latent bug — `const [q, setQ] = useState(() => searchParams.get("q") ?? "")` (line 34) initializes once, so a back/forward navigation to a different `?q=` leaves the input and filtered list desynced from the URL. The acceptance suite only types into the box, so this class of bug ships silently.
- **Moves aggregation** (`app/app/routes/pokemon.tsx:68-127`): min-level dedupe across `move|method` keys (lines 78-84), the fixed-then-alphabetical method comparator (lines 112-117), and the level-up (level, then name) sort (line 119). The acceptance suite checks one Pokémon's rendering, not the aggregation rules.
- **Client-side column sorting** (`app/app/routes/pokemon.tsx:221-247`): the "missing values sort last in both directions" rule and the flip-to-descending behaviour are exactly the sort of thing that breaks under refactor; only two tables on one Pokémon are exercised by the harness.
- **Error paths are untested and one is wrong**: `app/app/root.tsx:65-70` renders "Not found" for *every* thrown error, so an API 500/network failure masquerades as a 404. A loader-level or error-boundary test would catch this immediately; nothing will.
- **`apiGet`'s promise cache** (`app/app/lib/pokeapi.server.ts:18-40`) — delete-on-failure retry semantics — and the format helpers (`app/app/lib/format.ts:33-45` `latestEnglishFlavor`'s last-English-entry + whitespace collapse; `idFromUrl` returning `NaN` for malformed URLs) are the cheapest, highest-leverage unit tests in the repo and none exist.

On the positive side, the code is structured to be testable: pure helpers isolated in `app/app/lib/format.ts`, loaders separated from components, and a single `Section`/card component set in `app/app/components/ui.tsx` — so a test suite could be added with almost no restructuring. React Router 8 framework mode supports testing loaders in-memory and components with `@testing-library/react`; a day's work would cover items 1-3 above.

Scores: `coverage_of_risk` 1 and `regression_power` 1 (no tests exist; nothing the team owns would fail), `behaviour_not_implementation` 1 (no tests), `signal_to_noise` 3 (no noise, per the rubric's "no tests" anchor). Overall 1: for a data-transformation-heavy app that a team will own for years, shipping no safety net behind the acceptance suite is a reject-on-the-PR condition.
