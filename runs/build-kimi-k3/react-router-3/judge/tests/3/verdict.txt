# Review — Test quality

**Verdict: the app shipped with zero tests.** There is no test runner in `app/package.json:5-10` (only `build`, `start`, `dev`, `typecheck`), no test dependencies, no test files anywhere under `app/` (confirmed by grep across `**/*.{ts,tsx,js,mjs}`), and the measured facts agree (`tests: {files: 0, cases: 0}`). The only `test`-matching strings are in the build output (`app/build/`) and incidental comments. The acceptance suite in `tests/` (Playwright specs for home/layout/pokemon/details) is the sole safety net, and it won't exist once someone refactors.

That's a shame, because the app concentrates substantial risk in exactly the kind of logic that deserves tests:

- **Pure transforms begging for unit tests** — `app/app/lib/format.ts:16` (`humanize` word-splitting/capitalization), `format.ts:26` (`idFromUrl` regex, returns `NaN` on no match), `format.ts:33` (`dexNumber` zero-padding), `format.ts:38` (`latestEnglishFlavor` — "last English entry" + `\s+` collapse, a spec-pinned detail). All are dependency-free functions; not one has a test.
- **URL-state filtering/pagination** — `app/app/routes/home.tsx:34-66`: the client-side filter predicate (case-insensitive humanized substring, type-in-either-slot, generation), 48-per-page slice, page clamping, `pageHref` param omission at defaults, and `updateFilter`'s page-reset. And there's a live bug risk here: `q` is local state initialized once (`home.tsx:28`) with no resync effect, so after browser Back the URL and the applied filter can disagree — precisely the class of bug a URL-state test would catch.
- **Server data aggregation** — `app/app/lib/pokeapi.server.ts:118-184` (`buildIndex`): deriving per-species types from the type records, slot sorting, alternate-form exclusion (`id >= 10000`), generation back-mapping. `pokeapi.server.ts:191-220` (`pokemonRefsToCards`): form exclusion, dedupe, and the `existing.hidden || hidden` merge — a flipped comparison would silently drop or duplicate cards on the move/ability/type pages.
- **Moves table** — `app/app/routes/pokemon.tsx:68-130`: per-move min-level dedupe, the `FIXED_METHODS`-then-alphabetical method ordering, default game = highest `order`. And `pokemon.tsx:214-237`: client-side sortable headers with "missing last in both directions" and `aria-sort` — classic off-by-one territory, fully untested.
- **Error paths** — `app/app/lib/pokeapi.server.ts:14-35`: the promise cache, failure-eviction, `isNotFound` 404 discrimination; loaders' `data({notFound:true},{status:404})` branches in every route (`pokemon.tsx:48-51`, `move.tsx:11-15`, `ability.tsx:10-14`, `type.tsx:13-20`). A regression here blanks every 404 page at once.
- **Smaller drift risks** a test would have surfaced: `humanize` is used where the spec calls for English names (`pokemon.tsx:145` move-type label, `move.tsx:30`), and a move with no damage class yields an empty `category` (`pokemon.tsx:146`) instead of the spec's `—`.

The one mitigation is `app/package.json:9` — a `typecheck` script (react-router typegen + tsc) — which catches some refactor breakage, but nothing behavioural.
