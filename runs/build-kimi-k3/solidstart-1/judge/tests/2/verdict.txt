The riskiest logic is all in untested, mostly-pure code that would be cheap to test:

- `app/src/lib/util.ts:29` — `latestEnFlavor` ("last English entry" + `\s+` collapse): an off-by-one (first vs last) or missing trim would slip straight through.
- `app/src/lib/api.ts:60-79` — `toSpeciesCards`: alternate-form exclusion (`id >= 10000`), dedupe by id, species-name resolution (Deoxys `deoxys-normal` → `Deoxys`), sort by dex. A refactor that filters by name instead of id would leak forms or drop species with no failing test.
- `app/src/routes/index.tsx:44-57` — search/type/generation filtering, humanized-name matching, 48-per-page slicing, and the `Math.min(page(), totalPages())` clamp.
- `app/src/routes/index.tsx:34-40` — debounced URL state sync (`setSearchParams({ q, page: undefined })`); a regression that stops clearing `page` on filter change or pushes a history entry per keystroke would go unnoticed.
- `app/src/routes/pokemon/[name].tsx:141-186` — move-table grouping (dedupe key `${method}|${level}`), `METHOD_ORDER` sentinel-99 ordering, and level-then-name default sort.
- `app/src/routes/pokemon/[name].tsx:190-208` — column sorting: nulls-last in both directions, numeric vs string comparison, `aria-sort` toggling.
- `app/src/lib/api.ts:17-33` — promise-dedupe cache with failure eviction; caching a 404 forever would break the "live data overlay" scenario permanently with nothing to catch it.
- Error paths: `app.tsx:16` wraps routes in `Suspense` only, no `ErrorBoundary`; a single 500 among the ~100 parallel move fetches in `api.ts:158` (`Promise.all` over `pokemon.moves`) takes out the whole Pokémon page, and no test exercises it.

One point in the app's favor: the data-assembly logic is isolated in pure-ish server functions (`loadHomeData`, `toSpeciesCards`, `evoTree`) and pure helpers (`humanize`, `dexNumber`, `statLabel`), which is exactly the shape that makes adding tests easy — but none were added.
