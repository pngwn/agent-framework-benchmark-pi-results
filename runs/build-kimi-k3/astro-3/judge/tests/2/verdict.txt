This app has none of that — the measured facts and my own scan agree: no test files, no runner, no test script in `app/package.json:6-9`.

What makes this particularly costly is that the app's riskiest logic is well-factored into pure, trivially-testable functions that now have zero protection:

- **Data layer** — `app/src/lib/data.js:36-48` (`getPokemonTypesMap` builds id→types from 18 type records with slot ordering and `id > MAX_MAIN_ID` exclusion), `app/src/lib/data.js:76-90` (`pokemonRefsToSpecies` dedupes by species id and sorts). A refactor here (e.g., changing the dedupe or the exclusion bound) would silently corrupt every card list on move/ability/type pages.
- **Formatting** — `app/src/lib/format.js:10` (`humanize` — `mr-mime` → `Mr Mime`), `app/src/format.js:22-26` (`latestEnglishFlavor` last-English-entry + whitespace collapse), `app/src/lib/format.js:30` (`idFromUrl` regex). All pure, one-line-to-test, untested.
- **Filtering/pagination** — `app/src/pages/index.astro:36-58`: search substring match, type/generation membership, `Math.ceil`/`slice` pagination and the silent `Math.min(pageParam, totalPages)` clamp. An off-by-one here or a broken filter would only be caught by the acceptance suite.
- **URL state client script** — `app/public/js/home.js:20-44`: debounce, `pushState`, a `seq` race guard for superseded fetches, DOM-parsed `innerHTML` swap, and `popstate → reload`. Race/back-button bugs here are exactly the kind a unit or component test misses and only intermittent user reports reveal.
- **Table sorting** — `app/public/js/pokemon.js:10-41`: textContent-based compare, missing-values-last in both directions, aria-sort state machine. Fragile (e.g. `Number(av)` on unexpected cell text), untested.
