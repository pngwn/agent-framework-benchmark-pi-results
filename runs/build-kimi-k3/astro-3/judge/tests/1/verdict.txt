## Review — test quality

The app ships **zero tests of its own**. `app/package.json` has only `dev`/`build`/`start` scripts (app/package.json:6-11), there are no devDependencies (no runner, no assertion library), and a repo-wide search for `describe(`, `.spec.`, `.test.`, or `vitest` under `app/` returns nothing. `tests.files === 0` in the measured facts confirms it. Every guard on this codebase is the external Playwright acceptance suite, which the agent didn't write and which won't protect a refactor of the data layer.

That's a real loss here, because this codebase is unusually rich in exactly the logic the dimension asks about — pure transformation helpers, URL-state parsing, pagination math, and a hand-rolled concurrency/caching layer — all of which is unit-testable without touching Astro:

- **Pure formatters**: `humanize`, `dexNumber`, `englishName`, `collapseWhitespace`, `latestEnglishFlavor`, `idFromUrl`, `orDash` in `app/src/lib/format.js:3-33`. Trivial to test; regressions (e.g. someone "simplifying" `orDash` to `!value` and turning power `0` into `—`, or breaking the `mr-mime → Mr Mime` rule) would currently slip through.
- **Data-layer transformations**: `pokemonRefsToSpecies` (app/src/lib/data.js:56-70) does alternate-form exclusion (`id <= MAX_MAIN_ID`), species dedupe, and dex sort — the exact place a `deoxys-normal → Deoxys` mapping bug would live. `getPokemonTypesMap` (app/src/lib/data.js:32-49) does slot-order assembly from type records.
- **Fetch cache + concurrency pool**: `fetchJson` promise-caching with rejected-promise eviction (app/src/lib/api.js:13-32) and `mapAll`'s order-preserving worker pool (app/src/lib/api.js:35-45) are both subtle and completely unguarded.
- **URL state & pagination**: `index.astro` parses/clamps `page` (app/src/pages/index.astro:28-30), combines three filters (app/src/pages/index.astro:46-58), and builds canonical URLs that omit defaults (app/src/pages/index.astro:55-63). An off-by-one in `slice((page-1)*48, page*48)` or in `pageUrl` would only be caught by the acceptance suite, if at all.
- **Moves logic**: version-group selection/defaulting and per-method grouping with min-level dedupe (app/src/pages/pokemon/[name].astro:52-76), plus the method-order comparator with its `-1 → 99` fallback (app/src/pages/pokemon/[name].astro:85-91) — dense comparator logic that is classic regression bait.
- **Client JS**: table sorting with missing-values-last-in-both-directions and aria-sort toggling (app/public/js/pokemon.js:18-46), and the debounced filter fetch with its stale-response race guard (app/public/js/home.js:21-37). Both are DOM-behavioural and would be cheap to lock down with a couple of Playwright tests inside the app.
- **Error/404 paths**: three routes each reimplement the `err?.status === 404 → NotFound` pattern (app/src/pages/moves/[name].astro:40-47, app/src/pages/abilities/[name].astro:30-37, app/src/pages/pokemon/[name].astro:124-131), and types/[name].astro has a separate excluded-type branch (app/src/pages/types/[name].astro:17-19). Nothing verifies a non-404 error stays a 500 rather than rendering the not-found page (or vice versa).
