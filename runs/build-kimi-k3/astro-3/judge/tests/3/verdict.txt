## Review: test quality

The facts are unambiguous: **`app/` contains zero tests** — no test files, no test runner in `package.json` (`app/package.json:7-10` has only `dev`/`build`/`start`), no devDependencies at all, and no `tsconfig.json`/`astro check` as even a static guard. This is against a project with ~650 significant LOC of genuinely testable logic, and Astro's current testing guidance (Vitest via `getViteConfig()`, Playwright for e2e, the Container API for `.astro` components) makes setup a one-file job — verified against docs.astro.build's current testing guide. The acceptance suite in `tests/` is the *only* safety net, and once a refactor lands (say, splitting the data layer or touching the client scripts), nothing in `app/` will catch regressions.

What makes this especially costly is how much of the app's risk lives in exactly the shapes that are cheap to unit-test:

- **Pure helpers** at `app/src/lib/format.js:1-33` — `humanize`, `dexNumber` (`#0025` padding), `latestEnglishFlavor` (last-English-entry + whitespace collapse), `idFromUrl`. All deterministic, zero mocking needed.
- **Home filtering + pagination + URL params** at `app/src/pages/index.astro:34-52` — the combine of search/type/generation, the 48-per-page slice, `page` clamping, and `pageUrl`'s "omit defaults" rule (`index.astro:48-56`). A subtle change to any of these fails silently without tests.
- **Client URL-state script** at `app/public/js/home.js:22-48` — debounced re-fetch, `pushState` param omission, the `seq` race guard, and the `popstate` reload. This is the single most fragile file in the app and has no automated coverage of any kind (the acceptance tests do exercise it, but they aren't in `app/`).
- **Move-table sorting** at `app/public/js/pokemon.js:19-46` — the missing-values-last-in-both-directions comparator, `aria-sort` toggling, numeric-vs-string columns. Flip that comparator and tests wouldn't notice — because there are none.
- **Species/alternate-form mapping** at `app/src/lib/data.js:56-75` (`pokemonRefsToSpecies`: ID >10000 exclusion, dedupe by species, dex sort) and `app/src/lib/data.js:32-46` (`getPokemonTypesMap`: slot ordering — note it would happily record the same type twice if the data listed it in both slots).
- **Move grouping / game selection** at `app/src/pages/pokemon/[name].astro:55-84` — min-level-per-move, method-order comparator with the `-1 → 99` fallback, "highest `order` is default".
- **Error paths**: every `[name].astro` catch block (e.g. `app/src/pages/moves/[name].astro:41-48`, `app/src/pages/types/[name].astro:38-45`) only treats `err.status === 404` as Not Found and **rethrows everything else as a 500** — a missing `varieties` array would crash the Pokémon page instead of showing Not Found; nothing tests that boundary.

The one mitigation: the logic is reasonably well-factored into `lib/` modules that a future owner *could* test with minimal effort — but as delivered, a refactor of the data layer has no guard other than the acceptance suite.
