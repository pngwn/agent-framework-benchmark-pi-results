## Review

I read the spec, all of `app/src/` (pages, components, `lib/`, `public/js/`, `global.css`), and verified against current Astro (the app pins `astro@^7.4.4` — the current stable line as of 2026-10 — and `@astrojs/node@^11`, `app/package.json:11-12`, which is correct and current).

**Structure at a glance:** `output: 'server'` with the Node standalone adapter (`app/astro.config.mjs`), six routes, five components, and three small lib modules (`api.js` fetch+cache, `data.js` derived data, `format.js` pure formatting). Pages do their own data shaping; client enhancement lives in two IIFE scripts under `app/public/js/`.

**Scenario walk-throughs (evidence for the scores):**

1. **Remove Abilities** — delete `app/src/pages/abilities/[name].astro` and cut the clearly-bounded Abilities section at `app/src/pages/pokemon/[name].astro:200-209`. The nav (`app/src/components/Layout.astro:31-33`) has no Abilities link, and `NotFound`/404 are generic. Residue: `hidden` prop in `app/src/components/PokemonCard.astro:14,39` and `.card-hidden` in `app/src/styles/global.css:253` become dead — that's what keeps this from a 5.
2. **Sprite bug (Deoxys et al.)** — the sprite decision is centralized: `spriteFor()` at `app/src/lib/api.js:49`, used only by `app/src/components/PokemonCard.astro:22`, and all four card lists render through that component. So the simple fix is one place. But the card takes a species `id`, not a sprite URL; if the fix needs the default Pokémon's own `front_default`, every card producer must thread new data through: `app/src/lib/data.js:48-64` (`pokemonRefsToSpecies`), `app/src/pages/abilities/[name].astro:19-29` (its own inline copy of that mapping), and `app/src/pages/index.astro` (species list only). One fix covers every list for the spec-permitted case; the seam exists but is shallow.
3. **Sort cards by name** — touch `app/src/lib/data.js:63` (`out.sort` in `pokemonRefsToSpecies`, covers Moves "Learned by" and Types "Pokémon"), `app/src/pages/abilities/[name].astro:29` (second, independent sort), and `app/src/pages/index.astro:43-56` (the filtered list). Three files, two of which contain duplicated "unique species by dex" logic — a comparator that would also be written twice unless you factor it.
4. **Items section** — reusable: `Layout`, `NotFound`, `TypeBadge`, `PokemonCard`, and the whole `lib/` (fetch/404 semantics, `humanize`/`englishName`/`latestEnglishFlavor`/`orDash`, `pokemonRefsToSpecies`). Not reusable: the ~35-line page scaffold — `try { fetchJson(…); …shape data } catch (err) { if (err?.status === 404) … }` — is duplicated verbatim across `app/src/pages/moves/[name].astro:20-51`, `abilities/[name].astro:13-34`, `types/[name].astro:26-49`, `pokemon/[name].astro:33-155`, so `/items/:name` means copying it again.
5. **API base URL / caching** — one file: `app/src/lib/api.js:4,13` (base URL and `/api/v2` joining), `:8-38` (the promise cache and its retry-on-failure policy), `:49` (media base). Nothing else in `src/` hardcodes an origin (grep for `localhost|9000` confirms). Trivial.

**Cross-cutting observations:**

- The abilities page reimplements the Pokémon→species mapping that `data.js:48-64` already owns (it needs `is_hidden`, but the shared core — id extraction, `MAX_MAIN_ID` filter, fetch, species dedupe — is copy-pasted at `app/src/pages/abilities/[name].astro:19-29`). This is the sharpest duplication in the app; a change to form-exclusion rules lands in two places.
- Filter-state serialization exists twice: server-side `pageUrl` at `app/src/pages/index.astro:52-59` and client-side `apply` at `app/public/js/home.js:9-14` both encode "omit empty/default params", and `home.js` depends on five hardcoded element IDs that `index.astro` must keep producing. Adding a filter means editing both, plus the swap target `#results`.
- The `<p class="result-count">{n} Pokémon</p><ul class="card-grid">` card-list markup is repeated at `app/src/pages/moves/[name].astro:84-90`, `abilities/[name].astro:58-64`, `types/[name].astro:85-92`, `index.astro:105-113` — a `CardList` component is the obvious missing abstraction.
- Typing is weak at the seams: every page's shaped `data` object is `any` (e.g. `app/src/pages/pokemon/[name].astro:31,121-140`), so refactors get no compiler help — cheap to fix with interfaces in `lib/`.
- Styling is one 553-line `app/src/styles/global.css` shared by all pages. Consistent, but removing a feature leaves dead rules (`.card-hidden`, `.move-list`, `.relations`) and Astro's per-component scoped styles would localize them.

**What's good:** `format.js` is exactly the right pure-function layer; `api.js` cleanly isolates the one thing most likely to change (origin + caching); components take narrow props with no prop drilling; the server/client split is crisp — the client scripts only enhance already-working pages, so removing `home.js` breaks nothing functionally. On current Astro 7 this is a conventional, well-organized SSR app; nothing deprecated or experimental was used.
