I've reviewed the spec, the app source, and the acceptance suite. The measured facts are confirmed: `app/` contains **zero test files** — no test runner dependency, no `test` script (`app/package.json:5-10` only defines build/dev/start/typecheck). So this review focuses on where the unguarded risk lives.

**Where the risk is (all verified by reading):**

- **Home filtering/pagination** — `app/app/routes/home.tsx:79-96` does case-insensitive substring match against humanized names, type-in-either-slot, generation membership via `Set`, and page slicing with clamping. All pure, easily testable logic, none tested. The only guard is the acceptance suite, which checks a handful of fixed URLs.
- **URL state machinery** — `app/app/routes/home.tsx:43-77` is the classic bug nest: debounced search, `lastSubmitted` ref for back/forward sync, `next.delete("page")` on filter change, `pageHref` returning a bare `"?"` (`home.tsx:108-110`).
- **Move table sorting** — `app/app/components/MoveTable.tsx:26-38` implements the subtle "missing values sort last in both directions" rule plus direction flip and `aria-sort`; `app/app/routes/pokemon.tsx:101-127` implements default ordering (level-up by level then name, methods Level Up → Machine → Egg → Tutor → alphabetical). These are exactly the invariants a refactor breaks silently.
- **Data-layer index construction** — `app/app/lib/api.server.ts:76-165`: species index sort, `idFromUrl` regex, slot-ordered type map, alternate-form exclusion by "default Pokémon has same ID as species". A refactor of `getSpeciesTypeMap` (e.g., fetching per-pokemon) could reorder types or admit forms with no test failing inside `app/`.
- **Caching semantics** — `app/app/lib/api.server.ts:44-58` caches the promise *before* resolution and never evicts on rejection: one transient API hiccup permanently poisons that URL (and the species index) until process restart. No test could catch this because none simulates failure.
- **Error paths** — `app/app/root.tsx:47-56`: the `ErrorBoundary` renders "Not found" for *any* thrown error, so an API 500 would masquerade as a 404 page; loaders use the `data({notFound:true},{status:404})` pattern instead (`app/app/routes/pokemon.tsx:44`), so the boundary is only reachable by real errors.
- **Pure formatters** — `app/app/lib/format.ts:1-27` (humanize, dex padding, latest-English flavor text with `\f` collapsing) are trivially unit-testable and carry spec rules, but aren't.

The acceptance tests are decent behavioural coverage *today*, but they live outside `app/` and target fixed fixtures — none of the above logic has an in-repo regression guard.
