The app contains **zero tests of its own** — no test files, no test script in `app/package.json` (only `build`, `dev`, `start`, `typecheck` at `app/package.json:6-9`), and no test runner dependency. All quality risk therefore lives in untested application logic, which I've read in full: the cache/limiter layer, the home filtering/pagination/URL-state code, the move-table comparator, the pokemon loader's grouping/ordering, and the small format helpers.

The riskiest untested logic, with the concrete bugs it could hide:

- **Promise cache never evicts failures** — `app/app/lib/api.server.ts:52-64` stores the promise in `cache` before resolution and never removes rejected ones, so one transient 500/network blip poisons that URL for the process lifetime; the acceptance suite (green-path API) can't catch this.
- **Error semantics** — `getRecordOrNull` (`api.server.ts:176-181`) maps only 404 to "not found"; any other API error bubbles to `root.tsx:35-45`'s `ErrorBoundary`, which renders an h1 `Not found` for what is really a 500.
- **URL state / back-forward sync** — the debounce + `lastSubmitted` ref dance in `app/app/routes/home.tsx:41-71` is exactly the kind of code that breaks silently (box desyncs from URL on back/forward, `page` not deleted on new filter).
- **Page clamping** — `home.tsx:136-138` clamps `page` for rendering but leaves `?page=99` in the URL, and `pageHref` (`home.tsx:126-135`) steps from the clamped value, producing odd links.
- **Sort comparator** — `app/app/components/MoveTable.tsx:26-71`: missing-values-last-in-both-directions, direction toggle, and `aria-sort` are pure functions with no guard; an inverted sign flip would pass nothing in-house.
- **Move grouping/ordering** — `app/app/routes/pokemon.tsx:69-140`: version-group dedupe + `order` sort, default = highest order, `METHOD_ORDER` then alphabetical, level-up sort by level→name — many places to regress during a refactor.
- **Pure helpers** — `app/app/lib/format.ts` (`humanize`, `englishName`, `latestEnglishFlavor`'s whitespace collapse / last-`en`-entry selection) are trivially unit-testable and untested.
- **Alternate-form exclusion** — implemented implicitly via species-index membership (`api.server.ts:146-156`, `168-172`); a partial species index would leak forms into every list with no failing check.
