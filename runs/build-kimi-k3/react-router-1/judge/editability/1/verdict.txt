## Review notes

**Structure (good seams):** All API access, caching, concurrency limiting, and the API/media base URL live in one server-only module (`app/app/lib/api.server.ts`), imported only by loaders — the `.server` suffix keeps it out of the client bundle, which is the idiomatic framework-mode pattern. Route components are presentational and props-driven (`PokemonCard`, `PokemonCardList`, `Section`, `TypeBadge`, `MoveTable`). The sprite URL is built in exactly one place (`PokemonCard.tsx:30`), so the Deoxys-style sprite bug scenario has a single fix point covering home, move, ability and type lists.

**Where it costs you edits:**

- **Loader→component contract is untyped on 4 of 6 routes.** `pokemon.tsx:172`, `move.tsx:45`, `ability.tsx:40`, `type.tsx:52` all take `loaderData: any`, and `home.tsx:42` hand-rolls `Awaited<ReturnType<typeof loader>>` instead of the generated `Route.ComponentProps` from `./+types/<route>` (which the tsconfig already includes via `.react-router/types`, so typegen is set up but unused). Renaming a loader field compiles silently and breaks at runtime.
- **Three near-identical "collect species from Pokémon refs, exclude alternate forms, dedupe, sort by dex" loops** in `move.tsx:23-31`, `ability.tsx:14-28`, `type.tsx:22-28`. A bug in the alternate-forms rule means three fixes.
- **Not-found handling is copy-pasted four times** (`{ notFound: true as const }, { status: 404 }` + `if (loaderData.notFound) return <NotFound />` in pokemon/move/ability/type) instead of the documented pattern (`throw data("Not Found", { status: 404 })` + route `ErrorBoundary` — framework-mode.md:136), and `root.tsx:44-55` duplicates the `NotFound` component's markup a second time.
- **Small duplications/dead code:** `spriteUrl()` in `api.server.ts:63` is never used while `PokemonCard.tsx:30` re-implements the pattern; `short_effect` extraction is identical in `move.tsx:33-35` and `ability.tsx:27-29`; `home.tsx:149` builds its own `card-grid` list inline instead of reusing `PokemonCardList`.

**Framework currency check:** Manual `routes.ts` config is explicitly supported ("Many apps use file-system routing via `flatRoutes()`, but manual route config is also supported"), `Layout` export in root, `data()` helper, `loaderData` props on route components, SSR via config — all match current framework-mode guidance. Inline `<title>` elements instead of a `meta` export work under React 19 hoisting but are a minor idiom deviation.
