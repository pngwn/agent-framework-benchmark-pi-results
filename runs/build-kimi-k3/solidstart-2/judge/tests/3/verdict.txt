## Review

**What's in front of me.** `app/src/lib/data.js` holds all the risky logic: the memory-cached API client (`apiFetch`, data.js:15–24), alternate-form exclusion and species collapsing (`cardsFromPokemonRefs`, data.js:93–115), home filtering + pagination + count (data.js:139–200), moves grouping/ordering per version group (data.js:238–323), and damage-relation/type pages. `app/src/lib/util.js` holds the name/flavor/ID helpers. `app/src/routes/index.jsx:25–51` manages URL state (debounced search, filter→param sync, page hrefs). `app/src/components/MoveTables.jsx:13–49` implements column sorting with missing-values-last semantics. None of it has a single test.

**The critical observation:** once the acceptance suite is retired or someone refactors `data.js`, essentially *any* behavior is unprotected. The most fragile spots:

- **Filtering/pagination** (`app/src/lib/data.js:160–190`): the three-way filter conjunction, the `page > totalPages` clamp, and the `(page-1)*48` slice are classic off-by-one territory. A regression that breaks the count text, drops `q` while paging, or forgets to reset `page` on filter change (handled in `app/src/routes/index.jsx:33–38, 45–51`) would ship silently.
- **Move tables** (`app/src/lib/data.js:238–323` and `app/src/components/MoveTables.jsx:13–22`): method ordering (level-up/machine/egg/tutor then alphabetical), level-then-name default sort, and the "missing values sort last in both directions" comparator are intricate and exactly the kind of thing a refactor breaks invisibly. The grouping at data.js:240–248 can also emit duplicate rows if a move lists the same version group twice — nothing would catch that.
- **Error paths are conflated and fragile.** `apiFetch` (data.js:19–23) caches *rejections and non-OK responses as `null` forever*, so one transient API hiccup poisons the process; every caller treats `null` as "not found" (`app/src/routes/pokemon/[name].jsx:111–115` etc.), so an API outage renders 404s. And if the evolution-chain fetch fails, `evolution` is `null` (data.js:232) while `<EvoNode node={d().evolution} />` (`app/src/routes/pokemon/[name].jsx:107`) dereferences `props.node.name` unconditionally — a hard crash no test would prevent.
- **URL-state race** in the search box: `value={d().q}` (`app/src/routes/index.jsx:30`) reflects the server-confirmed query, so keystrokes typed while the refetch is in flight can be clobbered when the URL catches up. Behavioural tests of "type fast, expect results for the final input" would expose it.
- **Pure helpers** (`app/src/lib/util.js:5–38`): `humanize`, `latestEnglishFlavor` (last-English-entry semantics), `dexNumber` padding, `idFromUrl` regex — trivially unit-testable, currently untested.

The one mitigation is that `data.js` is a clean, query-based data layer with pure helpers; a test suite could be added cheaply against a stubbed `fetch` or the fixture API. That it wasn't is the finding.
