I've reviewed the app thoroughly. Key confirmation: `app/` contains **zero tests** — no test files, no test script in `package.json`, no test runner installed (`devDependencies` empty). All acceptance coverage lives in the repo's `tests/`, which the agent didn't write.

The riskiest logic is concentrated in `app/src/lib/data.js` (fetch/cache, filtering, pagination, move-table assembly) and `app/src/components/MoveTables.jsx` (sorting), all of it untested. Notable specific risks:

- `app/src/lib/data.js:25-34` — `apiFetch` returns `null` for both HTTP 404 and network failure, so a transient API outage renders "Not found" for real Pokémon; nothing would catch this regression.
- `app/src/lib/data.js:81-101` — `cardsFromPokemonRefs` implements alternate-form exclusion (`id > 10000`), species collapse (default-Pokémon ID ↔ species ID), and dedupe; a refactor flipping the cutoff or the ID↔name mapping would silently show/hide cards on the move, ability, and type pages.
- `app/src/lib/data.js:139-160` — pagination (48/page, clamp of `page > totalPages`), filter joins and the `q` match against the humanized name.
- `app/src/lib/util.js:31-37` — `latestEnglishFlavor` takes the **last** English entry; a refactor to `.find()` would silently pick the oldest text.
- `app/src/components/MoveTables.jsx:17-25` — missing-values-sort-last in both directions; the current `if (aMissing) return 1;` is correct but one negation away from wrong, and `aria-sort` wiring is easy to break.
- `app/src/lib/data.js:305-332` — method ordering (`METHOD_ORDER` then alpha) and level-up level/name tiebreaks.
- `app/src/routes/index.jsx:29-45` — debounced search + `updateParams` page-reset and default-omission; the `searchTimer` is also never cleared on unmount (low-severity leak/race).

These are mostly pure functions or server queries with clear inputs/outputs — ideal for cheap unit tests — so the absence of tests is a real gap, not an unavoidable cost.
