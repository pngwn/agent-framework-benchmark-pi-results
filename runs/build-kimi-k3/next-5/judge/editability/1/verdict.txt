## Review

The app is a clean Next.js 16 App Router implementation: `app/lib/api.js` (transport), `app/lib/data.js` (aggregates), `app/lib/format.js` (pure helpers), and five small components. `params`/`searchParams` are awaited (correct for Next 15+/16), `dynamic = 'force-dynamic'` is still valid in 16 without `experimental.cacheComponents`, and the root `not-found.jsx` convention is still current — nothing here is framework-outdated. The editability weaknesses are repetition, not coupling: the per-resource page scaffolding and the card-list markup are copy-pasted across the three detail pages and four list sites.

**Scenario walkthrough**

1. **Remove Abilities** — delete `app/app/abilities/` and remove one contiguous block (`app/app/pokemon/[name]/page.jsx:228-239`) plus the `abilities` variable (`:158`). No nav link, no shared helper becomes dead (`pokemonRefsToSpecies`, `englishShortEffect` still used by moves/types). Trivial.
2. **Sprite fix** — the URL is built in exactly one place, `app/components/PokemonCard.jsx:17`, and every list renders cards through that component, so one fix covers all four lists. The catch: the card only receives `id`/`speciesName`, so a data-driven fix (use `sprites.front_default`, which can be `null`) means widening the contract — new plumbing in `app/lib/data.js` plus prop threading at `app/app/page.jsx:65`, `app/app/moves/[name]/page.jsx:80`, `app/app/abilities/[name]/page.jsx:41`, `app/app/types/[name]/page.jsx:75`.
3. **Sort by name** — no card-list component exists; the `<ul className="cards">` + `map` idiom is duplicated in the four files above, so the change is either four local edits or a refactor-then-four-edits. Home pagination also assumes dex ordering (`app/app/page.jsx:48`), making that site slightly more involved.
4. **Items section** — `Section`, `TypeBadge`, `apiJson`, and the format helpers are directly reusable, but the page scaffolding (fetch-by-name + `generateMetadata` + `notFound` + `<dl className="facts">`) is re-typed in every detail page (`app/app/moves/[name]/page.jsx:18-27`, `app/app/abilities/[name]/page.jsx:9-25`, `app/app/types/[name]/page.jsx:14-22`), so roughly half the Moves page gets copied.
5. **Data source / caching change** — base URL is in one place (`app/lib/api.js:4`), the fetch cache in one place (`app/lib/api.js:13-15`), but the aggregate memoization is six separate `??=` blocks (`app/lib/data.js:12,23,34,51,59,76`) and `force-dynamic` is repeated in all six page files (`app/app/page.jsx:8` etc.). Findable, but spread over three layers.
