## Review — Pokédex on Next.js (forward-thinking)

**Version check first.** `app/package-lock.json:798` pins **Next 16.4.3** with React **19.3.1** — this is the current stable line (Next.js 16.4 shipped 2026-10-09 per nextjs.org/blog/next-16-4; Next 17 is not out, and 16.4 is where Vercel started recommending the Cache Components model for every new app). So the app is on the current release; the question is which *model* of that release it uses.

**What's current.** The Next 15/16 async-params breaking change is adopted everywhere (`await params` / `await searchParams` — `app/app/pokemon/[name]/page.jsx:136-137`, `app/app/page.jsx:23`); `generateMetadata` + title template (`app/app/layout.jsx:6-10`, `app/app/pokemon/[name]/page.jsx:34`); `notFound()` + `not-found.jsx` convention (`app/app/pokemon/[name]/page.jsx:139`); `useRouter`/`usePathname` from `next/navigation` (`app/components/MovesSection.jsx:7-8`); correct server/client split (only two `'use client'` components).

**What will churn.** All five routes opt out with `export const dynamic = 'force-dynamic'` (`app/app/page.jsx:8`, `app/app/types/page.jsx:5`, `app/app/types/[name]/page.jsx:11`, `app/app/moves/[name]/page.jsx:16`, `app/app/pokemon/[name]/page.jsx:16`) and the build runs with `cacheComponents: false`. Since 16.4 the framework recommends Cache Components (`cacheComponents: true` + `partialPrefetching: true`, `'use cache'` + `cacheLife`) for *every* app and it "will become the default in Next.js 17". The app also runs its own parallel cache: `fetch(..., { cache: 'no-store' })` plus a hand-rolled process-lifetime `Map` on `globalThis` (`app/lib/api.js:5,17-27`) — the framework's own data cache/`use cache` is explicitly disabled and rebuilt by hand. For a spec that demands request-time data this behavior is defensible, but it's the pre-16.4 model and will be the bulk of any Next 17 migration.

**Smaller non-idiomatic spots.** `HomeControls` reads `window.location.search` instead of the documented `useSearchParams()` hook (`app/components/HomeControls.jsx:46`), carries a `react-hooks/exhaustive-deps` suppression although no ESLint is installed (`:41`), and duplicates the "omit empty/default params, reset page" rule that the server page also implements in `queryString()` (`app/app/page.jsx:14` vs `HomeControls.jsx:44-52`). The 18 type colors are keyed out twice in CSS (`app/styles/globals.css:236`, `:263`) while the type list is governed by `EXCLUDED_TYPES` in `app/lib/data.js:11`.

**What's good for aging.** Data access is genuinely behind one boundary — every page goes through `lib/api.js`/`lib/data.js`, base URL is configured in exactly one place (`app/lib/api.js:3`), no framework internals, no copy-pasted boilerplate, and only three runtime dependencies (`app/package.json`), zero extraneous ones.
