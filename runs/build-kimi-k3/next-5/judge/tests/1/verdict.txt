## Review — Dimension: test quality

The agent wrote **no tests of its own**. `app/` contains zero test files, no test runner, no `test` script (`app/package.json:6-10` defines only `dev`/`build`/`start`), and no testing dependencies (deps are `next`, `react`, `react-dom` only — confirmed by the measured facts and `grep` finding only `package-lock`/`.next` artifacts). So `coverage_of_risk` and `regression_power` are scored on what would be caught: **nothing**. Per the rubric, `signal_to_noise` gets a 3 (no tests), and `behaviour_not_implementation` a 1.

That said, the code has an unusually high concentration of pure, cheaply-testable logic sitting completely unguarded, which is where the maintenance risk concentrates:

- **`app/lib/format.js`** is a textbook unit-test target: `humanize` (`format.js:4-9`, edge cases like `mr-mime`, leading/trailing dashes, empty words), `dexNumber` (`:12-14`, `padStart(4,'0')` width), `latestEnglishFlavorText` (`:33-38`, the spec explicitly demands "last English entry" — an off-by-one here that grabs the first entry or the newest non-English one would pass review unnoticed), `collapseWhitespace` (`:26-29`, `\f` collapsing), and `idFromUrl` (`:22-24`, regex on relative vs absolute URLs).
- **`app/lib/data.js:95-106` (`pokemonRefsToSpecies`)** does the trickiest mapping in the app: id parsing, alternate-form exclusion (`id >= 10000`), species resolution via `speciesById` (the `deoxys-normal` → `Deoxys` rule), and dedup by first occurrence. A refactor that drops the `id >= MAX_DEFAULT_POKEMON_ID` guard or changes the dedup silently puts Mega forms into every "Learned by" list — exactly the regression the acceptance suite would only catch if it happened to re-run against the form data, which a data-layer refactor does not re-exercise.
- **`app/app/page.jsx:40-53`** — search/type/generation filtering and the pagination math (`:55-58`, `Math.ceil(total/PER_PAGE)`, clamping, `slice` bounds). Off-by-one page clamping or a `slice` bound typo leaves every page subtly wrong.
- **`app/app/pokemon/[name]/page.jsx:52-129` (`buildMoves`)** — version-group ordering by `order`, default selection as "highest order" (`:74`), method ordering comparator (`:110-115`), min-level dedup (`:65-67`), and the fragile index-aligned `recordByName` map (`:78-83`). If any move record 404s (`apiJson` returns `null`, `api.js:17`), `record.name` on line 118 throws and the whole Pokémon page 500s with no test to notice.
- **`app/components/MovesSection.jsx:15-42` (`sortRows`)** — missing-values-last in *descending* direction via the filter/reverse/re-append trick; a rewrite of that block could easily flip missing values to the top in one direction only.
- **`app/components/HomeControls.jsx:28-37`** — the 300 ms debounce plus `navigate` reading `window.location.search` (`:40`) has a race with select-driven navigation before `router.replace` commits; nothing pins that URL-state behavior.
