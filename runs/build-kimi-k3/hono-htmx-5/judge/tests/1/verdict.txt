## Review — test quality

**Facts on the ground.** The app contains **no tests of its own**. `app/package.json:6-9` defines only `build` and `start` — no `test` script. `find` over `app/` surfaces no test files (only `src/*.js`, `src/views/*.js`, `public/app.js`, `scripts/build.mjs`), and the measured facts confirm: 0 test files, 0 cases, 0 assertions, no runner, `testLoc: 0`. The pure-function helpers in `app/src/format.js`, the whole data-assembly layer in `app/src/api.js`, the route/filter logic in `app/src/app.js`, and the client-side sort in `app/public/app.js` are all guarded only by the harness's acceptance suite, which the agent didn't write.

**Where the risk actually lives** (all verified by reading the code):

- **Home filtering/pagination** — `app/src/app.js:58-68`: three-way conjunction filter, `parseInt` page parsing, clamp-to-totalPages, `(page-1)*48` slicing. Off-by-one errors, a broken page clamp (`page=0`, `page=99999`), or a search that stops matching humanized names would silently pass review.
- **Species index assembly** — `app/src/api.js:94-121`: types reconstructed from per-type `pokemon` lists (not from `/pokemon/`), sorted by slot, generation mapped by species *name*. A refactor that mixes up slot order, drops the `id > 10000` exclusion, or keys the generation map by id instead of name would degrade cards and type filtering with no error.
- **Moves table assembly** — `app/src/app.js:101-157`: version-group ordering from a separate `order` map, default = highest order (`games[games.length-1]`), `METHOD_ORDER` tiered sort with a fiddly `-1 → 99` fallback, level-up sort by level-then-name. Wrong default game or method order would look plausible and slip through.
- **Client-side column sorting** — `app/public/app.js:14-46`: DOM `indexOf(th)` column math, missing-last in both directions, numeric vs `localeCompare`. Any markup change (extra column, reordered cells) silently breaks sorting; nothing in `app/` could catch it.
- **Card mapping** — `app/src/app.js:208-228`: dedup, alternate-form exclusion, pokemon-id→species-name resolution, `is_hidden` propagation. A dropped card undercounts `<count> Pokémon` without any visible failure.
- **URL state** — `app/src/views/home.js:8-16` (`pageUrl` omitting defaults) plus `app/public/app.js:6-10` (stripping empty htmx params). Regressions here pollute the canonical URLs the tests assert.
- **Error paths** — `app/src/app.js:303-308`: `notFound` fallback and `onError` returning a bare `c.text(...)` that abandons the page layout contract; a species whose API record errors mid-chain (`app/src/app.js:172-197`) renders partially.

Given the framework, nearly all of this is cheaply testable: `humanize`/`latestEnglishFlavor`/`dexNumber` are pure (`app/src/format.js:5-38`), and the routes are testable headlessly via `app.request()` from `hono` with a stubbed `API_BASE` or a `fetch` mock — no browser needed. That the agent wrote zero tests while shipping ~590 significant LOC of transformation logic is the headline finding.
