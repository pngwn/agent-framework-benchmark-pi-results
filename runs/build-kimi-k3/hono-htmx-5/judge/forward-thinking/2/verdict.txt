## Review: forward-thinking

**What this is.** A server-rendered Hono app (plain JS, `hono/html` tagged templates) + htmx 2 for partial swaps, served on Node via `@hono/node-server` v2. Data access is fully centralized in `app/src/api.js`; views are pure template functions. Deps are three, all pinned to current latest stable.

**API currency — verified against sources (today: 2026-10-30):**
- `hono ^4.13.14` is the latest stable (published 2026-10-25; v5 is only `5.0.0-rc.1`, per honojs/hono releases).
- `@hono/node-server ^2.1.5` is the current major (v2 GA'd 2026-04-21; 2.1.5 released 2026-10-13; v2's public API is unchanged from v1 per the release notes) — `app/src/index.js:5`, `app/src/app.js:2`.
- `serveStatic` imported from the adapter (`@hono/node-server/serve-static`) is the correct current location (adapter-provided `serveStatic` has been the way since Hono v3, per `docs/MIGRATION.md`).
- `import { html } from 'hono/html'` — current escaping template helper, no deprecated `c.body`/`c.render` patterns.
- `htmx.org ^2.0.11` is the latest htmx; all `hx-*` usage (`hx-get`, `hx-target`, `hx-swap="outerHTML"`, `hx-push-url`, delayed `hx-trigger`, `htmx:configRequest`) is idiomatic htmx 2.

**Platform use** is good: global `fetch` with a promise-memoized cache (`app/src/api.js:13,36-40`), `URLSearchParams` for canonical URLs (`app/src/views/home.js:6-13`), `??=`, optional chaining, ES modules throughout, `loading="lazy"` + intrinsic `width/height` on sprites (`app/src/views/components.js:17`), CSS custom properties from `design/tokens.css`, `:focus-visible` (`app/public/styles.css:27-33`), CSS grid `auto-fill/minmax` (`app/public/styles.css:202`). The one notable gap: no `AbortSignal.timeout()` on upstream fetches.

**Churn resistance** is above average: every API call goes through `api.js` (one module, one `API_BASE` env read at `app/src/api.js:4`); views are pure functions over plain view-models; forms keep a real `action`/`method="get"` fallback (`app/src/views/home.js:38-41`, `app/src/views/pokemon.js:69-76`) so the app degrades gracefully if htmx is removed/upgraded; table sorting uses delegated events so htmx-swapped content keeps working (`app/public/app.js:14`). Weak spots: untyped implicit view-model contracts, a config constant (`API_BASE`) leaking into the view layer, and a hand-enumerated static-asset list.
