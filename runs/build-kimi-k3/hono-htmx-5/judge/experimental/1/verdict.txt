# Review: Experimentalness — Hono + htmx Pokédex (`app/`)

I read `SPEC.md`, all of `app/src/` (12 source files), `app/scripts/build.mjs`, `app/package.json` / lockfile, and verified the status of every dependency and API against current releases (npm, hono.dev, GitHub release notes) as of 2026-10-30.

## What's there, verified against current stable releases

**Hono `^4.13.14`** (`app/package.json:8`) — 4.13.14 is the current `latest` on npm (published 2026-10-25); Hono **v5 is only at `rc.1`** (2026-10-10, pre-release). The app deliberately stayed on the stable v4 line rather than the RC that `@hono/node-server` 2.1.4+ explicitly permits as a peer (`hono: "^4 || ^5.0.0-0"`). Everything used is core, documented, stable-since-v3 API: `new Hono()` + `app.get/notFound/onError` (`app/src/app.js:13`, `app/src/app.js:293-300`), `c.html` / `c.req.*` (`app/src/app.js:29-31`), and the `html` tagged template from `hono/html` (`app/src/views/layout.js:1` and every view), which is the officially documented rendering approach (hono.dev/docs/helpers/html). Notably there is **no `raw()` anywhere** (grep: zero matches), so no hand-rolled escaping outside the safe helper.

**`@hono/node-server` `^2.1.5`** (`app/package.json:7`) — the only borderline item. v2.0.0 shipped 2026-04-21, so the major is ~6 months old ("recently-stable", right at the boundary). However, the v2.0.0 release notes state *"the public API stays the same"* — it was a performance rewrite — and the app only uses `serve({ fetch, port }, cb)` (`app/src/index.js:4`) and `serveStatic({ root })` (`app/src/app.js:15`), both identical to the v1 API from 2023. The app is on 2.1.5, which includes the serveStatic path-bypass security fix from 2.1.3 (GHSA-rmxm-3fg6-px4f, 2026-09-29).

**htmx.org `^2.0.11`** (`app/package.json:9`) — htmx 2.0 has been stable since 2024-06-17; the current major is **4.0.0 (2026-08-28)**, so the app is actually *lagging* one major, which is the opposite of experimental. Only core attributes are used: `hx-get`, `hx-target`, `hx-swap=outerHTML`, `hx-push-url`, `hx-trigger` with standard `delay`/`changed`/`from:` modifiers (`app/src/views/home.js:37-42`, `app/src/views/pokemon.js:66-74`), plus the documented `htmx:configRequest` event (`app/public/app.js:6-10`). No extensions, no OOB swaps, and no use of htmx 2.0.3's experimental `moveBefore()` Chrome-Canary support. htmx is vendored at build time (`app/scripts/build.mjs:8-11`) rather than pulled from a CDN — the boring, safe choice.

**Everything else** — `node:fs`, `node:path`, `node:url` in the build script (`app/scripts/build.mjs:1-3`), and global `fetch` in the data layer (`app/src/api.js:14`) — is long-stable Node/platform API. Zero `unstable_`/`experimental_` names, no config flags, no preview/beta/RC/canary usage anywhere in `app/` (measured facts agree: `experimental: []`).

## Scoring

**reach — 1.** Only long-stable APIs are touched. The one recently-major'd dependency (@hono/node-server v2, Apr 2026) exposes the exact same `serve`/`serveStatic` surface the app already used in the v1 era, and the app explicitly avoided the available Hono v5 RC. Nothing central rests on anything new.

**containment — 5.** Nothing to contain — but even the incidental coupling is tidy: all HTTP/data access sits behind `app/src/api.js` (`apiJson`, `memo` wrappers, `mapLimit`), the Node adapter appears in exactly two places (`app/src/index.js:4`, the static-route loop at `app/src/app.js:13-15`), htmx is confined to two view modules plus a 40-line progressive-enhancement script (`app/public/app.js`), and the whole htmx dependency is one vendored file that could be swapped or dropped (the app works without JS — both forms still do full GET submits).

**justification — 5.** Every API choice is the long-documented default rather than novelty: `hono/html` template literals over JSX, core htmx attributes over extensions, plain `fetch` + in-memory promise cache (`app/src/api.js:10-25`) over any caching/streaming helper, `Object`/`Map`/`URLSearchParams` over anything fancier. Nothing gratuitous; nothing that a stable API couldn't have done.

**count — 0** distinct experimental/preview/RC/canary APIs (the only "recently-stable" item, @hono/node-server v2, doesn't count per the rules — and its used API surface predates the major bump anyway).
