I've reviewed the app end to end: it's a plain Hono 4 + htmx 2 server-rendered Pokédex with zero experimental surface.

**API inventory (all verified stable):**
- `Hono`, `c.html`, `app.notFound`, `app.onError` — `app/src/app.js:1,30,40,306,308` — Hono 4.x core, stable since v4 (and largely since v3).
- `html` tagged template from `hono/html` — `app/src/views/layout.js:1` (and 4 other views) — stable, non-experimental HTML escaping helper in Hono's docs.
- `serve` — `app/src/index.js:1` — long-stable `@hono/node-server` API.
- `serveStatic` from `@hono/node-server/serve-static` — `app/src/app.js:2` — the recommended current import path.
- Node built-ins `fs`/`path`/`fileURLToPath` — `app/scripts/build.mjs:2-4` — ancient, stable.
- htmx 2.0.11 attributes (`hx-get`, `hx-trigger`, `hx-swap`, `hx-target`, `hx-push-url`) and the `htmx:configRequest` event — stable public API since htmx 2.0 (Nov 2024), and mostly since 1.x. Vendored locally by the build (`app/scripts/build.mjs:10`), which avoids any CDN-runtime surprises.

The only "recent" thing in the tree is the `@hono/node-server` **v2 major** (`app/package.json:6`), released 2026-04-21 per the GitHub release notes — i.e. right at the ~6-month line. That's a version bump, not a new API: the release notes state "the public API stays the same," and the app uses exactly the v1-shaped API (`serve`, `serveStatic`), so nothing it relies on is on a new surface. Hono itself is pinned at `^4.13.14`, the current stable line, with no use of newer additions (no streaming/SSE helpers, no `hono/jsx`, no WebSocket helpers — `app/src/app.js:307` uses plain `c.text` for the 500 handler). No `unstable_*`/`experimental_*` names, config flags, or canary-only features anywhere in `app/`.

So: descriptive verdict — this app is maximally conservative. That's a reasonable choice for a spec-driven acceptance-tested app with no requirement that could only be met by a preview API, and it means there is essentially no upgrade-breakage risk.
