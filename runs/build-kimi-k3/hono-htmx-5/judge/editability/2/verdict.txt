# Review — `app/` (Hono + htmx Pokédex), dimension: editability

## Structure at a glance

- `app/src/index.js` — server entry (`serve` from `@hono/node-server`)
- `app/src/app.js` — all six routes plus per-route data assembly (~300 lines)
- `app/src/api.js` — single data layer: `API_BASE`, promise-cache, `memo`d indexes (`speciesIndex`, `allTypes`, …)
- `app/src/format.js` — pure display helpers
- `app/src/views/` — `layout.js`, `components.js` (`pokemonCard`, `section`, `typeBadge`), `home.js`, `pokemon.js`, `details.js`; all pure `hono/html` template functions over plain data props
- `app/public/app.js` — the only client code: htmx param cleanup + event-delegated table sorting

Dependencies (`hono@^4.13`, `@hono/node-server@^2.1.5`, `htmx.org@^2`) are the current stable releases; the `hono/html` tagged-template approach and `@hono/node-server/serve-static` usage are current and idiomatic. Nothing here is out of date.

## Scenario walkthroughs

**1. Remove Abilities.** Route block at `app/src/app.js:253-266`, its import at `app/src/app.js:28`, `abilityPage` at `app/src/views/details.js:35-43`, the Abilities section on the Pokémon page (`app/src/views/pokemon.js:55-64`, used at `:128`) and its data mapping at `app/src/app.js:194-196`. Three files, ~6 edits, all easy to find; the nav (`app/src/views/layout.js:29-32`) has no Abilities link. Leftover: `pokemonCard`'s `hidden` flag / "Hidden ability" note (`app/src/views/components.js:14,23`) has exactly one caller and would go dead. Anchors say "a handful of scattered edits" → **3**.

**2. Sprite bug.** Every card on every list is built by one template, `pokemonCard` (`app/src/views/components.js:14-24`), which constructs the sprite URL at `:17` from the species id — home (`app/src/app.js:72`) and moves/abilities/types all funnel through `pokemonCard` or `speciesCardsFor` (`app/src/app.js:208-224`). One fix covers every list *as long as id+name is enough*; if the fix needs the Pokémon record's own sprite URL, the plumbing (`speciesIndex` in `app/src/api.js:101`, `speciesCardsFor` in `app/src/app.js:208`) must carry it. So: one obvious place, with a caveat. **4** for the happy case.

**3. Sort card lists by name.** Card rendering is shared, but ordering happens in two data spots (`app/src/app.js:65-72` home, `app/src/app.js:222-223` `speciesCardsFor`), the count+list markup is copy-pasted three times in `app/src/views/details.js:32,38,77`, and a sort control would have to be added at four render sites (plus client JS if interactive). **2**.

**4. Items section shaped like Moves.** Genuinely additive: a route block + `itemPage` in `app/src/views/details.js`, reusing `apiJson`, `englishName`, `orMissing`, `section`, `layout`, `renderPage`. But `movePage`'s `<dl class="facts">` (`app/src/views/details.js:5-31`) is duplicated inline with the Pokémon summary (`app/src/views/pokemon.js:33-46`), so the "facts list" shape gets copied a third time rather than reused. **4**.

**5. Change API base/caching.** Base URL and cache live in exactly one module (`app/src/api.js:2-25`, `memo` at `:57-61`). The one leak: the view layer re-derives media URLs (`app/src/views/components.js:2,17` hardcodes `${API_BASE}/media/sprites/pokemon/${id}.png`), so a media-path change touches a template. **4**.

## Scores

**removability — 3.** Route + import + view function + a section on a sibling page, with one caller-less flag left behind.

**changeability — 3.** Most fixes land in one obvious place (`pokemonCard`, `format.js`, `api.js`), but cards carry only `{id, name}`, so pokemon-level fixes need plumbing through `api.js` and `app.js`; and the `typeLabels` parameter accepts two shapes — a `Map` from `app/src/app.js:72` but a plain object from `app/src/app.js:297` — while `app/src/views/components.js:21` indexes it with `[]`, so the Map lookups silently fail and fall back to `humanize` (invisible today only because English type names equal their humanized forms). That's a trap for the next editor.

**coupling — 4.** Clean layering: pure template functions over data props, one data module, client code isolated in `public/app.js` with an explicit htmx seam (`isHtmx` at `app/src/app.js:20`, fragments `resultsFragment`/`movesSection` matching `hx-target="#results"` / `"#moves"`). Deductions: media URL layout known by the view (`app/src/views/components.js:17`), `PAGE_SIZE` (a pagination constant) exported from the view module (`app/src/views/home.js:4`) and consumed by the route (`app/src/app.js:66,71`), and the `—` missing-value token duplicated between server (`app/src/format.js:28`) and client sorter (`app/public/app.js:34`).

**abstraction_design — 3.** The abstractions track real variation well: `section()` (`app/src/views/components.js:31-38`), `speciesCardsFor` unifying three different API shapes via `entry.pokemon ?? entry` plus an `extra` callback (`app/src/app.js:208-224`), data-driven move tables (`app/src/views/pokemon.js:88-124`). But the facts-dl and "count + cardList" patterns are copy-pasted rather than factored, and `pokemonCard` is accumulating one-caller flags (`hidden`, `typeLabels`).
