I've reviewed the app end-to-end against React Router 8.5 (current stable, verified against the v8 release notes and framework-mode docs) and the SPEC/FEATURE requirements. Evidence-backed assessment:

## What's strong

- **Framework-mode fundamentals are right**: `app/app/routes.ts` config, generated `./+types/*` types used in every route, loaders parse URL search params (`app/app/routes/home.tsx:38-44`), `data()` thrown for 404s (`app/app/lib/api.server.ts:36`, `app/app/routes/type.tsx:28`, `app/app/routes/not-found.tsx:4`), root `Layout`/`ErrorBoundary` (`app/app/root.tsx:10-58`), cookie set via action response headers (`app/app/routes/team.tsx:55`), and a documented `@react-router/express` custom server (`app/server.mjs:15-18`).
- **Team feature fits the codebase well**: cookie in `team.server.ts` (HttpOnly, SameSite=Lax, validated on read at `app/app/lib/team.server.ts:14-27`), server-rendered toggle so there's no label flash (`app/app/routes/pokemon.tsx:90` + `app/app/components/TeamControls.tsx:11-14`), fetcher mutations, unknown cookie names defensively filtered (`app/app/routes/team.tsx:18-20`).
- **Deliberate correctness work**: page clamping (`app/app/routes/home.tsx:53-55`), debounce cleared on submit, pre-hydration input capture (`app/app/routes/home.tsx:79-84`, `app/app/routes/pokemon.tsx:212-215`), the no-JS form still GETs to `/` (`app/app/routes/home.tsx:100-103`).

## What I'd flag

- The API cache (`app/app/lib/api.server.ts:10-22`) never evicts expired entries — only rejections delete. On a long-lived server, every distinct URL's parsed JSON stays resident; a Pokémon page fans out to ~100 move-detail fetches (`app/app/routes/pokemon.tsx:114-117`). Bounded in practice by the API's size, but it's a slow leak.
- Rendered `<title>` in components instead of `meta` exports (works via React 19 hoisting, and neatly covers the error-boundary title, but departs from documented practice).
- The 404 splat route renders `null` while the UI lives in the root ErrorBoundary (`app/app/routes/not-found.tsx:12`) — works, slightly indirect vs. the docs' splat-route pattern.
- Duplicated near-identical `Move` type declarations (`app/app/routes/pokemon.tsx:35-44` vs `app/app/routes/move.tsx:10-22`).
- Home's ref-based uncontrolled filter controls plus three sync/mount effects (`app/app/routes/home.tsx:62-92`) — justified by the debounce requirement, but it's the highest-friction spot in the codebase.
