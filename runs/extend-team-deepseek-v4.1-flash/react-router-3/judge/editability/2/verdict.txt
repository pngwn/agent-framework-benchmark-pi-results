## Review: Pokédex app (React Router v8.5 framework mode)

**Structure**: 8 route modules + 5 components + 3 lib modules (one `.server`-suffixed pair). Idioms are current for v8: typed route args via `./+types/*`, `data()` throws for 404 (`app/app/lib/api.server.ts:29`), fetcher-Form for stay-on-page mutations (`app/app/components/TeamControls.tsx:12`), search state parsed in the loader so URLs are shareable (`app/app/routes/home.tsx:33`).

### Scenario walkthrough

1. **Remove Abilities**: delete `app/app/routes/ability.tsx`, one line in `app/app/routes.ts:8`, and the single `Abilities` Section in `app/app/routes/pokemon.tsx:271-280`. No nav link exists (`app/app/root.tsx:22-31`). Only residue is the shared `.plain-list` selector group at `app/app/app.css:410`. Essentially the ideal case.

2. **Sprite fix**: every card list (home, move, ability, type, team) funnels through `speciesCard` (`app/app/lib/api.server.ts:103-115`) → `spriteUrl` (`:39`). One fix covers all five lists. The detail page artwork comes from API data (`pokemon.tsx:143`), already correct.

3. **Sort cards by name**: ordering is decided in two places — `pokemonCards` (`api.server.ts:147`) for move/ability/type, and home's loader over the id-sorted `index.species` (`home.tsx:52-55`) — plus the conscious exception that `team.tsx:22-25` must *keep* add-order. Two edits plus a judgement call; workable but not a single seam.

4. **Items section**: add two route files + two `routes.ts` lines. Reusable: `apiOr404`, the whole `format.ts` helper set, `Section`, `PokemonCards`, `TypeBadge`, plus the new sprite helper goes next to `spriteUrl`. Not reusable: each detail route hand-rolls its own loader + `<title>`/`<h1>`/facts scaffold (compare `move.tsx:28-90` and `ability.tsx:14-32`), so ~40 lines of the new page are template-copy of move.tsx. `versionGroupOrders()` living in `pokemon.tsx:56-60` shows the pattern: route-private data helpers would be duplicated rather than moved into the data layer.

5. **Data source change**: `API_BASE_URL`, cache TTL, in-flight-dedup cache and the media path are all in one file (`api.server.ts:7-39`); nothing else in the app knows the API exists (`server.mjs` is the only other server file and contains no API references). Perfect centralization.

### Weak points

- Route paths are inline string templates in 7+ files (`PokemonCards.tsx:14`, `TypeBadge.tsx:8`, `MoveTable.tsx:90`, `pokemon.tsx:184,275`, `type.tsx:65`, `team.tsx`, `home.tsx`). A URL-pattern change is a repo-wide grep.
- The "sync uncontrolled inputs with the URL + replay pre-hydration edits" effect pattern is duplicated between `home.tsx:85-95` and `pokemon.tsx:217-223` — subtle logic a future maintainer must keep in sync by hand.
- `withTypes` (`api.server.ts:103`) and `showLevel` (`MoveTable.tsx:45`) are mild boolean-flag creep, though each has a single caller today.
- Dead dep: `isbot` (`app/package.json:15`) is never imported.
- 404s are handled by two mechanisms (catch-all route throwing, `root.tsx:47` rendering `NotFound`); it works, but the "Not found" UI living in `root.tsx` while `not-found.tsx` renders `null` is indirection a new editor has to discover.
