I've read the spec, feature, all of `app/` and the current React Router guidance (v8.5.x is current stable; the app is on `^8.5.0`, so I'm judging against current idiom). Summary of how the codebase is put together before the scores:

**Layout.** `app/routes.ts` (manual route config), one route module per page under `app/routes/`, server data access isolated in `app/lib/api.server.ts` (`.server` suffix keeps it out of the client bundle), pure helpers in `app/lib/format.ts`, shared UI in `app/components/` (`Section`, `TypeBadge`, `PokemonCards`, `MoveTable`), client team state in `app/lib/team.tsx`, one well-sectioned `app.css`. Loaders use `Route.LoaderArgs` from `./+types/...` typegen, 404s thrown via `data(..., { status: 404 })` and rendered by the root `ErrorBoundary` — all current framework-mode practice.

**Scenario walkthroughs.**

1. *Remove Abilities* — delete `routes.ts:7`, delete `routes/ability.tsx`, delete the `<Section title="Abilities">` block (pokemon.tsx:278-286) plus the `abilities` loader field (pokemon.tsx:161-165) and the type line (pokemon.tsx:33). Nav lives only in root.tsx. The only loose end is the now-dead `.plain-list` rule (app.css:410). Very clean.
2. *Sprite bug* — `spriteUrl` (api.server.ts:39) is the only sprite constructor, and every card list flows through `speciesCard`/`pokemonCards` (api.server.ts:140, 157): home (home.tsx:47), move, ability, type and team all reuse them. One fix genuinely covers every list. Exemplary.
3. *Sort by name* — touches `pokemonCards`' hard-coded dex sort (api.server.ts:169), home's pre-pagination ordering (home.tsx:33-44, where sorting must happen before the page slice or pages get inconsistent), and a new shared comparator (name comparisons via `localeCompare` are currently copy-pasted in MoveTable.tsx:43, type.tsx:31, pokemon.tsx:143). Team must be deliberately excluded. Findable, but not one place.
4. *Items section* — mostly additive: new entries in `routes.ts`, a new route module cloned from `move.tsx`'s shape; `apiOr404`/`getIndex`/`pokemonCards`/`Section`/`PokemonCards`/format helpers all reuse as-is, so cards for "held by" lists come free. Cost: API response types are declared inline per route (no shared types module), so the item shape gets redeclared.
5. *API base URL / caching* — `API_BASE_URL` (api.server.ts:7), `TTL_MS` (api.server.ts:8), the `cached()` cache (api.server.ts:12-20) and the sprite URL pattern (api.server.ts:39) all live in one file; full URLs from API payloads are handled centrally (api.server.ts:24). One file, period.

**Where it loses points:** `Move` is typed twice (pokemon.tsx:44 vs move.tsx:8, slightly different shapes); `MoveTable` keeps `COLUMNS` metadata for sorting while the `<td>` body is hard-coded in parallel (MoveTable.tsx:24-35 vs 86-96, with `showLevel` filtered in both), so adding a column means synchronized edits in three spots plus the loader mapping; `routes/pokemon.tsx`'s loader is a 130-line monolith shaping six concerns; the home page's uncontrolled-inputs + refs + hydration-hydration `useEffect` pattern (home.tsx:79-96) is subtle to extend (a fourth filter means touching `Filters`, `queryString`, three refs, `currentFilters`, two effects and markup); and `NotFound` is a presentational component exported from `root.tsx:78` while `routes/not-found.tsx` renders `null`.
