I've read the whole app and verified the framework version. Current stable Qwik is `@builder.io/qwik@1.20.3` (released Oct 25, 2026; 2.0.0 is still rc), and the app pins `^1.20.3` — so the APIs in use (`routeLoader$`, `useSignal`/`useTask$`, `resolveValue` in `head`, `cacheControl`, node-server adapter) are all current and idiomatically applied. The architecture is a clean split: `lib/api.ts` (fetch + stale-while-revalidate cache, server-only), `lib/data.ts` (per-page data builders, server-only), `lib/format.ts` + `lib/team.ts` (pure, shared client/server), thin route files, and reusable presentational components. Components import only *types* from the server-only `data.ts`, which keeps the seam clean.

The main editability costs I found: the "resolve default variety → Pokémon → types" logic is written twice (`data.ts:216-218` and `385-386`); card construction happens in three places (`data.ts:81`, `139`, `397`); the team page re-implements the card grid instead of reusing `CardList` because `CardList` can't host per-item buttons (`team/index.tsx:47-62` vs `ui.tsx:32-38`); and the generic `Card` type carries an ability-specific `hidden` flag that the generic `PokemonCard` renders (`ui.tsx:43`). All are real but small.
