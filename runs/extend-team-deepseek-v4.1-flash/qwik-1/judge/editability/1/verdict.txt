## Review: `app/` (Qwik + Qwik City Pokédex, plus team-builder feature)

The app is a textbook Qwik City layout: thin route files (`routeLoader$` + `head` + a component), a server-only data layer (`src/lib/data.ts`, explicitly marked "Server only" at `src/lib/data.ts:1`), a pure shared helper module (`src/lib/format.ts:1`), shared UI primitives (`src/components/ui.tsx`), and a single HTTP/cache module (`src/lib/api.ts`). Deps pin `@builder.io/qwik ^1.20.3`, which is the current stable line (1.20.3 released 2026-10-25; 2.0 is still RC), and every API in use (`routeLoader$`, `status(404)` in loaders, `resolveValue` in `head`, `cacheControl` in layout `onGet`, `useTask$`/`useComputed$`, `useNavigate`) is current and idiomatic.

**Scenario findings (evidence for scores below):**

1. **Remove Abilities pages**: delete `app/src/routes/abilities/[name]/index.tsx` and `abilityPage()` in `app/src/lib/data.ts:320-333`; the only inbound link is the Abilities section on the Pokémon page (`app/src/routes/pokemon/[name]/index.tsx:110-118`, data built at `app/src/lib/data.ts:232-235`). No nav link, no ability-specific CSS. Clean — 3 files, small edits, no dead code.
2. **Sprite bug fix**: card `sprite` is built in **three places with two strategies** — synthesized URL in `cardsForPokemon` (`app/src/lib/data.ts:81`) and `homePage` (`app/src/lib/data.ts:139`), but fetched `sprites.front_default` in `teamPage` (`app/src/lib/data.ts:432`). The render side is single (`app/src/components/ui.tsx:18`), but a real sprite fix must land in two card-construction sites, and the home one would need a default-variety lookup. This is the one place the "one obvious place" property fails.
3. **Sort by name on card lists**: lists on move/ability/type pages all go through `cardsForPokemon`, so one sort change (`app/src/lib/data.ts:85`) covers them; but the home list is paginated server-side from species data (`app/src/lib/data.ts:131-140`), so it needs its own sort before slicing — and the team list must be excluded (add-order per `FEATURE.md`). Two files, one trap.
4. **Items section like Moves**: new `app/src/routes/items/[name]/index.tsx` mirroring `app/src/routes/moves/[name]/index.tsx`, plus an `itemsPage()` in `src/lib/data.ts`. `Section`, `CardList`, `orDash`, `pageTitle`, `NotFound` (`app/src/components/ui.tsx:32-70`, `app/src/lib/format.ts`) are all reusable as-is; the loader/head boilerplate is framework convention, not duplication. High reuse.
5. **Change API base / caching**: `apiBase()` (`app/src/lib/api.ts:4`) is the only place the URL is derived (media URLs included via `spriteUrl` → `apiBase`, `app/src/lib/data.ts:23`); cache TTL and stale-while-refresh logic live entirely in `app/src/lib/api.ts:6,20-62`; page cache headers in `app/src/routes/layout.tsx:4-6`. Two files, both obvious.

Minor notes: `src/lib/data.ts` is a 430-line module holding every page's data builder (fine now, a split per resource would help as it grows); all styles live in one `src/global.css` (~590 lines, sectioned by comments) rather than Qwik's per-component scoped styles; `undici` dev-dependency and the `sharp` engine annotation in `app/package.json:4-8,29` are starter-template leftovers.
