## Review

**Layering** (the big picture): `lib/server/pokeapi.ts` (server-only data access + cache) → `lib/queries.ts` (`query`/"use server" wrappers, the single server/client seam) → route files → presentational components (`Section`, `PokemonCards`, `MoveTable`, `TypeBadge`) fed by props. Shared shapes live in `lib/types.ts`. This is a textbook seam structure, and it makes most of the change scenarios cheap.

**Scenario 1 — Remove Abilities**: delete `app/src/routes/abilities/[name].tsx`, then `getAbility` (`app/src/lib/queries.ts:39-42`), `abilityDetail` (`app/src/lib/server/pokeapi.ts:398-409`), `AbilityDetail` (`app/src/lib/types.ts:64`), the Abilities section (`app/src/routes/pokemon/[name].tsx:150-160`), and the `hidden` card note (`app/src/components/PokemonCards.tsx:26-28`). No nav link exists (nav is `Pokémon`/`Types`/`Team`, `app/src/app.tsx:23-43`). Every touch point greps under "ability"; TS won't flag the orphaned exports, but nothing unrelated is entangled.

**Scenario 2 — Sprite fix**: every card's sprite is built in `pokeapi.ts` — three times: `:114` (`card()`), `:185` (`homeList`), `:341` (`teamDetails`). A fix lands in one file but three sites; the natural refactor (funnel `homeList`/`teamDetails` through `card()`) makes it one place. Notably, `PokemonCards.tsx:18` renders `card.sprite` verbatim, so no view-layer fix is needed.

**Scenario 3 — Sort cards by name**: all five card lists render through one component, `PokemonCards` (`app/src/routes/index.tsx:106`, `moves/[name].tsx:47`, `abilities/[name].tsx:33`, `types/[name].tsx:44`, `team.tsx:46`), so a sort there (with an opt-out for the team's insertion order and home's dex order) covers everything in one edit.

**Scenario 4 — Items section**: the Moves shape (`routes/moves/[name].tsx` + `moveDetail` in `pokeapi.ts` + `getMove` in `queries.ts` + type in `types.ts`) is a clean, small template; an Items section is mostly new files plus appends to `queries.ts`/`pokeapi.ts`/`types.ts`, reusing `Section`, `PokemonCards`, `CountText`, `TypeLink`, `NotFound` and the `format.ts` helpers as-is.

**Scenario 5 — API base URL / caching**: single-sourced. `apiBase()` at `pokeapi.ts:24`, `TTL_MS` at `:19`, the cache itself at `:36-52`. One file, two constants.

**Weak spot**: `homeList` (`:152-186`) and `teamDetails` (`:321-342`) each re-implement the `typesById` map and inline card construction instead of reusing `card()`/`cardsFor()` (`:112-130`) — the only real duplication in the codebase, and it's confined to one module.
