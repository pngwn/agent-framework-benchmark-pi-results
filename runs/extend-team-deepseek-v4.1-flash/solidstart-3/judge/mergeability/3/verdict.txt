## Review

I read the whole of `app/` — routes, components, `lib/` (queries, server data layer, team store), config, and the CSS — and verified the framework choices against the current SolidStart v2 docs (released 2026-08-04): `vite.config.ts` with `solidStart()` + `nitro()` from `nitro/vite`, `query` + `"use server"` + `createAsync`, `route.preload`, `FileRoutes`, `createHandler(..., { mode: "async" })`, and `setSearchParams` deleting keys on `undefined`.

**Idiom** — this is textbook current SolidStart v2. `app/vite.config.ts:5` matches the docs example exactly; `app/src/lib/queries.ts:4-12` is the documented `query` + `"use server"` pattern; `app/src/routes/index.tsx:9-15` uses `route.preload` as documented; `app/src/app.tsx:12` uses `FileRoutes`; `app/src/routes/pokemon/[name].tsx:96-102` uses `Switch/Match` on a nullable `createAsync` with `HttpStatusCode` 404 (`app/src/components/NotFound.tsx:8`); the team feature reuses the framework's own `createContext`/`useContext` and `getRequestEvent()` for SSR-safe cookie reads (`app/src/lib/team.ts:48-51`) rather than inventing a persistence mechanism. No home-grown router, reactivity or data layer.

**Correctness** — 404s, form-alternate-form filtering, pagination clamping, dedup/in-flight caching, sorting with nulls-last and the coverage multiplier math are all handled deliberately. The main gap is error handling: `app/src/lib/server/pokeapi.ts:46` throws on any non-404 upstream response and there is no `ErrorBoundary` anywhere (`app/src/app.tsx:18-44`), so one API hiccup takes down every page. The rest is minor: TTL stamped at fetch start (`pokeapi.ts:49`), the sweep-every-500-writes magic number (`pokeapi.ts:51`), and the search-input resync effect that skips while a debounce timer is pending (`app/src/routes/index.tsx:29-37`).

**Abstractions** — the `queries.ts` → `lib/server/pokeapi.ts` split is the right boundary (thin RPC layer, server-only data module, DTOs in `types.ts`), but `pokeapi.ts` has grown into a single 440-line module covering every resource, with the `typesById` construction and sprite-URL template copy-pasted between `homeList` and `teamDetails` (`pokeapi.ts:152-186` vs `:321-342`), and `first()` duplicated between routes.
