## Review summary

This is a vanilla TypeScript + Vite SPA with a small Node static server, a hand-rolled `h()` DOM builder, a regex router, and a Promise-based API cache. I verified the toolchain against current releases: the app pins **Vite 8.3** (stable since 2026-03-12, Rolldown-based) and **TypeScript 7.0.2** (the native port, GA 2026-07-08) — both are the current stable versions, so no staleness there. Usage is idiomatic Vite: `index.html` entry, `import.meta.env` with `types: ["vite/client"]`, a minimal `defineConfig`, and a request-time `meta[name=api-base-url]` injection instead of baking the API origin at build time (which the spec explicitly forbids).

The strongest parts: clean module boundaries (`api` / `dom` / `format` / `components` / `pages`), race-aware navigation with a generation counter (`isCurrent`), token-guarded async in the moves section, XSS-safe DOM construction (no `innerHTML` anywhere; the server even escapes `<` in the injected API base), and careful accessibility (`aria-sort`, `role="status"`, `aria-current`, sections named by heading).

The main mergeability concerns are cross-file: the route table exists twice (`app/server.mjs:31` and `app/src/main.ts:22`) and will drift when a page is added; the home page's debounce timer isn't cancelled on teardown, so a pending `setTimeout` can `history.replaceState` a stale URL after the user has already navigated to another page (`app/src/pages/home.ts:132` with `applyFilters` at `:120`); and `setupMoves` reads live `location.href` instead of the page context's `url` (`app/src/pages/pokemon.ts:197`), reopening a small race the router otherwise closes. Everything else is nit-level (silently swallowed `ready` errors at `main.ts:93`, forever-cached 404s vs. the "treat the API as live" requirement, a duplicated default-variety loader between the team and Pokémon pages, HEAD responses carrying a body, an unguarded `pipe`).

I'd merge after one round of those fixes; nothing needs structural rework.
