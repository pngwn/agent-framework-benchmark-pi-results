## Review

This is a well-crafted vanilla TS + Vite SPA. The stack is current (Vite 8.3.5 / TS 7, both current stable), the module boundaries are clean (`api.ts` data access, `dom.ts`/`format.ts` primitives, `components.ts` shared UI, `pages/*` route handlers), and race-condition handling is unusually careful: a navigation token (`main.ts:66-88`), a per-table token in moves (`pokemon.ts:209-215`), detached-container rendering, and in-flight promise dedup with cache eviction on failure (`api.ts:141-155`). No `innerHTML` anywhere — all text goes through text nodes (`dom.ts:11-15`), so no escaping bugs; the server even escapes the injected API origin (`server.mjs:27-28`).

The problems I'd flag before merge:

1. **URL corruption after navigation** — `app/src/pages/home.ts:132` schedules `applyFilters(true)` (which calls `history.replaceState`, `home.ts:123`) with no `ctx.isCurrent()` guard. Type in search, click a card within 150 ms: the Pokémon page's URL is silently replaced with `/?q=…`. Back/forward and reload then land on the wrong page.
2. **Team page bricks on one stale entry** — `app/src/pages/team.ts:70` does `Promise.all(names.map(loadMember))` with no per-member error handling; one species name in `localStorage` the API no longer has (the spec explicitly says data changes; the test overlay adds a Pokémon) throws `NotFoundError`, and `main.ts:83` renders "Not found" for the whole team page instead of skipping the entry.
3. **Silently swallowed async errors** — `app/src/main.ts:93` (`result.ready?.catch(() => {})`) means a failed moves fetch leaves an empty, permanently `aria-busy` Moves section with no feedback or retry.
4. **Duplicated route tables** — `app/server.mjs:31` and `app/src/main.ts:26-34` each encode the route list; adding a route requires touching both (the feature diff proves the authors remembered, but it's a standing trap). Export the list or generate one side from the other.
5. Smaller nits: dead export `isOnTeam` (`app/src/team.ts:33`, unused), duplicated default-variety resolution (`pages/pokemon.ts:29-31` vs `pages/team.ts:16-19`) and type-label-map building (`pages/types.ts:26`, `pages/team.ts:24`, `api.ts` `typeNames`), `setupMoves` reads `location.href` instead of `ctx.url` (`pokemon.ts:197`), `history.scrollRestoration = 'manual'` (`main.ts:120`) means Back loses scroll position with nothing restoring it, and the `role="status"` count element is replaced wholesale on each update (`home.ts:99`) so screen-reader announcements may not fire.

The feature change itself fits the existing conventions well: `team.ts` is a small, defensive localStorage module (parse-safe, deduped, capped), the Pokémon page button re-renders synchronously from storage, and the team coverage math is correct per the spec (`0` beats `½`/`2` ordering in `pages/team.ts:24-28`, product over both types at `:44`).
