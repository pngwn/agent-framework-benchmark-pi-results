## Review

This is a well-structured TanStack Start app: server-only data access isolated in `server/pokeapi.ts`, page payloads via `createServerFn` in `server/functions.ts`, thin route components, and shared presentational components (`Section`, `TypeBadge`, `PokemonCardList`, `MoveTable`). The APIs used (`.validator()`, `getCookie` from `@tanstack/react-start/server`, `head` route option, Vite 8) all match the now-stable TanStack Start release. The main editability costs are the hub-like `server/functions.ts`, per-resource copy-paste in the route files, and a small amount of feature leakage into the shared card component.

**Scenario walkthroughs**

1. **Remove Abilities**: touches `routes/abilities.$name.tsx` (delete), `server/functions.ts:192-205`, `server/pokeapi.ts:291-311` (`RawAbility`/`getAbility`), `routes/pokemon.$name.tsx:112-121` (Abilities section) + `functions.ts:120-123` (payload field), and leaves dead code in `components/PokemonCard.tsx:43` and `lib/types.ts:10` (`hidden` flag exists only for ability cards). The nav has no abilities link, which helps. Moderately scattered.
2. **Sprite fix**: sprite URLs are built in exactly one helper, `lib/format.ts:23-25`, called only from `PokemonCard.tsx:25`; every card list on every page renders through `PokemonCardList`, so one fix covers all lists. If the fix needs the Pokémon's own name rather than the ID, `CardData` (`lib/types.ts:8-12`) would need a field and `toCards` (`pokeapi.ts:86-102`) would populate it — still contained in the server layer.
3. **Sort by name on every card list**: `PokemonCardList` is the single render path, so a sort there covers moves/abilities/types. Home is the exception: `index.tsx:76-78` paginates *before* rendering, so sorting inside the component would only sort the visible page; the ordering must also change in `speciesIndex` (`pokeapi.ts:169`) or `index.tsx`. Team order is insertion-order by spec, so a blanket server-side sort in `toCards` would break it — the variation is real and handled, but the change spans two files.
4. **Add Items shaped like Moves**: all presentational components and the whole `memo`/`fetchJson`/`englishName`/`toCards` data layer are reusable. What's copied is the ~20-line route boilerplate (`loader` → `notFound()` → `head` → `notFoundComponent`), a 4th repetition, plus ~40 lines appended to the `functions.ts` hub and ~30 to `pokeapi.ts`.
5. **Change API base URL / caching**: one place. `apiBase()` (`pokeapi.ts:8-10`), `TTL_MS` (`pokeapi.ts:5`) and the cache itself (`memo`, `pokeapi.ts:15-32`) all live in `server/pokeapi.ts`; the client only sees the base through a single seam (`getConfig` → `functions.ts:42` → `useMediaBase`, `lib/config.ts`). Excellent.
