I've explored the app and verified the framework facts I was leaning on (Nuxt 4's `shared/` directory for cross-boundary code/types, `useFetch` auto-generated keys, Nuxt 4 directory layout — this app uses the correct `app/app` + `server/` split). Here's my review.

## How the codebase is shaped

The app is a clean Nuxt 4 app: every page fetches from an internal server route via a single `usePageData` seam (`app/app/composables/format.ts:37-47`), all PokeAPI knowledge lives in `app/server/utils/pokeapi.ts` (client, cache, `cardsFor`, `spriteUrl`), and reusable UI primitives (`PageSection`, `CardList`, `PokemonCard`, `MovesTable`, `TypeBadge`) cover the real variation. The weak seams are: sprite URL construction duplicated in three places, `humanize` duplicated across the client/server boundary, the team page re-implementing the card grid instead of extending `CardList`, and response interfaces hand-declared in each page with no `shared/types`.
