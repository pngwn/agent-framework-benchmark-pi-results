I've now read every source file in the app. This is a SvelteKit 3 / Svelte 5 app using current idioms throughout — configuration in `vite.config.ts` via the `sveltekit()` plugin (per SvelteKit 3, released Oct 2026), the `#lib` subpath-import alias, `$app/state`, snippets, runes everywhere. The architecture is: thin API client (`lib/server/api.ts`) → per-resource data shapers (`lib/server/pokedex.ts`) → `+page.server.ts` loads → presentational components (`PokemonCard`, `CardList`, `Section`, `TypeBadge`, `MoveTable`, `Evolution`) → slim page templates, with team state split into a pure module (`team.ts`), a client store (`team.svelte.ts`, context + cookie), and a server seed (`+layout.server.ts`).

Working the five scenarios:

1. **Remove Abilities**: delete `routes/abilities/`, then `getAbilityPage`/`ApiAbility` (pokedex.ts:31-36, 332-345), the Abilities section (`routes/pokemon/[name]/+page.svelte:95-104`), the `abilities` mapping (pokedex.ts:259-261), and the now-dead `Card.hidden` flag (`types.ts:5`, `PokemonCard.svelte:21-23`). Four scattered files, one piece of orphanable state. Not bad, but not "delete a dir and a nav link" either.
2. **Sprite fix**: all card sprites flow through one `spriteUrl` (pokedex.ts:89); one fix there covers every list. The caveat: card *construction* happens in three places (pokedex.ts:141, 184, 413), so a fix needing more than the id — e.g. resolving the default variety — also has to touch the duplicated `varieties.find` logic at pokedex.ts:217 and :405.
3. **Sort by name**: every list renders through `CardList.svelte` (home, move, ability, type; team page intentionally renders `PokemonCard` directly at `team/+page.svelte:35`), so one component change covers all lists — or two server spots (`cardsFor` sort at pokedex.ts:144, home list ordering).
4. **Items section**: the Moves pattern (bespoke `getMovePage` at pokedex.ts:307 + 8-line `+page.server.ts` + ~70-line page template) is copied per resource rather than generalized; an Items section means writing a `getItemPage` and two route files modeled on moves, while reusing `api.ts`, `cardsFor`, `englishName`, `Section`/`CardList`/`TypeBadge`. Moderate copy-paste, but the real seams (API client, cards, formatting) are shared.
5. **API base URL / caching**: everything lives in `lib/server/api.ts:5-7` (base URL, TTL, entry cap, cache implementation), with `apiBase` exported once for the sprite prefix (pokedex.ts:89). One file.
