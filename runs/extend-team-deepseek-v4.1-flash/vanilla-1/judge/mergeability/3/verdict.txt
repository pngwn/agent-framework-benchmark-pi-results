## Review: Pokédex app (vanilla TS + Vite), with the Team-builder feature

This is a clean, framework-free SPA: a tiny history-API router (`app/src/main.ts`), a DOM `h()` builder (`app/src/dom.ts`), a cached fetch layer (`app/src/api.ts`), pure formatting helpers (`app/src/format.ts`), shared card/section components (`app/src/components.ts`), and one file per route under `app/src/pages/`. The production server (`app/server.mjs`) serves the Vite build with SPA fallback and injects `API_BASE_URL` into the HTML shell at request time — a nice touch that keeps the build env-agnostic and lets dev mode fall back to `import.meta.env` (`app/src/api.ts:9-14`).

**What's good**

- Rendering is 100% DOM-based (`createElement`/`textContent`), so there is no unescaped-HTML/XSS surface anywhere; `h()` (`app/src/dom.ts:9-31`) is a small, well-typed hyperscript, the idiomatic move for vanilla apps.
- Concurrency is taken seriously: a per-navigation generation counter (`main.ts:64-95`), a token guard on the moves tables (`app/src/pages/pokemon.ts:180-186`), and a promise-cache that evicts failed entries so a retry can succeed (`app/src/api.ts:157-170`). This is more care than most hand-rolled SPAs get.
- The team feature fits the existing conventions perfectly: it reuses `pokemonCard`/`section` (`app/src/pages/team.ts:103,121`), guards `localStorage` with try/catch for private-mode (`app/src/team.ts:30-39`), and renders the button label synchronously so there's no flash (`app/src/team.ts:76`).
- Accessibility details required by the spec (`aria-sort`, `role="status"` on the result count, `aria-busy` during moves load, `scope` on table headers) are all present and in the right places.

**What I'd push back on**

- One genuine race: the home search debounce fires up to 150 ms after the last keystroke (`app/src/pages/home.ts:129-133`). If the user types and then clicks a card within that window, `applyFilters(true)` runs *after* navigation and `history.replaceState`s the home URL over the Pokémon page's URL (`home.ts:120-126`). The guard pattern exists (`isCurrent`) but `renderHome` ignores `ctx.isCurrent` — a one-line fix.
- The route list exists twice and must be kept in sync by hand: regexes in the client (`app/src/main.ts:31-39`) and again in the server's 404 logic (`app/server.mjs:21`). Adding a route means editing both; a shared module (plain `.mjs` works for both ts-vite and the node server) would remove that trap.
- `pages/pokemon.ts` is ~340 lines mixing the page with the whole sortable move-table machinery; the latter is a self-contained unit and deserves its own module.
- Minor naming hazard: `typeNames` means "async-fetch type objects to get English labels" in `app/src/api.ts:186` but "build a Map from already-fetched types" in `app/src/pages/team.ts:46`.
