# Review: `app/` (Astro 7.4, Pokédex + Team builder)

The app is a clean, conventional Astro 7 SSR project (`output: 'server'` + `@astrojs/node`, current stable APIs, no deprecated flags). Structure: one data layer (`src/lib/api.ts`, `src/lib/pokedex.ts`), one layout, six small components, one page per route. Data is fetched at request time behind a hand-rolled SWR cache in `api.ts` — a defensible choice given Astro 7's new route-caching would be wrong for the cookie-dependent `/team` and filtered `/`.

**Scenario walkthroughs**

1. **Remove Abilities**: delete `app/src/pages/abilities/` and remove the section + links in `app/src/pages/pokemon/[name].astro:53,136-146`. Grep confirms no other references (nav has no Abilities link). One leftover: the `note` param/callback on `Card` (`pokedex.ts:95,104,112`) and `.card-note` CSS exist only for the ability "Hidden ability" text and would go dead.
2. **Sprite fix**: sprite URLs are constructed in exactly one place (`pokedex.ts:32`) and rendered by exactly one component (`CardList.astro:18`), so one fix covers every card list. (As it happens the app is currently correct — `data/api/v2/pokemon/386` confirms `deoxys-normal` shares the species id — but a fix to use the Pokémon record's `front_default` would need a sprite field threaded through `Card`'s three producers, `pokedex.ts:102,120,142`.)
3. **Sort cards by name**: one edit in `cardsForPokemon` (`pokedex.ts:113`) covers the move/ability/type lists; home needs a separate sort in `index.astro:21-27`; team must be left alone (it uses `getTeamMembers`, a different function, so the risk is only human).
4. **Items section**: `/items` can model on `types/index.astro`; `/items/[name]` must copy the detail-page skeleton from `moves/[name].astro:16-38` — the fetch-by-name → 404 → facts `dl` → effect-fallback pattern is duplicated across three pages rather than shared. `Base`, `Section`, `NotFound`, `CardList` and the `lib` helpers all reuse as-is.
5. **API base URL / caching**: one file. `API_BASE_URL` is defined once (`api.ts:4-5`), `FRESH_MS`/SWR/concurrency once (`api.ts:6-8,11-21`); `spriteUrl` imports the same constant (`pokedex.ts:1,32`). Only caveat: media base is assumed to equal the API base.

The feature change (team) is where editability degrades: the team concern is spread over six files, and the layout (`Base.astro:38-80`) now carries the team's client-side cookie read/write, duplicating `TEAM_COOKIE`/`MAX_TEAM_SIZE` and the JSON cookie format already in `lib/team.ts` — two implementations of the same serialization that must be edited in lockstep.
