# Editability review — Pokédex app (Angular 22.2)

## Architecture in brief

The app has a genuinely clean seam: server-only code (`app/src/server/`) builds compact view models (`app/src/server/loaders.ts`), the browser gets them either via TransferState or the `/_data` endpoint (`app/src/server.ts:31`, `app/src/app/data/page-data.ts:26`), and components are dumb presenters over typed VMs from `app/src/app/shared/models.ts`. Every page follows the same footprint: a directory under `pages/`, a route entry in `app.routes.ts`, a `loadX` function + switch case in `loaders.ts`, and a VM interface. That predictability is the app's biggest editability asset. Idiomatic for current Angular 22: signal inputs, `@Service()` (recommended per current guidance), `linkedSignal`, route resolvers, standalone components with default exports.

## Scenario walkthroughs

1. **Remove Abilities**: delete `pages/ability/`, then remove the route (`app.routes.ts:50-53`), the `abilities` case + `loadAbility` + `ApiAbility` (`loaders.ts:461`, `loaders.ts:325-338`, `loaders.ts:70`), `AbilityVM`/`AbilityRef` (`models.ts:76`, `models.ts:60-71`), and the Abilities section that links to them (`pokemon-page.html:72-83`). Five files, but each is the feature's own registry entry — no unrelated code entangled. If you skip the models/loader cleanup, dead code silently remains.

2. **Sprite bug (Deoxys)**: the sprite URL is derived in exactly one place — `pokemon-card.ts:73` (`sprite = computed(() => `${apiBase}/media/sprites/pokemon/${id()}.png`)`). Every list renders `PokemonCard` (home.html:38, card-list.ts:14, team-page.html:7), so one fix covers all lists. Caveat: the URL is built from the pattern, not from API data — if the fix requires the actual `sprites.front_default` (e.g. when species-id ≠ pokemon-id), the `Card` VM has no field for it, so `models.ts:11` and `toCards` (`loaders.ts:165`) must grow a field too.

3. **Sort by name everywhere**: three construction sites, because home and team bypass `CardList`: `toCards`/loaders (`loaders.ts:165`, sorted by id), home's `matches` computed (`home.ts:57`), team's `members` computed (`team-page.ts:19`). The "count Pokémon" text and grid markup are likewise duplicated in `card-list.ts:7` and `home.html:26`, `team-page.html:5`.

4. **Items section like Moves**: most infrastructure is reusable as-is — the `pageData()` resolver factory (`app.routes.ts:7`), PageData/TransferState plumbing, the `/_data` endpoint, `CardList`, `TypeBadge`, `NotFound`, `orDash`. What's copied: an `ItemVM` interface, a `loadItem` loader (~shape of `loadMove`, `loaders.ts:280`), and a page component (~copy of `move-page.ts`, ~60 lines), plus route entries and a nav link. Additive and cheap.

5. **Data source change**: base URL + caching live in `api-client.ts:13` (env + server TTL/eviction, lines 5-6) and `page-data.ts:9` (client TTL), plus the `Cache-Control` header at `server.ts:35`. The default `http://localhost:9000` is duplicated in `api-client.ts:13` and `page-data.ts:42`. Three-ish places, one accidental duplicate.
