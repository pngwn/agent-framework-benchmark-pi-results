## Review

**What this is:** a server-rendered Hono app using `jsxRenderer` for the layout, htmx for incremental list filtering and table sorting, and cookie-based team state with full-page POST/redirect (so every control works without JS). Data comes from the PokeAPI through a small hand-rolled stale-while-revalidate cache.

**Framework fit.** This uses current Hono and htmx the way their docs recommend: `jsxRenderer` with the `ContextRenderer` module declaration (`app/src/views/layout.tsx:3`), `hono/cookie` helpers for team state (`app/src/team.ts:14`), `c.render`/`c.html`/`c.redirect(303)`/`app.notFound`/`app.onError` (`app/src/index.tsx:24,89,95,101`), and `serveStatic` with the `root` option (verified against current `@hono/node-server` source). The htmx side is notably careful: partial-vs-full rendering keyed on `HX-Request` *and* `HX-History-Restore-Request` with a matching `Vary` header (`app/src/index.tsx:20,28`), `HX-Push-Url` to keep filter state shareable (`:31,49`), and `hx-sync="closest form:replace"` so typing, select changes and Enter-submit dedupe into one request stream (`app/src/views/home.tsx:61,78,87`). Form-trigger defaults (submit for forms, change for inputs) are relied on correctly.

**Risks found.** The SWR cache is an unbounded `Map` keyed partly by unvalidated `:name` URL params (`app/src/api.ts:9,35` + `app/src/index.tsx:38`), so junk URLs grow memory. First render of a moves page fans out ~100+ parallel fetches with no cap (`app/src/views/pokemon.tsx:74,94`). The fragment routes reuse the full-page 404 handler, so a crafted fragment request can swap a whole HTML document into a table div (`app/src/index.tsx:57,61`). No XSS (hono/jsx escapes), no leaked listeners, no SSR/CSR mismatch, 404s and 500s handled everywhere, cookie input validated and open-redirect-safe (`app/src/team.ts:18`, `app/src/index.tsx:104`).

**Structure.** Clean boundaries: `api.ts` (HTTP+cache), `data.ts` (domain), `team.ts` (feature domain), one file per view with colocated loaders. The feature diff follows existing conventions well — new `team.ts` mirrors `data.ts`, and `CardList` grew an `action` prop rather than being forked (`app/src/views/components.tsx:24`). Main maintainability gap: API payloads flow as `any` throughout (`views/pokemon.tsx:78,224,227,230`), which neutralizes the strict tsconfig.
