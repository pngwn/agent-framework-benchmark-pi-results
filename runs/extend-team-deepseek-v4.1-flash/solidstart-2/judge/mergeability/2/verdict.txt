## Review summary

This is a genuinely well-executed SolidStart v2 app. The stack matches the current stable release exactly: `vite.config.ts` with `solidStart()` + `nitro()` (app/vite.config.ts:5), `query` + `"use server"` wrappers (app/src/lib/queries.ts:6), `createAsync` in routes with `route.preload` (app/src/routes/index.tsx:12, app/src/routes/pokemon/[name].tsx:24), `FileRoutes`, `HttpStatusCode` 404s, `getCookie` from `@solidjs/start/http`, and `mode: "async"` in `createHandler` (app/src/entry-server.tsx:24). The team-builder feature was folded in without distorting anything: a context provider hydrated from a cookie-read server query, cookie parsing shared client/server in `team-store.ts`, and reuse of `PokemonCards` via an optional `onRemove` prop.

The main systematic gap is error handling: `api()` throws on any non-404 upstream failure (app/src/lib/server/pokeapi.ts:48) and there is no `ErrorBoundary` anywhere in `src/`, so a 500 from the API becomes an unhandled rejection (SSR 500 / a client-side Suspense that never resolves). The server data module is also a ~400-line funnel every page goes through — cohesive today, but the first place growth will hurt. Remaining items are nits: a debounce/Back-button race in the search box, a descending-sort tie-break that isn't flipped, small duplication of param/sprite-URL helpers, `any` types at the API boundary, and no unit tests for the pure logic (`parseTeamCookie`, `typeMultiplier`).

I'd approve after one light round asking for the ErrorBoundary and the two dedupes; everything else is non-blocking.
