## Review: editability of the TanStack Start Pokédex

**Framework check first.** The app is on the current stable line — `@tanstack/react-start@^1.169.4` / `react-router@^1.170.46` (1.169 is the first stable Start release, Oct 2026), Vite 8, React 19 — and it uses the *canonical* APIs: `createServerFn({ method }).validator().handler()` (`validator()` is the post-1.168 canonical name; `inputValidator()` is the deprecated one, so this is right-side-up), `createFileRoute`, `loaderDeps`, `HeadContent`, and a custom `srvx` production server wrapping `dist/server/server.js` exactly like the framework's own examples. Nothing here reads as stale.

**What's good for editability**

- Server/client split is a real seam: all API access lives in `app/src/server/pokeapi.ts` (one module, one `apiBase()` at line 9, one TTL/memo at lines 6–33), surfaced to routes only through typed server functions in `app/src/server/functions.ts` that return view models declared in `app/src/lib/types.ts`. Client components never see a raw API shape.
- Every list of Pokémon cards in the app renders through one component (`PokemonCard.tsx:4`), and the team feature was absorbed by it via a `renderAction` prop (`PokemonCard.tsx:44`, used at `routes/team.tsx:50`) rather than a copy of the card markup — the abstraction actually stretched.
- Features are named and colocated: one route file, one named server fn, one named getter, one `<Section>`.

**Where it costs you**

- `CardData` is assembled in **three** independent places: `toCards` (`pokeapi.ts:96`), the species index that the home page feeds straight into the card list (`pokeapi.ts:172`), and hand-rolled construction inside `getTeamData` (`functions.ts:55`). Any new card field is a three-site change.
- The sprite URL is *derived in the view* from the species ID (`format.ts:23`, `PokemonCard.tsx:25`) instead of carried from `sprites.front_default`. So the Deoxys-style fix isn't a one-liner: the data layer must start carrying the URL, which means touching `CardData`, all three producers, and the component.
- "Types in slot order" is copy-pasted four times (`functions.ts:65`, `125`, `156`, `pokeapi.ts:196`).
- Home-page pagination slices *before* the card list (`routes/index.tsx:78`), so a cross-cutting card-list behavior like "sort by name" can't live in `PokemonCardList` alone — the home page needs its own sort before slicing and the team page needs an opt-out to preserve insertion order.
- Client-side caching rules are spread across four routes (`__root.tsx:11`, `index.tsx:31`, `team.tsx:13`) plus `router.tsx:9`, separate from the server TTL in `pokeapi.ts:6`.

Minor smells: `__root.tsx:18` reads the underscore-private `m._notFound`; `typeLabels` maps are rebuilt per route (`index.tsx:63`, `team.tsx:28`) with a silent `humanize` fallback in the component (`PokemonCard.tsx:38`); `PokemonCard.tsx` exports `PokemonCardList`; `lib/config.ts` is a one-function hook module misnamed "config". The app also ships zero tests of its own (acceptance tests are external).
