I've reviewed the whole app, checked it against the current stable TanStack Start (v1.169.4 / router 1.170.46, released 2026‑10‑22, and the official Start skill docs), and worked through the five scenarios. The app matches the documented idioms closely (`tanstackStart()` before `react()` in `vite.config.ts:6`, `createServerFn({ method: 'GET' }).validator().handler()`, loaders calling server functions, `Route.useLoaderData()`, `HeadContent`/`Scripts` root document) and pins the current stable versions, so none of my findings are about outdated framework usage.

Structure in brief: 7 route files → one `server/functions.ts` of server functions → one server-only `server/pokeapi.ts` data layer with a TTL cache → shared view-model interfaces in `lib/types.ts` → small presentational components. Display rules all live in `lib/format.ts`. That layering is the app's main editability asset; the main costs are that `CardData` is assembled in three independent producers, and that type labels exist in two shapes (server-resolved `TypeRef` vs. raw strings + client-side label maps).
