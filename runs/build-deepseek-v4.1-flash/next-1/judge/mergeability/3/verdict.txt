I've reviewed the app end to end. Here's my assessment as a senior Next.js reviewer.

**Structure** (17 source files): App Router pages under `app/app/**`, six small components, a shared data layer `app/lib/api.ts` + pure helpers `app/lib/format.ts`. Server components fetch over HTTP per request (spec requirement), with two client islands (`HomeBrowser`, `MovesSection`). Next 16.4.3 with React 19.3, async `params`/`searchParams`, `generateMetadata` with a title template — all current-framework idioms.

**What's good**: `cached()` deletes the promise on rejection so a failed fetch never poisons the cache (`lib/api.ts:19-26`); `mapLimit` bounds fetch fan-out; filter/page state is clamped; no server-only code leaks into client components; sections use `aria-labelledby`, tables use `caption`/`aria-sort` correctly; pagination preserves query params.

**What I'd push back on**: hand-rolled history mutation plus raw `<a>` pagination links in `HomeBrowser`; detail pages return HTTP 200 "Not found" instead of calling `notFound()`; triple-redundant route segment config cargo-culted onto every file; no `error.tsx`; small duplication (`first()`, `EvolutionTree`/`EvolutionBranch`).
