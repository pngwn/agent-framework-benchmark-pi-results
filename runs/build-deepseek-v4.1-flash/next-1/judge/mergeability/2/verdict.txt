## Review

A well-organized App Router app that mostly follows current Next 16 conventions (Promise `params`/`searchParams`, `generateMetadata`, server components for data, `history.replaceState` for URL sync — which the current docs explicitly bless), but it hand-rolls two things the framework provides for free: unmatched-URL 404s and `notFound()`.

**What's good**
- `app/app/page.tsx:31-37`, `app/app/pokemon/[name]/page.tsx:83-88` — params/searchParams awaited as Promises, the Next 15+ convention; `generateMetadata` used on every dynamic page.
- `app/lib/api.ts:14-21` — a small, single-purpose data layer: module-level promise cache with rejection-eviction (a failed fetch isn't poisoned into the cache), bounded concurrency via `mapLimit`. Clean server/client boundary — only plain serializable props cross into `HomeBrowser`/`MovesSection`.
- `app/components/MovesSection.tsx:53-55` — the client `game` state is re-synced from server props via `useEffect`, the right pattern for state that also lives in the URL.

**What I'd push back on**
- `app/app/[...slug]/page.tsx:12` — a catch-all page that renders "Not found" with HTTP 200. Since Next 13.3 the root `not-found.tsx` already handles unmatched URLs **and returns a real 404 status**; this file exists only to downgrade the framework's built-in behavior.
- `app/app/pokemon/[name]/page.tsx:91` (and moves/abilities/types) — inline `<NotFoundContent />` instead of `notFound()`. Same UI, but no 404 status, and `not-found.tsx` is dead code except for the catch-all.
- `app/lib/api.ts:31` — any non-OK response, including 5xx and rate limits, is collapsed to `null` → rendered as "Not found". A transient API blip shows a page confidently telling the user the Pokémon doesn't exist. No `error.tsx` anywhere either, so a network-level fetch failure gives the default 500 page.
- `app/components/HomeBrowser.tsx:33-36` — filter state is seeded from props once with `useState(initial.…)` and never re-synced (unlike `MovesSection`). Soft-navigating from a filtered home (`/?q=pika`) to `/` via the nav `Link` re-renders the server page with clean `initial` props but leaves the old client state mounted: URL says unfiltered, UI stays filtered. A `useEffect` sync (or `key` from the query) is needed.
- `app/components/HomeBrowser.tsx:154,158` — raw `<a>` for pagination causes full document reloads and forfeits prefetch; these should be `Link`. Likewise raw `<img>` (`app/components/PokemonCard.tsx:28`) instead of `next/image` (defensible given the runtime-configured media origin, but worth a comment or an `unoptimized`/`remotePatterns` config decision).
- Small duplication: `first()` defined twice (`app/app/page.tsx:12`, `app/app/pokemon/[name]/page.tsx:36`); `EvolutionTree`/`EvolutionBranch` are near-identical (`app/app/pokemon/[name]/page.tsx:37-60`); the type-badge link markup is re-implemented inline in the moves and types pages (`app/app/moves/[name]/page.tsx:63`, `app/app/types/[name]/page.tsx:77-81`) instead of reusing the `link` variant of `TypeBadge`.
- `app/app/layout.tsx:5-8` plus `app/lib/api.ts:30` — no-store is asserted four ways (`dynamic`, `revalidate`, `fetchCache`, per-fetch `cache: 'no-store'`), then re-asserted on every page. Harmless but noisy; one mechanism suffices.
