# Editability review — Pokédex app (Next.js 16.4.3, App Router)

## Structure at a glance

The app is a textbook App Router layout: one route directory per resource (`app/pokemon/`, `app/moves/`, `app/abilities/`, `app/types/`), a single data layer (`app/lib/api.ts`) that is the only file that knows `API_BASE_URL` and fetch/caching strategy, pure formatting helpers (`app/lib/format.ts`), and six small presentational components. Server components fetch and hand plain data to two client components (`HomeBrowser`, `MovesSection`) — the server/client seam is clean.

**Scenario 1 — remove Abilities.** Delete `app/app/abilities/`, drop the `Abilities` section in `app/app/pokemon/[name]/page.tsx:259-267` and the `getAbility`/`AbilityRecord` helper in `app/lib/api.ts`. No nav link exists for it, and the catch-all at `app/app/[...slug]/page.tsx` handles stale URLs. Trivially contained.

**Scenario 2 — sprite fix (Deoxys).** Every card list computes its sprite through the single helper `frontSpriteUrl` (`app/lib/api.ts:179`), called from `app/app/page.tsx:54`, `app/app/moves/[name]/page.tsx:106`, `app/app/abilities/[name]/page.tsx:69`, `app/app/types/[name]/page.tsx:105`. One fix in one function covers all four lists. This is the strongest seam in the codebase.

**Scenario 3 — sort all card lists by name.** There is no shared card-list component: each list assembles its own array and inlines its own ordering — `app/components/HomeBrowser.tsx:37-46` (client), `app/app/moves/[name]/page.tsx:41-56`, `app/app/abilities/[name]/page.tsx:36-45`, `app/app/types/[name]/page.tsx:46-57`. Four files, four edits.

**Scenario 4 — an Items section shaped like Moves.** You'd add `getItem`/`ItemRecord` to `app/lib/api.ts` (the `cached`/`apiFetch`/`mapLimit` machinery at `app/lib/api.ts:14-56` is reusable as-is) and copy `app/app/moves/[name]/page.tsx`. Reusable pieces: `Section`, `PokemonCard`, `TypeBadge`, `NotFoundContent`, all of `lib/format.ts`. But the "Learned by" resolution — `speciesById` map, alternate-form exclusion, dedupe, sort — is already copy-pasted three times (`moves:39-56`, `abilities:32-45`, `types:44-57`), so Items becomes the fourth copy.

**Scenario 5 — API base URL / caching.** `API_ORIGIN` lives only at `app/lib/api.ts:12` and is consumed by `apiFetch` (`:26`), `assetUrl` (`:185`), and `frontSpriteUrl` (`:179`) — one file. Runtime cache is the single `cached` map (`:14-21`) plus `cache: 'no-store'` in `apiFetch`. However, per-route segment config (`dynamic = 'force-dynamic'`, `revalidate = 0`, plus `fetchCache = 'force-no-store'` in the layout) is duplicated in **seven** route files (`app/layout.tsx:3-6`, `app/page.tsx:5-6`, and every other page) — a change to caching policy means touching all of them, and most of it is redundant under Next 15+/16 defaults anyway.

**Minor smells.** Two different URL-sync idioms (`window.history.replaceState` at `app/components/HomeBrowser.tsx:67` vs `router.replace` at `app/components/MovesSection.tsx:112`); the `first()` query-param helper duplicated (`app/app/page.tsx:12`, `app/app/pokemon/[name]/page.tsx:36`); type-badge link markup hand-rolled in `app/app/moves/[name]/page.tsx:104-106` and `app/components/MovesSection.tsx:155-159` instead of using `TypeBadge`'s `link` prop; near-duplicate recursive `EvolutionTree`/`EvolutionBranch` components (`app/app/pokemon/[name]/page.tsx:42-66`); `PokemonCard`'s `hidden` boolean leaks ability-page context into a generic card.

## Scores

- **removability: 4** — routes are cleanly scoped per resource; the only cross-file residue is the pokemon page's Abilities section and a dead `getAbility` helper.
- **changeability: 3** — the specific sprite bug is a one-file fix, but the species-filtering/ordering rule ("alternate forms excluded", sort by dex) exists in three near-identical copies that would each need fixing.
- **coupling: 4** — narrow prop-driven components, explicit data flow server→client, one data layer; small knocks: `MovesSection` hardcodes `/pokemon/` and `/moves/` routes, and card lists know sprite URLs rather than a `Pokemon` concept.
- **abstraction_design: 3** — the helpers that exist (`Section`, `TypeBadge`, `PokemonCard`, cached fetcher, format utils) are well-shaped, but the "resource detail page with a Pokémon card list" pattern was never extracted, so Moves/Abilities/Types are clones and Items would be a fourth.
