## Review: experimentalness

**What's there.** The app pins `next@16.4.3` (`app/package.json:11`) and uses:

- App Router file conventions only — `layout.tsx`, `page.tsx`, `not-found.tsx` (e.g. `app/app/layout.tsx:1`, `app/app/[...slug]/page.tsx:1`) — stable since Next 13.4.
- Route segment config: `dynamic = 'force-dynamic'`, `revalidate = 0`, and in the layout also `fetchCache = 'force-no-store'` (`app/app/layout.tsx:4-6`, repeated on every route page, e.g. `app/app/pokemon/[name]/page.tsx:28-29`). These are stable APIs (docs: route-segment-config), **not** experimental — but per the v16.0.0 version history they are *removed when the experimental `cacheComponents` flag is enabled*, i.e. they belong to the "previous model" Next 16 is migrating away from. Since the app never enables that flag, everything works and is fully supported.
- `fetch` with explicit `cache: 'no-store'` plus a hand-rolled in-memory `Map` promise cache (`app/lib/api.ts:11,28`) — plain, stable.
- `Metadata` / `generateMetadata` with a title template (`app/app/layout.tsx:8-12`, `app/app/pokemon/[name]/page.tsx:41`) — stable.
- Async `params`/`searchParams` as Promises (`app/app/pokemon/[name]/page.tsx:23-24`) — required (stable) since Next 15.
- Client-side: `useRouter().replace(url, { scroll: false })`, `useState`, `useEffect`, `useMemo` (`app/components/MovesSection.tsx:4,102-116`, `app/components/HomeBrowser.tsx`) — all long-stable.
- Plain `<img>` instead of `next/image` — the conservative choice.

**What's not there.** Zero `unstable_`/`experimental_` markers, no `use cache`/`cacheLife`/`cacheComponents` (experimental in Next 16), no middleware/proxy.ts, no PPR, no React 19.2 experimental hooks (`useEffectEvent`, View Transitions), no Turbopack-specific config, empty `next.config.mjs`.

**Assessment.** For this dimension the app is maximally conservative: every API is long-stable, and the one place Next 16 offers a new (still-experimental) direction — Cache Components — it was deliberately avoided in favor of the supported-but-legacy segment configs, with a redundant triple opt-out of dynamism (`force-dynamic` + `revalidate = 0` + `fetchCache` + per-fetch `no-store`). The redundancy is noise rather than risk today, but those exported constants are exactly what a future Cache Components migration would have to delete from all ~8 route files. Containment is trivially fine (one `lib/api.ts` module centralizes data access), and every dynamic-rendering choice is justified by the spec's "live service, request-time data" requirement.
