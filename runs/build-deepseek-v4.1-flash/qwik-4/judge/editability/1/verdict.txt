I've reviewed the full app: 13 source files, ~860 significant LOC, one central data module, thin shared components, self-contained routes. Qwik 2.0 is still at RC as of today, so `^1.20.3` with `routeLoader$`/`useComputed$`/`useSignal` is the current stable idiom — no deprecation concerns in what was written.

**How the scenarios play out:**

1. **Remove Abilities**: delete `app/src/routes/abilities/[name]/`, remove the Abilities section at `pokemon/[name]/index.tsx:389-398` (the only inbound links — nav at `layout.tsx:12-14` never mentions abilities), then optionally prune the `hidden` plumbing in `data.ts:265-278` / `ui.tsx:40` and `.hidden-ability` in `global.css:278`. Two real files, three optional cleanups. Clean.
2. **Sprite bug (Deoxys)**: sprite extraction exists twice — `data.ts:257` (home catalog) and `data.ts:290` (shared card builder). Both are in the same file, and a single `spriteFor(id)` helper applied to both covers every card list, because moves (`moves/[name]/index.tsx:34`), abilities (`abilities/[name]/index.tsx:33`) and types (`types/[name]/index.tsx:22`) all go through `speciesCardsFromRefs`. The home page is the one list that *doesn't* — that's the duplication cost.
3. **Sort by name everywhere**: change the sort at `data.ts:287` covers the three ref-based lists; home needs its own sort in `index.tsx:47-56`. Two places, both obvious. No shared card-list component means you touch data twice, but never four times.
4. **Items section**: `getRecord` (`data.ts:~300`), `englishName`, `latestEnglishFlavor`, `speciesCardsFromRefs`, `PokemonCard` and `NotFound` all reuse as-is; the page scaffold (h1 + `<dl>` + effect section + card grid + `head` export with the `notFound` sentinel) is copy-pasted from `moves/[name]/index.tsx` and adjusted — exactly as moves/abilities/types already copy it from each other.
5. **API base URL / caching**: one place. `apiBase()`/`apiUrl()` at `data.ts:52-62`, cache store at `data.ts:48-50, 70-81`. `vite.config.ts` headers concern the app's own responses, not the API.

The persistent warts: three near-identical filter handlers in `index.tsx:61-66, 77-82, 100-105` each repeating the page-reset + `replaceState` logic; inline literal types in JSX that re-declare loader return shapes by hand (`types/[name]/index.tsx:86,100`; `pokemon/[name]/index.tsx:241,371-376`); and an `any`-typed data layer.
