The app targets Angular **^22.2** (app/package.json:4-9), which is the current stable major (v22 released 2026-06-03, and Angular moved to a yearly release cycle). I verified each "new" API against v22 release notes:

| Zoneless (no zone.js dep) | implicit | Default since v21, stable since v20 |

Notably **absent**: every genuinely experimental/developer-preview v22 feature — `@boundary`, Router resources, `provideWebMcpTools`, `injectAsync`, `debounced` — none appear (grep across `app/src` returned nothing). No `unstable_`/`experimental_` names, no experimental build flags in `angular.json` (only the standard `experimentalDecorators` TS flag, required for Angular decorators). The only `meta` ambient usage is a type declaration in runtime-config.ts.

The recently-stable APIs are used centrally — `resource()` is the data-loading mechanism on every page (app/src/app/pages/home-page.ts:135, pokemon-page.ts:217, 273, move-page.ts:100, ability-page.ts:65, type-page.ts:97, type-list-page.ts:33), always in the recommended `params`/`loader` shape with `hasValue()`/`error()` handling. All loaders funnel through the two `@Service()` classes (`PokeApi` with its request cache at app/src/app/core/poke-api.ts:10-22, `PokedexData`), so HTTP access is centralized even though `resource()` call sites span 5 files. The spec's requirement that filter state live in the URL and drive refetching is exactly what `resource(params)` + `withComponentInputBinding` buys over manual HttpClient/switchMap plumbing — each use is justified rather than novel. One mild wrinkle: home-page.ts:196-199 mirrors `resource.value()` into a `view` signal via `effect()` to keep the previous page rendered during refetch — defensible, slightly unusual.
