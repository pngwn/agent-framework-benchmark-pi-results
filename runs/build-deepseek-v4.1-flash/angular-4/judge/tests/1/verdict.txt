## Review: test quality

**The agent wrote no tests.** Static facts confirm it (`tests: { files: 0, cases: 0 }`), a grep for `describe(`/`.spec.` in `app/` returns nothing, and the scaffolding is telling: `app/package.json` installs `vitest` and `jsdom` as devDependencies and defines `"test": "ng test"`, and `app/tsconfig.spec.json:12-14` includes `src/**/*.spec.ts` — but not a single spec file exists. The tooling was wired up and then never used; `ng test` runs against zero tests and passes vacuously.

That means every judgement here is about *what the acceptance suite no longer guards*. The app has a lot of exactly the kind of logic that regresses silently under refactor:

**Riskiest untested areas (read in full):**

- **Home filtering/pagination/URL state** — `app/src/app/pages/home-page.ts:31-40` (`parseQuery`: NaN/negative `page` coercion), `:63-103` (humanized-name substring match, type/generation filters, 48-per-page slice, `currentPage` clamped to `totalPages`), `:101-111` (`pageLink` omitting default params) and `:122-138` (`navigateWithFilters` resetting `page` to 1 on every filter change). A refactor of the catalog map shapes or the clamp logic breaks pagination/filters with nothing failing.
- **Move-table construction and sorting** — `app/src/app/pages/pokemon-page.ts:186-232` (`buildTables`: method priority `level-up → machine → egg → tutor → alphabetical`, Level column only in the level-up table, default sorts) and `:106-126` (`compareRows`: the deliberate "nulls sort last in *both* directions" rule, achieved by returning `1`/`-1` before applying the direction factor — a very easy thing to "simplify" into a bug). Also `:420-436` (`toggleSort` direction flipping feeding `aria-sort`).
- **Catalog cross-indexing** — `app/src/app/core/catalog.service.ts:90-130`: `typeByPokemonId` with the `id <= 10000` alternate-form exclusion (`:101`) and slot ordering, `generationBySpeciesId`. Note the 10000 cutoff is duplicated in three places (`catalog.service.ts:101`, `type-page.ts:74`, `move-page.ts:63`) — changing one breaks the others silently.
- **Error handling conflated with not-found** — `app/src/app/core/api.service.ts:38-41`: `optional()` maps *any* HTTP failure (500, network down) to `null`, so every page's "Not found" branch (`pokemon-page.html:163-167`) doubles as the error state. A transient API outage renders "Not found" pages; no test distinguishes absence from failure.
- **Pure formatters** — `app/src/app/core/format.ts:14-64`: `latestEnglishFlavor` (last-English-entry + whitespace collapse — easy to regress to *first* entry), `displayValue` em-dash, `humanize`, `padDex`, `idFromUrl`'s regex. Trivially unit-testable, zero tests.
- **Evolution tree recursion** — `app/src/app/pages/pokemon-page.html:154-167`: recursive `ngTemplateOutlet` for branching chains (Eevee), with `track child.species.name` — duplicate species names in a chain would collide keys.
- **Caching** — `app/src/app/core/api.service.ts:24-35`: in-memory cache keyed by path with `shareReplay({ refCount: false })`; stale-cache or key-collision bugs would be invisible.

**Scoring** — with no tests in `app/`, `coverage_of_risk`, `behaviour_not_implementation` and `regression_power` are 1 by the anchors (nothing would be caught). `signal_to_noise` is 3 per the rubric (no tests). The scaffolding-without-tests is worse than nothing in one sense — it signals intent without follow-through — but adds no maintenance noise. `overall: 1`: a data layer this dense (Rx streams, signal/rxjs-interop bridging, URL-synced filters, multi-table sorting) with zero regression net is a liability for a codebase owned for years.
