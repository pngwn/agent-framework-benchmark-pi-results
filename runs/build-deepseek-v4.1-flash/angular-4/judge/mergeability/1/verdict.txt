I've reviewed the app thoroughly against the spec, Angular 22 (current stable per the v22 release notes — `resource`/`httpResource`/Signal Forms stabilized), and the official skill guidance. Here's my review.

## Review summary

**Structure**: clean `core/` (ApiService, CatalogService, format helpers, models), `pages/` per route, `shared/` (PokemonCard, NotFound) — sensible and consistent.

**Strengths**
- Modern Angular throughout: standalone components, `inject()`, OnPush everywhere, signal `input()`, `@if/@for` control flow, `toSignal` with explicit initial values, `computed` chains, recursive `ng-template` + `NgTemplateOutlet` for evolution trees (`app/src/app/pages/pokemon-page.html:160-174`).
- `ApiService` is a well-bounded data layer: in-memory cache, media-URL resolution, path parsing (`app/src/app/core/api.service.ts:19-56`), and the sort/table-building logic in the Pokémon page is factored into small pure functions (`app/src/app/pages/pokemon-page.ts:127-200`).
- Race handling is mostly right: `switchMap` chains cancel stale fetches, 404s route to a shared `NotFound` component, and filtering/sorting logic handles nulls ("missing values sort last") correctly.

**Where I'd ask for changes**
- Data fetching is pre-`resource`-era: hand-built `switchMap`/`forkJoin`/`shareReplay` chains + `toSignal`, when `resource`/`httpResource` (stable in v22, and the skill says "prefer httpResource for reads") would replace ~150 lines of plumbing with cancellation and status built in. Route params are read via `route.paramMap` boilerplate instead of `withComponentInputBinding()`.
- Error semantics: `optional()` maps *every* error to `null`, and `get()` caches the errored observable (`api.service.ts:28-34`) — a transient network hiccup renders a permanent "Not found" until a full reload. This is the one thing I'd block on.
- Three page components each rebuild an identical `speciesById` map and copy-paste the alternate-form filter/dedupe/sort block that `CatalogService.catalog$` already computes.
- The `#moves` anchor jump is hand-rolled in an `effect` with a bare `setTimeout` (`pokemon-page.ts:371-380`), where `withInMemoryScrolling({anchorScrolling: 'enabled'})` or `afterRenderEffect` is the framework feature; the timer has no `onCleanup`.
- Zero unit tests even though vitest + jsdom are installed and the unit-test builder is configured; the pure helpers in `format.ts` and `compareRows`/`buildTables` are trivially testable.
- Minor: mixed naming suffixes in `core/` (`.service.ts` vs suffixless files), `dexNumber()` duplicating `padDex()`, a `as unknown as Map` cast, `track $index` on sortable rows.
