I've reviewed the app against the spec, the Angular 22 skill guidance (`httpResource`/`resource` recommendations, naming conventions, effects guidance), and read every source file. Scoring:

**Idiomatic (4):** Modern Angular throughout — standalone components with `input()`/`signal()`/`computed()`/`toSignal`, OnPush everywhere, `@if/@for` control flow, `provideRouter`, `provideBrowserGlobalErrorListeners` (`app/src/app/app.config.ts:1`). Titles set via `effect()` in constructors is exactly right. Docked one point because it bridges RxJS by hand where v22 recommends `httpResource`/`resource` for reads (`app/src/app/core/api.service.ts:23`), hand-rolls response caching, and hand-rolls `#moves` anchor scrolling (`app/src/app/pages/pokemon-page.ts:372`) instead of `withInMemoryScrolling({ anchorScrolling: 'enabled' })` — home-grown workarounds where framework features exist.

**Correctness risks (3):** Three real but non-fatal issues: (1) component-scoped streams use `shareReplay({ refCount: false })`, so every visit to a Pokémon page leaks its species/pokemon/version-group/moves pipelines and their emitted values for the app's lifetime (`app/src/app/pages/pokemon-page.ts:199,217,244,303`); (2) `ApiService.get` caches the raw observable including errors, so one transient failure serves "Not found" for the whole session (`app/src/app/core/api.service.ts:31-33,36`); (3) the `#moves` scroll effect re-fires whenever the tables signal changes, so sorting while on `#moves` yanks the user back to the section (`app/src/app/pages/pokemon-page.ts:372-380`).

**Global abstractions (3):** `CatalogService` is a coherent, well-bounded catalog, but three pages each rebuild `speciesById` from `species$` instead of consuming `catalog$.speciesById` (`app/src/app/pages/move-page.ts:31-36`, `ability-page.ts:30-35`, `type-page.ts:33-38`), duplicating the alternate-forms dedupe too. `PokemonPage` is a ~430-line god component (species, pokemon, evolution, version groups, move tables, sorting, scrolling in one class).

**Readability (3):** Clear naming, small helper functions, predictable structure — but only 9 comment lines in 25 source files, a subtle `undefined` (loading) vs `null` (not-found) sentinel convention repeated in every template (`app/src/app/pages/pokemon-page.html:1`, `type-page.html:1`), and mixed naming styles (legacy `core/api.service.ts`/`catalog.service.ts` vs modern suffixless `shared/not-found.ts`).

**Review cost (3):** A round of changes before approval: fix the leaked subscriptions, evict failed requests from the cache, dedupe the `speciesById` logic, and add unit tests — the repo ships vitest and an `ng test` script but zero test files for logic like `buildTables`/`compareRows`/`format.ts`.
