2. **Sprite bug**: sprite URL derivation lives in the shared card (`shared/pokemon-card.ts:32` `spriteUrl`, plus `onImageError` fallback at `:44-49`) on top of `core/api.service.ts:44-47` `spriteFor()`. Caveat: the card's inputs are `speciesName` + `pokemonId` only — if the fix needs the default-variety Pokémon, the input contract and all four callers change.
3. **Sort by name on every list**: each page builds its own list — `home-page.ts:96`, `type-page.ts:81`, `move-page.ts:79`, `ability-page.ts:72` — each with its own `.sort((a,b) => a.id - b.id)` and no shared list helper. Four files.
4. **Items section shaped like Moves**: reusable pieces exist (`ApiService`, `format.ts`, `PokemonCard`, `NotFound`), but the page-level pattern (route-param fetch + tri-state loading template + title effect + "count + cards" section) is per-page code; e.g. the ref→species-card pipeline (`idFromUrl`, `>10000` filter, dedupe, species-name lookup) is copy-pasted at `type-page.ts:66-82`, `move-page.ts:66-80`, `ability-page.ts:58-73`. `.panel`/`.count`/`.card-grid` CSS is likewise copied in `move-page.css:8,51,57`, `type-page.css:8,53,59`, `ability-page.css:8,23,29`, `pokemon-page.css:121`, `home-page.css:46`. An Items page means a fourth copy.
5. **API base URL / caching**: fully centralized in `core/api.service.ts` (`:15-19` baseUrl, `:23` cache map, `:33-40` mediaUrl, `:44-47` spriteFor, `:62` getAll limit) with `server.mjs:7,15` injecting the runtime global. Two files share the `__POKEDEX_API_BASE_URL__` contract, but client-side it's one seam.

Notable idiom check: the app is modern Angular (standalone components, signal `input()`, `computed`, `toSignal`, `@if/@for` control flow, `provideBrowserGlobalErrorListeners`). Against v22 guidance, route-param-driven fetching via long RxJS chains (`pokemon-page.ts:222-296`, five interdependent streams with `shareReplay`) is where the skill now recommends `resource()`/`httpResource`-style signal-first loading; the hand-rolled `x() === undefined || (x() && y() === null)` loading tri-state appears in all six page templates and is implicit convention rather than an abstraction. `CatalogService.catalog$` also builds a `speciesById` map (`catalog.service.ts:94-95,128`) that no consumer uses — every page rebuilds its own private copy instead.
