## Review notes

**Architecture.** The app is a cleanly layered CSR Angular 22 app: `core/` (ApiService, CatalogService, `format.ts`, `models.ts`), `pages/` (one flat, self-contained directory per route), `shared/` (PokemonCard, NotFound). Routes are a single flat table (`app/src/app/app.routes.ts:8-15`). Naming follows the v20+ "intent over role" convention consistently (`home-page.ts` / `HomePage`, no `.component.ts` suffixes), components are standalone with signal `input()`s, `computed`, OnPush, `toSignal` for RxJS interop — all current idioms for v22 (verified against the Angular skill guidance). Server and client code are cleanly separated (`app/server.mjs` is a dumb static file server; the only handoff is the `window.__POKEDEX_API_BASE_URL__` config script it injects into `index.html`, read in exactly one place).

**Scenario walkthroughs** (files you'd actually touch):

1. **Remove Abilities**: delete `pages/ability-page.{ts,html,css}`, one line in `app.routes.ts:20`, the Abilities section in `pokemon-page.html:58-73`, and the now-dead `Ability` interface at `models.ts:144`. Nav (`app.html`) has no ability links. Well contained.
2. **Sprite bug**: sprite resolution is a *single* seam — `PokemonCardComponent.spriteUrl` → `ApiService.spriteFor()` (`shared/pokemon-card.ts:32-34`, `core/api.service.ts:44-47`), with an `onerror` fallback that fetches the real pokemon and uses `sprites.front_default` (`pokemon-card.ts:37-48`). All four card lists (home, move, ability, type) render through the same shared component, so one fix covers everything.
3. **Sort cards by name**: four files, because each page sorts its own list independently (`home-page.ts:93-94`, `move-page.ts:77`, `ability-page.ts:71`, `type-page.ts:80`), and the "pokemon refs → card rows" transform (strip IDs > 10000, dedupe, map to species name, sort) is copy-pasted three times verbatim with the magic `10000` appearing in four files.
4. **Items section**: there is no shared "resource detail page" abstraction — the paramMap→`optional()`→`toSignal` load, the `Title` effect, and the loading/not-found template branches are duplicated across all four detail pages (`pokemon-page.ts:345-353`, `move-page.ts:94-101`, `ability-page.ts:84-91`, `type-page.ts:105-112`). An items page means copying move-page's scaffolding (plus copying `.panel`/`.card-grid` CSS yet again). Reusable: ApiService, `format.ts`, NotFound, PokemonCard. Copied: the page skeleton and styles.
5. **API base URL/caching**: base URL is genuinely centralized (`api.service.ts:12-17`, injected by `server.mjs:12-14`), but caching is smeared — `shareReplay({bufferSize:1, refCount:false})` appears in 10 places across three files, so changing cache policy means hunting them all.

**CSS duplication** is the biggest structural smell: `.panel`, `.card-grid`, `.loading` and h1/h2 rules are copy-pasted into 4-5 page stylesheets, and the 18 type-color classes exist in **four** stylesheets even though `styles.css:128-145` already defines them globally (page-scoped copies are redundant against global styles). Adjusting card layout = 5 file edits.

Minor: `@angular/forms` is an unused dependency; `ng test` script + vitest/jsdom devDeps + `tsconfig.spec.json` exist with zero spec files; `type-page.ts:79` falls back to `entry.url` as a species *name*, which would emit a broken link; three pages rebuild the `speciesById` map that `CatalogService.catalog$` already builds (`catalog.service.ts:62`).
