# Review — forward-thinking

The app is on the current stable framework (React Router 8.5.1, published Oct 27, 2026 — the latest release at time of review) and its dependency set is minimal and current. What holds it back is that it opts out of the framework's flagship current-generation feature — generated route types — and hand-rolls patterns (a `{ notFound: true }` sentinel, pervasive `any`) that the framework now covers natively.

## latest_apis — 4

Everything in use is current-generation: manual route config with `index()`/`route()` (`app/app/routes.ts:3-15`), `loader`/`meta`/`links` route exports (`app/app/routes/home.tsx:7-13`, `app/app/root.tsx:1-8`), `useSearchParams` (`app/app/routes/home.tsx:3`), the standard `Links/Meta/Outlet/Scripts/ScrollRestoration` root shell (`app/app/root.tsx:4-9`), and SSR via `react-router-serve` (`app/package.json:8-9`). Verified against the current docs (reactrouter.com/start/framework/data-loading, reactrouter.com/how-to/route-module-type-safety) and the react-router skill reference: all current. Two gaps keep it off 5:

- The generated `./+types/*` route types are the documented, current pattern (`Route.LoaderArgs`, `Route.ComponentProps`, "The type for the `loaderData` prop is automatically generated" — reactrouter.com/start/framework/data-loading). The tsconfig is wired for typegen (`app/tsconfig.json:3,16-18`) but not one route imports it; every loader, `meta` and component is `any` (`app/app/routes/pokemon.tsx:7,13,42`, `app/app/routes/move.tsx:5,20`, `app/app/routes/type-detail.tsx:5,20`, `app/app/routes/ability.tsx:4,19`).
- Missing-record handling is documented as `throw data("Not Found", { status: 404 })` + `ErrorBoundary` (skill reference, framework-mode.md); the app returns a `{ notFound: true }` marker instead (`app/app/routes/pokemon.tsx:20`, `move.tsx:7`, `ability.tsx:7`, `type-detail.tsx:7`), which also means no HTTP 404 status.

## platform — 4

Good platform-first instincts: global `fetch` with a promise cache instead of an HTTP client (`app/app/lib/api.server.ts:29-43`), `URL`/`URLSearchParams` throughout (`app/app/lib/api.server.ts:19-22`, `app/app/routes/home.tsx:35-45,129`, `app/app/routes/pokemon.tsx:18`), native form controls and `type="search"` (`app/app/routes/home.tsx:57-99`), `loading="lazy"` + intrinsic `width`/`height` on images (`app/app/components.tsx:33-38`), and modern CSS: custom properties, grid `auto-fill`/`minmax`, `min()` (`app/app/app.css:1-70,242-244,648`). The server fetches carry no `AbortSignal`/timeout (`app/app/lib/api.server.ts:29`), and ID extraction is a hand-rolled regex rather than the `URL` parsing already in the same module (`app/app/lib/format.ts:44` vs `app/app/lib/api.server.ts:18-24`).

## dependencies — 5

Six runtime dependencies, every one earned. `react-router`/`@react-router/{dev,node,serve}` at 8.5.1 is the newest stable (npm, Oct 27, 2026); `react`/`react-dom` 19.3.1 satisfies the v8 requirement of 19.2.7+; `isbot` is genuinely used by the framework's default server entry (`app/build/server/index.js:4`) since the app ships no custom `app/entry.server.tsx` — that's the churn-resistant choice. No HTTP client, no state library, no CSS framework, no date/string libs — `URL`, `Map`, `Intl`-free formatting all hand-rolled appropriately. Vite ^8 is the current major. Only nit: `typescript ^5.9` (`app/package.json:21`) while TS 7.0.2 is stable (Aug 2026) and RR 8.3+ explicitly supports `typescript@7` (@react-router/dev 8.3.0 changelog).

## churn_resistance — 3

Strong bones: all data access sits behind one module (`app/app/lib/api.server.ts`, `.server.ts` suffix guarantees client exclusion), pure formatting helpers isolated (`app/app/lib/format.ts`), route components thin, one config file for the router (`app/app/react-router.config.ts:3-5`), no framework internals touched. But two things will ripple on the next requirement or framework bump:

- Types stop at the HTTP boundary and never resume: the API layer is `Promise<any>`/`(entry: any)` (`app/app/lib/api.server.ts:15,25,274,295-310,430`) and route props are `any` (`app/app/routes/pokemon.tsx:42`). `tsconfig` declares `"strict": true` (`app/tsconfig.json:12`) but the app bypasses the framework's typegen, so renaming a loader field or upgrading params typing will surface as runtime breakage, not compile errors.
- The not-found pattern is copy-pasted into four loaders plus a matching `meta` branch each (`app/app/routes/pokemon.tsx:19-26`, `move.tsx:6-16`, `ability.tsx:6-16`, `type-detail.tsx:6-16`); a single `ErrorBoundary`/`throw data()` convention would change one place instead of eight.

## Findings

1. **medium** — `app/app/routes/pokemon.tsx:7,42` — Every loader/`meta`/component signature is `any`; the framework's generated route types (`./+types/*`) are configured in `app/tsconfig.json:3,16-18` but never imported, losing the current type-safety feature. Adopt `import type { Route } from './+types/pokemon'` with `Route.LoaderArgs`/`Route.ComponentProps`.
2. **medium** — `app/app/routes/pokemon.tsx:20` — `{ notFound: true }` sentinel returned from loaders (also `move.tsx:7`, `ability.tsx:7`, `type-detail.tsx:7`) instead of the documented `throw data('Not Found', { status: 404 })` + `ErrorBoundary`; duplicates the not-found branch in each route's `meta` and never sets a 404 status.
3. **low** — `app/app/lib/api.server.ts:25` — `Promise<any>` cache and `any`-typed entry mappers (`:274,295-310`) leave the upstream API untyped; define interfaces for the PokeAPI shapes so server changes fail compilation.
4. **low** — `app/app/root.tsx` (absent exports) — No `ErrorBoundary` anywhere; an API outage renders the framework's default error page rather than an app-branded one.
5. **low** — `app/package.json:21` — `typescript ^5.9.0` while TS 7.0.2 is stable and `@react-router/dev` 8.3+ supports `typescript@7`; also no `typecheck` script (`react-router typegen && tsc`) to make the strict tsconfig enforceable in CI.
6. **low** — `app/app/lib/format.ts:44` — `idFromUrl` uses a regex when the same codebase already parses `URL` objects (`app/app/lib/api.server.ts:18-24`); a shared URL-based parser is one less place to drift.
7. **low** — `app/app/lib/api.server.ts:108-112` — `cardSprite` hard-codes the `id <= 1025` snapshot boundary; the fallback exists, but every species beyond the snapshot costs an extra per-card fetch — brittle as live data evolves.
