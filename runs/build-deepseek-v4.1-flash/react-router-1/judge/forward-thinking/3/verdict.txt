## Review

I read the full app (7 route modules, shared components, `lib/api.server.ts`, `lib/format.ts`, `app.css`, configs), the React Router skill files, and verified the framework's current state against the live changelog: **React Router 8.5.1 is the current stable** (released 2026‑10‑27; v8 blog, remix.run, June 2026), React 19.3.1 is the latest, Vite's latest is 8.3.5, and I confirmed current not-found/error-boundary guidance on reactrouter.com/how-to/error-boundary ("Throw a 404 and move on") and the skill's `references/framework-mode.md` (typegen via `./+types/<route>`, `throw data("Not Found", { status: 404 })`).

What holds up well: exact-latest RR 8.5.1 pins across all five `@react-router/*` packages, correct v8-era usage (`react-router` imports, no `react-router-dom`, `meta` uses `loaderData` — the deprecated `data` arg was removed in v8), `?url` CSS asset import, `useSearchParams` for URL state, all data access confined to one `lib/api.server.ts` module that even follows the `.server.ts` bundler convention, and a lean dependency set with zero extras.

What will cause churn: typegen is configured in `app/tsconfig.json:3` (`.react-router/types/**/*`, `rootDirs`) but never used — every loader/meta/component is `any`-typed; 404s are handled by returning a `{ notFound: true }` sentinel through four route files instead of the documented `throw data(..., { status: 404 })` + `ErrorBoundary` pattern; there is no root `ErrorBoundary`/`Layout`, so any thrown error (API outage) bypasses the app shell entirely; and `app/build/` is present in the repo with no `.gitignore` entry.
