I've reviewed the whole app (sources live under `app/app/`: `root.tsx`, `routes.ts`, `components.tsx`, `lib/api.server.ts`, `lib/format.ts`, `routes/*.tsx`), checked it against the React Router framework-mode guidance (skill + v8 release notes — the app is on the current stable v8.5.1, and v8's conventions are `Route.*` generated types and `throw data(..., {status: 404})` + ErrorBoundary for missing records). Here's my review.

**What's good for editability**
- Server/client seam is clean: all HTTP, caching and page-shaping live in `app/app/lib/api.server.ts` (correctly named `.server.ts` so it can't leak into the client bundle); route components receive plain serializable data and keep filter state in the URL (`app/app/routes/home.tsx:31`, `app/app/routes/pokemon.tsx:59`).
- The hypothetical sprite bug is genuinely centralized: every card list funnels through `cardSprite()` (`app/app/lib/api.server.ts:118`), so one fix covers home, move, ability and type pages.
- Shared `Section`/`PokemonGrid`/`EvolutionList` and a `lib/format.ts` helpers module absorb most repeated markup/formatting.

**What hurts**
- Route modules throw away framework-mode type generation: loaders are `({ params, request }: any)` and components `({ loaderData }: any)` (`app/app/routes/pokemon.tsx:8`, `app/app/routes/move.tsx:5`, `app/app/routes/ability.tsx:4`, `app/app/routes/type-detail.tsx:5`) instead of `Route.LoaderArgs` / `Route.ComponentProps` from `./+types/<route>`. Loader return shapes are invisible to the components, so any data-shape change is unguarded by the compiler; only `home.tsx:19` and `types.tsx:10` approximate it via `Awaited<ReturnType<typeof loader>>`.
- The `{ notFound: true }` sentinel is copy-pasted four times (loader + meta branch + component branch, e.g. `app/app/routes/move.tsx:7,13,22`, `ability.tsx:6,12,21`, `type-detail.tsx:7,13,22`, `pokemon.tsx:10,16,46`) where the framework idiom is one `throw data("Not Found", { status: 404 })` + `ErrorBoundary`. Changing not-found behavior means four synchronized edits, and each `meta` re-implements the identical title branch.
- Several cross-cutting details are duplicated: dex formatting re-implemented inline (`app/app/routes/pokemon.tsx:83` vs `app/app/lib/format.ts:9`), the `type-badge type-*` class string repeated in five files (`app/app/routes/types.tsx:20`, `move.tsx:32`, `type-detail.tsx:37`, `pokemon.tsx:89,273`, `components.tsx:36`), and card assembly exists twice (`api.server.ts:137` `cardFromPokemonRef` vs the inline loop in `homeDataPromise` at `api.server.ts:213-224`). Two parallel card types (`components.tsx:27` `Card` vs `api.server.ts:130` `PokemonCard`) and an unused `humanize` import (`pokemon.tsx:5`) round it out.
- `api.server.ts` is one 530-line module mixing transport, two separate caching layers (`recordCache` at :15 plus six module-scope IIFE promise caches at :65, :82, :96, :174, :258), indexes, and per-page shaping. Changing "the API base URL and caching rules" stays in one file (good) but touches several distinct mechanisms, and adding an Items section grows this file further. A new detail route (items) mostly copies `move.tsx`'s ~50-line skeleton plus a `getMovePage` clone — no shared "resource detail page" abstraction, and `PokemonGrid` is already collecting flags (`showTypes`, `hidden`, `components.tsx:70` bakes the ability-specific "Hidden ability" label into a generic card list).
