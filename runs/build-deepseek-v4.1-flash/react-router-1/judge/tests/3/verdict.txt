The facts are confirmed: `app/` contains **zero tests** — no test files, no runner dependency, no test script (`app/package.json:5-8` defines only `build` and `start`), and no test configuration anywhere under `app/`. All 878 script LOC — including the riskiest logic (filtering, pagination, URL-state sync, multi-column sorting with missing-value semantics, a 1025-species index build, and a promise-level HTTP cache) — are guarded only by the harness's acceptance suite, which the agent didn't write and which won't run when someone refactors the data layer later.

The code is unusually testable, which makes the absence more notable: `app/app/lib/format.ts` is a file of pure spec-encoding functions (`humanize`, `dexNumber`, `englishFlavor`'s whitespace-collapse, `valueOrDash`) that would take minutes to unit test; the home page's filter/slice logic in `app/app/routes/home.tsx:78-100` is pure over `loaderData`; and `MovesTable`'s sort comparator (`app/app/routes/pokemon.tsx:200-226`) is a classic comparator-bug incubator. While reading it I found exactly the kind of latent bug a single unit test would have caught: after the tiebreak `if (comparison === 0) comparison = a.moveLabel.localeCompare(...)`, the return flips the *whole* comparison with `-comparison` for descending sort, so the name tiebreak reverses direction too (`app/app/routes/pokemon.tsx:224-225`) — rows that tie on the sorted column come out in descending-name order when sorting descending. Also, `cardSprite`'s hardcoded `id <= 1025` boundary (`app/app/lib/api.server.ts:99-106`) encodes a snapshot assumption about live data, and the loaders' not-found contract (`{ notFound: true }` sentinel, `app/app/routes/pokemon.tsx:16-20`) plus the cache-eviction-on-error logic (`app/app/lib/api.server.ts:36-41`) are invisible invariants no test protects.
