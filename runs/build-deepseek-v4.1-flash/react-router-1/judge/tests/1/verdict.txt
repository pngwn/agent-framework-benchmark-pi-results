## Review — Test quality

**Ground truth:** `app/` contains **zero tests** and zero test infrastructure — no test script in `app/package.json:6-8` (only `build`/`start`), no runner in devDependencies (`app/package.json:15-22`), and the measured facts confirm `tests: {files: 0, cases: 0, runner: []}`. So `wroteTests` is false, and the value of this review is the map of what's unprotected.

**Framework context (verified):** React Router 8 (the app pins `react-router@8.5.1`, `app/package.json:10`) has a first-class testing story: the official guide (reactrouter.com/start/framework/testing) documents `createRoutesStub` for rendering route components with loader data in isolation, and loaders are plain async functions that can be unit-tested directly. All the app's logic lives in exactly those two shapes — loaders (`app/app/routes/home.tsx:10-12`) and pure helpers (`app/app/lib/format.ts`) — so there was no tooling barrier at all.

**Scoring against the rubric**

- `coverage_of_risk` → 1: nothing is covered. The codebase is dense with exactly the logic the rubric flags as high-risk: filtering/pagination, URL state, data transformation, and error paths, all enumerated below with locations.
- `behaviour_not_implementation` → 1: no tests to classify.
- `regression_power` → 1: any refactor of the data layer or sort logic lands unguarded; the only safety net is the acceptance suite the agent doesn't own.
- `signal_to_noise` → 3: the rubric's anchor for "no tests".

What's particularly frustrating is how *cheap* the missing tests would have been: `format.ts` is 38 lines of pure, dependency-free functions with spec-defined edge cases, and `humanize`/`englishFlavor`/`dexNumber` encode named spec definitions. The most fragile non-pure logic (sprite fallback boundary, move-group dedup, alternate-form exclusion) would take one small fixture each.
