## Review

Stack check first: the app is on the current stable TanStack Start (`@tanstack/react-start` 1.169.4 — the first stable line), uses the canonical `.validator()` server-fn API (the `inputValidator` → `validator` rename landed in 1.168.25/1.169), the `nitro()` vite plugin from `nitro/vite`, and `HeadContent`/`Scripts` in a root route component — all current-recommended patterns. `queries.ts` (RPC stubs) → `data.server.ts` (fetching/shaping) → `format.ts` (pure helpers) is a clean layer cake; routes import only server fns and type-only DTOs.

**What works well for editability**

- Every Pokémon card list renders through one component (`components/PokemonCard.tsx:34`), so "change every list" changes are usually one edit. Adding sorting to all card lists is a one-liner there.
- All API knowledge (base URL, caching, sprite URL scheme, alt-form exclusion) is in one file: `lib/data.server.ts` (`API_ORIGIN` :10, `cache` :102, `mediaSprite` :127, memoized singletons :158–183). Changing the data source touches nothing else.
- Server/client separation is real: `routes/*.tsx` only call `loadXPage` from `queries.ts`; only `import type` crosses into `data.server.ts` (e.g. `components/PokemonCard.tsx:2`).

**What costs editability**

- Three near-identical card-building loops (`data.server.ts:627-636`, `675-683`, `745-755`): `idFromUrl` → `id > 10000` skip → `seen` dedupe → `speciesIndex().get` → `speciesCard` → `sort by id`. Same ~12 lines, three times.
- The alternate-forms threshold `10000` is spelled out four times in two different idioms — `id <= 10000` at `data.server.ts:288` vs `id > 10000` continue at `:630/:678/:749`. A rule change is four edits and easy to miss one.
- The sprite rule is split: `speciesCard`'s default (`data.server.ts:220`) covers move/ability/type lists, but the home page re-implements the fallback inline at `:322` — the Deoxys-style fix needs both spots.
- Home-page filter state is canonicalized three times in one file: `validateSearch` (`routes/index.tsx:28-38`), `update` (`:41-56`) and `linkSearch` (`:66-72`), plus `loaderDeps`. Adding a filter means four edits.
- `<title>` head logic is copy-pasted across four routes (`abilities.$name.tsx:11-17`, `moves.$name.tsx:10-16`, …).
- Minor: `TypeBadge` is a generic primitive exported from the card module and imported by `MoveTable.tsx:4` and `types.index.tsx:5`; `CardData`/`MoveRow` shared types live in the server-named `data.server.ts`. Both work, but they blur seams a future refactor could trip over.
