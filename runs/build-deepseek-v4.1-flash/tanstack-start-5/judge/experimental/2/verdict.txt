## Review: experimentalness

The app is built entirely on TanStack Start's current stable line. The only non-stable dependency in the whole tree is Nitro, and it sits exactly where the framework's own hosting docs put it.

**What I found**

- `app/package.json:21` — `"nitro": "^3.0.261029-rc"`. Confirmed against the Nitro release page: this is the **v3 release candidate**, published 2026‑10‑29 — one day before today. It is a dev dependency, resolved and locked as `3.0.261029-rc` in `app/package-lock.json:1769-1770`.
- `app/vite.config.ts:2,9` — the RC's only appearance in source: `import { nitro } from 'nitro/vite'` and the `nitro()` plugin entry, mirroring verbatim the config in TanStack Start's Node.js/hosting guide.
- Zero `unstable_`/`experimental_` markers anywhere (`grep` over `app/` returns nothing), no experimental config flags in `app/vite.config.ts` or `app/tsconfig.json`.
- Everything else is current **stable**: `@tanstack/react-start@1.169.4` / `@tanstack/react-router@1.170.46` (the latest stable, released 2026‑10‑22 per TanStack/router releases), React 19.3.1, Vite 8.3 (stable since 2026‑03‑12). `createServerFn().validator()` (`app/src/lib/queries.ts:13`) is the current documented API — `.inputValidator()` is the deprecated alias, so the app is on the forward side of that rename (stabilized ~June 2026, `react-start` ≥1.168.25).
- Routes use only long-stable primitives: `createFileRoute`/`createRootRoute`/`HeadContent`/`Scripts`/`Outlet` (`app/src/routes/__root.tsx:2-6`), `validateSearch`/`loaderDeps`/`head` (`app/src/routes/index.tsx:27-35`), `scrollRestoration` (`app/src/router.tsx:7`).

**Is the RC justified?** Yes. TanStack Start's Node.js/Docker hosting guidance routes self-hosted deployments through the Nitro `nitro/vite` plugin ("Follow the Nitro deployment instructions… `start: node .output/server/index.mjs`"), and Nitro's own TanStack Start example ships the same plugin line and same TanStack versions. There is no stable-major alternative for a runnable self-hosted server with a Vite build; the docs do warn the integration is "still under active development." The RC announcement states the v3 API is stable and "Stable is close!", and the `^3.0.261029-rc` range will roll up to the eventual `3.0.0` — a reasonable, forward-looking pin, though it means the production server layer got a brand-new RC with no soak time.
