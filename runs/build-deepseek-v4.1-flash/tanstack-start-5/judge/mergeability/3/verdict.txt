## Review

The app is a competently built TanStack Start app that uses the framework's current APIs almost everywhere, with one recurring design decision — rolling its own 404 mechanism — where the framework provides one.

**Idiom (verified against current docs/releases).** The stack choices are current and correct: `tanstackStart()` from `@tanstack/react-start/plugin/vite` + `nitro()` from `nitro/vite` + `viteReact()` in `app/vite.config.ts:9-11` (matches the official example, and `tanstackStart()` correctly precedes `viteReact()`); `.validator()` on server functions in `app/src/lib/queries.ts:9` (the canonical name since 1.168 — `inputValidator` is deprecated); `createServerFn({ method: 'GET' })` called from route loaders is exactly the documented data-loading pattern; `HeadContent`/`Scripts`/`Outlet` root shell (`app/src/routes/__root.tsx:17-30`), `head: ({ loaderData })` meta titles, `validateSearch` + `loaderDeps` for URL-driven filter state (`app/src/routes/index.tsx:30-47`), and the `getRouter()` export (`app/src/router.tsx:4-9`) all read like the framework's own examples.

The main deviation: TanStack Router's documented way to handle a missing resource is `throw notFound()` from the loader, handled by a `notFoundComponent`/`defaultNotFoundComponent` — the docs are explicit that "you, the developer must throw a not-found error when a resource cannot be found". Instead the app threads a `{ notFound: true }` discriminated union through every loader (`app/src/lib/data.server.ts:363,602,656,709`), checks it in every component (`app/src/routes/moves.$name.tsx:15`, `abilities.$name.tsx:15`, `types.$name.tsx:13`, `pokemon.$name.tsx:47`), duplicates the "Not found – Pokédex" title logic in four `head` functions, and adds a splat route for unmatched paths (`app/src/routes/$.tsx:5`). It works and is type-safe, but it's a home-grown parallel to `notFound()` that also forfeits the HTTP 404 the spec encourages and gives up the shared `defaultErrorComponent` the official example registers — a non-404 API failure renders the router's bare default error UI.

**Correctness.** Nothing serious. The module-level promise cache (`app/src/lib/data.server.ts:102`) is unbounded in principle but effectively bounded by the dataset and explicitly permitted by the spec; failures are evicted (`data.server.ts:117`). The debounced search (`app/src/routes/index.tsx:68-77`) correctly re-syncs from URL state and clears its timer. Sorting, missing-value handling and the move-table state are client-only and deterministic, so no SSR/CSR mismatch. Minor: `fetch` has no timeout/abort (`data.server.ts:106`), and the Scarloth-Violet moves table fans out ~200 parallel move fetches with no concurrency cap (`data.server.ts:531-541`).

**Structure.** `app/src/lib/data.server.ts` is a 777-line monolith: API client, cache, response types, shared card helpers and all six pages' data shaping in one file. The boundary is clean (`.server.ts` + a thin serverFn layer), but shared view types are reached back out of it by client components (`app/src/components/PokemonCard.tsx:2`, `MoveTable.tsx:3`, `routes/pokemon.$name.tsx:5`) — type-only so it erases at build, but a `types.ts` would keep the boundary honest. `format.ts` carries three dead helpers (`app/src/lib/format.ts:45,49,53,57`) while the height/weight formatting they'd do is inlined verbatim in `data.server.ts:588-589`.
