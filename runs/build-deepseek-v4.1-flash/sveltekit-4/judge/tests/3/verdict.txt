## Assessment

**No tests of any kind were written in `app/`.** Confirmed three ways: the measured facts report `tests: 0 files / 0 cases / 0 assertions / runner: []`; a grep for `*.spec.*`/`*.test.*` files under `app/` returns nothing; and `app/package.json:6-13` has no `test` script and no test dependency (no vitest, no @testing-library/svelte, no Playwright CT). The framework's current recommendation (svelte.dev/docs/svelte/testing, verified) is Vitest for unit/component tests — the app doesn't even have the harness scaffolding a future contributor would need. Everything therefore rests on the acceptance suite in `tests/` (not the agent's work), which exercises rendered pages end-to-end but will not guard the data layer during a refactor.

The most fragile, completely unguarded logic:

- **Home filtering/pagination** — `app/src/routes/+page.server.js:60-87`: page clamping (`Math.min(totalPages, Math.max(1, ...))`), `totalPages = Math.max(1, Math.ceil(count/48))`, slice bounds at line 88, and silent fallback for invalid `type`/`generation` params (lines 60-65). An off-by-one or a broken clamp (e.g. page 0 or a page beyond the last) would ship silently.
- **Moves pipeline** — `app/src/routes/pokemon/[name]/+page.server.js:93-160`: default game = `groupRecords.at(-1)` after sorting by `order` (line 117) assumes `order` is monotonic; method ordering (`level-up, machine, egg, tutor`, then alphabetical) at lines 119-126; level-up sort with missing levels pushed to `MAX_SAFE_INTEGER` at lines 37-46; per-method move dedup keeping the *first* detail (lines 128-140). All spec-precise, all untested.
- **`buildCards`** — `app/src/lib/server/pokeapi.js:113-138`: alternate-form exclusion (`id > 10000`), species-name mapping, and the asymmetric hidden-ability merge (a hidden entry upgrades an existing card, but a non-hidden entry never downgrades one — order-dependent). This is exactly the kind of data transformation that breaks when the API shape shifts.
- **Client URL state** — `app/src/routes/+page.svelte:27-64`: the `pending`/`displayedQ` debounce dance, `commit()`'s override-merge, timer teardown, and `replaceState` navigation. Subtle, spec-visible ("results update as the user types", "changing a filter goes back to page 1"), and only partially exercised by acceptance tests at best.
- **`MoveTable.svelte` sorting** — `app/src/lib/components/MoveTable.svelte:34-53`: missing-values-last in both directions, `aria-sort` toggling. A regression here (e.g. applying the direction flip to the missing branch) passes unnoticed.
- **Caching** — `app/src/lib/server/pokeapi.js:9-14`: `memo` caches promises forever and deletes on rejection; no test pins the "failed fetch isn't negatively cached" behavior or the unbounded growth.
- **`format.js`** — pure, zero-dependency functions (`humanize`, `dexNumber`, `latestEnglishFlavorText`, `displayValue`) that encode spec rules verbatim; the cheapest possible unit tests, absent.
- **Error paths** — 404 via `error()` in each `+page.server.js` (e.g. `pokemon/[name]/+page.server.js:70`) and the non-404-throw path in `fetchJson` (`pokeapi.js:24-29`); note `+error.svelte:7` renders `Not found` even for a 500.

The pure-function and load-function code is cleanly factored (`format.js`, `pokeapi.js`, server loads returning plain serializable data), which would make adding Vitest tests genuinely cheap — the omission is a choice, not a structural obstacle.
