## Review: `app/` (SvelteKit Pokédex) — forward-thinking

**Framework context (verified, not from memory):** The app targets SvelteKit 3 (`^3.0.0`, released Oct 2026), which moved config from `svelte.config.js` into the `sveltekit()` Vite plugin, replaced `$lib` with `#lib` subpath imports, and removed `$app/stores` in favour of `$app/state` (svelte.dev/docs/kit/migrating-to-sveltekit-3, svelte.dev/blog/sveltekit-3-is-here). The app is on the current generation almost everywhere: Kit 3-style `vite.config.js` with `adapter: adapter()` (`app/vite.config.js:9-15`), `#lib` via `package.json` `imports` (`app/package.json:20-23`), `jsconfig.json` extending `$app/tsconfig` (`app/jsconfig.json:2`), `$app/state#page` (`app/src/routes/pokemon/[name]/+page.svelte:3`), non-throwing `error(404, ...)` (`app/src/routes/moves/[name]/+page.server.js:4`), snippets/`@render`, and even the function form of `compilerOptions.runes` (`app/vite.config.js:11-14`) that only landed in Svelte in March 2026 (github.com/sveltejs/svelte PR #17951). No `svelte.config.js` remains — correctly, since Kit 3 no longer supports it.

**Two real drift points.** First, both `goto` call sites pass Kit 2 option names: `keepFocus: true, noScroll: true, replaceState: true` (`app/src/routes/+page.svelte:34-38`, `app/src/routes/pokemon/[name]/+page.svelte:12-16`). Kit 3 removed these in favour of `reset: false` and `replace` (svelte.dev/e/kit/goto_options_removed, migration guide §"goto options are updated"); I grepped the built client runtime and the strings `keepFocus`/`noScroll`/`replaceState` appear nowhere in it, so the options are silently dropped — every debounced search commit and game change now resets scroll/focus and pushes rather than replaces a history entry. Second, `process.env.API_BASE_URL` (`app/src/lib/server/pokeapi.js:3`) bypasses Kit 3's current env mechanism (`src/env.js` + `defineEnvVars` + `$app/env/private`), coupling the data layer to adapter-node rather than the framework contract.

**Ageing characteristics.** All API access lives behind one server module (`app/src/lib/server/pokeapi.js`) with a promise-memo cache, load functions build view models, and config is in exactly one place — an upgrade or API change touches few files. Against that: the extensionless `#lib/format` / `#lib/server/pokeapi` imports used throughout (e.g. `app/src/lib/server/pokeapi.js:1`) contradict the Kit 3 migration guide's explicit "add the module extensions" requirement and only work because Vite tolerates them; sprite-URL construction is duplicated between the data module (`app/src/lib/server/pokeapi.js:146`) and the home load (`app/src/routes/+page.server.js:79`); `buildCard`/`hiddenCard` are copy-paste twins (`app/src/lib/server/pokeapi.js:151-165`); and with zero type annotations anywhere, load-contract changes ripple silently. Platform usage is solid: native `fetch`, `URLSearchParams`, `localeCompare(…, { numeric: true })`, `padStart`, lazy images with intrinsic dimensions, CSS custom properties. Dependencies are exemplary: six dev dependencies, all official, all at current majors, zero runtime packages.
