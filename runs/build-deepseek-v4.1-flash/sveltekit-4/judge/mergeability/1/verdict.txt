## Review: SvelteKit Pokédex (`app/`)

**Framework baseline.** The app depends on and was scaffolded for the current stable stack: SvelteKit 3.1.0, Svelte 5.57.3, Vite 8, adapter-node 6 (verified in `app/package-lock.json`), created with the current `sv` CLI (`app/README.md`). Its configuration is correctly Kit-3 style — options live on the `sveltekit` Vite plugin in `app/vite.config.js` (no `svelte.config.js`), the `#lib` alias is declared via `package.json` `imports`, and runes mode is forced. `$app/state`, `untrack`, snippets, keyed `{#each}` blocks and `error(status, message)` are all current-release idiom. Data loading is where SvelteKit wants it: server-only code in `src/lib/server`, pure helpers in `src/lib/format.js`, one `+page.server.js` per route.

**The one real framework mismatch.** Both `goto()` calls use Kit 2 option names that the current release removed/renamed — `keepFocus`/`noScroll` were replaced by `reset: false` (breaking, kit#16558, released in 3.0.0-next.13) and `replaceState` is deprecated in favour of `replace` (kit#16449). Against Kit 3.1.0 these options are no-ops: after the 200 ms debounced commit fires, SvelteKit's default `reset: true` takes the focus off the search input (keystrokes after a >200 ms pause are lost) and scrolls the page to the top; on the Pokémon page the `#moves` position is lost when changing game. The acceptance tests type at 50 ms intervals (single commit at the end), so they don't catch it — a real user typing at a human pace does.

**Other risks.** `+error.svelte` renders "Not found" for *every* error, including a 500 from a failed API call (`fetchJson` throws on non-404), mislabelling outages; `goto` rejections are unhandled in both pages; the module-level cache is unbounded (fine per spec, but a full crawl pins ~2,000 API records in memory); `commit()`'s `pending = false` after `await goto` can clobber a newer pending search started during navigation.

**Structure.** Boundaries are clean: `lib/server` vs `lib/format` vs two small components. Minor smells: `buildCards` sniffs three different API shapes and a nonexistent `item.hidden` field; `buildCard`/`hiddenCard` are near-duplicates; the sprite URL is built in two places; all 628 lines of CSS live in one global `app.css` where the framework favors component-scoped styles; `PokemonCard` has both a `hidden` prop and a `pokemon.hidden` field. Comments are nearly absent (1 line) — the cache rationale and the alternate-form exclusion deserve a "why".
