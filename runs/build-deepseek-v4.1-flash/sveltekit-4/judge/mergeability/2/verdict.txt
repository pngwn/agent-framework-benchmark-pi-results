# Review: Pokédex SvelteKit app (mergeability)

## Verification of framework-version claims

The app targets **SvelteKit 3** (`@sveltejs/kit ^3.0.0`, Svelte 5.57, Vite 8 — `app/package.json:12-19`). I checked the current docs before judging:

- Config in `vite.config.js` with `sveltekit({ adapter, compilerOptions })` and `runes: ({filename}) => …` is exactly the Kit 3 pattern (`app/vite.config.js:5-12`); `svelte.config.js` is correctly absent, and the `#lib` subpath-import alias is declared per the migration guide (`app/package.json:23-26`). `$app/state`, `error()`-throws, `+page.server.js` loaders, snippets, keyed each-blocks — all current idioms.
- **But**: the Kit 3 migration guide states `goto` options changed — "`keepFocus: true` and `noScroll: true` have been combined as `reset: false`" and "`replaceState` is now `replace`". PR sveltejs/kit#16558 *removed* `noScroll`/`keepFocus`. The app uses the removed/renamed names in two places: `app/src/routes/+page.svelte:34-37` and `app/src/routes/pokemon/[name]/+page.svelte:12-15`. On the app's own pinned version these options are ignored, so every debounced search commit and game change falls back to defaults: a **pushed** history entry per keystroke-group and a **scroll+focus reset** — the user loses focus in the search box 200 ms after typing. The acceptance tests (`tests/specs/home.spec.mjs:85-93`) fill and assert URL/content only, so they can't see this.
- Kit 3 deprecates `$env/*` in favour of explicit declarations: "Add a `src/env.ts` … exports a `variables` object" consumed via `$app/env/private`. The app instead reads `process.env.API_BASE_URL` directly at module scope (`app/src/lib/server/pokeapi.js:3`). Works under `adapter-node`, but it's off-doc for the pinned version.
- The tutorial's canonical `+error.svelte` branches on `page.status` (`$app/state`); this app's `+error.svelte` hardcodes "Not found" for every error (`app/src/routes/+error.svelte:6,9`), so an API 500 renders a 404-titled page.

## Scores

- **idiomatic: 3** — Setup is impressively current (Kit 3 config, `#lib` alias, runes, `$app/state`), but the two `goto` calls use Kit 2 option names removed in Kit 3 (`app/src/routes/+page.svelte:35-37`, `app/src/routes/pokemon/[name]/+page.svelte:13-15`), env access bypasses `src/env.js` (`app/src/lib/server/pokeapi.js:3`), and `#lib/format` imports omit the module extensions the Kit 3 docs call for (`app/package.json:25`).
- **correctness_risks: 3** — The dead `goto` options cause real misbehaviour (history pollution, focus/scroll loss) invisible to tests; all non-404 errors surface as "Not found" (`app/src/routes/+error.svelte:9`); level-up moves keep only the first detail per move/game (`app/src/routes/pokemon/[name]/+page.server.js:118-121`), an edge the snapshot may or may not exercise; the home load rebuilds two large lookup maps per request (`app/src/routes/+page.server.js:17-48`).
- **global_abstractions: 4** — The server/client boundary is exemplary (`src/lib/server/` is the only place touching the API, with a bounded, rejection-evicting cache at `app/src/lib/server/pokeapi.js:7-14`); `format.js` is small and pure. Minor duplication: the sprite URL pattern exists twice (`app/src/lib/server/pokeapi.js:147`, `app/src/routes/+page.server.js:79`) and `buildCard`/`hiddenCard` differ by one field (`app/src/lib/server/pokeapi.js:152-166`).
- **readability: 4** — Consistent route layout, clear names, keyed each-blocks, accessible section/labelling discipline throughout; dents: one comment in the whole app, the phantom `item.hidden` read (`app/src/lib/server/pokeapi.js:135`) that matches no API shape, `PokemonCard`'s dual "hidden" channels (prop vs `pokemon.hidden`, `app/src/lib/components/PokemonCard.svelte:5`), and home's title hardcoded while the server returns one (`app/src/routes/+page.svelte:26` vs `app/src/routes/+page.server.js:104`).
- **review_cost: 3** — Approvable only after a round: fix the two `goto` calls, branch the error page on `page.status`, declare env vars per Kit 3, then nits (dedupe sprite URL, drop the redundant `hidden` prop, memoize the home lookup maps).
