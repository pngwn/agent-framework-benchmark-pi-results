## Review: editability

**Shape of the app.** Data access is fully centralized in `app/src/lib/server/pokeapi.js` (base URL, cache, record/list fetchers, `buildCards`); pure formatting in `app/src/lib/format.js`; two presentational components (`PokemonCard`, `MoveTable`); per-route `+page.server.js` / `+page.svelte` pairs. Filter state lives in the URL with `goto(..., { replaceState: true })` and `untrack` for the initial value (`app/src/routes/+page.svelte:13,51-60`) — current, idiomatic Svelte 5. This is a clean, conventional Kit layout; the pain points are a handful of duplicated seams rather than structural entanglement.

**Removability — 3.** Deleting Abilities means the route directory plus the Abilities *section* on the Pokémon page (its markup `app/src/routes/pokemon/[name]/+page.svelte:90-97` and the load that builds it `app/src/routes/pokemon/[name]/+page.server.js:90-98,187`), because the spec puts ability links there. Nav links (`app/src/routes/+layout.svelte:16-18`) are untouched. Dead CSS is left behind: `.plain-list` (`app/src/app.css:505`) and `.hidden-ability` (`app/src/app.css:260`) exist only for abilities. A handful of scattered, but findable, edits.

**Changeability — 3.** `buildCards` covers the three secondary card lists (moves/abilities/types) in one place (`app/src/lib/server/pokeapi.js:124-141`), so most fixes land once. But the home list builds its own cards inline (`app/src/routes/+page.server.js:76-88`), including a second, separately-written sprite URL (`+page.server.js:79`) that duplicates the module-private `spriteUrl` (`pokeapi.js:146-148`) — a sprite fix (the Deoxys-class bug) must be written twice, and nothing ties the two together. Naming/format rules are correctly single-sourced in `format.js`.

**Coupling — 3.** Server/client separation is clean: all API access in `src/lib/server` (framework-enforced server-only), pages receive plain serializable props, `MoveTable`/`PokemonCard` depend only on their props. Tangles: `getApiBase` is exported solely so the home route can hand-roll a media URL (`pokeapi.js:21`, `+page.server.js:79`), leaking data-layer internals into a route; the `PokemonCard` contract is defined twice (two card shapes) and split between props and data (`hidden` prop passed redundantly at `app/src/routes/abilities/[name]/+page.svelte:17` even though `pokemon.hidden` is already on the object); and all component styles live in a single 708-line global stylesheet, so editing `PokemonCard` means editing `app.css` ~200 lines away from the markup (`.pokemon-card` at `app/src/app.css:210`).

**Abstraction design — 4.** The data layer is genuinely shaped to the real variation: `getRecord`/`getList`/`getByUrl` are resource-generic, `memo` is the single caching seam (`pokeapi.js:6-18`), and `buildCards` transparently handles both ref shapes (`item.pokemon ?? item`, `pokeapi.js:128`) plus hidden-ability marking. `MoveTable` is parameterized by a `table` object rather than move-specific flags. Weaknesses: `hiddenCard` is a copy-paste clone of `buildCard` (`pokeapi.js:150-166`), and `PokemonCard` has mild boolean-flag creep (`showTypes`, `hidden`, `PokemonCard.svelte:5`). An Items section reuses the data layer and formatters wholesale; only the page markup (`facts` dl, effect section) is copied.

**Scenario results.**

1. Remove Abilities: `app/src/routes/abilities/`, `app/src/routes/pokemon/[name]/+page.server.js`, `+page.svelte`, `app/src/app.css` — difficulty 3 (cross-page section + dead CSS).
2. Deoxys sprite fix: `app/src/lib/server/pokeapi.js` (one fix covers moves/abilities/types via `buildCards`) plus the inline URL at `app/src/routes/+page.server.js:79` — difficulty 3.
3. Name sorting on every card list: sort in `pokeapi.js:141` covers three lists; the home list needs a second sort in `+page.server.js` — difficulty 4.
4. Items section: reuse `getRecord`, `format.js`, `panel`/`facts` classes; copy ~25 lines of page markup from the moves route — difficulty 4.
5. Data source / caching change: base URL, endpoint, cache all in `pokeapi.js:3,20-24,6-18`; the one straggler is the inline media URL in `+page.server.js:79` — difficulty 4.
