## Review: SolidStart Pokédex app — editability

**Framework currency.** The app is on the current stable stack: `@solidjs/start ^2.1.0` (v2 went stable Aug 2026), Vite 8, Nitro 3 as a Vite plugin, Node ≥ 24 (`app/package.json:6-13`, `app/vite.config.ts:5`). `solidStart({ ssr: false })` is a valid current option, and API routes in `src/routes/**/*.ts` are the idiomatic place for server code — the server/client split (`api-proxy`, `media`) is clean and idiomatic. Nothing here is a legacy pattern from v1.

**What works well.** `PokemonCard`, `TypeBadge`, `MoveTable` and `NotFound` are small, data-driven components with narrow interfaces (`CardData`, `MoveRow`), so every card list in the app renders through one component and one sprite-expression. Data fetching is centralized behind `api.ts` (one `fetch` prefix, one TTL cache), formatting behind `format.ts`, and `data.ts` gives one function per page — you can usually guess where something lives.

**What a maintainer will feel.** The resource-page *shell* is not abstracted: the `resource → loading fallback → NotFound → Title → panels` pattern is copy-pasted across four route files, and each page's data function re-does the same `apiGet → catch → null → speciesById map → cards` scaffolding. So "add an Items section shaped like Moves" is mostly duplication, not reuse. There are also three separate places where the same 1025-entry `speciesById` map is rebuilt, two independent caching layers, two copies of `API_BASE`, and `TypeBadge` bypassed by inline copies in three templates. The card *shape* is built in two places (`getHomeData`'s items vs `cardForSpeciesId`), which is exactly where the hypothetical sprite fix bites.

### Scenarios

1. **Remove Abilities** — easy: delete `app/src/routes/abilities/`, delete `getAbilityPage` (`app/src/lib/data.ts:314`), remove the Abilities section from the Pokémon page (`app/src/routes/pokemon/[name].tsx:154-163`), drop the CSS block (`app/src/app.css:473-478`). No nav links point there.
2. **Sprite bug** — the URL is built in exactly one template expression (`app/src/components/PokemonCard.tsx:18`) from the *species* id, so one fix covers all four lists — but a correct fix needs the default variety's Pokémon data plumbed into `CardData`, which touches both card-construction sites in `data.ts` (`:170-177` and `:173-191`).
3. **Name-sort every card list** — sorts live in three data functions (`data.ts:303, 341, 363`) plus the home ordering; there's no shared list component, so a UI-level sort is added in four routes.
4. **Items section** — components, formatters and `api.ts` are reusable; the page shell and data-function scaffolding are not (~150 lines copied).
5. **API base URL / caching** — base URL duplicated in two server routes; caching spread across `api.ts` TTL, permanent module-level promise memos in `data.ts`, and `cache-control` headers in both proxies.
