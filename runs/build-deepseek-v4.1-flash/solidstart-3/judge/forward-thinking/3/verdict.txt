## Review

**Stack currency.** This is a genuinely current-generation SolidStart app: `@solidjs/start@2.1.0` (v2, stable since Aug 2026) with the Vite-8 `vite.config.ts` + `solidStart()` + `nitro()` from `nitro/vite` pattern, `@solidjs/router@1.0.0`, Node ≥24 — exactly the stack the v2 migration guide prescribes (`app/vite.config.ts:1-6`, `app/package.json:4-13`). The documented `ssr: false` SPA option is used with server routes intact (`app/vite.config.ts:5`), `APIEvent` is the current API-route type, and `@solidjs/meta` is the current head-management library.

**Where it misses the current API.** The one place a current-generation primitive exists and isn't used is data fetching: `createResource` + a hand-rolled TTL/inflight cache (`app/src/lib/api.ts:21-44`) plus a hand-rolled concurrency pool (`app/src/lib/api.ts:63`) re-implement what the router's `query()`/`createAsync()` data API provides (dedupe, revalidation, and `createAsync` is literally "a wrapper around `createResource`" — docs.solidjs.com/solid-router data APIs). It works, but it's duplicate machinery the framework now ships.

**Churn surface.** The data layer is correctly centralized behind `lib/api.ts`/`lib/data.ts`/`lib/format.ts`, but the "typed boundary" is mostly `any` — `PokemonPageData.species/pokemon: any` (`app/src/lib/data.ts:186-199`), `Promise<any | null>` (`app/src/lib/data.ts:344`) — so API-shape changes surface at runtime in views, not at compile time. Two dead interfaces (`app/src/lib/data.ts:4,12`) and a copy-pasted loading scaffold across five routes round it out.
