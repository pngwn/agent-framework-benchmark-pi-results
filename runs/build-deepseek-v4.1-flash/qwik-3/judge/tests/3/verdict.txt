## Review: test quality

The app under review (`app/`) contains **no tests of its own** — confirmed both by the measured facts (`testLoc: 0`, `tests.files: 0`, no runner in `devDependencies`) and by reading the code: there is no `test` script in `app/package.json:6-20`, no Vitest/Playwright/Qwik test harness installed (`app/package.json:22-41`), and no test files anywhere under `app/src/`. The agent shipped purely against the acceptance suite in `tests/` and added nothing that would survive its removal.

### Where the risk actually lives (all unguarded)

Reading the riskiest code, these are the places where a refactor after the acceptance suite is retired would let real bugs through:

- **The entire data layer** — `app/src/lib/api.ts:33-50` (`idFromUrl` regex URL parsing, `englishName`, `latestFlavor` whitespace collapse), `app/src/lib/api.ts:139-176` (generation/type → species mapping with the `id > 10000` alternate-form exclusion, slot ordering with a `?? current.length + 1` fallback, and a duplicate-type guard), `app/src/lib/api.ts:213-231` (`cardsFromPokemonRefs` dedupe + hidden-ability flagging), `app/src/lib/api.ts:351-365` (per-method move dedupe with min-level selection — genuinely subtle logic where the "wrong" entry can win a refactor), and `app/src/lib/api.ts:406-417` (the `METHOD_ORDER`-then-alphabetical table ordering).
- **Client-side sorting invariants** — `app/src/components/MoveTables.tsx:24-26` returns `1` for null values *ignoring* `direction`, which is exactly what makes "missing values sort last in both directions" work. This is an invariant that looks like a bug to a well-meaning cleanup ("shouldn't the factor apply here?") and would be broken silently. Nothing in `app/` would catch that.
- **URL/filter state** — `app/src/routes/index.tsx:30-42` (popstate sync), `app/src/routes/index.tsx:14-21` (`buildHomeUrl` omitting empty/default params), and `app/src/routes/index.tsx:44-125` (page clamping, reset-to-page-1 on filter change). Notably, the page uses raw `window.history.pushState/replaceState` instead of Qwik City's `useNavigate` (`app/src/routes/index.tsx:60-66`), passing `window.history.state` through to keep the router's state object alive — a fragile coupling to Qwik City SPA-router internals that back/forward navigation exercises and nothing verifies. The acceptance tests don't cover back/forward either.
- **Caching semantics** — `app/src/lib/api.ts:70-77` evicts a failed promise from the cache so a transient API 500 isn't cached for the process lifetime. Deleting that two-line `catch` block in a refactor would poison the in-memory cache permanently and no test would notice until production.
- **Error/not-found paths** — `status(404)` in each route loader (`app/src/routes/moves/[name]/index.tsx:10`, `app/src/routes/[...slug]/index.tsx:5-6`) and the invalid-`?game=` fallback at `app/src/lib/api.ts:346-348`; plus unhandled non-404 fetch errors (`app/src/lib/api.ts:65-67`) which currently surface as a framework 500 page.
- **Display formatting** — `app/src/lib/format.ts:1-13` (`humanize`, `dexNumber` padding, em-dash for missing values) and the `toFixed(1)` height/weight math at `app/src/lib/api.ts:397-398`. All pure functions, trivially unit-testable, untested.

One latent divergence worth flagging: `app/src/lib/api.ts:286-288` sorts a type's moves by the *humanized label* via `localeCompare`, while the spec says "sorted alphabetically by name" — hyphen vs space handling can order these differently for names like `farfetch-d-slash`. That's precisely the kind of subtle bug an in-app unit test of the sort key would have surfaced.
