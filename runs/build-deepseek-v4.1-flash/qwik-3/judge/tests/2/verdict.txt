## Review — Test quality

**The app contains zero tests of its own.** There is no test runner in `app/package.json` (scripts at `app/package.json:6-25` are build/serve/lint/fmt only), no `vitest`/`playwright`/`@builder.io/qwik/testing` anywhere in `app/`'s devDependencies, and no `*.spec.*` / `*.test.*` files under `app/src/`. The measured facts agree (`tests: { files: 0, cases: 0 }`). This is not a Qwik limitation: the framework's current guidance is `npm run qwik add vitest` with `@builder.io/qwik/testing`'s `createDOM` for component tests (qwik.dev/docs/integrations/vitest), and the pure-logic modules here (`src/lib/format.ts`, `src/lib/api.ts` helpers, `MoveTables.tsx` comparator) are trivially unit-testable.

That's a real gap, because the risky surface is large: this app is mostly data transformation over raw PokeAPI payloads, plus URL-state and a hand-rolled sortable table. Once the acceptance suite in `tests/` is no longer the only guard, any refactor of `src/lib/api.ts` is flying blind.

### What isn't tested, and what bugs that could hide

- **Filtering/search/pagination math** — `app/src/routes/index.tsx:53-61`: case-insensitive substring match on the *humanized* name, type/generation filters, page clamp (`Math.min(Math.max(1, page.value), totalPages)`) and slice at `:62-63`. A refactor that matches against the raw API name (`mr-mime` vs `Mr Mime`) or forgets the clamp (empty results → `page=999`) would slip through.
- **URL state building** — `app/src/routes/index.tsx:20-29` `buildHomeUrl` omits defaults/`page=1`; the popstate re-sync task at `:35-46`. Regressions: query params leaking into every link (`/?page=1&…`), back/forward desyncing the selects from the URL.
- **`latestFlavor`** — `app/src/lib/api.ts:51-58`: "last English entry" + whitespace collapse (`\n`, `\f`). It returns `null` if the *last* English entry has empty `flavor_text` even when earlier English entries have text — a plausible latent bug no test would currently catch. Same pattern for species, moves, and the move/ability effect fallback chain at `:226-228`.
- **Alternate-form exclusion** — the `id > 10000` / `species.byId.has(id)` guard is repeated in three places (`app/src/lib/api.ts:162`, `:171`, `:209`), not centralized. Dropping or weakening one copy re-admits Mega Evolutions to exactly one list — a silent data bug.
- **Table sort comparator** — `app/src/components/MoveTables.tsx:24-35`: the "missing values sort last in *both* directions" rule is encoded by returning before applying `factor`; anyone "simplifying" that comparator breaks spec-mandated behaviour with no failing test. Default ordering (level-then-name, `:47-52`) likewise.
- **Move-method ordering comparator** — `app/src/lib/api.ts:414-421`: the `if (ai !== -1 || bi !== -1)` branch with the `999` sentinel is subtle and easy to break; spec mandates `Level Up, Machine, Egg, Tutor, then alphabetical`.
- **Level-up min-level merge** — `app/src/lib/api.ts:373-381`: picking the lowest `level_learned_at` per move/method. Swapping `<` for `>` shows the wrong level on every Pokémon page.
- **`fetchJson` caching/error semantics** — `app/src/lib/api.ts:64-80`: 404→`null` is cached forever, non-OK throws and the cache entry is evicted on rejection. A refactor that caches the rejected promise (or stops deleting on error) turns one transient API hiccup into a permanently broken page.
- **Evolution tree recursion** — `app/src/lib/api.ts:324-328`: branching chains (Eevee) are rendered from this nested structure; an infinite-depth or malformed chain currently has no guard and no test.
- **Number formatting** — `app/src/lib/format.ts:1-17` (`humanize`, `dexNumber` `#0025`, `displayNumber` `—`), height/weight division at `app/src/lib/api.ts:436-437`, stat total at `:448`.

The only thing standing between these and production is the acceptance suite, which lives outside `app/` and exercises rendered pages against live data — it will not catch a unit-level regression introduced mid-refactor before CI, and it isn't owned by this PR.
