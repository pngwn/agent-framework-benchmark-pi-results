## Review: forward-thinking

The app is a Qwik City 1.20.3 Pokédex — and I verified that 1.20.3, released 2026-10-25 (days before today), is the **current stable line** on npm; Qwik 2.0 exists only as RC/beta (`@qwik.dev/core@2.0.0-rc.4`, renamed packages, requires Vite 8). So building on `@builder.io/qwik@^1.20.3` is the right call, not a legacy choice. API usage is otherwise solidly current: `routeLoader$` with `status(404)`, `resolveValue` in `DocumentHead`, `useSignal`, `useNavigate`, `QwikCityProvider`/`RouterOutlet`, and the node-server adapter.

The two things that will not age well:

1. **The home page hand-rolls client-side navigation** (`app/src/routes/index.tsx:69,86,108,141,158` — raw `window.history.pushState/replaceState`, `preventDefault` on pagination anchors, and a `popstate` listener in `useVisibleTask$` at `:31-41`). This fights the Qwik City SPA router: the router's qwikloader never sees these navigations, route loaders never re-run, and `useLocation` (which is reactive to router navigations) is bypassed — hence the manual `popstate` re-sync hack. The Pokémon page does it the idiomatic way (`navigate(url.pathname + url.search + url.hash)`, `app/src/routes/pokemon/[name]/index.tsx:108-114`), which proves the pattern was known and just not applied on the home route. When the Qwik 2 router lands (its RC is already changing SPA navigation internals), this is exactly the code that breaks.

2. **The API boundary is `any`-typed** (`app/src/lib/api.ts:48,52,107,202,324,349,424`, plus `(type: any)` callbacks in routes) despite well-defined outbound types like `MoveRow`/`HomeCard`. Upstream PokeAPI shape changes would surface as runtime `undefined`s rather than type errors.

Dependencies are lean — zero runtime deps, framework at the latest stable — but carry starter-template dead weight (`undici: "*"`, `typescript-plugin-css-modules: "latest"` that the tsconfig comment itself says to delete, `@types/node@20` under a Node 24 runtime, TS 5.4.5 pinned from 2024). Data access is commendably centralized behind `src/lib/api.ts`, and the untouched generated boilerplate (`entry.*`, `root.tsx`, `router-head`, `adapters/`) means a framework upgrade regenerates cleanly.
