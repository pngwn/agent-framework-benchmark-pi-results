## Scenario walkthroughs

1. **Remove Abilities** — delete `app/src/routes/abilities/` (self-contained route dir), then three scattered edits: the Abilities section in `app/src/routes/pokemon/[name]/index.tsx:82-95`, the `getAbilityPage` function plus the `abilities:` block built inside `getPokemonPage` (`app/src/lib/api.ts:247-260`, `:416-425`), and `.abilities-list` in `global.css:497`. The nav (`app/src/routes/layout.tsx:13-15`) has no Abilities link, so nothing dangles there. A handful of scattered edits, not a clean delete.

2. **Sprite bug fix** — every card list funnels through two server-side builders: `cardsFromPokemonRefs` (`app/src/lib/api.ts:201-217`, feeds move/ability/type pages) and `loadHomeIndex` (`:160-188`, feeds home), both calling `spriteUrl` (`:60`). The components just render `card.sprite` (`components/ui.tsx:20,42`). One fix in `api.ts` covers every list. Caveat: `cardsFromPokemonRefs` implicitly assumes pokemon id == species id (used for both name lookup and sprite, `:208-212`), which is where such a bug would live; a name→species mapping fix stays inside that one function.

3. **Name sorting on every card list** — three of four lists render through `PokemonCards` (`components/ui.tsx:18-34`), so adding a sort there covers move/ability/type pages in one edit. Home is separate: `HomeCards` (`:36-56`) is a near-duplicate, and sorting interacts with pagination in `routes/index.tsx:48-58, 106-160`. Two components plus one route file.

4. **Items section** — copy the ~25-line route skeleton (`routeLoader$` + `status(404)` + `notFound` branch + `head`, cf. `routes/moves/[name]/index.tsx:6-18,40-43`) into `routes/items/[name]/index.tsx`, add one `getItemPage` next to `getMovePage` in `lib/api.ts`, and reuse `PokemonCards`, `NotFound`, `displayNumber`, `humanize`, and `cardsFromPokemonRefs` as-is. The route-file boilerplate is per-page but it's the framework's idiom, and the genuinely shared logic is genuinely shared.

5. **Data source / caching change** — `API_BASE_URL` is read in exactly one place (`lib/api.ts:5`), URL joining in `apiUrl` (`:53-57`), and the response cache in `fetchJson` (`:70-88`). The only wart is a second, separate cache map for version groups (`:303-308`) with its own globalThis key; changing cache rules means touching both, though both live in the same file.

## Judgement

This is a well-seamed codebase: server-only data access is confined to `lib/api.ts` behind `routeLoader$`, components receive small serializable props (`type`-only imports in `components/ui.tsx:2`), `MoveTables.tsx` owns its sorting, and `NotFound`/`format` helpers are shared rather than inlined. The deductions are real but local: `PokemonCards` vs `HomeCards` is copy-paste that makes card-level changes land twice; Abilities removal requires touching the Pokémon page and two spots in `api.ts`; `any` at the API boundary (`lib/api.ts` throughout, `(stat: any)` in `routes/pokemon/[name]/index.tsx:60,68,86,90`) erodes the safety of component edits; and one 668-line global stylesheet means every UI change crosses the same file.
