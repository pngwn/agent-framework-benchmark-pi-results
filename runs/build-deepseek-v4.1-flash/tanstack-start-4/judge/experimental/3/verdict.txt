I've reviewed the app against TanStack Start's current stable release (1.0, declared stable 2026-10-13). Here's what I found.

**What the app uses.** Every import in `app/src` is framework core: file-based routes (`createFileRoute`, `createRootRoute`), `Link`/`Outlet`/`useNavigate`, `HeadContent`/`Scripts`, `head` route option, and `createServerFn().validator().handler()` for the data layer (`app/src/lib/data.functions.ts:1-28`). The root shell uses `shellComponent` (`app/src/routes/__root.tsx:12`), the documented replacement for the older exported-`RootDocument` convention (added in TanStack/router PR #4528, June 2025, used in the official `start-basic` example on `main`). Production serving uses `srvx serve --prod` against the standard (non-Nitro) Vite build (`app/package.json:11`), which is exactly the pattern TanStack's own examples adopted in PR #5915 (Nov 2025) and the hosting guide documents.

**What it deliberately avoids.** Zero `unstable_`/`experimental_` names, zero plugin flags (`app/vite.config.ts:7` is a bare `tanstackStart()`), and none of the framework's still-experimental corners: no RSC, no static/server-fn build-time caching, no streaming, no `strict: false`, no `generateFunctionId` (the one API the current server-functions guide labels experimental), no Nitro, no middleware/`start.ts` (Start installs the CSRF middleware automatically when `start.ts` is absent, per the guide). The server-only fetch code is confined to `app/src/lib/api.server.ts`, imported solely by the server-fn wrapper module — the exact `.server.ts` / `.functions.ts` split the docs recommend.

**The one structural caveat.** TanStack Start's APIs became 1.0-stable only on 2026-10-13 — 17 days before today — so the whole data layer rests on "recently stable" rather than "long-stable" ground. The app mitigates this well: exact version pins (`app/package.json:14-15`) on the stable line (`react-start` 1.169.4 pairs with `react-router` 1.170.46, matching the framework's own dependency skew), Vite 8 (which Start 1.0 requires; Vite 7 is no longer supported), and React 19.3.1 (stable since Oct 2025). The only mildly aggressive devDependency is TypeScript 7.0.2, the native Go port — stable since 2026-07-08, dev-only, and `build` never runs `tsc`, so it can't break the shipped artifact.
