## Review

**Verified against current TanStack Start (stable `1.169`, released per the official "Migrate from the Release Candidate" doc) and TanStack Router docs.** Key confirmations: `.validator()` is now the only server-function validator method (`inputValidator()` was deprecated in `1.168` and removed in stable — PR #7566, migration doc); `shellComponent` replaced the old `RootDocument`/`rootComponent` pattern (PR #4528, merged 2025-06); `HeadContent`/`Scripts` correctly come from `@tanstack/react-router` (moved there in `1.105`); stable Start **requires Vite 8**, which the app pins (Vite 8 shipped March 2026); the official examples serve the prod build with `srvx` (PR #5915). The app's pinned pair `react-start@1.169.4` + `react-router@1.170.46` is exactly the matched set published in the 1.169.4 release notes.

The app is genuinely current: `createServerFn().validator().handler()` (data.functions.ts:11–32), `shellComponent` (__root.tsx:14), `head` meta/links API (__root.tsx:9–13), `validateSearch`/`loaderDeps`/`Route.useLoaderData()`/`Route.useSearch()` hooks (routes/index.tsx:26–40, pokemon.$name.tsx:19–20), splat route `/$` for not-found (routes/$.tsx), Vite 8's native `resolve.tsconfigPaths` (vite.config.ts:6). React 19.3, TS 7 (native port), srvx prod server — all 2026-current.

Where it falls short of "point others at it": not-found handling is hand-rolled (each loader returns `null`, four components branch to `<NotFound />` instead of throwing `notFound()`, which would also give HTTP 404); the `#moves` hash scroll is hand-rolled with `useEffect`+`requestAnimationFrame` even though the router scrolls hashes out of the box (`hashScrollIntoView` defaults `true`); validators are no-op identity casts; the upstream PokeAPI JSON is typed `any` end-to-end; and `srvx`, which `npm start` needs at runtime, sits in `devDependencies`.
