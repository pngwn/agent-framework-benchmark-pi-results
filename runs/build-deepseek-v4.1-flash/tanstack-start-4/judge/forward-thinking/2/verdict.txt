## Review: `app/` (TanStack Start Pokédex) — forward-thinking

**Currency verification (2026-10-30):** `@tanstack/react-router@1.170.46` and `@tanstack/react-start@1.169.4` are exactly the npm `latest` dist-tags (both last published 2026-10-22, per registry.npmjs.org). `typescript@7.0.2` is npm `latest` (the native compiler). `srvx@1.0.8` is npm `latest` (published 2026-10-27), and its CLI (`serve --prod --entry --static`) is the documented pattern for running TanStack Start's Vite build output (`dist/server/server.js` + `dist/client`) on a Node server — the current docs' `node-server` hosting path, not the removed Nitro `.output` convention. `shellComponent` on `createRootRoute` is the current root API (tanstack.com/start routing guide + official TanStack devtools example), and `createServerFn().validator().handler()` with `.server.ts`/`.functions.ts` file organization matches the current `start-core/server-functions` skill.

**Scores**

- **latest_apis — 5.** Nothing legacy-era anywhere: `shellComponent` + `HeadContent`/`Scripts` (`app/src/routes/__root.tsx:15,24-40`), `getRouter()` export with `scrollRestoration` (`app/src/router.tsx:4-10`), `createFileRoute` with `validateSearch` + `loaderDeps` (`app/src/routes/index.tsx:29-37`), typed `Route.useLoaderData()`/`Route.useSearch()` hooks, `?url` CSS import (`__root.tsx:3`), splat `$.tsx` for not-found, GET server fns (preloadable). Deps are pinned to the exact current latest, including post-training-data releases (TS 7 native, Vite 8/rolldown, srvx 1.x).

- **platform — 4.** Fetch-first API client with proper 404 draining (`app/src/lib/api.server.ts:58-71`), native `type="search"`/`<select>`/`<label>`, `caption`+`aria-sort` tables, CSS custom properties throughout, zero polyfills. Deductions: hand-rolled regex URL parsing instead of `new URL()` (`app/src/lib/format.ts:19`), no `AbortController`/timeout on the client (`api.server.ts:58-66`), and a hand-rolled `requestAnimationFrame` hash-scroll effect (`app/src/routes/pokemon.$name.tsx:47-54`) that duplicates router-core's built-in `handleHashScroll`, which is present and working in 1.170.x.

- **dependencies — 5.** Four runtime deps, all current and all needed; no state lib, no HTTP lib, no CSS framework. `srvx` (zero-dependency, h3/unjs-maintained) is the leanest possible prod-server for Start's fetch-handler output. Nits: `srvx` is a `devDependency` though `npm start` needs it at runtime, and the `#/*` / `@/*` alias config (`app/package.json:5-7`, `app/tsconfig.json:8-10`) is declared but unused — every import is relative.

- **churn_resistance — 4.** All API access lives behind one module (`api.server.ts`) producing typed view models (`model.ts`), with routes consuming only those types — a framework upgrade touches `router.tsx`/`__root.tsx` and nothing else; config is centralized (`vite.config.ts`, `router.tsx`, `API_BASE_URL` at `api.server.ts:25`). Held back from a 5 by: `type Json = any` making the entire data layer untyped (`api.server.ts:25`), no-op pass-through `.validator((d) => d)` on every server fn (`app/src/lib/data.functions.ts:11`), not-found handled by null-returning loaders + per-route `<NotFound/>` renders (`pokemon.$name.tsx:56`, `moves.$name.tsx:17`, `abilities.$name.tsx:16`, `types.$name.tsx:16`) instead of the current `notFound()` helper (so no 404 status, and the root `notFoundComponent` at `__root.tsx:16` is effectively dead next to the `$.tsx` splat), and a vestigial `found: true` field (`app/src/lib/model.ts:58,80,93,106`) nothing reads.

**Findings**

1. **medium** — `app/src/lib/api.server.ts:25` — `type Json = any` types nothing; API shape changes become runtime `undefined` bugs, not compile errors. Suggestion: minimal `interface` per PokeAPI resource at this single boundary.
2. **medium** — `app/src/lib/data.functions.ts:11` — `.validator((data) => data)` is a no-op on all six server fns; either give it a real schema (zod) or drop it and annotate the handler input.
3. **medium** — `app/src/routes/pokemon.$name.tsx:56` (also `moves/abilities/types.$name`) — not-found is rendered from a null loaderData instead of `throw notFound()`, so no HTTP 404, four copies of the `?? 'Not found'` head fallback, and a dead root `notFoundComponent`.
4. **low** — `app/src/routes/pokemon.$name.tsx:47` — rAF-based hash scroll reimplements router-core's built-in hash scrolling and only fires on mount.
5. **low** — `app/src/lib/api.server.ts:58` — fetch without `AbortController`/timeout; a stalled upstream stalls SSR forever.
6. **low** — `app/src/lib/format.ts:19` — regex ID extraction where `new URL(url).pathname` is the platform tool.
7. **low** — `app/package.json:21` — `srvx` is required by the production `start` script but sits in `devDependencies`.
8. **low** — `.gitignore:1-3` — `app/dist` isn't ignored, so build output can get committed.
9. **low** — `app/package.json:5-7` / `app/tsconfig.json:8-10` — `#/*` and `@/*` alias config is unused (all imports relative); remove it.
10. **low** — `app/src/lib/model.ts:58` — `found: true` in four view models is never read; delete the field.
