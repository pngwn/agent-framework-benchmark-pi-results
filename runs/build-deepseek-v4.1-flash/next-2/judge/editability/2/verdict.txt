## Review

I've read the full app (`app/lib/api.js`, `app/lib/cards.js`, `app/lib/format.js`, all five route trees, and all five components) and checked the Next.js 16 route-segment-config docs, since the app is on `next@16.4.3`.

**Framework currency check:** the app correctly awaits `params`/`searchParams` as Promises (e.g. `app/pokemon/[name]/page.jsx:66`), uses `generateMetadata` per route, keeps client components (`Filters`, `MovesSection`) isolated from server data fetching, and centralizes all HTTP behind `lib/api.js`. `export const dynamic = 'force-dynamic'` on every route is the legacy caching model in Next 16 — still fully supported when Cache Components is off (which it is here, `next.config.mjs` only sets `reactStrictMode`), but it's repeated on all 6 route files and every route would need revisiting if the project adopted Cache Components. Not a defect today.

**Scenarios worked through:**

1. **Remove Abilities** — `grep` shows `/abilities` referenced only in `app/pokemon/[name]/page.jsx:249-257` (one self-contained `<Section>`); the nav in `app/layout.jsx:20-23` has no Abilities link, and `lib/api.js:200` (`getAbility`) is one deletable function. Delete a directory, one section, one helper.
2. **Sprite bug** — the sprite/species resolution logic exists twice: `app/lib/cards.js:27-34` (`buildPokemonCards`) and inline in `app/page.jsx:80-96` (home page builds its own cards because it also needs types). A fix lands in `lib/cards.js` but the home page copy must be fixed separately — two places, and nothing (type check, comment, shared helper) warns you they must stay in sync.
3. **Sort by name** — three lists go through `buildPokemonCards` (returns entries sorted by id, `app/lib/cards.js:21`), so a sort there covers moves/abilities/types; the home page's inline list (`app/page.jsx:79`) needs its own edit. If sorting must be a UI control, the count + `<ul class="card-grid">` + empty-message block is copy-pasted verbatim in `app/moves/[name]/page.jsx:78-90`, `app/abilities/[name]/page.jsx:43-55` and `app/types/[name]/page.jsx:70-82`.
4. **Items section** — infra is reusable: generic `api()`/`mapLimit` (`app/lib/api.js:59,83`), `Section`, `NotFound`, `TypeBadge`, `displayValue`/`humanize`. You'd add `getItem` to `lib/api.js` and two route files. The one real copy risk is `MovesSection.jsx:38-45`, which hardcodes the move-table column list — a different-shaped table means prop-izing that component or copying it.
5. **Data source** — base URL and fetch/cache rules live entirely in `app/lib/api.js:4-6` (`apiBase()`) and `:35` (`cache: 'no-store'`), with the promise cache at `:51`. No component constructs an API URL. Excellent centralization; only the per-route `dynamic` exports are a second (minor) surface.
