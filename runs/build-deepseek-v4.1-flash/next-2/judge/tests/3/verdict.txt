## Test quality review

**The agent wrote no tests of its own.** `app/package.json` defines only `dev`, `build` and `start` (app/package.json:5-11), there is no test runner in `devDependencies`, and a repo-wide grep for `describe(`/`expect(`/`.test.` inside `app/` finds nothing. The measured facts agree: `tests.files: 0`, `runner: []`. So this review's value is in mapping what the acceptance suite does *not* guard.

### What's risky and unguarded

The app is thin but its logic is concentrated in exactly the places that break during refactors:

1. **Home filtering + pagination** (`app/app/page.jsx:63-79`) — three filter predicates (humanized-name substring, type-ID set, generation-ID set), 48-per-page slicing, page clamping, and `Page <n> of <total>` math. A refactor that swaps `humanize(species.name).toLowerCase()` (line 67) for the raw API name would still pass most snapshot-y checks while silently breaking searches like "mr m" — that's the classic bug this code hides.
2. **Move-table sorting** (`app/components/MovesSection.jsx:8-26`, default ordering in `app/app/pokemon/[name]/page.jsx:100-108`) — missing-values-sort-last in *both* directions depends on the missing check running before the direction negation (lines 11-14). Move that check below the flip and descending sort puts `—` first; nothing would catch it. `aria-sort` toggling (lines 68-77) is likewise regression-prone.
3. **Formatting helpers** (`app/lib/format.js`) — `formatDecimal` divides by 10 (line 45: the API gives decimetres/hectograms), `latestEnglishFlavor` must take the *last* English entry (line 28), `dexNumber` zero-pads to 4 (line 39). All are one-character mistakes away from wrong output, and all are pure functions that would be trivially testable.
4. **URL state** (`app/components/Filters.jsx:12-27`) — debounce, `page` deletion on filter change, `replace` vs `push` semantics, and building URLs from `window.location.search` (line 8, which can be stale mid-transition). The acceptance tests click through happy paths; regressions in edge interactions (typing while navigating, e.g.) slip through.
5. **The data layer** (`app/lib/api.js`) — an unbounded promise cache (lines 50-53) that also caches 404s as `null` forever, module-level singletons (`speciesListPromise`, `typesPromise`, …) with reset-on-error logic. This is the code most likely to be refactored, and it has zero characterization tests. `buildPokemonCards` (`app/lib/cards.js:21-35`) maps Pokémon refs to *species* names — the "deoxys-normal → /pokemon/deoxys" rule — an invariant nothing pins down.
6. **Error and not-found paths** — `requestJson` throws on non-OK (api.js:41-44) and there is no `error.jsx` boundary, so an API hiccup renders Next's default crash page with none of the required landmarks. Not-found is handled (NotFound component, `[...slug]` catch-all) but untested beyond what the harness checks.

The acceptance tests in `tests/` are decent, but they're the *harness's*, not the app's, and they exercise the built product end-to-end; unit-level invariants (sort comparator, humanize, pagination math) have no fast guard at all.
