## Review: `app/` (Pokédex, Next.js)

**Framework currency.** The app is pinned to `next@16.4.3` / `react@19.3.1` — exactly the current stable line (16.4 shipped 2026-10-06). It correctly adopts Next 16's breaking changes: `params`/`searchParams` are awaited as promises (`app/app/page.jsx:38`, `app/app/pokemon/[name]/page.jsx:100`), and `generateMetadata` is used per-route.

The one significant "yesterday's model" choice is the rendering/caching strategy. All seven route files carry `export const dynamic = 'force-dynamic'` (e.g. `app/app/page.jsx:14`, `app/app/types/[name]/page.jsx:9`, `app/app/[...slug]/page.jsx:3`) and every fetch sets `cache: 'no-store'` (`app/lib/api.js:43`). That's the segment-config escape hatch that Vercel's own "Journey with Caching" post said they'd keep only for backward compatibility; as of Next 16.4, Cache Components is recommended for *every* app and is what `create-next-app` now generates, and it becomes the default in Next 17 — where `export const dynamic` is *incompatible* (vercel/next.js discussion #84894, nextjs.org/blog/next-16-4). Since data fetching is dynamic-by-default under Cache Components, the semantically-required always-fresh behavior could have been achieved with `cacheComponents: true` and *less* code. When Next 17 lands, this upgrade touches all 7 routes plus the fetch layer.

**Platform & dependencies.** Strong: `URL` parsing (`app/lib/api.js:45`), `URLSearchParams` for query building (`app/app/page.jsx:96`), an inline `data:` SVG placeholder instead of an asset request (`app/lib/format.js:2`), native lazy images with dimensions (`app/components/PokemonCard.jsx:26`), tokens-driven CSS custom properties (`app/app/globals.css:11`). Zero non-framework dependencies; the debounce and the `mapLimit` concurrency helper are hand-rolled and lean.

**Churn resistance.** Data access is genuinely well-isolated — everything flows through `lib/api.js` / `lib/format.js` / `lib/cards.js`, so an API-shape change or framework swap has one seam. But there's drift-prone duplication: `single()` copy-pasted in two pages (`app/app/page.jsx:21`, `app/app/pokemon/[name]/page.jsx:29`), an inline re-implementation of the `idFromUrl` regex (`app/app/abilities/[name]/page.jsx:29` vs `lib/format.js:48`), and two different URL-param patterns (`window.location.search` in `app/components/Filters.jsx:7` vs the correct `useSearchParams()` in `app/components/MovesSection.jsx:31`). The framework's `notFound()` + `app/not-found.jsx` convention is bypassed in favor of a hand-rolled catch-all + inline component, and there's no `error.jsx`/`loading.jsx` despite multi-waterfall dynamic fetches. The codebase is entirely untyped at an external-JSON boundary.
