## Review: `app/` — Gracile 0.11 (with Lit), Pokédex

I read `SPEC.md`, every source file under `app/src/` (routes, `lib/`, `document.js`, CSS), and verified the framework contract against the current stable release: `@gracile/gracile` 0.11.0 **is** the current stable on npm (published ~6 months ago), and the app pins exactly that. Its `server.js` is a near-verbatim copy of the official "minimal server (Express)" starter (`nodeAdapter`, `getClientBuildPath`, `dist/server/entrypoint.js` handler), and the `document.ts` annotated example on gracile.js.org matches `app/src/document.js`'s shape (`document` export consuming `context.props.GET`). The `*.client.js` per-route client-script convention, `defineRoute` with `handler`/`document`/`template`, and `output: 'server'` are all current-stable idioms. The framework usage is not the problem; the internal duplication is.

### How the five scenarios actually play out

**1. Remove Abilities.** Delete `app/src/routes/abilities/` (routes are self-contained; the nav in `document.js:20-23` doesn't link to abilities). But you must also strip the Abilities section from the Pokémon page (`routes/pokemon/[name].js:342-351`, plus its data prep at `:260-270`), and clean up the now-dead `getAbility` (`lib/api.js:141`), the `hidden` card option (`lib/components.js:23,38`, used only at `routes/abilities/[name].js:74`), and `.hidden-ability` CSS (`document.css:209`). A handful of small, findable edits — the routes themselves never entangle.

**2. Sprite bug (Deoxys-type species).** Cards all render through one seam: `pokemonCardList` → `pokemonCard` (`lib/components.js:22-39`) → `spriteUrl` (`lib/api.js:245`). Home, Moves "Learned by", Abilities "Pokémon" and Type "Pokémon" lists all funnel through `uniqueSpeciesFromPokemonReferences`/`getSpeciesIndex`, so a fix in one function covers every list. The only second sprite site is the artwork fallback on the detail page (`routes/pokemon/[name].js:234-236`), which is a separate concern (artwork, not cards).

**3. Sort cards by name.** The data-order seam is single (`lib/api.js:242` hard-sorts by dex id for the three secondary lists; `:121` for home), but the user-facing section — `<p class="count-line">N Pokémon</p>` + `pokemonCardList` — is copy-pasted in three templates (`moves/[name].js:83-84`, `abilities/[name].js:73-74`, `types/[name].js:112-113`) and rendered differently on home. A sort control + URL param means editing 4 handlers + 4 templates.

**4. Add `/items` shaped like Moves.** Reusable directly: `document` wiring, `getRecord`/`englishName`/`englishEffect`/`latestEnglishFlavorText`/`displayValue`/`humanize` (`lib/api.js`), `typeBadgeLink`/`pokemonCardList` (`lib/components.js`). You'd copy the ~30-line route skeleton: the `BUILDING()` guard, the try/catch → `{ notFound: true }` shape, and the "Not found" template block — boilerplate already duplicated in four existing routes.

**5. Change API base URL / caching rules.** Everything lives in one file: `API_BASE` (`lib/api.js:1`), URL building (`:13-25`), the promise-cache (`:3,31-43`), and `spriteUrl` (`:245-247`). Client scripts fetch same-origin HTML and know nothing about the API. One-file change.

### Scores

**removability — 4.** Routes are file-contained and the nav is centralized (`document.js:20-23`), but removing a cross-linked feature drags in the Pokémon page section (`routes/pokemon/[name].js:342`) and leaves three small dead spots (`lib/api.js:141`, `lib/components.js:38`, `document.css:209`) unless you grep for them.

**changeability — 4.** Card rendering and species normalization are single seams (`components.js:30`, `api.js:226-243`), so the classic card bugs fix in one place across all four lists. Deduction: list-section markup and error/not-found boilerplate are repeated, so page-level behaviour changes touch 4 files.

**coupling — 4.** Handlers normalize raw API records into view-model props before templates (e.g. `routes/moves/[name].js:29-45`); client scripts are cleanly separate vanilla-DOM files with contracts limited to IDs/attributes (`(home).client.js:32` ↔ `(home).js:126`, `pokemon/[name].client.js:36` ↔ `.move-table th button`); components consume a tiny species shape, not API internals. Deductions: those magic-ID contracts are implicit, `lib/api.js` is one grab-bag, and the `GRACILE_BUILD` env convention spans `package.json:7` plus six route files.

**abstraction_design — 3.** The real variation in the app (cards with/without types, with/without hidden badge) is captured by two narrow options rather than flag creep (`components.js:22-38`) — good. But route-level structure is copy-paste: `BUILDING` guard ×6, not-found template ×4, count-line pattern ×3, plus dead exports (`api.js:27,222`) and an empty `src/features/` placeholder. Some copy-paste; no over-generalization.
