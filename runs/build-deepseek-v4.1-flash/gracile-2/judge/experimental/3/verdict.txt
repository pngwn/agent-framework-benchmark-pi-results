## Review notes

**Framework version check (verified, not assumed):** `@gracile/gracile` 0.11.0 is the current stable release — npm dist-tags show `latest: 0.11.0` and `next: 0.11.1-next.2` (registry.npmjs.org/@gracile/gracile, socket.dev). The app pins it exactly (no caret) and does **not** use the `-next` channel — `app/package.json:13`, `app/package.json:7`.

**Experimental markers:** zero. The measured facts show `experimental: []`, and a grep for `unstable_` / `experimental_` / `beta` / `canary` across `app/` finds nothing but a literal npm script name (`app/package.json:10`). No `@gracile-labs/*` packages, no framework config flags marked experimental.

**What the app deliberately avoided (the interesting part):** Gracile's ecosystem has several explicitly-experimental pieces, and the app routes around all of them:

- `@gracile-labs/client-router` — npm README says *"Experimental. This is not well tested"* — not used. Instead the home page does search-as-you-type with plain `history`/`fetch`/`DOMParser` + `replaceWith` (`app/src/routes/(home).client.js:33-77`).
- `@gracile-labs/islands` — *"Experimental … its API may change"* — not used. Zero hydration, zero custom elements (measured `elements: 0`); only server-rendered Lit `html` templates (`app/src/lib/components.js:3-43`).
- Lit Web Components generally — the app uses `lit#html` for SSR templates only, and vanilla DOM for interactivity (table sorting in `app/src/routes/pokemon/[name].client.js:30-53`).
- JSX plugins (`@gracile-labs/vite-plugin-babel-jsx-to-literals` / `jsx-forge`) — not used; plain template literals.
- `@gracile/metadata` add-on (docs marked "under construction") — not used; `<title>` is hand-rolled in `app/src/document.js:8`.

**What the app does use** is the framework's core, documented surface: `defineRoute` with `handler`/`document`/`template` (`app/src/routes/(home).js:33-91`, `app/src/routes/404.js:5-15`), `html` from `@gracile/gracile/server-html` and the `route-template-outlet` element (`app/src/document.js:1,26`) — both still shown verbatim in the current gracile.js.org docs; the Node adapter `nodeAdapter(handler)` + `getClientBuildPath()` (`app/server.js:5,8,11`), which matches the official "Minimal server (Express)" starter pattern; the Vite plugin with `output: 'server'` (`app/vite.config.js:4`), matching the current "Modes: SPA, MPA, SSG, SSR, CSR" doc; and the `.client.js` route-script convention (`app/src/routes/(home).client.js`, `app/src/routes/pokemon/[name].client.js`).

**Residual risk (framework-level, not API-level):** Gracile is pre-1.0 and actively restructuring — split packages `@gracile/engine` 0.11.x and `@gracile/server` 0.7.6 (Apr 2026) are published alongside the umbrella package, so a future upgrade will likely involve migration. The exact pin mitigates surprise breakage.

**One non-standard convention:** `GRACILE_BUILD=1` (`app/package.json:7`) with a `BUILDING()` guard duplicated across six route files (`app/src/routes/(home).js:15,36`, `app/src/routes/pokemon/[name].js:23,162`, `app/src/routes/moves/[name].js:18,23`, `app/src/routes/abilities/[name].js:15,20`, `app/src/routes/types/index.js:7,12`, `app/src/routes/types/[name].js:13,33`) is an app-invented build-time fetch guard, not a documented framework API — and it borrows the framework's env-var namespace.
