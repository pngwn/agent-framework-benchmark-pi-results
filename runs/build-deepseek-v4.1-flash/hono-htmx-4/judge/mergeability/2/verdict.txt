So the pinned versions are current, not stale.

**Idiom.** This is genuinely idiomatic Hono + htmx: `hono/html` tagged templates with automatic escaping (the `${cond ? html\` selected\` : ''}` conditional-attribute idiom at `app/server.mjs:513` is straight from the hono/html docs), `app.notFound`/`app.onError` per the Hono skill's error-handling guidance, and htmx partial responses with `HX-Push-Url` (`app/server.mjs:492`, `:582`) plus `hx-target`/`hx-swap`/`hx-sync` (`:496`) in patterns matching the htmx docs (active-search debounce via `input changed delay:` — confirmed against 2.0.11 source that `changed` tracks the event target's value, so the form-level trigger works). The main departures are organizational, not framework-fighting: three hardcoded static routes instead of one middleware, and an 810-line `server.mjs` that ignores the skill's "organize large apps by feature with `app.route()`" best practice.

**Correctness.** A careful look found no XSS paths (hono/html escapes all interpolations, including attribute contexts), no missing 404 handling (NotFoundError → 404 for every named-resource route plus `app.notFound`), and the promise-based cache at `lib/api.mjs:28-34` correctly evicts on rejection, eliminating stampede/race concerns. Remaining issues are minor: the filter form double-fires on `<select>` changes (`input` + `change` triggers), the search term is matched untrimmed, `fetch` has no timeout, and move-detail loading fans out unbounded (cached afterward).

**Abstractions.** `lib/api.mjs` / `lib/format.mjs` have clean, earned boundaries and the one comment in the codebase explains the cache policy. But the species→card dedupe pipeline is written three times (`speciesCardsForRefs` plus hand-rolled loops in the abilities and types routes), and the shared helper carries an unused, speculative `hiddenBySpecies` option (including a function-value branch) — classic locally-fine/globally-messy drift.
