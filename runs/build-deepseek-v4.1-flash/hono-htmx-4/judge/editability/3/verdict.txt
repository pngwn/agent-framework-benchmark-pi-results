## Review summary

I read the full app: `app/server.mjs` (all six routes, the moves machinery and the Pokémon page composition in one 820-line file), `app/lib/api.mjs` (fetch + in-memory cache, one `API_BASE`), `app/lib/format.mjs` (pure formatters), `app/views/layout.mjs` (layout + shared card/badge/section components), `app/scripts/build.mjs` (copies htmx to `public/`).

Framework currency: Hono 4.13.14 is the current stable (v5 is still RC) — the app is on the latest release. htmx 4.0.0 exists since Aug 2026, but 2.x is deliberately kept as npm `latest` per the release announcement, so pinning `htmx.org@2.0.11` and using `hx-get`/`hx-target`/`hx-swap`/`hx-sync`/`hx-push-url` is current and idiomatic. The Hono skill's best practice of organizing larger apps with `app.route()` feature sub-apps is the one convention this app ignores.

The strong suits for editability: the API base URL, URL joining and the response cache live exclusively in `lib/api.mjs` (verified — no other file references `API_BASE` or calls `fetch`), and every Pokémon card in the app — home, moves, abilities, types — renders through a single `pokemonCard` component, so a sprite bug is fixed once. The weak suits: the species-refs → deduped/sorted card list pipeline is written three times (once as a helper, twice inline), the `NotFoundError` → 404-page catch is copy-pasted in five handlers, and route/domain/page code all share one file, so "remove a feature" means several scattered edits inside a monolith rather than a clean delete.
