## Review: forward-thinking

**Stack currency.** The app pins exactly the current stable releases of all three of its dependencies: `hono@4.13.14` (latest stable as of 2026-10-25; v5 is only at RC), `@hono/node-server@2.1.5`, and `htmx.org@2.0.11` (latest, per npm registry). Every Hono API in use (`c.req.query/param/header`, `c.html`, `c.body(content, status, headers)`, `c.header`, `app.notFound`, `app.onError`, `serve`) matches the current reference in the Hono skill doc. Every htmx construct (`hx-get/hx-target/hx-swap="outerHTML"/hx-include/hx-trigger` with `delay:300ms`, `hx-push-url`) and the `HX-Push-Url` response header are current 2.x — notably it avoids the deprecated `HX-Push` header.

**Platform.** Native `fetch` with in-flight dedup (`app/src/api.mjs:44-66`), `URLSearchParams` for URL building (`app/src/render.mjs:96`), `Map`/`Set`, `replaceAll`, `localeCompare(..., {numeric:true})` (`app/src/views.mjs:270`), zero hand-written client JS (all interactivity via htmx attributes), CSS custom properties throughout plus `aspect-ratio` (`styles.css:412`) and `:focus-visible` (`styles.css:130`). Two platform lags: the `__dirname` via `fileURLToPath` shim (`app/server.mjs:24`) when `engines: >=24` ships `import.meta.dirname`, and no `AbortSignal.timeout` on outbound API fetches (`app/src/api.mjs:53`).

**Churn.** Data access is cleanly isolated behind one module (`src/api.mjs`) and templates are framework-agnostic HTML strings, so a framework upgrade mostly touches `server.mjs`. Against that: no types or JSDoc anywhere, manual `escapeHtml` sprinkled over ~50 interpolation sites instead of `hono/html`'s `html` tagged template (one missed call is an XSS hole), three exported `render*PageByName` wrappers that are dead code while `server.mjs` reimplements the same logic inline, hand-rolled static-asset serving instead of `serveStatic`, and htmx target selectors duplicated between server and views.
