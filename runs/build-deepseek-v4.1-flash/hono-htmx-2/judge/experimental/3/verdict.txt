## Review: experimentalness

The measured facts show zero `experimental` markers, and my reading of all six source files confirms it. The complete external API surface:

**Hono core (4.13.14, stable 4.x line):** `new Hono()`, `app.get`/`app.notFound`/`app.onError`, `c.req.query/param/header`, `c.html`/`c.body`/`c.header` — all long-stable core APIs, no middleware at all, nothing from Hono's `unstable_` namespace (`app/server.mjs:27,44,63,93,144-145`).

**@hono/node-server 2.1.5:** a single `serve({ fetch, port, hostname }, cb)` call (`app/server.mjs:147`). Version 2.1.5 is the current latest on npm; the v2.0.0 major was released 2026-04-21 — about six months before today — and the release notes explicitly state "the public API stays the same" (the major is a perf rewrite). So the API being used has been stable for years; only the version line is young.

**htmx.org 2.0.11 (current latest, 2.0 stable since Aug 2024):** only core attributes — `hx-get`, `hx-target`, `hx-swap`, `hx-push-url`, `hx-include`, `hx-trigger="input changed delay:300ms, change"` (`app/src/views.mjs:109-114`, `345-347`, `486-491`) and the documented `HX-Request`/`HX-Target`/`HX-Push-Url` header protocol (`app/server.mjs:48,127,133`). All stable since htmx 1.x and unchanged in 2.0.

**Node builtins:** `fs`, `path`, `module.createRequire` (stable since v12.2), `url.fileURLToPath` (stable since v10), global `fetch` (stable since Node 21; engines pin Node ≥24 in `app/package.json:9`). No cutting-edge JS (`Promise.withResolvers`, `Object.groupBy`, `toSorted`, etc. — grep came back empty), and the CSS is plain custom properties, no `:has()`, nesting, container queries, or new color functions.

In short: this app is maximally conservative. The only recent thing about it is that its Node adapter sits on the newest stable major, whose public API is identical to the previous major.
