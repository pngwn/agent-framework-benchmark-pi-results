## Review: test quality

The facts say it, and I confirmed it on the ground: `app/` contains **zero tests** — no test files (`grep` for `describe(|it(|test(|vitest|playwright|cypress` matches nothing), no runner or `test` script in `app/package.json:6-8` (only `build`/`start`), no test config. The only dependency is `nuxt` itself. Everything the acceptance suite covers works today; nothing the acceptance suite *doesn't* cover has any guard, and the app is dense with exactly the logic that breaks under refactor.

The riskiest untested logic, read in full:

- **Index build / data transformation** — `app/server/utils/pokeapi.ts:141-201` (`buildIndex`): 18-type filtering (`:105` exclusion set), species→generation mapping (`:181-188`), alternate-form exclusion `id > 10000` (`:193`, `:263`), slot ordering (`:196`), dex-number sort (`:200`). A refactor that flips one predicate silently corrupts every list page.
- **Name/text rules** — `humanize` (`:32-38`), `latestEnglishFlavor` (`:76-81`, "last" English entry — easy to break into "first"), `englishName` (`:67-71`). The humanized-vs-English-name distinction (`Mr Mime` cards vs `Mr. Mime` headings) is a one-character class of bug.
- **Card assembly** — `cardsFromRefs` dedup + dex sort (`:276-287`), hidden-ability aggregation (`:394-400`, `hidden.set(id, Boolean(hidden.get(id) || item.is_hidden))` — the OR-accumulate here is exactly what a careless rewrite to `item.is_hidden` would break).
- **Filter/pagination/URL state** — `app/pages/index.vue:82-98` (case-insensitive substring, type-slot match, generation match, 48/page math, page clamping), `:100-118` (`queryObject` omitting empty/default params, hand-rolled `searchString`), `:126-131` (200 ms debounce). URL-state code is triplicated between `pageUrl`, `replaceUrl` and the route watcher (`:142-156`) — prime refactor bait with no net.
- **Sortable tables** — `app/components/MoveMethodTable.vue:73-97`: missing-values-last in both directions, `aria-sort` flip, default Level-Up ordering (level then name) — pure comparator logic, the textbook candidate for unit tests, untested.
- **Move-section coupling** — `app/pages/pokemon/[name].vue:129-131` assumes `data.games` is sorted ascending by `order` (sorted server-side at `pokeapi.ts:319`) to pick "highest order" as default; method ordering `level-up/machine/egg/tutor` then alphabetical at `:145-156`. Cross-layer invariants like this are the first casualty of a data-layer refactor.
- **Not-found paths** — `{ notFound: true }` returns at `pokeapi.ts:261`, `:383`, `:408`, `:434` and their consumption at `app/pages/pokemon/[name].vue:2` / `app/pages/moves/[name].vue:2` etc.; a changed return shape would render empty pages instead of 404s.

I also spotted a live latent bug that a single URL-state test would have caught: `app/pages/index.vue:150-152` clamps `pageValue` when `totalPages` shrinks but never rewrites the URL, so loading `/?page=999&q=z` displays page 1 while the URL still claims page 999 — a spec violation ("Filter state lives in the URL query") with no guard.
