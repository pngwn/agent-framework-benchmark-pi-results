# Review: forward-thinking — Nuxt Pokédex app

**Framework currency check.** `app/package.json` pins `nuxt@4.6.3` — the newest patch (2026-10-27) of the newest stable minor, Nuxt 4.6 (2026-10-05), per the official releases feed and the 4.6 announcement (nuxt.com/blog, 2026-10-05). So the app is running on the current release, not a training-data-era one.

**What holds up well.** All PokeAPI access is funneled through one module (`app/server/utils/pokeapi.ts`) with thin Nitro routes delegating to it (`app/server/api/pokemon/[name].get.ts:1-6`), so API-shape changes touch one file. Data loading uses the current primitives — `useFetch` with reactive URLs, `useHead`, `definePageMeta`, `<script setup>` — and the server uses the platform's global `fetch` with promise-level in-memory caching rather than a fetch library (`app/server/utils/pokeapi.ts:30,58-75`). Dependencies are exactly one: `nuxt`. CSS is hand-written around the design tokens, using custom properties, grid and `:focus-visible`.

**What will churn.** (1) The API layer is typed in the util (`PokemonIndexEntry`, `PokedexIndex` at `app/server/utils/pokeapi.ts:9-25`) but that typing stops dead at the HTTP boundary — every page does `useFetch<any>` (`app/pages/index.vue:63`, `app/pages/pokemon/[name].vue:116`, moves/abilities/types likewise) and the util internals are `any` too, so Nuxt 4.6's rebuilt typed `$fetch` buys nothing here. (2) Server handlers rely on h3 auto-imports (`defineEventHandler`, `getRouterParam`, e.g. `app/server/api/pokemon/[name].get.ts:3,5`); that's still fully supported on 4.6 (verified: the 4.6 release notes and third-party migration write-ups confirm h3 auto-imports keep working), but 4.6 introduced `nuxt/server` precisely because Nuxt 5 moves to Nitro v3 / h3 v2 — code importing from `nuxt/server` won't care, code on h3 auto-imports will need a touch-up. (3) "Not found" is a data flag returned with HTTP 200 (`app/server/utils/pokeapi.ts:252,256,402,428,454`) handled by copy-pasted `v-if="data?.notFound || !data"` + `useHead` fallback in five pages, instead of `createError({ statusCode: 404 })` and the framework's error pipeline — the spec explicitly encouraged 404s. (4) `compatibilityDate: '2025-07-15'` (`app/nuxt.config.ts:14`) is over a year stale. (5) Hand-rolled URL machinery — a custom `encodeURIComponent` join (`app/pages/index.vue:112-115`) and regex URL-id parsing (`app/server/utils/pokeapi.ts:22-24`) where `URLSearchParams`/`URL` exist. (6) `process.env.API_BASE_URL` at module scope (`app/server/utils/pokeapi.ts:4`) instead of `runtimeConfig`/`useRuntimeConfig` — works because `nitro.preset: 'node-server'` is pinned (`app/nuxt.config.ts:12`), but a preset switch would break it.
