## Review: Pokédex app (`app/`)

A vanilla-JS + Vite 8 SPA: client-side router in `src/main.js`, API client/cache in `src/api.js`, derived datasets in `src/data.js`, HTML primitives in `src/ui.js`, and a hand-rolled static server (`server.mjs`) that injects the runtime API base URL. I verified Vite 8.3.5 is the current stable release, so the toolchain is up to date.

**What's good.** The race-discipline is unusually careful: every `await` in a page renderer is followed by a `renderToken` check (e.g. `app/src/main.js:161`, `:456`, `:630`), stale renders are suppressed, and the search debounce timer is cleared on route change (`app/src/main.js:795-799`). HTML output is consistently escaped (`app/src/api.js:88-99`, used everywhere interpolation touches API data), URL construction goes through `encodeURIComponent` for every path segment, and the static server has a correct path-traversal guard (`app/server.mjs:68-70`). Filter state-in-URL, pagination and the sort `aria-sort` handling match the spec's recommended primitives (`URLSearchParams`, `history.pushState/replaceState`, native form controls).

**What I'd ask about.** The game `<select>` handler pushes `?game=…` to the URL *before* awaiting move data, with no error handling (`app/src/main.js:424-434`): a failed fetch leaves the URL saying one game while the tables show another, plus an unhandled rejection. All API failures — including transient network errors — render the "Not found" page (`app/src/main.js:818-822`), conflating "resource missing" with "request failed". Structurally, `main.js` is an 877-line module holding the router plus all five page renderers plus the moves-table domain logic, and `api.js` is really a `utils.js` grab-bag (config, HTTP client, escaping, formatting, concurrency) that the pure view module `ui.js` imports from. The type-badge anchor markup is hand-rolled four separate times instead of reusing the `typeBadge` helper in `ui.js`. None of these block me; they're one round of changes.
