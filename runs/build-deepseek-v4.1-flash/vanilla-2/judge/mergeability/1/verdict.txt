I've reviewed the whole app (6 source files + server + markup) against the spec and current Vite 8 docs. Here's my assessment.

**What's good:** This is a disciplined vanilla-JS/Vite SPA. The Vite setup matches the current vanilla template exactly (`app/index.html` entry + `/src/main.js`, `"type": "module"`, `vite@^8.3.5` — the current stable line as of Oct 2026). Rendering is escaped-template-string `innerHTML` with a consistent `escapeHtml`/`escapeAttr` discipline, routing/state/history are hand-rolled because there is no framework — which is the correct choice here, not a fight with one. The `renderToken` guard (`app/src/main.js:46`, checked after every `await`) is applied consistently across all page renderers, and the `api()` promise cache deletes failed entries so retries work (`app/src/api.js:34-44`). Runtime API base injection via `server.mjs` + `window.__API_BASE_URL__` respects the "no build-time data" rule while keeping `vite build` clean.

**What I'd ask to change:** module-level promise singletons in `data.js` permanently cache rejections (a transient startup failure bricks the session); the game `<select>` handler pushes history then awaits without a catch (race + unhandled rejection); the static server falls back to `index.html` for missing assets; non-404 errors render as "Not found". All are small, contained fixes — nothing structural.
