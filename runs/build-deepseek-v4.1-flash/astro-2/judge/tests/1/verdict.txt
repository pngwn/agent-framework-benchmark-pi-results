I've reviewed the app against the test-quality dimension. Key facts:

- **No tests exist in `app/`**: `app/package.json:10-15` defines only `dev`/`build`/`start`/`preview` — no test script, no test runner or devDependencies (confirmed by the measured facts: 0 test files, 0 cases). The acceptance suite in `tests/` (root) is the only guard.
- The app contains a substantial amount of genuinely risky logic that is completely untested:
  - **Pure helpers** that would be trivially unit-testable: `humanize`, `dexNumber`, `formatHeight`/`formatWeight`, `latestEnglishFlavorText` (whitespace collapsing, "last English entry" selection), `englishShortEffect`, `idFromUrl` regex, `apiUrl`/`mediaUrl` URL joining (`app/src/lib/pokeapi.ts:11-100`).
  - **URL state + pagination math**: filter param parsing/validation, 48-per-page slicing, page clamping, param omission in `pageHref` (`app/src/pages/index.astro:17-46`).
  - **Client-side search**: 300 ms debounce, fetch-and-replace of `#results`, a `requestId` race guard, and `pushState` with **no `popstate` handler** — browser Back changes the URL but leaves stale DOM (`app/src/pages/index.astro:96-142`).
  - **Client-side table sorting**: missing-values-last is implemented **only for numeric columns**; text columns with `—` (e.g. Category) sort by string with missing values sorting first ascending, violating the "missing sorts last in both directions" rule; also `aria-sort` cycling (`app/src/pages/pokemon/[name].astro:322-363`).
  - **Method ordering/grouping and level-up default sort** built inline in the page frontmatter (`app/src/pages/pokemon/[name].astro:120-146`).
  - **Caching layers**: promise memoization with error-eviction in `getJson` (`app/src/lib/pokeapi.ts:19-37`) and six module-level cache promises in `app/src/lib/data.ts:21-37` — a refactor could easily break the eviction-on-failure behaviour or make failed fetches sticky.
  - **Error/not-found paths**: `NotFoundError` mapping to 404 is duplicated per route (`[name].astro:12-27`, `moves/[name].astro:11-20`, `abilities/[name].astro:10-18`, `types/[name].astro:10-19`) with no regression net.
  - **Alternate-form exclusion** (`id > 10000` filters) and hidden-ability aggregation appear in three routes with subtly different code paths (`abilities/[name].astro:25-31`, `moves/[name].astro:39-46`, `types/[name].astro:46-53`).

The code itself is reasonably factored (pure helpers in `lib/`, consistent not-found handling), which is exactly what makes the absence of tests frustrating — the highest-risk logic is *in a perfect shape to test* and nobody tested it.
