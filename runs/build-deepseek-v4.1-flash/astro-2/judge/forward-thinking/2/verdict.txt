## Review: forward-looking

### What the app is

A server-rendered Astro 7 Pokédex: `output: 'server'` + `@astrojs/node` standalone, four resource routes under `app/src/pages/`, all PokeAPI access behind `app/src/lib/pokeapi.ts` / `app/src/lib/data.ts`, and two small vanilla `<script>` blocks for filtering and table sorting. No client framework, no client runtime dependencies.

### API / version verification (done against current sources)

- **Astro 7** exists: released 2026-06-22 (astro.build/blog/astro-7). The lockfile resolves `astro@7.4.4` and pulls `@astrojs/compiler-rs@^0.5.1` + `@astrojs/markdown-satteri` — the Rust-compiler/Vite-8 era, i.e. genuinely the current major line, not a training-data-era version. `app/package-lock.json:1638-1646`.
- **@astrojs/node 11.1.9** is the current adapter series for Astro 7 (peer `astro: ^7.2.1`; changelog HEAD is 11.1.9). `app/package.json:11`.
- `output: 'server'` + Node adapter is still the documented way to get on-demand rendering (docs.astro.build/en/guides/integrations-guide/node). `app/astro.config.mjs:5-8`.
- Astro 7 stabilized **route caching** (`memoryCache()`, `routeRules`, `Astro.cache.set`) — the app doesn't use it (see findings).
- `Astro.params`, `Astro.url.searchParams`, `Astro.response.status` are all current, documented APIs. Nothing in the app is deprecated or removed in v7 (no `astro:transitions` internals, no `@astrojs/db`, no `output: 'hybrid'`).

### Per-criterion judgment

**latest_apis — 4.** The stack is the current major, current adapter, current config shape, zero legacy APIs. It misses Astro 7's newly-stable route caching, which maps almost exactly onto this workload (per-request upstream fetches, snapshot data) — that keeps it off a 5.

**platform — 4.** Genuinely platform-first: `fetch` with status handling (`app/src/lib/pokeapi.ts:44-53`), `URLSearchParams`/`FormData` for filter state (`app/src/pages/index.astro:101-108`), `DOMParser` for partial HTML swap (`app/src/pages/index.astro:112-118`), native `<form method="get">`, `<details>`-free accessible tables with `aria-sort` driven from `dataset` (`app/src/pages/pokemon/[name].astro:348-361`). One miss: the debounced search guards races with a hand-rolled `requestId` counter instead of `AbortController`, so superseded requests still run to completion (`app/src/pages/index.astro:105-121`).

**dependencies — 5.** Exactly two dependencies — `astro` and `@astrojs/node` — both required for server output; nothing on the client; versions pinned exactly and lockfile-consistent (`app/package.json:10-11`). There is nothing here to trim and nothing heavy.

**churn_resistance — 3.** Strong skeleton: every PokeAPI call funnels through `lib/pokeapi.ts` (fetch/caching/humanizers) and `lib/data.ts` (view-models), config is one 9-line file, and only documented framework APIs are touched — an Astro 8 upgrade would likely touch `package.json` and little else. But the boundary types are hollow: `strict: false` (`app/tsconfig.json:5`) and `Promise<any>`/`any[]` for every API payload (`app/src/lib/pokeapi.ts:27-28`, `app/src/lib/data.ts:29,79`, `app/src/pages/pokemon/[name].astro:17-21`), so when the API shape drifts, nothing catches it. URL construction (`/types/${name}`, `/pokemon/${name}`) is re-derived in five templates, and the memoize-with-reset pattern is copy-pasted across eight accessors (`app/src/lib/data.ts:37-41, 48-56, 60-68, 76-83, 88-93, 104-110, 116-121, 130-139`).
