## Reality check

There are **no tests in `app/`** — confirmed by the measured facts (`testLoc: 0`, no runner in deps) and by inspection: `app/package.json:6-9` defines only `build`, `dev`, `start`, `typecheck`; there is no test script, no runner dependency (no vitest/playwright/node test), and not a single spec file anywhere under `app/`. The app's correctness rests entirely on the harness-owned acceptance suite in `tests/`, which the team won't own once this merges.

## What the acceptance suite will stop guarding, and what bugs that invites

The app contains a substantial amount of exactly the logic that breaks under refactor:

- **Filter/pagination/URL-state pipeline** — `app/app/routes/home.tsx:34-71` chains type filter (species↔`type.pokemon` ID join), generation filter, and case-insensitive humanized search, then slices pages with a clamp (`Math.min(requestedPage, totalPages)`) and a `Math.max(1, …)` total-pages floor. The URL side is equally delicate: `home.tsx:131-144` debounces search (250 ms, `replace`), deletes `page` on every filter change, and `pageHref` (`home.tsx:175-182`) omits `page` at 1. A refactor that reorders these effects, or changes clamp/default-omission rules, silently breaks deep links like `/?type=fire&generation=generation-i`.
- **Column sorting** — `app/app/routes/pokemon.tsx:56-77` (`compareRows`) implements missing-values-sort-last in *both* directions, numeric vs `localeCompare` dispatch, plus `aria-sort` state; default ordering for `level-up` vs other tables is separate (`pokemon.tsx:223-234`). A one-character change (`1`/`-1`, or `?? MAX_SAFE_INTEGER` dropped) inverts missing-last and nothing currently owned by the app fails.
- **English-name / flavor-text selection** — `app/app/lib/format.ts:17-25` reverse-scans for the *last* English entry and collapses `\s+`; `englishName`/`displayName` (`format.ts:7-11`) fall back to humanized names. Picking the first instead of last, or matching the wrong language key, renders plausible-looking wrong text everywhere.
- **Alternate-form exclusion** — the `id > 10000` cut is hand-rolled in four places: `app/app/lib/data.server.ts:109`, `home.tsx:51`, `ability.tsx:24`, `type.tsx:47`. Any one site drifting (or the `refId` regex at `data.server.ts:48-51` mis-parsing a URL shape) leaks Mega forms into one list but not the others.
- **Promise cache** — `data.server.ts:12-21` evicts on rejection and keys `getResource` by lowercased name (`data.server.ts:59-61`) but `getByUrl` by raw URL. Key-collision or eviction bugs produce stale/cached-error behavior that's invisible until the API data changes (which the spec's `live-data-overlay.json` fixture explicitly exercises).
- **Move-method grouping / default game** — `pokemon.tsx:157-160` picks the default game as the highest `order`, and `methodSortValue` (`pokemon.tsx:44-47`) enforces the Level Up/Machine/Egg/Tutor-then-alphabetical order. Both are pure logic, trivially unit-testable, currently untested.
- **Smaller gaps**: the empty state keys off `cards.length` rather than `total` (`home.tsx:96-99`), so an enrichment failure would show "No Pokémon found" beside a nonzero count; `HashScroller`'s double-`setTimeout` scroll hack (`app/app/root.tsx:33-49`); and the not-found contract is duplicated as a `{ notFound: true }` loader flag + per-route render branch in five routes (e.g. `move.tsx:25`, `pokemon.tsx:144`) — nothing would fail if one route dropped its branch. (Throwing a 404 response would let the framework's `ErrorBoundary` centralize this; spec says HTTP 404 is encouraged but untested.)

The framework usage itself is current and idiomatic — React Router v8.5.1 in framework mode with route-module loaders/meta, `react-router-serve`, `isRouteErrorResponse` — so none of the untested risk comes from outdated APIs; it's all the app's own transformation logic.
