## Review

I read the spec, all 7 route modules, `root.tsx`, both lib modules, both components, the config files, and cross-checked behavior against the React Router v8 (current stable, 8.5.1) framework-mode guidance in the installed skill.

**What's good.** The app is textbook framework mode in structure: manual `app/routes.ts` with an explicit catch-all (`app/app/routes.ts:1-14`), `Layout`/`App`/`ErrorBoundary` exports in root (`app/app/root.tsx:15,64,88`), loaders that own URL state (`app/app/routes/home.tsx:21-105` parses `q/type/generation/page` from the request URL, exactly what the docs recommend for filter pages), the current `meta({ loaderData })` API (`app/app/routes/pokemon.tsx:22-24`), and a clean server boundary: all API access lives in `app/app/lib/data.server.ts`, which the `.server` naming keeps out of the client bundle, backed by a promise-level cache that evicts rejected entries (`app/app/lib/data.server.ts:11-22`).

**Biggest idiomatic gaps.** Type generation is wired up (`.react-router/types` in `app/tsconfig.json:6`, `typecheck` runs `react-router typegen`) but every loader/props signature is `any` (`app/app/routes/home.tsx:21,110`, `app/app/routes/pokemon.tsx:142,292`, etc.) — v8's generated `Route.LoaderArgs`/`Route.ComponentProps` are the documented standard and would eliminate this. Missing resources are handled with a home-grown `{ notFound: true }` return flag instead of the documented `throw data("Not Found", { status: 404 })` + `ErrorBoundary` pattern (flag set in `app/app/routes/move.tsx:27`, `type.tsx:31`, `pokemon.tsx:144`, `ability.tsx:20`, then re-checked in each component and each `meta`) — it works, keeps the header/footer, but also serves 200s and is plumbed by hand in 12 places. `HashScroller` (`app/app/root.tsx:33-49`) re-implements hash scrolling that `<ScrollRestoration>` already performs, including its own decode + double-timer retry.

**Correctness.** No serious bugs found. Minor: the root `ErrorBoundary` renders raw `error.message` (`app/app/root.tsx:96`); `decodeURIComponent(location.hash.slice(1))` can throw a `URIError` on a malformed hash and crash the effect (`app/app/root.tsx:40`); card sprites are fabricated from a pattern (`app/app/lib/data.server.ts:99`) and only the home route falls back to the API's `front_default` (`app/app/routes/home.tsx:90`) — other lists would show broken images if the API ever returned `null` sprites. `isbot` is a dependency but nothing imports it (only the default `entry.server` would).
