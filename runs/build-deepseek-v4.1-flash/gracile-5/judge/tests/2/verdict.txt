## Review — test quality

The app under review contains **zero tests of its own**. `app/package.json:6-8` defines only `build` and `start`; the sole dev dependency is `vite` (`app/package.json:12`), and there is no test file, runner, or script anywhere under `app/` (confirmed by the measured facts: `tests.files: 0, cases: 0, assertions: 0`). The only safety net is the repo-root Playwright acceptance suite (`tests/run.mjs`, root `package.json:8`), which the agent didn't write and won't guard future refactors.

What makes this a notable miss rather than a mere omission: a large fraction of this codebase is **pure, dependency-free logic that is trivially unit-testable** — `app/src/lib/format.ts:1-31` (humanize, dexNumber, flavor-text whitespace collapse, stat labels), `app/src/lib/data.ts:286-341` (`buildMoveTables`: method ordering, level-up sort with tie-break), `app/src/lib/data.ts:232-245` (`evolutionTree` recursion), and the pagination/URL math in `app/src/routes/(home).ts:26-31,74-79`. None of it has a single assertion. Node 24 ships `node:test`; Gracile itself publishes a "minimal setup with various test suites" starter, so this is an established pattern in the ecosystem, not an unsupported one.

The absence of tests is not hypothetical risk — I found a latent bug that one error-path test would have caught immediately:

- **`app/src/lib/api.ts:22`** references undefined `res` (`HTTP ${res.status}` inside a callback whose parameter is `response`). Every non-ok API response throws `ReferenceError` instead of the intended message. It's masked because `tryApi` (`api.ts:30-35`) swallows everything, and `app/src/routes/abilities/[name].ts:19` adds a belt-and-braces `.catch(() => null)`, so 404s still render — but the error handling layer is effectively broken and untestable-as-written. The exported `ApiError` class (`api.ts:4-8`) is dead code, never thrown.
- **`app/src/lib/api.ts:25`** caches the promise *before* it settles, so a single transient API hiccup poisons that URL's cache with a permanently-rejected promise until process restart.

Both live in the exact layer (data fetching/caching/error paths) the dimension cares about, and both are invisible to the acceptance suite as long as the API behaves.
