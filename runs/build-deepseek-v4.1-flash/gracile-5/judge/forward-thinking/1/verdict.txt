## Review — forward-thinking

**Framework currency check (verified against sources, not memory):** `@gracile/gracile@0.11.0` is the latest stable on npm (fetched from `registry.npmjs.org/@gracile/gracile/latest`), and `vite@8.x` is current (8.2.2). The app's server bootstrap (`app/server.mjs:9-11` — `serveStatic({ root: gracile.getClientBuildPath(...) })` + `gracile.honoAdapter(handler)`), the Vite plugin (`app/vite.config.js:7` — `gracile({ output: 'server' })`), and the route shape (`defineRoute` with `handler`/`document`/`template`, `context.props.GET`, `responseInit.status`, `<route-template-outlet>` at `app/src/document.ts:25`) all match the official `gracile-web/starter-projects` "minimal server (Hono)" starter and the annotated examples on gracile.js.org, byte for byte in shape. Nothing here is a legacy-era Gracile API.

**Where it will age well**

- All HTTP access is funneled through one module pair: `app/src/lib/api.ts` (fetch + cache) and `app/src/lib/data.ts` (API-shaped view models). Routes consume view models, never raw endpoints. Swapping the API or adding caching headers would touch two files.
- The framework integration surface is exactly one file (`app/server.mjs`) plus 8 lines of Vite config — a Gracile upgrade touches almost nothing, and no framework internals are relied on.
- Platform usage is good: `URL`/`URLSearchParams` for all query handling (`app/src/routes/(home).ts:19-35, 102`), native `fetch`, the native `search` input event (`app/src/client/interactions.ts:42`), `padStart`/`.at(-1)`/`localeCompare` throughout `format.ts`.

**Where it will churn**

- TypeScript is present in name only. `api<T = any>` (`app/src/lib/api.ts:17`), pervasive `any` in every view model (`app/src/lib/data.ts:24,63,117` and every route template), **no `tsconfig.json` at all**, no `typescript` devDependency, and `npm run build` is bare `vite build` (`app/package.json:7`) — nothing ever type-checks. When the PokeAPI schema shifts (the tests literally do this via the live-data overlay), nothing catches it.
- `app/src/lib/api.ts:22` throws `HTTP ${res.status}` — `res` is undefined in that scope; the intended error path throws a `ReferenceError` instead. The `ApiError` class (`api.ts:4-8`) is dead code. This is exactly the class of bug a missing typecheck lets through.
- `cache.set(url, request)` (`api.ts:25`) caches the promise unconditionally: one transient upstream failure permanently poisons that resource until restart.
- Duplicated logic/markup: the species-ID regex is re-implemented inline in `app/src/routes/(home).ts:60` next to the existing `idFromUrl` (`api.ts:38`), and the "Not found" template is copy-pasted in five places (`routes/404.ts:11`, `pokemon/[name].ts:56`, `moves/[name].ts:32`, `types/[name].ts:31`, `abilities/[name].ts:35`) while an exported `notFound()` component sits unused at `app/src/lib/components.ts:44-49`.
- The stack is "Gracile with Lit", yet zero Lit code exists (grep for `from 'lit'`/`LitElement`/`customElement`: no matches). All interactivity is hand-rolled vanilla DOM in `app/src/client/interactions.ts`, and `lit` is declared as a direct dependency (`app/package.json:10`) without being imported once. (It *is* a required peer of `@gracile/server`, so it can't simply be dropped — but the framework's component/hydration model is bypassed entirely.)
