I've reviewed the app against Astro 7.4.4 (the current stable, released 2026-10-28) and the v7 docs. Here is my review.

**Framework currency check:** `app/package.json:14` pins `astro@7.4.4` / `@astrojs/node@11.1.9` — current stable. `output: 'server'` + `node({ mode: 'standalone' })` is the documented SSR setup; the 404 pattern (`Astro.response.status = 404` in `[name].astro:30`) is lifted almost verbatim from the on-demand rendering guide. Nothing deprecated or removed in v7 is used. The docs explicitly note `export const prerender = false` is "Not needed in 'server' mode", and the app repeats it in all 8 pages anyway — harmless noise.

**Main structural concern:** `src/lib/pokeapi.ts` is a 370-line god module that mixes three concerns — pure formatting (`humanize`, `dash`, `idFromUrl`), URL resolution, and a server-only promise cache plus five module-level singletons (`pokeapi.ts:17`, `pokeapi.ts:117-121`). Because the pure helpers live next to `process.env` and `fetch` code, the client script on the home page cannot import them, so `pages/index.astro` re-implements `humanize` (`index.astro:146`), the filter predicate (`index.astro:228`), pagination link building, and the whole Pokémon card (`index.astro:188`, duplicating `components/PokemonCard.astro`) inside an inline `<script>`. The duplication has already drifted: the server renders `<span id="page-status">` / `<a id="previous-page">` (`index.astro:118-120`) but the client re-render (`index.astro:246-262`) rebuilds the pagination without those ids. Astro's bundled `<script>` tags support `import` from `src/`, so a `format.ts` shared by frontmatter and script was available and is the fix I'd ask for.

**Correctness:** mostly solid. Rejected promises are evicted from the cache (`pokeapi.ts:41-44`), query params are validated against real option lists on both sides, 404s are handled with the documented pattern, and a catch-all plus `404.astro` cover unknown URLs. Risks I'd flag: the Pokémon page fires unbounded parallel fan-out (every version group resource plus every move of the selected game, `pokeapi.ts:300`, `pokeapi.ts:317`) with no error isolation and no custom `500.astro`, so one 5xx from the API produces an unstyled framework error page; `set:html={JSON.stringify(payload)}` (`index.astro:124`) doesn't escape `<`, so a `</script>` in API data would break the document; and the home page serialises all ~1,025 species (with absolute sprite URLs) into every response and then re-renders the server-rendered list on load — wasteful and a standing SSR/CSR-mismatch hazard.
