## Review: experimentalness of `app/` (SvelteKit 3.1 / Svelte 5.57, judged against the current stable release)

**Verification context (sources checked):** SvelteKit 3.0 shipped 2026-10-01 (`svelte.dev/blog/sveltekit-3-is-here`, GitHub release tag `@sveltejs/kit@3.0.0`), so this app is on the current stable line, four weeks old. Per the Kit 3 migration guide: config now lives in the `sveltekit()` Vite plugin (`vite.config.js`), `$lib` is replaced by `#lib` subpath imports, `$app/stores` is removed in favour of `$app/state`, `error(status, message)` is the new signature, and `goto` gained `shallow`/`replace`/`reset` while **`noScroll`/`keepFocus` were removed** (#16558, Kit error `goto_options_removed`).

**What I found in the code:**

- **No experimental/preview/RC/canary APIs anywhere.** No `experimental.*` config flags in `app/vite.config.js`, no remote functions, no `compilerOptions.experimental.async`, no unstable names (`grep` across `app/src` came back empty except false positives). The measured `experimental` markers list is empty — confirmed.
- Svelte 5 runes, snippets, `untrack`, `style:`/`class:` directives are all stable since Svelte 5.0 (Oct 2024) — e.g. `app/src/lib/components/MoveTable.svelte:28` uses `untrack` for its documented purpose, `app/src/lib/components/EvolutionList.svelte:7-21` uses a recursive snippet.
- The only "new" surface is Kit-3-era: `sveltekit({ adapter })` plugin config (`app/vite.config.js:7`), `#lib` imports (`app/package.json:18-21`), `$app/state#page` (stable since 2.12, long-stable now), and `goto(..., { shallow: true, reset: false })` on the home page — the newest API in the app, and a justified one (keeps per-keystroke URL sync from re-running the dex load / a server round trip).
- **One stale-API slip:** `app/src/routes/pokemon/[name]/+page.svelte:14` calls `goto(url, { noScroll: true, keepFocus: true, replace: true })` — `noScroll`/`keepFocus` were *removed* in Kit 3 (replaced by `reset: false`), and Kit ships the dedicated error `goto_options_removed` for exactly this call. This is the opposite of leaning on experimental APIs — it's holding on to a removed one — but it's the one place the app isn't aligned with the current release.
- Minor: `app/src/lib/server/pokeapi.js:3` reads `process.env.API_BASE_URL` directly, bypassing Kit 3's newly-stable explicit env vars (`src/env.js` + `$app/env/private`). Works fine under adapter-node; just skips validation and the framework's dev-time `.env` support.

Risk profile overall: very conservative. Zero experimental dependencies; the only exposure is that the whole app sits on a major version four weeks post-release, plus one removed-options bug.
