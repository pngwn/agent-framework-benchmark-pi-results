## Findings

**What the app uses.** The app targets the current stable framework: SvelteKit 3.1.0 with Svelte 5.57 and Vite 8 (`app/package.json:10-15`), all stable releases — no `next`/`canary` tags, no `experimental.remoteFunctions`, no `experimental.async` compiler flags (`app/vite.config.js` contains only `adapter` and the plugin). The measured `experimental` markers are empty, and my grep for `unstable_|experimental` across `app/src` confirms it.

**The new-API surface is small and central in one place.**

- `goto(url, { shallow: true, replace, reset: false, state })` — `app/src/routes/+page.svelte:46-53`. Shallow routing via `goto` was added in `3.0.0-next.13` (2026-07-29) and went stable in SvelteKit 3.0 on **2026-10-01** — four weeks before today. It's the recommended replacement for the now-deprecated `pushState`/`replaceState` (confirmed in `svelte.dev/docs/kit/shallow-routing` and `svelte.dev/docs/kit/$app-navigation`, which say "Use `goto(url, { state, shallow: true })` instead"). This is "recently-stable" — the single most new API in the app, and it carries the home page's filter/pagination URL-sync, i.e. a central feature.
- The rest is long-stable Svelte 5: runes (`$state`/`$derived`/`$props`), snippets and recursive `@render` (`app/src/lib/components/EvolutionList.svelte:5-16`, stable since Svelte 5.0, Oct 2024), and `untrack` (`app/src/lib/components/MoveTable.svelte:28`), used exactly as documented for reading non-reactive initial props.
- SvelteKit-3-native conventions: config via the `sveltekit` Vite plugin instead of `svelte.config.js` (`app/vite.config.js:6-11`, mandatory in v3 per the migration guide) and `#lib` subpath imports (`app/package.json:12-14`). Both are v3-stable but only a month old.
- `error(404, 'Not found')` at `app/src/routes/pokemon/[name]/+page.server.js:29` uses the two-argument form v3 prefers (the `error(status, {...})` overload is deprecated) — correct adoption.

**One stale half-adoption.** `app/src/routes/pokemon/[name]/+page.svelte:13` calls `goto(url, { noScroll: true, keepFocus: true, replace: true })`. SvelteKit 3 **removed** `noScroll`/`keepFocus` in favor of `reset` (PR #16558, merged 2026-07-29); with kit 3.1.0 installed this hits the `goto_options_removed` error in dev (it throws) and silently ignores the options in prod, losing the intended scroll/focus preservation. The home page correctly uses `reset: false` — so the codebase straddles the v2 and v3 option sets for the same function.

**Justification.** Each new-API use buys something a stable alternative couldn't: shallow routing updates the URL on every keystroke without re-running the server `load` (the spec requires live URL reflection, `SPEC.md:96-101`), `untrack` suppresses the reactive-dependency warning on initial state, and v3 config/imports are simply what the current framework mandates. Nothing is used for novelty.
