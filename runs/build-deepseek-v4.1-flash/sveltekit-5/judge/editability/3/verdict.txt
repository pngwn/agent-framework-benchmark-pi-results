I've read all the app source. Here's my review.

## What I found

**Structure** — The app is cleanly layered: all data access lives in `app/src/lib/server/pokeapi.js` (correctly under `lib/server/`, so it can't leak to the client), consumed only by `+page.server.js` loads; pages render precomputed plain objects; four small prop-driven components. Svelte 5 idioms are current throughout: runes (`$props`, `$state`, `$derived`/`$derived.by`), `onclick`, snippets, keyed each blocks, `$app/state`'s `page`, `error()` helper. No legacy constructs, no experimental flags.

**Scenario walk-through**

1. **Remove Abilities** — delete `app/src/routes/abilities/`, then strip the Abilities section from the Pokémon page (`+page.svelte:90-99`, styles at 242-248) and the `abilities` mapping in its load (`+page.server.js:70-77,166`). The only other trace is the now-dead `getAbility` one-liner (`pokeapi.js:234`). Nothing else links to `/abilities`.
2. **Sprite bug** — every card list flows through `pokeapi.js`: `getDexData` (line 181) for home and `cardFromSpecies` (192-199, reached via `cardsFromPokemonRefs`/`getPokemonCard`) for moves/abilities/types. One file covers all lists — but the fix must land in **two** functions, because `getDexData` duplicates the card shape instead of calling `cardFromSpecies`.
3. **Sort by name** — `cardsFromPokemonRefs`'s sort (`pokeapi.js:217`) covers three pages in one edit; the home page's order comes from `getDexData`'s dex array, so a second edit in `routes/+page.svelte` (or `pokeapi.js:174-183`). Two trivial edits.
4. **Items section** — add `getItem` one-liner to `pokeapi.js`, create `routes/items/[name]/` reusing `PokemonCard`, `cardsFromPokemonRefs`, `englishName`, and the global `panel`/`detail-list`/`card-grid` CSS — but the details-page `<dl>` + Effect section markup would be copy-pasted from the Moves page (~half the page), since there's no shared "resource detail" abstraction. Helpers like `isMissing` would be copied a third time.
5. **Data source change** — `API_BASE`, `getJson`, the `memo` cache and `spriteUrl` all live in `pokeapi.js:3-24,58`. Exactly one file knows about them.

**Main deductions** — duplicated card shape (`getDexData` vs `cardFromSpecies`), card-list markup repeated in four `+page.svelte` files, `latestEnglishFlavorText` exported but unused while its logic is inlined twice, `isMissing` triplicated, zero type/JSDoc contracts, and the slightly magic `Object.assign(card, {hidden})` → `pokemon.hidden` read in the ability page.
