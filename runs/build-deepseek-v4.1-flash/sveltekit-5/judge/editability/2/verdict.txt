## Review: editability of `app/` (SvelteKit 3 / Svelte 5)

I read every source file in `app/src` (routes, `lib/server/pokeapi.js`, all four components, `app.css`, `+layout`, `+error`), the SPEC, and verified the current-framework claims (Kit 3's `goto(url, { shallow, replace, reset, state })` from the Kit 3.0 release notes, `$app/state#page`, `error()` throwing, snippets, `$props/$state/$derived`, `untrack`). The app uses Svelte 5 runes and current Kit 3 APIs idiomatically throughout — nothing I found is stale API usage.

### How the structure holds up

The architecture is a textbook SvelteKit split: **all** API access, caching and shaping lives in one server-only module (`app/src/lib/server/pokeapi.js`), pages are thin DTO-producing `+page.server.js` loads plus presentational `+page.svelte`s, and four small prop-driven components. This makes the two most common edits — data-source changes and per-card bugs — single-file changes. The weaknesses are minor and localized: a hidden coupling between the Pokémon page's `{#key}` and `MoveTable`'s `untrack` sort initialization, a custom `#lib` import alias instead of the framework's `$lib` convention, and some template-level copy-paste (count + card-grid markup repeated on three pages; `MoveTable`'s column knowledge defined twice).

### Scenario walkthroughs

1. **Remove Abilities** — delete `app/src/routes/abilities/[name]/` (2 files) and prune the one section that links to it (`app/src/routes/pokemon/[name]/+page.svelte:90-97` + styles at 242-249, load code at `+page.server.js:70-77,166`). No nav link, no other references (grepped). Easy.
2. **Sprite bug (Deoxys)** — every card list (home, moves, abilities, types) derives sprites through `spriteUrl` at two call sites in one module (`pokeapi.js:181` and `pokeapi.js:197`); the species↔default-Pokémon mapping (`deoxys-normal` → ID 386 → species) is already centralized in `cardsFromPokemonRefs` (`pokeapi.js:200-217`). A shallow fix touches one function; a policy change touches one file twice.
3. **Sort all card lists by name** — one sort in `pokeapi.js:217` covers moves/abilities/types; the home list needs its own edit in `routes/+page.svelte:28-34`. Two places total.
4. **Items section shaped like Moves** — data layer fully reusable (`getResource`/`getList`/`englishName`, `pokeapi.js:27-46`); route files are copied from the moves/types pattern and adapted (new `/items` index has no in-repo template). Copy-adapt, not reuse, at the route layer.
5. **Change API base URL / caching** — one file: `pokeapi.js:3` (base), `:8-16` (`memo` cache), `:18-25` (`getJson`), `:58-60` (sprite URLs). Nothing else knows where the API lives.
