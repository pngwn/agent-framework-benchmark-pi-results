## Review: `app/` on SvelteKit 3.1 / Svelte 5.57 (current stable, Oct 2026)

**Verification sources used:** SvelteKit 3 migration guide (`svelte.dev/docs/kit/migrating-to-sveltekit-3`), `svelte.dev/docs/kit/shallow-routing`, `svelte.dev/e/kit/goto_options_removed`, `svelte.dev/docs/kit/environment-variables`, `svelte.dev/docs/kit/server-only-modules`, Kit 3.0/3.1 release notes, and the repo's Svelte skill files.

### What's genuinely current (and better than most training-data-era code)

- **Kit 3 config pattern**: no `svelte.config.js`; the adapter lives in the `sveltekit()` Vite plugin options (`app/vite.config.js:7`) — exactly what SvelteKit 3 requires (Kit 3 dropped `svelte.config.js` support, per migration guide).
- **`#lib` subpath imports** (`app/package.json:19`, used in all load functions/components) instead of the removed `$lib` alias — the current Kit 3 convention (Node subpath imports).
- **`page` from `$app/state`** everywhere; no trace of the removed `$app/stores` (`grep` for `$lib|$app/stores|$env/` finds nothing).
- **Shallow routing**, the newest navigation API: the home page drives URL filter state via `goto(url, { shallow: true, replace, reset: false })` (`app/src/routes/+page.svelte:44-49`) and syncs on back/forward via `afterNavigate` (`+page.svelte:90-92`). This is the post-training-data Kit 3 API and avoids re-running the server `load` per keystroke — a deliberate, well-matched use.
- **`error(404, message)`** from `@sveltejs/kit` (`app/src/routes/pokemon/[name]/+page.server.js:29`, also moves/abilities/types loads) — the current signature (Kit 3 deprecated `error(status, {...})` in favor of `(status, message)`).
- Runes, snippets, `onclick`/`onchange`, `style:` directives throughout; no legacy `on:`, `export let`, `$:`, slots, or `<svelte:component>` anywhere.
- **One data-access module**: every HTTP call in the app goes through `app/src/lib/server/pokeapi.js` (the only `fetch(` in `src/` is `pokeapi.js:19`), with a memoized promise cache (`pokeapi.js:8-16`). `src/lib/server/` is the *enforced* Kit 3 server-only boundary, so the API layer can't leak into client bundles. This is excellent churn resistance: swapping the API or adding caching touches one file.
- **Dependencies**: exactly 5 devDependencies, all mandated by the framework's current majors (Kit 3.1.0, Svelte 5.57.3, Vite 8, vite-plugin-svelte 7.3.1, adapter-node 6.0.0 with `peerDependencies: @sveltejs/kit ^3`), zero runtime deps, zero polyfills.
- **Platform**: native `<input type="search">` with live `oninput` filtering (no debounce needed since filtering is a `$derived`), `URLSearchParams` for query building (`+page.svelte:35`), `new URL(page.url)` to correctly copy the now-readonly `page.url` (`pokemon/[name]/+page.svelte:11`), CSS custom properties for theming, `decoding="async"`/`width`/`height` on images.

### What will age badly

1. **Removed `goto` options in the Pokémon page** — `app/src/routes/pokemon/[name]/+page.svelte:13` calls `goto(url, { noScroll: true, keepFocus: true, replace: true })`. SvelteKit 3.0 removed `noScroll`/`keepFocus` and combined them into `reset` (`svelte.dev/e/kit/goto_options_removed`); passing them raises `goto_options_removed` in dev and is silently ignored in prod (the production bundle contains no trace of the check), so changing the Game select resets scroll/focus contrary to intent. The same file mixes the *new* `replace: true` with the *old* options, and the home page already uses the correct `reset` — so this is an un-migrated leftover, not a stylistic choice.
2. **`process.env` instead of the Kit 3 env system** — `app/src/lib/server/pokeapi.js:3` reads `process.env.API_BASE_URL` at module load. Kit 3's current API is `defineEnvVars` in `src/env.js` + import from `$app/env/private` (which offers validation and works across adapters); the deprecated `$env/*` modules aren't used either, so the app simply bypasses the framework's env layer entirely.
3. **No types at any boundary** — plain JS throughout (`typeLines: 0`, no `tsconfig.json`/`src/app.d.ts`, only two stray `/** @type */` in `pokeapi.js`). Kit scaffolds TypeScript by default; when Kit's load types or the API shape change, nothing will catch it at build time.
4. Minor API misuse/noise: `untrack` wrapping a `$state` initializer (`app/src/lib/components/MoveTable.svelte:28`) is a no-op at init; `state: {}` in the shallow `goto` (`+page.svelte:48`) is a no-op; a `{#key}` block remounts all move tables just to reset sort state (`pokemon/[name]/+page.svelte:117`) where the skill guidance recommends sparing `#key` use; `class:` directives (`MoveTable.svelte:114`, `PokemonCard.svelte:8`, `TypeBadge.svelte:6`) where current guidance prefers class arrays/objects.
