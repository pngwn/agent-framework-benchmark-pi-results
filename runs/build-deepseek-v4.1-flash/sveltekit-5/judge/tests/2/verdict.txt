## Review: test quality

The app contains **zero tests of its own** — confirmed by static analysis (`tests: { files: 0, cases: 0 }`) and by inspection: `app/package.json` has no test script, no `vitest`/`playwright`/`@testing-library` in devDependencies, and no `*.test.*`/`*.spec.*` files anywhere under `app/src/`. Everything passing in CI today comes from the harness-owned acceptance suite in `tests/`, which the agent did not write and cannot credit for.

The acceptance suite itself is browser-level and behavioural (roles, accessible names, URLs — see `tests/specs/home.spec.mjs`, `pokemon.spec.mjs`), so it *currently* guards a lot. But the review question is what happens when someone refactors the data layer and that suite is no longer the only guard. Almost all of this app's real logic lives in pure, easily-testable functions and load functions — `app/src/lib/server/pokeapi.js` (memoized fetch + three big data-shaping transforms), `app/src/routes/pokemon/[name]/+page.server.js` (moves-table assembly), `app/src/lib/components/MoveTable.svelte` (sorting), `app/src/routes/+page.svelte` (filter/pagination/URL state) — and none of it has a single regression net the team owns.

Notable specifics that would break silently without tests:

- `app/src/routes/+page.svelte:79-92` — URL sync only happens on `popstate` navigations; the derived clamp at `:46-47` (silently coercing out-of-range `page`) and the param-omission rules in `queryUrl` (`:41-49`) are classic refactor traps.
- `app/src/lib/server/pokeapi.js:204-211` — `cardsFromPokemonRefs` silently drops any Pokémon whose species isn't in the index and filters `id >= 10000`; a species-resolution regression would just make cards vanish from move/ability/type pages with no error.
- `app/src/lib/components/MoveTable.svelte:54-80` — the missing-values-last-in-both-directions rule is subtle (handled *before* the direction flip at `:58-62`, while the both-missing tie-break at `:60` is *not* direction-flipped) and entirely unguarded.
- `app/src/routes/+error.svelte:6` — the error page renders `Not found` for **every** error, so an API outage (`pokeapi.js:23-26` throws a plain `Error` → SvelteKit 500) is indistinguishable from a 404; nothing would catch that masking.
- `app/src/lib/server/pokeapi.js:14-19` — the promise memo caches `null` (404) responses forever; with the "live API" premise in the spec, a stale-404 bug would be invisible.
- `app/src/routes/pokemon/[name]/+page.server.js:167-170` — fallback evolution chain fabricates a node when `evolution_chain.url` is missing; untested.
- `app/src/lib/server/pokeapi.js:52` — `latestEnglishFlavorText` exists but is unused: the same logic is inlined twice (`pokemon/[name]/+page.server.js:51-53`, `moves/[name]/+page.server.js:24-27`), a duplication that tests would have forced into one place.

On the positive side, the app's structure makes adding tests cheap: `humanize`, `cardsFromPokemonRefs`, the memo, and every `+page.server.js` load function are pure/async functions with obvious inputs and outputs, and the load functions are the kind SvelteKit unit-tests routinely with mocked `fetch`. The agent simply didn't invest any of the effort there.
