## Review

**Setup & currency.** This app is built on the current SolidStart v2 stack: `vite.config.ts` with `solidStart()` + `nitro/vite` (the post-Vinxi architecture, matching the current docs reference at docs.solidjs.com/solid-start/v2/reference/entrypoints/vite-config), `@solidjs/start` 2.1.0 on Vite 8, and `@solidjs/router` 1.0 (the stable realignment). Data loading uses `query` with an *inner* `"use server"` directive — exactly the pattern the `"use server"` reference page prescribes (placing it file-level would break the client-side `query` wrapper) — read via `createAsync`. `entry-server.tsx`'s `createHandler`/`StartServer document` and `HttpStatusCode` from `@solidjs/start` both match the v2 reference docs. I found no legacy-era API anywhere: no `app.config.ts`/vinxi, no deprecated router primitives, no pre-1.9 Solid idioms.

**Platform & dependencies.** Data fetching is native `fetch` with a promise-cache, `URL`/`URLSearchParams` for URL handling, and native form controls throughout. No abort/cancellation on the fetch layer, and a couple of hand-rolled conveniences (regex ID extraction from resource URLs, setTimeout debounce), but nothing that a platform or framework primitive covers better. The dependency list is exactly the six packages the framework docs require — no CSS framework, no utility library, nothing redundant.

**Churn resistance.** All API access lives behind one module (`src/lib/queries.ts`) with typed DTOs consumed by components, which is the strongest thing going for long-term ownership. Against that: the query-param encoding rules exist twice in the home page (`navigateWith` vs `pageHref`), the `HomeData` shape is duplicated inline as prop types, and the internals of the data layer lean on `any` heavily, so upstream API-shape changes surface at runtime rather than compile time. One correctness/currency gap: the 404-determining resources don't pass `{ deferStream: true }` to `createAsync`, and the docs note that status codes can only be applied before the first stream flush under streaming SSR — so `HttpStatusCode 404` for missing Pokémon likely won't reach the wire. The spec says 404 status isn't tested, so it's a latent issue rather than a blocker.
