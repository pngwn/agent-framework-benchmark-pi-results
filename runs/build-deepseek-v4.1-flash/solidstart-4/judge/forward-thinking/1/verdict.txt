I've reviewed the app against SolidStart's current stable release (v2.1.0, published 2026-10-22) and the official v2 docs. Here's my assessment.

## What's current (verified against docs.solidjs.com / npm registry)

- **Toolchain is the current generation**: `@solidjs/start@^2.1.0` (latest stable), `@solidjs/router@^1.0.0` (latest stable), `solid-js@^1.9.17` (correct — Solid v2 is only RC; SolidStart v2 is built on Solid v1), Vite 8, Node >= 24 engines (`app/package.json:8-19`).
- **`vite.config.ts` with `solidStart()` + `nitro()`** matches the documented v2 pattern exactly, replacing v1's `app.config.ts`/vinxi (`app/vite.config.ts:5-8`).
- **Data loading** uses the current model: `query()` + `"use server"` server functions read via `createAsync` (`app/src/lib/queries.ts:347-349`, `app/src/routes/index.tsx:220`) — no v0.16-era `cache()`, no `createResource` waterfalls.
- **`HttpStatusCode` from `@solidjs/start`**, `FileRoutes`, `MetaProvider`/`Title`, `useSearchParams`/`useParams`/`useLocation` are all the documented v2/router-v1 APIs.

## Concerns

The most serious one is a **silent functional bug hidden behind an unsafe cast**: `MoveTable` sorts rows by indexing `a[sort.key as keyof MoveRowData]`, but the column keys `"move"`, `"type"`, `"category"` (`queries.ts:637-641`) don't exist on `MoveRowData` (which has `moveLabel`, `typeName`, `categoryLabel`…). Sorting by Move/Type/Category is therefore a no-op — the spec requires every column sortable, and the acceptance test only checks the Move header's `aria-sort`, so it slipped through. The 404 status also likely never reaches the wire for data-driven not-found pages: the docs note status codes only apply before the stream's first flush, and the gating `createAsync` lacks `deferStream: true` (`pokemon/[name].tsx:159`, `components/NotFound.tsx:5`).

Minor debts: `nitro` exact-pinned to a June beta on a fast-moving prerelease line (latest is `3.0.261029-rc`); five copy-pasted promise-memoization blocks in `queries.ts`; a duplicated inline prop type in the home route; no type-check script anywhere despite `strict: true`; and stale v1-template boilerplate in `.gitignore`/`README.md`.
