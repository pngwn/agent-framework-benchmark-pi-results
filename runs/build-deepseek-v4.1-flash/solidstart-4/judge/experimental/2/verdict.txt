## Review: experimentalness

**What I verified**

- **Nitro v3** is the one beta-channel dependency: `app/package.json:17` pins `nitro@3.0.260610-beta` (exact pin, June 2026 build). Nitro's own blog confirms v3 is a **public beta** (announced 2026-03-11, [nitro.build/blog/v3-beta](https://nitro.build/blog/v3-beta)), and the first **RC** (`v3.0.261029-rc`) shipped 2026-10-29 — yesterday — with an "Upgrading from Beta" breaking-changes section ([releases](https://github.com/nitrojs/nitro/releases)).
- Crucially, this is not a novelty pick: **SolidStart v2 is the current stable** (stable announcement Aug 4 2026, [discussion #2281](https://github.com/solidjs/solid-start/discussions/2281)), and its official deployment guide says to install `nitro` and add `nitro()` after `solidStart()` exactly as `app/vite.config.ts:5` does ([docs.solidjs.com/solid-start/v2/guides/deployment-plugins](https://docs.solidjs.com/solid-start/v2/guides/deployment-plugins)). Given the spec's requirement that `npm start` serve a production build on `$PORT`, Nitro's node preset is the natural choice — and there is no stable-channel Nitro that works with SolidStart v2 (v1 used Nitro v2/vinxi; the migration guide removes `nitropack` in favor of `nitro/vite`).
- **Everything in application code is long-stable, idiomatic SolidStart v2 / solid-router.** The `query(...) => { "use server" }` pattern in `app/src/lib/queries.ts:347-348, 358-359, 512-514` matches the current docs verbatim (directive *inside* the inner function, not file-level — the docs explicitly warn about the file-level mistake, and the app gets it right). `createAsync`/`useSearchParams` (`app/src/routes/index.tsx:2`), `FileRoutes`/`Router` (`app/src/app.tsx:2-3`), `createHandler`/`StartServer` (`app/src/entry-server.tsx:2-4`), `HttpStatusCode` (`app/src/components/NotFound.tsx:8`), and core primitives (`createSignal`/`createMemo`/`For`/`Show`/`Suspense`) have all been stable since router 0.15 / solid 1.x — roughly two years old.
- Static analysis found **zero** `unstable_`/`experimental_` names or config flags; `app/vite.config.ts` has no experimental options, and the app uses no nitro-specific config at all (no preset/prerender flags), so the beta surface is a single line in config plus a pinned version.
- Fresh-but-stable context: `@solidjs/start@2.1.0` released 2026-10-22 and `@solidjs/router@1.0.0` (~July 2026) are stable releases, not experimental; Vite 8 is the version SolidStart v2 *requires*. The app does **not** opt into the genuinely new 2.1.0 API (`ssr: "data-only"`).

**Assessment.** The app is about as conservative as the framework's current stable release permits: one beta dependency, but it's the framework-documented deployment plugin, confined to `vite.config.ts`, pinned to an exact version, with no deep nitro API usage anywhere in source. The main residual risk is upstream churn (beta → RC already lists breaking changes), which an exact-pin upgrade path handles cleanly.
