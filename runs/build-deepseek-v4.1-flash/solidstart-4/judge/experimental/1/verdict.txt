## Review: experimentalness

**What's actually in the app.** The 14 source files import nothing experimental: the full import surface (grep of `app/src`) is `@solidjs/meta` (`MetaProvider`, `Title`), `@solidjs/router` (`A`, `Router`, `createAsync`, `query`, `useLocation`, `useParams`, `useSearchParams`), `@solidjs/start` (`HttpStatusCode`, `FileRoutes`, `mount`/`StartClient`, `createHandler`/`StartServer`), and long-stable Solid primitives (`createSignal`, `createMemo`, `createEffect`, `onCleanup`, `For`, `Show`, `Suspense`). The measured facts report `experimental: []`, and my own grep for `unstable|experimental|islands|clientOnly|preload|cache(` found no matches in `app/src`. `vite.config.ts` passes zero options to either plugin — no `solidStart({experimental…})`, no `nitro: { experimental: { tasks: true } }`, and none of the features brand-new in 2.1.0 (`ssr: "data-only"`, per the GitHub release of 2026-10-22).

**Where the experimentalness actually lives — the dependency stack.**

1. **`nitro@3.0.260610-beta`** (`app/package.json:17`) is the one genuine pre-release dependency, and it's load-bearing: it is the production server (`app/package.json:8` → `node .output/server/index.mjs`) and the build plugin (`app/vite.config.ts:8`). Nitro v3 is still pre-stable — nitro's own README says "For the current stable release, see Nitro v2" (registry.npmjs.org/nitro), and the v3 channel moved from beta (`3.0.260903-beta`) to an RC (`3.0.261029-rc`, published 2026-10-29, with a documented "Upgrading from Beta" breaking-changes list). The exact pin is also ~4.5 months stale (date-coded 2026-06-10).
2. **`@solidjs/start@^2.1.0`** (`app/package.json:14`) is *recently stable*: v2.0.0 went stable 2026-08-04 (GitHub release: "SolidStart v2 is now stable"), and 2.1.0 shipped 2026-10-22 — eight days ago. It's central to every file.
3. **`vite@^8.3.5`** (`app/package.json:16`) — Vite 8 has been stable since 2026-03-12 (vite.dev/blog/announcing-vite8), and is a required peer of `@solidjs/start` (`vite: ^8 || ^9`).

**Mitigating context:** every pre-release choice is exactly what SolidStart v2's current docs prescribe. The deployment-plugins guide mandates `npm i nitro` and `plugins: [solidStart(), nitro()]` (docs.solidjs.com/solid-start/v2/guides/deployment-plugins), and the migration guide explicitly deprecates the nitro-2 path (`@solidjs/vite-plugin-nitro-2`). For a plain Node server on `$PORT` behind a proxy (the spec's requirement), nitro is the only portable option. The app also uses `query` + `"use server"` correctly per the v2 data-fetching docs, including the subtle "place `"use server"` inside the inner function, not the file" rule — all six occurrences in `app/src/lib/queries.ts:348,353,359,408,445,514` follow it.
