## Review

**Structure & framework use.** The app is squarely idiomatic Nuxt 4 (pinned to the current stable, 4.6.3, released two days before "today"): `app/` srcDir with `pages/`, `components/`, `layouts/` (`app/app.vue:1`), Nitro routes under root `server/` with `defineEventHandler`/`getRouterParam`/`getQuery`/`setResponseStatus` (`app/server/api/app/pokemon/[name].get.ts:2-6`), reactive URL `useFetch` for param-driven pages (`app/app/pages/pokemon/[name].vue:104-107`), a keyed `useAsyncData` for the shared dex index (`app/app/pages/index.vue:55`), and URL-as-state routing for filters. The server/client boundary is clean: app code never imports the data layer, everything goes through `/api/app/*`.

**What I'd flag before merging**

1. **Leaked debounce timer on the home page** — `app/app/pages/index.vue:104-113`: the 250 ms `setTimeout` is never cleared on unmount. Type a query, then click a card within 250 ms: after navigating to `/pokemon/x`, the timer fires `router.replace({ path: '/' })` and yanks the user back to the home page. Clear it in `onUnmounted`/`onBeforeUnmount`.
2. **Errors conflated with not-found** — every detail page renders `NotFoundPage` whenever `data` is falsy (`app/app/pages/moves/[name].vue:46`, `types/[name].vue:33`, …). Since `useFetch` swallows the error into `error` and leaves `data` null, a 500 or a network hiccup shows "Not found" for a resource that exists. The `error` ref is never inspected anywhere.
3. **The data contract is `any` end-to-end** — `getPokemonPage`/`getMovePage`/etc. return `Promise<any | null>` (`app/server/utils/pokeapi.ts:243`, 438, 469, 496), the callbacks annotate nearly everything `(a: any, b: any)` (e.g. `pokeapi.ts:167-169`), and components consume the results untyped. In a codebase with typed route handlers (`defineEventHandler`), exporting one interface per page payload and `useFetch<PokemonPage>(…)` would let the compiler catch renames across the server/app boundary. This is the biggest maintainability gap.
4. **Deprecated overload in a page** — `app/app/pages/[...slug].vue:6` calls `setResponseStatus(404)`; the docs' current signature is `setResponseStatus(event, 404)` and the no-event form is marked deprecated (safe on the client, but not what the docs teach).
5. **Duplication and small smells in the data layer** — `typeLabel` map is built four times (`pokeapi.ts:161,230,282,442`), `displayNumber`/`isMissing` exist in two components (`MoveTables.vue:126` and `moves/[name].vue:56`), `index.species.find(...)` is a linear scan inside loops instead of one `Map` keyed by id (`pokeapi.ts:433,454,527`), and `findSpeciesSummary` (`pokeapi.ts:220`) is dead code.
6. **No failure state on the home page** — if `/api/app/dex` fails, `index.value` is null and the page shows "No Pokémon found" and "0 Pokémon" (`index.vue:39,55`) rather than anything indicating a load problem.
7. **Redundant `watch: [game]`** on the pokemon page's `useFetch` (`pokemon/[name].vue:109`) — the reactive `query` object already drives refetching; harmless but noise.

**What's good**: promise caches with rejection-eviction (`pokeapi.ts:89-95`), failed index builds reset so a retry happens (`pokeapi.ts:140`), `loading="lazy"` + explicit sprite dimensions (`PokemonCard.vue:8-14`), thoughtful `aria-sort` handling with missing-values-last tie-breaks (`MoveTables.vue:110-133`), recursive `EvolutionTree` using Vue's implicit self-reference, and a single consistent stylesheet.
