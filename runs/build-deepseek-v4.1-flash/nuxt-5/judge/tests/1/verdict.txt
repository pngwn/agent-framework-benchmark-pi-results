## Review: test quality

**The agent wrote no tests at all.** The measured facts agree with what I found on disk: zero test files anywhere in `app/`, no `test` script in `app/package.json`, and no devDependencies (only `nuxt`, `vue`, `vue-router`). There is no `vitest.config`, no `@nuxt/test-utils`, nothing. The app's only safety net is the externally-provided acceptance suite, which the agent was told to satisfy — so per the dimension rules, `coverage_of_risk` and `regression_power` score at 1, and the useful output here is the untested-risk map below.

This is a real loss, because the code is unusually testable for a Nuxt app and the risk is concentrated in exactly the places cheap tests would guard:

- `app/server/utils/pokeapi.ts` is a ~600-line data layer with hand-rolled logic (index building, form exclusion at line ~190, generation mapping, move-table grouping, a custom concurrency pool) that a Vitest suite could cover directly — `humanize`, `collapseWhitespace`, `latestEnglishFlavor`, `englishName` are already exported (lines 24–52), and the current stable path is `@nuxt/test-utils` v4 + Vitest (v4.3.4 is current; `mountSuspended`/`registerEndpoint` would cover both component and server-route layers).
- `app/app/pages/index.vue:57-136` and `app/app/components/MoveTables.vue:100-131` hold the fiddliest client logic (URL query sync, debounce, missing-values-last sorting) and would fall to the first careless refactor.

Notable latent bugs that a test would have caught, but nothing did:

- `app/app/pages/index.vue:127-132` — the debounce watcher's `same` check compares `route.query[key] === query[key]` by strict equality; an array-valued param (`/?q=a&q=b`) would never compare equal and would push a redundant history entry. Untested URL-state handling invites exactly this class of bug.
- `app/server/utils/pokeapi.ts:300-303` — an evolution-chain fetch failure is silently swallowed into a single-node "chain", so a Pokémon would render an empty evolution section with no signal anywhere.
- `app/app/pages/index.vue:88-89` — `requestedPage` accepts `?page=2.5` via `Math.floor`, and clamping to `totalPages` silently rewrites user-visible pagination; both are guessable-by-hand behaviours with no assertions.
