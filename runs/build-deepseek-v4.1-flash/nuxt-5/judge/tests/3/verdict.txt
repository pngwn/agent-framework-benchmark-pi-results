## Review — Test quality

The app contains **zero tests of its own**: no test files, no test runner in `package.json` (`app/package.json:6-9` defines only `dev`/`build`/`start`), no test dependencies, no config. Every verification relied on the acceptance suite in `tests/`, which the agent doesn't own. Per the dimension rules, `coverage_of_risk` and `regression_power` score 1, and the value of this review is the map of what's unguarded.

Where the bugs will hide once someone refactors:

**Data layer (`app/server/utils/pokeapi.ts`, ~550 lines, entirely untested).**
- `humanize` and `collapseWhitespace` (`app/server/utils/pokeapi.ts:45-55`) are pure functions feeding every label and flavor text in the app; a one-character regex change silently mangles everything, and no app-owned test would notice.
- The alternate-forms exclusion is a single comparison (`app/server/utils/pokeapi.ts:184` — `ref.id < 10000`; also `:221`). Drop it and Mega forms flood every list; invert it and the dex is empty.
- `apiGet`'s cache evicts rejected promises so failures aren't cached forever (`app/server/utils/pokeapi.ts:99` — `promise.catch(() => rawCache.delete(key))`). This is the kind of line that disappears in a refactor and produces a permanently-broken page after one upstream 500.
- Game selection: default = highest-order available group, query override only if valid (`app/server/utils/pokeapi.ts:327-330`), method table ordering (`:260-264`), level-up sort by level-then-name and the `${method}|${move}|${level}` dedup key (`:341-343`, `:382-386`).
- Species↔Pokémon reconciliation for move/ability/type pages (`:459-465`, `:489-495`, `:541-546`) — mapping `deoxys-normal` back to species `deoxys` and excluding ID ≥ 10000 again.
- The effect fallback chain short_effect → flavor → `—` (`:455-457`) and the `—` for null power/accuracy/PP are each one-off conditionals.

**Frontend URL state and sorting (untested).**
- The debounced search watcher and the "same query" comparison in `app/app/pages/index.vue:97-111` — this is the subtlest logic on the home page (dropping `page` from the equality check so filters reset pagination; `router.replace` vs `push`). A bug here shows up as double history entries or lost filter state.
- Pagination clamp: `page=abc`/`page=0` → 1, `page=999` → last page (`app/app/pages/index.vue:75-80`).
- The move-table comparator (`app/app/components/MoveTables.vue:104-131`): missing-values-last in both directions, numeric vs. label columns, descending flip, tie-break, and `aria-sort` on exactly one header — high bug density, zero coverage.
- Game select preserving hash and query (`app/app/pages/pokemon/[name].vue:96-98`).

**Error paths.** 404 → `{found:false}` + `setResponseStatus(404)` (`app/server/api/app/pokemon/[name].get.ts:3-6`), the catch-all page (`app/app/pages/[...slug].vue:1-7`), and what happens when the upstream API returns 500 (unhandled throw → Nitro error page) are unguarded by anything the team owns.

The cheapest high-value first step would be Vitest + `@nuxt/test-utils` unit tests on the pure functions in `pokeapi.ts` and the `MoveTables` comparator, plus a couple of Playwright specs mirroring the URL-state rules.
