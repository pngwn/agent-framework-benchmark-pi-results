## Review: Nuxt Pokédex (`app/`)

**Framework baseline.** I verified the current stable releases before judging: Nuxt **4.6.3** (2026-10-27, the newest stable — github.com/nuxt/nuxt/releases), Vue **3.5.44** (3.6 is still at RC.13), vue-router **5.4.0** (2026-10-07). The app pins exactly those (`app/package.json:8-10`), so it is on the current generation, not the one in my training data.

**What ages well here.** This is textbook current Nuxt 4: the `app/` srcDir layout with `pages/`, `layouts/`, `components/` (`app/app/`), Nitro server routes under `server/api/app/**` with h3's `defineEventHandler`/`getRouterParam`/`getQuery`, and reactive `useFetch` — e.g. `app/app/pages/pokemon/[name].vue:101-104` uses a URL function plus `watch: [game]`, the current way to refetch on query change. `setResponseStatus(404)` in a page (`app/app/pages/[...slug].vue:6`) is a real supported composable, not a Nitro util smuggled into the client — confirmed in the generated `app/.nuxt/imports.d.ts:16` (`export { … setResponseStatus } from '#app/composables/ssr'`). `defineEmits<{ 'select-game': [name: string] }>()` (`app/app/components/MoveTables.vue:67`) is the newer tuple-of-args signature. Filter state lives entirely in the URL (`app/app/pages/index.vue:96-113`), which is the churn-resistant choice for a list page. All upstream data access is funneled through one module, `app/server/utils/pokeapi.ts`, with in-memory promise caching (`pokeapi.ts:27`, `84-92`) — an API data change ripples through exactly one file.

**Where it will show wear.** The boundary types are thin: the page getters return `Promise<any | null>` (`pokeapi.ts:267`, `432`, `473`, `506`) and `MoveTables.vue:56` types rows as `Array<any>`, so a field rename on the server is invisible to the compiler on the client; Nuxt 4's `shared/` folder exists precisely for this. `VALID_TYPE_NAMES` hardcodes the 18 type names (`pokeapi.ts:33-40`) rather than deriving "everything except stellar/unknown/shadow" from `/type/`, so a data change silently hides content. `process.env.API_BASE_URL` is read directly (`pokeapi.ts:4`) instead of `runtimeConfig`/`useRuntimeConfig`, and `displayNumber` plus the dex-number formatting are each implemented twice (`app/app/pages/moves/[name].vue:55` vs `MoveTables.vue:132`; `PokemonCard.vue:13` vs `pokeapi.ts`). `compatibilityDate: '2025-07-15'` (`app/nuxt.config.ts:2`) is ~15 months stale relative to the pinned Nuxt, which is exactly the flag that gates new default behavior.

**Platform.** Good instincts: native `fetch` + `new URL` for API URLs (`pokeapi.ts:68`, `84-85`), native form controls including `type="search"` (`app/app/pages/index.vue:8`), `loading="lazy"` with explicit width/height to avoid layout shift (`PokemonCard.vue:9-14`, `pokemon/[name].vue:9-16`), CSS custom properties throughout (`main.css:8-12`), `:focus-visible` (`main.css:34`), and zero polyfills or wrapper libraries. Two hand-rolled spots hold it back from a 5: the manual `scrollToHash` dance (`pokemon/[name].vue:114-126`) re-implements what a `router.options.ts` `scrollBehavior` would handle, and the debounce timer (`index.vue:104-113`) does not cancel superseded requests.

**Dependencies.** Three direct deps, all at the current stable version, matching what `nuxi init` generates; nothing extra, no CSS framework, no lodash/axios. This is the best-case answer for this axis.
