## Review — test quality

The app is a vanilla TS + Vite SPA served by a small static `node:http` server. There is **no test infrastructure at all in `app/`**: no test runner dependency (`app/package.json:6-9` — only `typescript` and `vite`), no test script (`"scripts"` has only `dev`/`build`/`start`), and no `*.test.*`/`*.spec.*` files anywhere under `app/src` (grep for vitest/jest/playwright/spec patterns: zero matches). The acceptance suite in `tests/` (Playwright, ~50 cases) is the *only* guard, and it was provided by the harness — the agent deserves no credit for it.

That means the pure logic — exactly the parts that a refactor will silently break — is unit-testable but untested:

- **`sortRows` / `compareValues`** (`app/src/pages/pokemon.ts:74-110`): null-values-last in *both* directions, per-method default ordering, tie-break by name, `aria-sort` state. This is the single most regression-prone function in the codebase; the acceptance test only clicks one header once.
- **Species mapping** (`app/src/api.ts:216-262`): the `id > 10000` alternate-form exclusion, Map-based dedup (which also merges `hidden` flags), and dex-number sorting. Swapping the exclusion predicate or the sort comparator would only fail the suite for the specific fixture species.
- **URL state** (`app/src/pages/home.ts:17-27` and `101-108`): `buildUrl`'s "omit empty/default params" rule and the page clamping (`state.page > totalPages` → clamp, `totalPages === 0` → 1). Deep-link cases like `/?page=999` are not exercised by the suite.
- **`escapeHtml`-based string rendering** (`app/src/components.ts:3-10`): every page is built by `innerHTML` concatenation; one missed escape on a humanized name (`Farfetch'd`, `Mr. Mime`) breaks markup or worse. There is no test that would catch someone deleting an `escapeHtml` call.
- **Helper fallback chains** (`app/src/api.ts:167-196`): `englishName` → humanized fallback, `latestEnglishFlavor` (last English entry, whitespace collapse), `englishShortEffect`. Inverting "last" to "first" or dropping the trim would pass the fixtures by luck.
- **Race guards** (`app/src/main.ts:19-23` renderToken, `app/src/pages/pokemon.ts:349-359` gameRequest): removing the stale-render checks produces intermittent bugs the sequential Playwright suite will essentially never catch.
- **`server.mjs`** (`app/server.mjs:45-56`): path-traversal guard (`file.startsWith(DIST + path.sep)`), `<`-escaping of the injected `__API_BASE_URL__` script, and the SPA fallback branch — all untested, all security-adjacent.

On the plus side, the risky logic is factored into exported, side-effect-free functions (`humanize`, `englishName`, `latestEnglishFlavor`, `speciesFromPokemonList`, `sortRows`, `buildUrl`) that a unit suite could target directly with a couple of dozen lines — the architecture makes the *absence* of tests the more glaring.

### Scores

**coverage_of_risk: 1** — no tests exist; none of the transformation/filtering/sorting/URL-state logic above is covered by anything the app owns (`app/src/api.ts:167-262`, `app/src/pages/pokemon.ts:55-110`, `app/src/pages/home.ts:17-27`).

**behaviour_not_implementation: 1** — no tests at all.

**regression_power: 1** — with zero app-owned tests, any refactor of the data layer (`getHomeData`'s type-index construction at `app/src/api.ts:325-350`, the species mapping, move-table assembly) is guarded only by the frozen acceptance suite, which won't follow the code into new branches.

**signal_to_noise: 3** — no tests, hence no noise (per the rubric's no-tests anchor).

**overall: 1** — the spec's only hard testing requirement was the provided suite, so this isn't a spec violation, but as a PR into a codebase we'll own for years, shipping ~850 significant LOC of untested sorting/filtering/string-building logic with zero runner even configured is a reject-and-ask-for-tests situation.
