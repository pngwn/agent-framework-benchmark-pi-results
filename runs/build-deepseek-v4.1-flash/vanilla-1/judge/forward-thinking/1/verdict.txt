## Review: `app/` (vanilla TS + Vite Pokédex)

**Toolchain currency (verified).** `vite ^8.3.5` (`app/package.json:12`) is the latest stable — 8.3.5 shipped 2026-10-21 per npm/releases page. `typescript ^7.0.2` (`app/package.json:11`) is the current stable native (Go) compiler, GA 2026-07-08. Both are pinned at today's newest, so the project starts on the current generation rather than needing an upgrade pass. TS 7.0 has no programmatic API, but nothing here consumes tsc programmatically — Vite 8 transpiles with its own toolchain — so the pairing is sound.

**Architecture.** All API access, response types, normalization and caching are centralized in `app/src/api.ts` (cache at api.ts:184–200; species/generation/type aggregates at api.ts:255–379). Routing is one hand-rolled dispatcher over `history.pushState`/`popstate` (main.ts:47–96) with a render-token guard (main.ts:18–23) — still the correct vanilla-JS pattern; the Navigation API exists but `pushState` is neither deprecated nor superseded guidance. Config injection is a single resolution point (api.ts:1–6) backed by the server injecting one script tag (server.mjs:31–34). Nothing depends on framework internals.

**Platform use.** Good reach for the platform: `fetch` with a promise-cache instead of a data layer, `URL`/`URLSearchParams` (home.ts:13–19), `loading="lazy"` + intrinsic `width`/`height` on sprites (components.ts:49), `replaceAll`/`padStart`, `aria-live` results region (home.ts:70), CSS custom properties and grid throughout.

**Deductions.**
1. The dominant pattern is HTML string concatenation with a hand-rolled `escapeHtml` (components.ts:3–11). Every new interpolated value depends on a developer remembering to escape — a per-field XSS/rendering-churn risk as requirements move. A tagged-template `html` helper or DOM/`<template>` construction would make escaping structural.
2. Inline `onerror="this.style.visibility='hidden'"` (components.ts:49) breaks under any future CSP with `unsafe-inline` disabled; a delegated `error` listener (capture phase) or CSS fallback ages better.
3. `apiFetch<any>` (pokemon.ts:144, 150) punches through the otherwise-solid typed boundary — the one place the API types could drift undetected.
4. `<a href="/pokemon/${encodeURIComponent(...)}">` in `renderEvolutionNode` (pokemon.ts:112) duplicates `speciesHref` (components.ts:14) — two places to change if routes move.
5. TypeScript is declared as a devDependency but no script runs it (`package.json:6–9`, `tsconfig.json` `noEmit`); types can rot silently since nothing gates on them.
6. `loadMoveTables` fires one request per distinct move for the selected game (pokemon.ts:129–147) — fine while cached, but a boundary the "live data can change" requirement could stress; version-group `order` lookups (pokemon.ts:395–410) add ~10 more requests per Pokémon page on first visit.

No legacy or deprecated framework APIs found; nothing that a Vite 9 or TS 7.1 release would force to ripple.
