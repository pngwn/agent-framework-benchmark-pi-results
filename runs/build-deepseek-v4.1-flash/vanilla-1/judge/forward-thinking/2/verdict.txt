# Forward-thinking review: Pokédex (vanilla TS + Vite)

## Toolchain currency (verified)

- **Vite 8.3.5** is the current stable (released 2026-10-21; only `vite@8.3` gets regular patches — vitejs/vite releases page). The app pins `^8.3.5` in `app/package.json:8` — exactly current.
- **TypeScript 7.0.2** is the current stable native port (released 2026-08-20, per microsoft/TypeScript releases; `create-vite@9.3.2` switched its templates to TS 7). The app pins `^7.0.2` (`app/package.json:7`). Notably, Vite 8 is the Rolldown/Oxc-based major, so the whole stack is post-training-data current.
- **Vite 8 default `build.target` is `'baseline-widely-available'`** (chrome111/edge111/firefox114/safari16.4 per the v8 migration guide). The app pins `chrome120` (`app/vite.config.ts:4`) — a valid, slightly conservative choice, not legacy.
- `import.meta.env` (`app/src/api.ts:3`), `defineConfig`, `moduleResolution: "bundler"` + `isolatedModules` (`app/tsconfig.json`) are all current-generation APIs; nothing in the tsconfig is on TS 7's removed-options list.

## What ages well

- **Zero runtime dependencies.** Only two devDependencies, both current. Data access is entirely `fetch` (`app/src/api.ts:154`) behind one typed module; caching is a promise-map (`app/src/api.ts:152`).
- **No hand-rolled server framework**: `app/server.mjs` is ~85 lines of `node:http` + `fs.createReadStream` with a correct path-traversal guard (`app/server.mjs:60`), instead of pulling in Express for a static file server. Correctly leaves compression/TLS to the proxy per spec.
- **Platform-first client code**: native `fetch`, `URL`/`URLSearchParams` (`app/src/pages/home.ts:13`), native form controls with real `<label>`s, `loading="lazy"`, CSS custom properties throughout, `aspect-ratio` (`app/src/style.css:611`), `:focus-visible`, `object-fit`, `font-variant-numeric: tabular-nums`. No polyfills anywhere.
- **Data-driven resilience**: the home page's type-by-species map is derived from the type catalog at runtime (`app/src/api.ts:376-396`), not hardcoded, so it survives the live-data-overlay test scenario; API base URL resolves in exactly one place (`app/src/api.ts:1-5`).
- **Churn containment**: all API record shapes live in `app/src/api.ts:19-124`; the router is a single ~30-line pushState dispatcher (`app/src/main.ts:25-80`) with a central not-found path; the `isActive` render-token pattern (`app/src/main.ts:26-27`) guards against stale async renders on every page.

## What will cause churn

1. **The typed boundary is broken for moves.** `app/src/pages/pokemon.ts:144` uses `apiFetch<any>(url)` and `:150` maps `(record: any)` even though a complete `MoveRecord` interface exists at `app/src/api.ts:88-97` and is unused. This is the one place API shape changes would silently ripple.
2. **TypeScript is installed but never run.** `build` is just `vite build` (`app/package.json:6`); there's no `tsc --noEmit`. The current `create-vite` vanilla-ts template convention is `tsc && vite build`, and TS 7 makes that nearly free (8–12x faster builds). Today the 170 lines of types are editor-only decoration and drift (see finding 1) goes uncaught in CI.
3. **Inline event handler**: `app/src/components.ts:49` embeds `onerror="this.style.visibility='hidden'"` in an `innerHTML` string — a legacy pattern that's CSP-hostile and invisible to the typed code. An `'error'` listener attached after insertion (or a small `onError` helper) is the modern equivalent.
4. **Title-setting is scattered**: `document.title` is assigned ad hoc in 8 places (`app/src/pages/details.ts:68,99,117,182,192`, `home.ts:83`, `pokemon.ts:356`) instead of one page-shell helper — a new page (or a title-rule change) must remember it.
5. **Data/CSS coupling**: `.type-<api-name>` classes (`app/src/style.css:261-277`) require a CSS rule per type name; a token-to-color map setting a custom property would decouple data from stylesheet.
