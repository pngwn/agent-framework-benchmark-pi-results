## Review: `app/` — experimentalness

**Baseline:** The app targets SvelteKit 3 (`app/package.json` pins `@sveltejs/kit@^3.1.0`, `svelte@^5.57.2`, `@sveltejs/adapter-node@^6`, `vite@^8`), which shipped as stable on 2026-10-01 (confirmed via svelte.dev/blog/sveltekit-3-is-here). Every "new-looking" API in the concepts list is part of that stable release, not a preview channel. The static facts already report `experimental: []`, and my own grep for `experimental`/`unstable_`/`remote` across `app/src` confirms it: zero experimental flags, zero remote functions, zero `.remote.ts` modules.

**What's actually new here (and how new):**

- `defineEnvVars` from `@sveltejs/kit/env` (`app/src/env.ts:1-8`) — added as an experimental option in SvelteKit 2.62, moved to its own subpath in 2.70 (Aug 2026, per the "What's new in Svelte: August 2026" blog), and is now the *standard* mechanism in Kit 3, where the legacy `$env/*` modules are deprecated and slated for removal in Kit 4 (svelte.dev/docs/kit/environment-variables). **Recently stable, and the current recommendation.** Using the old `$env/static/private` here would have been the outdated choice.
- `API_BASE_URL` from `$app/env/private` (`app/src/lib/server/api.ts:2`, used at `:22`, `:23`, `:87`) — the Kit 3 replacement for the deprecated modules. ~4 weeks stable as part of the 3.0 release.
- SvelteKit 3 conventions: config in `vite.config.ts` with `compilerOptions` on the plugin (`app/vite.config.ts:6-11`), `#lib/*` subpath imports (e.g. `app/src/routes/+page.server.ts:1`), `goto(..., { reset: false })` replacing `noScroll`/`keepFocus` (`app/src/routes/+page.svelte:45`, `app/src/routes/pokemon/[name]/+page.svelte:111` — confirmed against svelte.dev/e/kit/goto_options_removed and the Kit 3 migration guide). All stable, but all four weeks old.
- `runes` compiler option given as a function of `filename` (`app/vite.config.ts:8-10`) — this form was merged into Svelte in March 2026 (sveltejs/svelte#17951) and is stable in 5.57; the inline comment correctly notes it's a temporary shim until Svelte 6.
- Everything else — `$state`/`$derived`/`$props`, `Snippet` + `{#snippet}`/`@render` (`app/src/lib/components/Section.svelte:2-4`, `app/src/routes/pokemon/[name]/+page.svelte:19-31`), `page` from `$app/state` (`app/src/routes/+error.svelte:2`, stable since Kit 2.12, Jan 2025), `afterNavigate`/`goto` (`app/src/routes/+page.svelte:2,18`) — has been stable for one to two years.

**Restraint worth noting:** the Kit 3 blog explicitly says remote functions are "not quite ready", and Svelte 5.5x shipped experimental async APIs — the app uses neither, and solves client-side URL-sync with plain `afterNavigate` + `goto` (`app/src/routes/+page.svelte:17-47`). No `kit.experimental`, no `data-sveltekit-*` edge flags, no canary anything.

**Containment:** the env-var surface (the most recently-stabilized API) is exemplary — one declaration module (`app/src/env.ts`), one consuming import (`app/src/lib/server/api.ts:2`), all data flowing through `lib/server/api.ts` so a future API change has a single seam. The Kit-3-wide choices (`#lib`, `vite.config.ts`, `reset: false` in two routes) are inherently spread across the tree, but that's platform adoption, not gratuitous novelty.
