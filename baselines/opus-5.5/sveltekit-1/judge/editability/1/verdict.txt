## Scenario walk-through

**1. Remove the Abilities pages.** Delete `app/src/routes/abilities/` (self-contained, no nav link to remove — nav only has Pokémon/Types). But links and support code leak elsewhere: the Abilities section on the Pokémon page (`app/src/routes/pokemon/[name]/+page.svelte:105-116`), the `abilities` mapping in its load (`app/src/routes/pokemon/[name]/+page.server.ts:135-140`), and — the real entanglement — the "hidden ability" feature threads from `app/src/lib/server/api.ts:86-97` (`cardsFor`'s `is_hidden` propagation, used *only* by the ability page) through `Card.hidden` (`app/src/lib/types.ts:16`) into the generic `CardList.svelte:18-20`. Deleting just the route leaves all of that dead. ~6 files, all grep-findable.

**2. Sprite fix (Deoxys-class bug).** Sprite URL construction is centralized in `spriteUrl` (`app/src/lib/server/api.ts:83-85`), so a URL-shape fix is one place and covers every list. But card *assembly* is duplicated: `cardsFor` builds cards for moves/abilities/types (`api.ts:80-100`) while the home page builds its own cards inline (`app/src/routes/+page.server.ts:70-79`). A fix needing the default Pokémon's own data (not derivable from the species ID) lands twice, and the home-page loop doesn't currently have that data.

**3. Sorting by name on every card list.** `CardList.svelte` renders all four lists via one `cards` prop, so one change there covers moves/abilities/types. The home list is paginated server-side (`+page.server.ts:84-88` slices before the client sees it), so full-set name ordering also needs a sort change in the load. Two obvious files.

**4. Items section shaped like Moves.** Route boilerplate is per-route by design, but everything load-bearing is shared: `fetchByName`/`fetchOr404` (`api.ts:44-60`), `englishName`/`cleanText`, `Section`, `CardList`, `TypeBadge`, `orDash`/`pageTitle`. You'd add an item-sprite helper next to `spriteUrl` and copy the ~40-line `+page.svelte` pattern. High reuse, no flag-parameter creep.

**5. Data source change.** `API_BASE_URL` is declared in `app/src/env.ts:3-8` and consumed only in `app/src/lib/server/api.ts` (`resolveUrl`, `spriteUrl`). Caching is one constant + one Map in the same file (`api.ts:11-13`). Two files, trivial.

## Strengths worth noting

- Server/client seam is exemplary: all API knowledge lives in `#lib/server/api.ts`; pages receive serializable view-models typed in `#lib/types.ts`; components take narrow typed props (`Card`, `TypeRef`, `MoveTable`).
- 404 handling is centralized in `fetchOr404`/`fetchByName` — one place controls "resource missing → Not found" for all four resource types.
- Formatting rules (humanize, dex number, em dash, page title) each have exactly one home in `#lib/format.ts`.
