## Review: forward-thinking

### Framework currency

SvelteKit 3 went stable **2026-10-01** (a month ago), and this app is not merely "migrated" to it — it is written *natively* in the Kit 3 idiom. I verified each API against the official docs, the Kit 3 migration guide and release notes:

- **Config in `vite.config.ts`, no `svelte.config.js`** — exactly what Kit 3 requires; `adapter` and `compilerOptions` are top-level plugin options (`app/vite.config.ts:5-17`). Confirmed against `svelte.dev/docs/kit/migrating-to-sveltekit-3`.
- **`#lib` subpath imports** replace `$lib`, declared in `package.json` `imports`, and imports carry explicit `.ts` extensions (`app/package.json:12`, `app/src/lib/components/CardList.svelte:2`) — the exact Kit 3 pattern.
- **Explicit environment variables**: `src/env.ts` with `defineEnvVars` + `$app/env/private` (`app/src/env.ts:3`, `app/src/lib/server/api.ts:2`) — the stable Kit 3 replacement; `$env/*` is deprecated (docs: "deprecated in SvelteKit 3, removed in SvelteKit 4"). The app uses **zero** deprecated `$env/*` imports (grep-verified).
- **`compilerOptions.runes` as a function** with the "skip `node_modules`" trick (`app/vite.config.ts:11-14`) — this is the *newest* form, added in svelte PR #17951 (March 2026), matching what `sv create` generates, with a correct "can be removed in svelte 6" comment.
- **`goto` with Kit 3 option names** `{ replace, reset: false }` (`app/src/routes/+page.svelte:43`) — post-migration naming (`replaceState`→`replace`, `keepFocus`/`noScroll`→`reset`), not the removed older forms.
- **`$app/state`** (`app/src/routes/+error.svelte:2`) — current; `$app/stores` was *removed* in Kit 3.
- **`PageProps`/`LayoutProps`** generated types (`app/src/routes/+page.svelte:5`, `app/src/routes/+layout.svelte:3`), runes throughout (`$state`/`$derived`/`$derived.by`), snippets + `{@render}` instead of slots (`app/src/routes/pokemon/[name]/+page.svelte:21-30`, `app/src/lib/components/Section.svelte`), keyed each-blocks, `oninput`/`onchange` event attributes, `style:` custom properties (`app/src/lib/components/TypeBadge.svelte:7`). No legacy `export let`, `on:click`, `$:` or stores anywhere.
- **`tsconfig.json` extends `$app/tsconfig`** with its own `include` (`app/tsconfig.json:1-7`) — the Kit 3 form, not the old `./.svelte-kit/tsconfig.json`.
- Remote functions aren't used — correct, since the Kit 3 announcement says they're not ready yet; server `load` functions remain the current data-loading primitive.

### Platform

Reaches for the platform first: native `fetch` everywhere, `URLSearchParams` for all query-string building (`app/src/routes/+page.svelte:28-35`), `Array.prototype.findLast` (`app/src/lib/server/api.ts:92`), `localeCompare` sorting, CSS custom properties + grid + `clip-path` visually-hidden pattern (`app/src/app.css:124-134`), `loading="lazy"` + intrinsic `width`/`height` on sprites (`app/src/lib/components/CardList.svelte:10`), and a real `method="get"` form fallback so filtering degrades gracefully without JS (`app/src/routes/+page.svelte:48-56`). No polyfills or hand-rolled URL parsing beyond a trivial ID regex (`app/src/lib/server/api.ts:96-98`).

### Dependencies

Zero runtime dependencies; all eight devDependencies are the required toolchain at exactly the Kit 3-paired majors: Kit `^3.1.0`, Svelte `^5.57.2` (Kit 3 minimum is 5.57.1), Vite `^8.3.0` (rolldown-based, Kit 3 minimum 8.0.12), vite-plugin-svelte `^7.2.0`, adapter-node `^6.0.0` (the release that pairs with Kit 3 and drops the `ORIGIN` env var), TypeScript `^6.0.3`, `engines.node >=22.17` matching the documented minimum, plus `@types/node ^24` and `svelte-check`. Nothing questionable, nothing missing that should be there.

### Churn resistance

Data access is fully behind one module (`app/src/lib/server/api.ts`), page-boundary types in `app/src/lib/types.ts`, env in one `src/env.ts`, all framework config in `vite.config.ts`. Upgrading Kit or swapping the API base URL would touch almost nothing. The deductions: the `Move` API-shape interface is copy-pasted between two load files (`app/src/routes/moves/[name]/+page.server.ts:12-22` vs `app/src/routes/pokemon/[name]/+page.server.ts:53-60`); `spriteUrl` derives sprite URLs from an ID pattern rather than the API's `front_default` field (`app/src/lib/server/api.ts:82`); and `+error.svelte` could use Kit 3's newer zero-config `error`/`status` props instead of reading `page`. All minor.
