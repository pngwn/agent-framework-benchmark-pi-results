# Editability review — Pokédex app (vanilla TS + Vite)

**Architecture in one line:** a hand-rolled client-side router (`src/main.ts`) over per-route page modules (`src/pages/*`) that share thin helpers in `src/api.ts` (typed fetching + cache), `src/components.ts` (UI primitives), `src/format.ts` (pure formatters), `src/dom.ts` (`h`), `src/table.ts` (generic sortable table), and a static `server.mjs` for production serving. No page imports another page; only `main.ts` knows the route table.

**Scenario walkthrough**

1. **Remove Abilities.** Grep for `abilit` finds everything: `main.ts:6,22` (import + route), delete `pages/ability.ts`, the Abilities section in `pages/pokemon.ts:93-108,126` (and its `content` array slot), the `Ability` interface and `pokemon.abilities` field in `api.ts:57,79`, and the route entry in `server.mjs:36`. Nav is static in `index.html:14-16` and doesn't link abilities, so no template edit. Leaves one dead CSS rule (`.card-note`, `style.css:247`). Five files, but every edit is a one-liner found by a single grep — good, not great.

2. **Sprite bug (Deoxys).** Every card list funnels through `pokemonCard` (`components.ts:43`) and `spriteUrl` (`api.ts:143`); references → species mapping is centralized in `speciesCards` (`components.ts:66-80`). One fix covers type/move/ability lists. The catch: home builds cards separately (`home.ts:81-89`) from species refs, and `CardData` carries only `{id, name, extra}` (`components.ts:38`) — a fix needing the Pokémon record's `sprites.front_default` would ripple to every caller. A URL-pattern fix is one line.

3. **Sort by name.** Two spots: `speciesCards` sorts by id (`components.ts:78`) and home's order comes implicitly from the pre-sorted `speciesList()` (`api.ts:152`) with no explicit sort in `home.ts:75-86`. No shared "order" knob on `cardList`.

4. **Items section.** Page-shape helpers (`section`, `descriptionList`, `count`, `cardList`, `englishName`, `humanize`, `getResource`) are all reusable; a new `pages/item.ts` modelled on the 35-line `pages/move.ts` is nearly free. But you must touch `main.ts:17-24`, `server.mjs:46-52` **and** `api.ts` — and the route regexes are hand-duplicated between the client router and the server's 404 prober.

5. **Data source change.** Base URL lives in `api.ts:6` (client, injected via `window.__API_BASE_URL__` by `server.mjs:30`) and `server.mjs:14` (server) — two runtimes, so two places is fair. Caching is a single in-flight promise cache inside `get` (`api.ts:87-103`); changing cache policy is one edit.

**What's genuinely good:** the `speciesCards` abstraction captures the real variation in the app ( Pokémon-reference lists need de-duplication, form filtering, species renaming, and an optional `extra` note) instead of flag params; `sortableTable` is generic over columns with a clean sort-key/missing-last contract (`table.ts:5-40`); `MISSING`/`orMissing` centralize the em-dash rule; formatters are pure and dependency-light.

**What costs it the last point:** route patterns duplicated between `main.ts` and `server.mjs` (drift risk on every new route), `home.ts:69` re-implementing `idFromUrl`, the `?? humanize(...)` type-label fallback repeated in four files, and zero unit tests in the app itself, so any refactor is validated only by the external acceptance suite.
