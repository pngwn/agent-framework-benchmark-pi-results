## Review: experimentalness

I've read the whole app surface (server, DOM helpers, api layer, pages, table, styles, configs) and checked the toolchain versions against current release notes.

**What's in the code.** The runtime surface is deliberately conservative: `node:http`/`node:fs`/`node:path`/`fileURLToPath` in `app/server.mjs:5-9`; global `fetch` plus `AbortSignal.timeout(3000)` (`app/server.mjs:56`) — a Node API stable since v17.3 (2022) and Baseline-widely-available in browsers since 2022; `Element.replaceChildren` (`app/src/dom.ts:40`), `history.pushState/replaceState/scrollRestoration` (`app/src/main.ts:68,90`, `app/src/url-state.ts:14-15`), `URL`/`URLSearchParams`, `findLast` (`app/src/format.ts:31`, ES2023), `padStart`, `localeCompare`, `img loading="lazy"/decoding="async"` (`app/src/components.ts:49`), ARIA (`aria-sort`, `aria-busy`, `aria-current`). `import.meta.env.VITE_API_BASE_URL` (`app/src/api.ts:9`) is a long-stable Vite API. No `vite.config` exists at all, so there are zero bundler flags; `tsconfig.json` is plain strict-mode ES2023 with no bleeding-edge compiler options; `style.css` uses no new CSS (no `:has`, `@layer`, `light-dark`, `@property`, `oklch` — grepped).

**Toolchain.** `app/package.json:7-8` pins `vite ^8.3.5` and `typescript ^7.0.2`. Both are the current **stable** majors, but both are recent: Vite 8.0 (Rolldown-based) went stable 2026-03-12 (vite.dev/blog/announcing-vite8) and TypeScript 7.0, the Go-native rewrite, went stable 2026-07-08 (devblogs.microsoft.com/typescript/announcing-typescript-7-0). Neither is experimental/preview; usage is vanilla (`tsc --noEmit && vite build`, no config, no plugin API), so TS 7's "no stable programmatic API until 7.1" caveat doesn't bite. That's the only early-adopter exposure, and it's confined to devDependencies.
