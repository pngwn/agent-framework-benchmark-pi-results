## Review — `app/` (TanStack Start + React Pokédex)

I read `SPEC.md`, all of `app/src` (routes, components, lib, server), `app/server.mjs`, `app/package.json` / lockfile, and verified every framework API I judged against the current TanStack Start/Router docs, the npm registry, and the official examples repo. The app pins **exactly the current stable versions** (`@tanstack/react-start` 1.169.4 = today's `latest`, `@tanstack/react-router` 1.170.46, React 19.3.1, Vite 8.3.5, TypeScript 7.0.2, srvx 1.0.7), and uses the current-generation API everywhere I checked:

- `getRouter()` in `src/router.tsx:12` matches the documented Start router shape verbatim (docs: "You must export a getRouter function…").
- `createServerFn({ method: 'GET' }).validator(...)` (`server/functions.ts:51,126,139,164`) — `.validator()` is the current spelling; `.inputValidator()`/`.input()` are the deprecated ones (confirmed against a June 2026 migration commit and the current server-functions docs).
- `HeadContent` / `Scripts` / `createRootRoute` with a `head()` handler, `notFound()` from `@tanstack/react-router`, `Route.useLoaderData()`, `validateSearch` + `loaderDeps`, `navigate({ hash: (prev) => prev ?? '' })` (`routes/pokemon.$name.tsx:142`) — the hash updater form is documented in `ToOptions`. All current.
- The production server (`server.mjs`) uses srvx to serve `dist/client` and forward to the Start fetch handler — precisely the shape the current hosting docs bless for custom Node servers, and the same srvx approach used in the official `TanStack/router` examples.

Deductions: one read of an underscore-prefixed router internal, no `AbortSignal` plumbed into the fetch layer, regex URL parsing instead of the `URL` API, and a build script that never type-checks.

**latest_apis: 5** — Every API is the current generation, on today's latest versions; no legacy patterns found.
**platform: 4** — Native fetch, native form controls, CSS custom properties + `auto-fill/minmax` grids, `useId`, `loading="lazy"`/`decoding="async"`, `encodeURIComponent`; but no abort/`URL` usage in the data layer.
**dependencies: 5** — Five zero-fluff runtime deps, all latest; srvx is zero-dependency and the documented choice.
**churn_resistance: 4** — Excellent layering (all API access behind `server/pokeapi.ts`, view-models typed in `lib/types.ts`, config in one place), marred by the `_notFound` internal read and `vite build`-only CI.

**overall: 4** — This is current, lean, and well-isolated; the few rough edges are cheap to fix.
