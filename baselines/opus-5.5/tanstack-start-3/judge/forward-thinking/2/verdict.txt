# Review: forward-thinking — Pokédex on TanStack Start 1.0

## What I verified before judging

- **Versions**: the app pins `@tanstack/react-start@^1.169.4` and `@tanstack/react-router@^1.170.46` — exactly the **latest stable** on npm today (checked registry; Start 1.0 went stable 2026-10-13, 1.169 is the first stable line). `srvx@^1.0.7` (latest is 1.0.8), `vite@^8`, `@vitejs/plugin-react@^6`, `react@^19.3.1`.
- **`.validator()`** (`app/src/server/functions.ts:29,64,84,…`): Start renamed `.inputValidator()` → `.validator()` (merged Jun 2026; the 1.169 "Migrate from the Release Candidate" guide lists `.inputValidator()` as removed). The app already uses the current name.
- **`HeadContent`/`Scripts` from `@tanstack/react-router`** (`app/src/routes/__root.tsx:2`): current — these moved out of `react-start` in v1.105 and match today's official e2e example verbatim, including the `head: ({ matches })` shape and `*.css?url` links.
- **`tanstackStart()` vite plugin** (`app/vite.config.ts:5`) with `viteReact()` after it, and `getRouter()` in `app/src/router.tsx:4` with `scrollRestoration` — matches current docs exactly; no removed `nitro-v2-vite-plugin`.
- **`notFound()` + `notFoundComponent`/`defaultNotFoundComponent`** (`app/src/routes/pokemon.$name.tsx:6`, `app/src/router.tsx:7`) — the current API (deprecated `NotFoundRoute` is not used).
- **srvx prod server** (`app/server.mjs`): `staticMiddleware({dir, compress, maxAge, immutable})` from `srvx/static` is the documented, current API, and the Node.js hosting doc explicitly blesses "serve `dist/client` as static assets and forward all other requests to the server entry's fetch handler. `srvx` is one way to do that." This is a leaner choice than pulling in Nitro.

## Scoring notes

**latest_apis — 5.** Everything is current-generation, including APIs renamed after most training data (`.validator()`), with exactly-latest-stable pins. One small blemish: `app/src/routes/__root.tsx:13` reads `m._notFound`, an internal, underscore-prefixed match property that the public `RouteMatch` docs don't document (the public signal is `m.status === 'notFound'`, which the same line already checks; `_notFound` also exists in the shipped types but not in docs).

**platform — 5.** Native-first throughout: native `type="search"`/`<select>`/`<label>` filters (`app/src/routes/index.tsx:96-121`), semantic tables with `caption`, `scope` and `aria-sort` (`app/src/components/MoveTable.tsx:101-116`), `res.body?.cancel()` on 404s to release connections (`app/src/server/pokeapi.ts:47`), CSS custom properties for all theming/type colors (`app/src/tokens.css`, `app/src/styles.css:171-188`), responsive `grid auto-fill/minmax` (`app/src/styles.css:261-266`), `loading="lazy"`/`decoding="async"` with explicit dimensions (`app/src/components/PokemonCard.tsx:14-19`), `useId` (`app/src/components/Section.tsx`), `import.meta.url`+`fileURLToPath` (`app/server.mjs:4-5`). Minor nit: `localeCompare` with no explicit locale (`app/src/components/MoveTable.tsx:37`).

**dependencies — 5.** Five runtime deps, all needed and at latest stable; zero-dep `srvx` instead of Nitro; no CSS framework, no validation lib, no query lib — router loaders + server functions cover it. `server/pokeapi.ts` is server-only (only `server/functions.ts` imports it), so nothing leaks across the boundary today.

**churn_resistance — 4.** Genuinely strong: all PokeAPI access behind one module (`app/src/server/pokeapi.ts`), one server-fn boundary (`app/src/server/functions.ts`) with typed inputs and view-model types in `app/src/lib/types.ts`, filter state in the URL via `validateSearch` rather than client state, and named constants everywhere (`TTL_MS`, `PAGE_SIZE`, `METHOD_ORDER`, `RELATIONS`). Deductions: (1) `"verbatimModuleSyntax": true` in `app/tsconfig.json:17` contradicts the current Start docs ("Enabling verbatimModuleSyntax can result in server bundles leaking into client bundles… keep this option disabled") — benign today only because every type import uses `import type`; (2) `m._notFound` internal property; (3) `build` is `vite build` with no `tsc --noEmit`, so 124 lines of types are never actually checked in CI; (4) `server.mjs:10` hard-codes the `dist/server/server.js` output path (documented, but a Start output rename would break `npm start` opaquely).

**Overall — 4.** This is the way I'd want a Start 1.0 app to look: current APIs, lean deps, centralized data access. The deductions are real but each is a one-line fix.
