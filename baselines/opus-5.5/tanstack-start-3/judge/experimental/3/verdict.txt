## Review: experimentalness of `app/` (Pokédex, TanStack Start + React)

**What's there.** Every dependency resolves to a stable release: `@tanstack/react-start@1.169.4` (the first stable release — Start 1.0 GA'd 2026‑10‑13, i.e. 17 days before "today"), `@tanstack/react-router@1.170.46` (stable for ~a year), `srvx@1.0.x` (GA'd ~Oct 2026; identical to 0.12.8), `react@19.3`, `vite@8` (the version Start 1.0 requires), `typescript@7`. A repo-wide grep for `unstable|experimental|preview|beta|canary` matches nothing in `app/` source (only a transitive lockfile entry), and `vite.config.ts` uses zero exotic flags — just `tanstackStart()` + `viteReact()`.

**API-level.** The only non-trivial framework surfaces are `createServerFn(...).validator().handler()` (the current, non-deprecated API — the RC-era `inputValidator` was *removed* in 1.169 and this app uses the right one), `createFileRoute`/`createRootRoute`/`HeadContent`/`Scripts`/`notFound()` (all stable Router v1 APIs), and the srvx fetch-handler convention (`dist/server/server.js` + `serve()`/`staticMiddleware`) — which is the exact pattern TanStack's own docs and examples use for Node production serving.

**Risk profile.** Zero experimental APIs, but the app necessarily rests on a framework that reached 1.0 two weeks ago. That risk is well-managed: every `createServerFn` lives in one module, the data layer is behind `src/server/pokeapi.ts`, and the entire production-server surface is a single ~18-line `server.mjs`. If any of these APIs shift, the swap points are concentrated and small.
