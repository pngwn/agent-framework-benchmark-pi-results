## Review: Pokédex (Next.js 16.4 App Router)

I read `SPEC.md`, all 16 source files in `app/src`, the acceptance tests, and verified the Next.js 16 idioms this code relies on against the current docs (App Router linking/navigating guide, the v16 upgrade guide, and the release notes for Turbopack/async-params/viewport/caching).

### What's good

- **Solid Next 16 alignment.** Async `params`/`searchParams` are awaited (`app/src/app/pokemon/[name]/page.tsx:10`), `generateMetadata` + `viewport` exports (`app/src/app/layout.tsx:6-16`), `metadata.title.template` for the `– Pokédex` suffix, `notFound()` per route, top-level `turbopack` config (`app/next.config.ts:6`), `compress: false` matching the stated proxy deployment.
- **The client-filter architecture for `/` is the docs' own pattern.** Filtering/paginating 1,026 entries client-side from server-computed props and syncing the URL with `window.history.pushState/replaceState` (`app/src/app/HomeView.tsx:84-98`, `app/src/app/HomeView.tsx:135`) is exactly the use case the "Native History API" section of the linking guide documents; the alternative (`<Link>` navigation) would force a server round-trip per keystroke.
- **Thoughtful data loading.** Building the home index from the 18 type records instead of 1,025 Pokémon records (`app/src/app/page.tsx:19-29`) is a genuinely smart read of the API shape. The shared cache dedupes concurrent in-flight requests, evicts on rejection, and is bounded (`app/src/lib/api.ts:8-26`, `app/src/lib/api.ts:57-59`).
- **Careful details**: modifier-key pass-through on pagination links (`HomeView.tsx:103-107`), NaN/0 page guard (`HomeView.tsx:19-27`), missing values always sort last (`MovesSection.tsx:52-56`), `aria-sort` only on the active header (`MovesSection.tsx:85`).

### What I'd ask to change

1. **Hand-rolled TTL cache where a framework feature exists** (`app/src/lib/api.ts:12`, `:8`). `cache: 'no-store'` + a custom `Map` with TTL and LRU-ish pruning reimplements what `fetch(url, { next: { revalidate: 30 } })` or `cacheLife` provides. The comment justifies it, and the spec permits in-memory caching, but a reviewer should be asked to either use the built-in or note why not.
2. **No `loading.tsx` on any route.** Every route here is dynamic (`connection()` in `api.ts:40`), and prefetch is explicitly disabled everywhere (e.g. `app/src/components/PokemonCard.tsx:19`). The docs' "What can make transitions slow?" section calls out exactly this combination: a cold visit to `/pokemon/pikachu` fans out species + Pokémon + chain + 18 types + every move record + version groups (`app/src/app/pokemon/[name]/page.tsx:55-90`) with no streaming and no loading UI.
3. **Pervasive `any` in the data layer.** `api<T = any>` and casts like `pokemon.abilities` / `type.data.pokemon as {...}` (`app/src/app/page.tsx:20`, `app/src/app/pokemon/[name]/page.tsx:118`) mean `strict: true` is doing almost no work where the data flows.
4. **`MovesSection`'s game `<select>` is a controlled component whose only "state" is the URL**, updated via `history.replaceState` and re-read via `useSearchParams` (`app/src/app/pokemon/[name]/MovesSection.tsx:131-135`, `:126`). This is docs-sanctioned, but it depends on Next's patched history API re-syncing the hooks; popstate edge cases (entries with `null` state cause a hard reload) make it fragile where a plain `useState` + URL write would be robust.
5. Smaller nits: `apiBase` prop-drilled through three layers (`PokemonCard.tsx:18`), near-duplicated `getX`/`notFound`/`generateMetadata` boilerplate in four detail pages (`app/src/app/moves/[name]/page.tsx:8-16`), synthetic row keys `` `${move}-${level}-${rows.length}` `` (`MovesSection.tsx:141`), out-of-range `?page=999` clamps the display but stays in the URL (`HomeView.tsx:81`), and manual `type Props = {...}` where `next typegen`'s `PageProps<'/pokemon/[name]'>` is the v16 recommendation.

Nothing here is a reject. It's a small, well-organized, well-commented codebase with clear server/client boundaries (`lib/format.ts:1` even states the boundary). I'd merge after one round of minor changes.
