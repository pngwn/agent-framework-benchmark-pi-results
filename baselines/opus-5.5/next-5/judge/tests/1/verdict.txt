## Review — Dimension: test quality

**The facts on the ground:** `app/` contains **zero tests**. There is no test runner in `app/package.json` (`app/package.json:6-9` — only `dev`, `build`, `start`), no test dependencies beyond types (`app/package.json:12-17`), no spec/test files anywhere under `app/src/`, and static analysis confirms `tests: 0 files, 0 cases`. The acceptance suite in `tests/` is the only guard, and it isn't owned by this app.

**Why that matters here specifically:** this app is unusually rich in exactly the kind of logic that unit tests are cheap for and that the acceptance Playwright suite exercises only through full-page snapshots:

- **Pure helpers, fully testable, fully untested** — `humanize`, `dexNumber` padding, `cleanText` whitespace collapse, `latestEnglishFlavorText` ("last en entry"), `orMissing`, `idFromUrl` regex (`app/src/lib/format.ts:7-45`). A one-line refactor of the `en.at(-1)` selection in `latestEnglishFlavorText` would pass every compile check and could silently regress the effect text on dozens of pages.
- **Data-layer shape coercion** — `cardsFor` drops alternate forms (`id > MAX_SPECIES_ID`), dedupes by species id, and sorts by dex number (`app/src/lib/cards.ts:15-30`). This is the spec's most explicit correctness rule, and dedup-vs-order bugs (Map insertion order + `sort`) are classic silent regressions.
- **URL state** — `readFilters` clamps NaN/negative/garbage `page` and `toQuery` decides when `q`/`page` get serialized (`app/src/app/HomeView.tsx:25-52`); page clamping `Math.min(filters.page, pageCount)` and the "searching → page 1" interplay (`app/src/app/HomeView.tsx:107-109`) are easy to break with an innocent edit. The acceptance suite covers a few happy URL shapes (`tests/specs/home.spec.mjs:54,66,108`) but not out-of-range pages, mixed query/URL races, or the `lastWritten` ref debounce dance (`app/src/app/HomeView.tsx:60-78`).
- **The API cache** — TTL eviction, failed-promise eviction, `NotFoundError` on 404, and the fragile-looking re-rooting of absolute URLs via `path.indexOf('/api/v2/')` (`app/src/lib/api.ts:44-60`). `indexOf` returning `-1` for an off-shape URL would silently produce a wrong path (`slice(-1+8)` → wrong offset); a regression here poisons every page.
- **Move-table sorting** — missing-values-last regardless of sort direction (`app/src/app/pokemon/[name]/MovesSection.tsx:54-56`), `compareMethods` with `Infinity` sentinels (`:47-52`), and the composite row key `${move}-${level}-${rows.length}` (`:140`) that can collide/duplicate under refactors.

**Latent bug an app-level test would catch and the acceptance suite won't:** each dynamic route runs `decodeURIComponent(name)` on the raw param (`app/src/app/pokemon/[name]/page.tsx:40`, same pattern in moves/abilities/types pages). A malformed percent sequence (`/pokemon/%zz`) throws `URIError` *before* `notFound()` is reached, so the user gets a 500 crash page, not "Not found" — the acceptance 404 tests only use well-formed names (`tests/specs/details.spec.mjs:159-163`). Likewise there is no `error.tsx` anywhere, so a non-404 API failure is entirely unguarded and untested.
