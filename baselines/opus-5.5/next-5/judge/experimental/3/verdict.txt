## Review: experimentalness

**Ground truth on the stack:** `app/package.json` pins `next@16.4.3` / `react@19.3.1` — the current stable line (Next 16.4 shipped 2026-10-06; 16.5 is still canary). The measured `experimental` array is empty, and my own grep across `app/src` and `app/next.config.ts` finds **zero** `unstable_`/`experimental_` names, no `cacheComponents`/`use cache`/`dynamicIO`/PPR flags, and no canary-only APIs.

What the app actually uses, and the status of each:

| API | Location | Status (verified) |
|---|---|---|
| `connection()` from `next/server` | `app/src/lib/api.ts:40` | Stable since v15.0.0 — "connection stabilized" per https://nextjs.org/docs/app/api-reference/functions/connection |
| `turbopack: { root }` config | `app/next.config.ts:5-8` | Top-level `turbopack` config stable since 15.3 (formerly `experimental.turbo`), Turbopack is the *default* bundler since 16.0 — per https://nextjs.org/docs/app/api-reference/config/next-config-js/turbopack and the Next 16 blog |
| `fetch(url, { cache: 'no-store' })` + hand-rolled 30s in-memory cache | `app/src/lib/api.ts:26-56` | Long-stable fetch semantics |
| Promise `params`/`searchParams`, `generateMetadata`, `Metadata`/`Viewport` exports, `notFound`, `useSearchParams`, `Link` | `page.tsx` files throughout | All stable since 14/15; async params are *required* in 16 |
| React 19 hooks, `fetchPriority` on `<img>` | `app/src/app/pokemon/[name]/page.tsx:117` | React 19.3 stable |

The only "new-ish" surface at all is `connection()`, and it's (a) two years stable, (b) isolated to the single `api()` wrapper that every data fetch goes through — one-line removal if it ever changed, and (c) genuinely justified: the spec demands live data at request time, and this makes every route request-dynamic without scattering `no-store` everywhere.

The one *directional* observation cuts the other way: Next 16.4's headline is that **Cache Components (`use cache`) is now "the best choice for every Next.js app"** and becomes the default in Next 17 (https://nextjs.org/blog/next-16-4). This app stays on the older dynamic-rendering model with a hand-rolled TTL cache (`app/src/lib/api.ts:12-14, 26-56`) and disables prefetch on nearly every link (`app/src/components/PokemonCard.tsx:19`, `app/src/app/pokemon/[name]/page.tsx:48,168`, etc.). That's zero experimental risk today, but it's deliberately behind the framework's current recommendation, not ahead of it — a migration (or at least a prefetch re-think) will be on the roadmap for 17.
