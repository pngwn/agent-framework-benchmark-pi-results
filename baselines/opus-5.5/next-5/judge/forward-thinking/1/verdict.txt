## Review: `app/` (Pokédex, Next.js)

**Context check.** The app pins `next@16.4.3` — which *is* the current stable release as of today (v16.4.3, Oct 23 2026). But the Next.js 16.4 announcement (Oct 6 2026, nextjs.org/blog/next-16-4) recommends **Cache Components** ("the new programming model… will become the default in Next.js 17"; new `create-next-app` apps enable it by default), and the docs label fetch-based caching without `use cache` the "Previous Model" (nextjs.org/docs/app/getting-started/caching, 2026-10-06). That's the pivotal forward-thinking fact for this codebase: it is written entirely in the previous model.

### What ages well

- **Data access is centralized** in `app/src/lib/api.ts` (all HTTP, 404 handling, list walking) plus `app/src/lib/cards.ts` and pure helpers in `app/src/lib/format.ts`. An API change touches one module — genuinely good.
- **Current stable APIs, correctly used**: `await connection()` (`app/src/lib/api.ts:44`, current per nextjs.org/docs/app/api-reference/functions/connection), Promise-based `params`/`searchParams` (`app/src/app/pokemon/[name]/page.tsx:14,113`), split `Metadata`/`Viewport` exports (`app/src/app/layout.tsx:3,11`), `notFound()` + `generateMetadata` per route, native `history.pushState/replaceState` URL-state pattern (`app/src/app/HomeView.tsx:66`, documented App Router behavior).
- **Dependencies are as lean as it gets**: three runtime deps, zero CSS/UI packages, hand-written CSS with custom properties (`app/src/app/globals.css`, `tokens.css`).
- Sensible config: `turbopack.root` via `import.meta.dirname` for the nested app dir, `compress: false`/`poweredByHeader: false` matching the reverse-proxy assumption (`app/next.config.ts:1-9`).

### What will cause churn

- **The whole data layer is the documented "Previous Model"** — `fetch(url, { cache: 'no-store' })` plus a hand-rolled module-scope `Map` TTL cache (`app/src/lib/api.ts:16-29,46-70`). Since 16.4 the recommended equivalent is `cacheComponents: true` + `'use cache'` with `cacheLife` profiles; that's exactly the API this cache re-implements by hand (in-flight promise dedup, expiry, eviction). When 17 makes Cache Components default, this is the module that gets rewritten. Spec-compliant (request-time data, short TTL), but built on the outgoing model.
- **No static shell / streaming anywhere**: every route is fully dynamic with no `loading.tsx` or Suspense boundaries, so nothing benefits from PPR/instant-navigation guarantees the framework now optimizes for.
- **Types at the API boundary are `any`**: `api<T = any>` (`app/src/lib/api.ts:46`) and `getMoves(pokemon: any)` with `s: any`/`a: any`/`t: any` map callbacks (`app/src/app/pokemon/[name]/page.tsx:58-111`). Domain types exist only *after* parsing (`Game`, `MoveInfo`, `CardData`, `IndexEntry`), so the raw API shape is untyped everywhere it matters; PokeAPI shape changes would surface as runtime bugs, not compile errors.
- **`prefetch={false}` on essentially every link** (`app/src/components/PokemonCard.tsx:16`, `app/src/components/TypeBadge.tsx:12`, `app/src/app/pokemon/[name]/page.tsx:41,168,178`…). Valid today, but it deliberately opts out of the framework's navigation optimizations (incremental/partial prefetching) with no comment explaining why.
- Minor: `new URLSearchParams(searchParams.toString())` round-trips what `useSearchParams` already provides (`app/src/app/HomeView.tsx:82`); per-table `<button>` sort headers rebuild sort state in `useState` rather than deriving from one place (`MovesSection.tsx:53`) — fine, just more hand-rolling than needed.

### Scores

- **latest_apis: 3** — Current stable version, current stable APIs throughout (async params, `connection()`, metadata/viewport, history-API URL state). But the data-loading/caching model is the one the framework itself now calls "Previous Model" and will flip defaults on in 17; a 16.4-era greenfield app built from current defaults would use `cacheComponents`/`use cache`.
- **platform: 4** — Reaches for the platform readily: `URLSearchParams`/`URL` (`HomeView.tsx:31,42`, `MovesSection.tsx:118`), `fetch` with explicit `no-store`, `Array.at(-1)`, `padStart`, `localeCompare`, native `<select>`/`<form>`/`<dl>`, CSS custom properties and `rem` media queries. Only misses 5 because the in-memory cache hand-rolls something the framework/platform now provide, and sprite URLs are string-concatenated rather than `URL`-built (`PokemonCard.tsx:11-13`).
- **dependencies: 5** — next 16.4.3 (exact pin), react 19.3.1, react-dom, and four dev-only type packages. Nothing heavy, nothing redundant; the platform/framework cover everything else.
- **churn_resistance: 3** — One well-defined data module and pure shared helpers mean API/upstream changes are localized, and there's no reliance on framework internals. But the untyped `any` boundary and the bespoke cache are precisely the things a Next 17 / API-shape change would break silently.
