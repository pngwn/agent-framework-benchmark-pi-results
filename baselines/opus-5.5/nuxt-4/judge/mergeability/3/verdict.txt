## Review

I read the spec, all of `app/` (server routes, pages, components, composables, utils, config), and verified current Nuxt guidance: the app targets Nuxt **4.6.2** (latest stable is 4.6.3, released 2026-10-27), uses the Nuxt 4 `app/` directory layout, and its API choices (`useFetch`/`createError`/`clearError`/`useId`/`useHead`/`defineEventHandler`/`getRouterParam`, `shared/` availability, `scrollBehaviorType`) are all current, per the v4 docs and vue-router/Nuxt source.

**What's strong**

- Clean two-layer architecture: Nitro server routes shape data (`app/server/api/**`), pages stay thin and render, with a single `usePageData` composable (`app/app/composables/usePageData.ts:5`) centralising 404-as-error handling — exactly the full-stack split Nuxt is for.
- Idiom density is high: `titleTemplate` in `app.vue:2`, `useId()` for section heading ids (`app/app/components/PageSection.vue:2`), `NuxtPage :page-key` chosen deliberately so query changes don't remount (`app/app/app.vue:7`), error.vue with `clearError({redirect:'/'})` (`app/app/error.vue:8`), catch-all 404 page (`app/app/pages/[...slug].vue:2`).
- Server cache is honest: promise-deduped, failures evicted (`app/server/utils/pokeapi.ts:33`), TTL documented with a *why* comment (`:4`).
- Filtering logic on the home page is correct and race-free: local `search` ref is source of truth while typing, URL follows via `router.replace`, `setFilter` drops `page` so filters reset pagination (`app/app/pages/index.vue:20`).
- Accessibility work (aria-sort, row headers, `scope`, captions, decorative sprite `alt=""`) matches spec without hacks.

**What I'd ask to change (all small)**

1. The app↔server API contract is implicit: server handlers return untyped `any` shapes (`app/server/api/pokemon/[name].get.ts:73`) while each page hand-declares its own interface (`app/app/pages/types/[name].vue:6`, `:2` TypeRef duplicated at `app/app/pages/pokemon/[name].vue:5`). These can drift silently; Nuxt 4's `shared/types/` is the documented home.
2. `humanize` is duplicated verbatim at `app/app/utils/format.ts:3` and `app/server/utils/pokeapi.ts:51` — `shared/utils/` exists precisely for this.
3. `app/server/api/pokemon/[name].get.ts:46` correlates `gameRecords` with `[...gameNames][i]` across two independent Set spreads — correct (Set iteration is deterministic) but fragile; build an array once.
4. `app/nuxt.config.ts:15` sets `scrollBehaviorType: 'auto'`, which is already the default — no-op config.
5. `app/app/pages/index.vue:51` clamps `?page=` for display but never syncs the out-of-range URL back.

No correctness bug of any consequence found: 404s flow to the error page with the right status, unhandled rejections are surfaced as 500s, HTML is never interpolated raw, hydration state is URL-derived on both sides, and caches are bounded-ish. The only structural watch-item is the cold-request fan-out of one fetch per learned move on a Pokémon page (`app/server/api/pokemon/[name].get.ts:40`), mitigated by the 60s cache.
