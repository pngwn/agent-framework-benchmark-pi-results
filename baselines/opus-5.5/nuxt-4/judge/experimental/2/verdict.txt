## Review: experimentalness

**What's in the app.** The code reaches exclusively for long-stable Nuxt/Vue APIs. Grepping the whole `app/` source tree finds no `experimental`/`unstable_`/`preview` markers, no `definePage`/typed-routes usage, no `routeRules`, and no `future:` flags — the only `experimental` matches are in `package-lock.json` (transitive `rolldown`/`gensync` versions, not app choices). Every composable in use (`useFetch`, `useHead`, `useRoute`, `useRouter`, `useId`, `createError`, `clearError`, `computed`, `ref`, `watch`) and every server helper (`defineEventHandler`, `getRouterParam`, `createError`) is documented, non-experimental API in current stable Nuxt 4.x / Nitro.

**Version freshness.** `app/package.json` pins `nuxt ^4.6.2` (current stable line; 4.6.3 shipped 2026-10-27) and `vue-router ^5.4.0` (stable since 2026-10-07, ~3 weeks before "today"). The vue-router pin is redundant — Nuxt 4.6.x already requires exactly `vue-router ^5.4.0` (confirmed via the npm registry metadata for `nuxt@4.6.2`), and the app never imports vue-router directly (all 4 import lines in the codebase are type-only: `app/error.vue:2`, `app/app/pages/pokemon/[name].vue:2-3`, `app/app/composables/usePageData.ts:1`). Riding the newest patch train is the only freshness exposure, and it mirrors the framework's own ranges.

**Containment.** Even the non-default choices are trivially contained: all data fetching on the client goes through a single 10-line wrapper (`app/app/composables/usePageData.ts`) and all upstream API access through a single server util (`app/server/utils/pokeapi.ts`), so any future framework change has one obvious swap point.

**Minor nits.** `router.options.scrollBehaviorType: 'auto'` (`app/nuxt.config.ts:15`) is a documented, stable Nuxt-injected option (typed in `@nuxt/schema`'s `RouterOptions` since late 2023) but `'auto'` is already the default, so it's a no-op. `key: url` in `useFetch` (`app/app/composables/usePageData.ts:8`) is also redundant since Nuxt auto-generates keys from URL + options.
