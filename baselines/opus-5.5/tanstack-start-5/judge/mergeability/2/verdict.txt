## Review summary

I read `SPEC.md`, every source file in `app/` (14 files, ~700 significant LOC), and verified the framework's current guidance: the shipped `@tanstack/react-start@1.169.4` is the first **stable** release (RC migration notes: `.validator()` is canonical, `inputValidator()` removed), the official server-functions skill prescribes exactly this `.functions.ts` / `.server.ts` split, and the hosting docs/community examples prescribe exactly this srvx "static `dist/client` + `fetch` handler" production shape.

**What's strong:** the data layer mirrors the official skill almost verbatim — `createServerFn({ method: 'GET' }).validator().handler()` wrappers in `pokedex.functions.ts:5-28`, server-only helpers behind them in `pokedex.server.ts`, loaders that only call server functions (`pokemon.$name.tsx:27-33`, `index.tsx:24-25`), typed search via `validateSearch` + `loaderDeps` (`index.tsx:22-26`), `throw notFound()` in loaders with root/global `notFoundComponent` (`router.tsx:11`, `__root.tsx:17`), `head()` per route with `HeadContent`/`Scripts`, `styles.css?url` in root links, and `hashScrollIntoView` used correctly for the `#moves` game-switch case (`pokemon.$name.tsx:147-152`). The production server (`server.mjs:13-18`) matches the documented Node/srvx deployment shape. Boundaries are clean: shared types in `lib/types.ts`, shared formatters in `lib/format.ts`, server-only code never leaks into client modules.

**What I'd flag:** the root `head` reaches into the router's private `_notFound` field to compute the not-found title (`__root.tsx:16`); the search box's focus-guard can desync the input text from the URL after Back/Forward (`index.tsx:43-46`); the server module is ~350 lines of `any`-typed internal record handling; and the in-memory cache only prunes expired entries and only on the 5001st write (`pokedex.server.ts:43-46`). Nothing rises above "minor" — there are no serious races, no leaks, no SSR/CSR mismatch hazards, and 404 handling is thorough.
