## Review: Pokédex (TanStack Start + React)

**Verification against current docs:** The app targets the current stable TanStack Start (react-start 1.169.x / react-router 1.170.x, Vite 8). I verified against current docs that:
- `createServerFn().validator()` is the **canonical** API (`.inputValidator()` was removed in 1.169's RC→stable migration; `app/src/lib/pokedex.functions.ts:9` uses it correctly).
- The `lib/types.ts` / `lib/pokedex.server.ts` / `lib/pokedex.functions.ts` split matches the official import-protection guidance (`*.server.*` denied in client builds) and the recommended file-separation convention exactly.
- The `server.mjs` srvx production server wrapping `dist/server/server.js`'s `fetch` handler is a documented, supported self-hosting pattern.
- `hashScrollIntoView` (`pokemon.$name.tsx:151`), `Route.useLoaderData()`, `validateSearch`/`loaderDeps`, the route `head()` API, `notFound()` + `notFoundComponent`, and `scrollRestoration` are all current, non-deprecated APIs.

**What's good:** loaders call server functions and throw `notFound()` (`pokemon.$name.tsx:22-26`), the env var is read per call rather than at module scope (`pokedex.server.ts:24` — matches the start-server-core skill's explicit guidance), the fetch cache stores promises so concurrent requests dedupe and evicts on rejection (`pokedex.server.ts:30-50`), the search box keeps local state with a debounce while the URL remains the source of truth (`index.tsx:38-51`), sorting keeps missing values last in both directions with an explanatory comment (`pokemon.$name.tsx:196-200`), and names/comments are excellent throughout.

**Main concerns:** one ~350-line god data module with `any`-typed internals behind an otherwise well-typed contract; validators that are identity casts; a peek at the private `m._notFound` match flag; and no `tsc --noEmit` script even though `vite build` doesn't typecheck.
