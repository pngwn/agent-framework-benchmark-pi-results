## Review — Test quality

The app contains **zero tests of its own**: no test files anywhere in `app/` (grep for `test|spec|vitest|jest` across `app/` returns only source matches), no runner in `app/package.json:23-32` (devDependencies are types/plugins/toolchain only), and no `test` script (`app/package.json:6-9` defines only `dev`, `build`, `start`). The measured facts confirm it (`tests.files: 0`, `runner: []`). All quality guarding is therefore borrowed from the acceptance suite in `tests/`, which the agent didn't write and doesn't live in `app/`.

That's a real cost here, because the risky logic is concentrated in a single untested server module, `app/src/lib/pokedex.server.ts`, which is exactly the file a future refactor would touch:

- **Filter + pagination math** (`pokedex.server.ts:154-181`): the type/generation/search predicates, the page clamp `Math.min(Math.max(1, Math.floor(filters.page ?? 1)), pageCount)` at line 174, and the slice at 176. An off-by-one in the slice or a dropped clamp would show an empty or duplicated page.
- **Unknown filter values are a latent bug no test pins down**: `?generation=bogus` finds no generation, so `!generation?.speciesIds.has(s.id)` (line 162) excludes *every* species and the page says "No Pokémon found" instead of ignoring the bad value; same for an unknown `type` (line 160). Nothing in `app/` asserts the intended behaviour, so neither the current quirk nor a fix can regress-test it.
- **Move table construction** (lines 222-263): per-move dedup key `${method}:${level}` (line 226), method ordering via `rank` (line 257), and the subtle one-line default sort `(method === 'level-up' ? a.level - b.level : 0) || a.label.localeCompare(b.label)` (line 261). Refactoring that comparator naively (always sort by level, or by `a.name`) would silently misorder Machine/Egg/Tutor tables.
- **Text extraction**: `latestFlavorText` (line 60, "last English entry, whitespace collapsed") and `englishEffect` (line 66, `$effect_chance` substitution). These are cheap pure-ish functions with fiddly rules and no coverage.
- **Client-side sortable tables** (`app/src/routes/pokemon.$name.tsx:160-186`): missing-values-last in both directions uses `va === null`; a refactor to `!va` would mis-sort 0-power/0-PP moves (power 0 exists in the data). Tie-breaking always reverts to label-ascending regardless of direction — unspecified, unpinned.
- **In-memory cache** (`pokedex.server.ts:29-50`): TTL, promise de-duplication, and a size purge that only deletes *expired* entries (lines 45-47) — if >5000 live entries accumulate, the map grows without bound in a long-running server. Untested and unbounded.
- **URL-state plumbing** (`app/src/routes/index.tsx:12-24`, 43-44): `cleanFilters` default-stripping and the `page: undefined` reset trick, plus the 150 ms debounce race (lines 60-65). And `humanize` in `app/src/lib/format.ts:2-8` is secretly coupled to search semantics — search matches *against the humanized name* (`pokedex.server.ts:159`), so changing humanization changes search behaviour with no test to notice.
