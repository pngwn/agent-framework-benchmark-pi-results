## Review: Test quality

**No tests exist in `app/`.** Confirmed three ways: `grep` for `*.{test,spec}.*` files returns nothing, `app/package.json:5-8` has no `test` script, and no test runner (vitest/playwright) appears in dependencies. The static analysis agrees (`testLoc: 0`, `tests.files: 0`). The app's behaviour is currently guarded *only* by the acceptance suite in `tests/`, which the team doesn't own — the moment someone refactors `pokedex.server.ts`, nothing in-repo will catch regressions.

That's a shame, because this app has an unusually high ratio of pure, easily-testable logic to glue code, and almost all of it sits in files that are trivially unit-testable:

- `app/src/lib/format.ts:3-19` — `humanize`, `dexNumber`, `orDash` are pure functions with spec'd edge cases (`mr-mime` → `Mr Mime`, `#0025`, `—` for missing power).
- `app/src/lib/pokedex.server.ts:161-175` — the list filtering (search substring against humanized name, type/generation membership) and pagination math (clamp, `slice((page-1)*48, page*48)`), which is exactly the code the acceptance tests exercise least directly.
- `app/src/lib/pokedex.server.ts:66-79` — `latestFlavorText` (last English entry, whitespace collapse) and `englishEffect` (`$effect_chance` substitution), both full of format edge cases.
- `app/src/lib/pokedex.server.ts:130-144` — alternate-form exclusion (`id < 10000`) and card dedupe, which three different pages depend on for correctness.
- `app/src/routes/pokemon.$name.tsx:139-152` — the sortable move table comparator, including the "missing values last in *both* directions" rule, which is a classic silent-breakage spot.
- `app/src/routes/index.tsx:10-24` — `cleanFilters` (URL state serialization, "omit empty/default params") is a pure function begging for tests.

Per the scoring rules: `coverage_of_risk` and `regression_power` are 1 (nothing would be caught), `behaviour_not_implementation` is 1 (no tests), and `signal_to_noise` gets the anchor's 3 for the no-tests case. The `untested` list below is where the real value of this review lives.

Notably, even the debounce timer logic (`app/src/routes/index.tsx:66-77`) and the in-memory fetch cache (`app/src/lib/pokedex.server.ts:30-52` — promise caching, TTL, eviction-on-error) would benefit from tests, since they're stateful and the acceptance suite only exercises happy paths.
