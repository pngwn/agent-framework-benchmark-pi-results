I've reviewed the app and verified every framework API and dependency version against current release notes. Here's what I found.

## What's in the app

The application code itself (`app/src/**`) uses only long-stable Solid primitives: `createSignal`, `createEffect`, `createMemo`, `on`, `For`/`Show`/`Suspense`, the standard `Router`/`FileRoutes`/`A`/`useParams`/`useSearchParams` stack, and the router's data APIs (`query`, `createAsync`, `preload`). `createHandler(..., { mode: "async" })` in `app/src/entry-server.tsx:24` is a documented stable option (`sync | async | stream`, default `stream`) — confirmed in the SolidStart v2 `createHandler` reference. No `unstable_`/`experimental_` names, no experimental config flags anywhere in `app/` (the measured `experimental` list is empty, and my own grep found none).

The one genuinely pre-stable piece is the deployment layer:

- `app/package.json:17` — `"nitro": "^3.0.260903-beta"` (locked at `3.0.260903-beta`, published 2026-09-03 per npm). Nitro's own README still says *"You're viewing the v3 branch. For the current stable release, see Nitro v2."*
- `app/vite.config.ts:8` — `nitro()` from `nitro/vite`, called with no options; `app/package.json` `start` script serves Nitro's `.output/server/index.mjs`.
- Transitively this pulls `h3 ^2.0.1-rc.26`, `unenv ^2.0.0-rc.24`, `unstorage 2.0.0-alpha` (via `app/package-lock.json:2335-2343`) — not the app's choices, but part of the beta risk surface.

Crucially, this is exactly what the **official SolidStart v2 docs prescribe**: the "Deployment plugins" and `vite.config.ts` reference pages both show `plugins: [solidStart(), nitro()]` with `import { nitro } from "nitro/vite"`, and SolidStart v2 requires Vite 8 / Node 24. SolidStart v2 went stable 2026-08-04 (`@solidjs/start@2.0.0` release notes: "SolidStart v2 is now stable"), `@solidjs/router@1.0.0` (2026-07-28) explicitly declares itself "a version realignment, not a breaking change" of the API-stable 0.16 line, and Vite 8 has been stable since 2026-03-12. So the app sits squarely on the framework's current stable release; the Nitro beta is the documented cost of entry for that release line, and the semver prerelease rules effectively pin it (a `^3.0.260903-beta` range won't jump to a different dated beta tuple), with a lockfile committing it exactly.
