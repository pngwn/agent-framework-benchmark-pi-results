I've reviewed the app end to end. Here's my assessment against the current stable Qwik (1.20.3; v2 is still RC, so `routeLoader$`, `useTask$`, `useComputed$`, `resolveValue` in `DocumentHead` are all current idiomatic APIs — no deprecated usage found).

Key observations driving the scores:

- Data access is centralized in `src/lib/api.ts` (base URL, cache TTL/size, sprite URL, species/pokemon→card mapping) and display helpers in `src/lib/format.ts`; routes are thin loaders + render.
- All card lists except the home page go through `cardsForPokemon`, and all rendering goes through `PokemonCards`, so most cross-cutting fixes land in one place. The one real duplication is card *construction*: `routes/index.tsx:42-47` builds `CardData`s from the species index separately from `lib/api.ts:104-112`.
- Removing a feature is nearly clean (route dir + one section), but all CSS lives in one monolithic `global.css` and the `hidden`/`card__note` plumbing would linger unless hunted down.
- Components are fed narrow serializable types (`CardData`, `MoveRow`), giving a clean server/client seam; minor tangles are the DOM-form-traversal in the home filter `go()` and `TypeBadge`'s flag creep.
