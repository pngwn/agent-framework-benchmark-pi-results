## Review: experimentalness of `app/`

**What I checked.** The app pins Angular `^22.2.0` (app/package.json:6), i.e. the current stable major (v22, June 2026; latest v22.2). The static-analysis facts report zero `unstable_`/`experimental_` markers and no experimental config flags, and my grep agrees: the only hit for "experimental" in the whole app is the TypeScript `experimentalDecorators` tsconfig flag (app/tsconfig.json:12), which is the CLI's long-time default.

**The newest APIs in use, verified against current docs and release notes:**

- `resource()` — used in **all 7 data paths** (home.ts:26, pokemon-page.ts:29 and 40, move-page.ts:77, ability-page.ts:45, type-page.ts:86, types-page.ts:27). It was experimental through v21 and **became stable in v22** (June 2026) — confirmed by the v21 release notes (experimental Signal Forms/Aria; resources still experimental at v21) and the current angular.dev API page, which carries no preview badge. This is a "recently-stable" central dependency.
- `@Service()` decorator (app/src/app/core/poke-api.ts:52) — brand-new in v22, already stable; it's the current recommended DI API per the official skill guidance. Used exactly once.
- Everything else is long-stable: `signal`/`computed`/`input`/`effect`/`untracked`, `takeUntilDestroyed`, `booleanAttribute`, `afterNextRender`, `@if/@for/@else/@let` control flow, `provideBrowserGlobalErrorListeners` (default CLI template since v20), Vitest via `@angular/build:unit-test` (default runner since v21), and implicit zoneless (no zone.js in deps — zoneless is stable since v20.2 and default since v21).

**Notably absent** (restraint): `linkedSignal`, `httpResource`, Signal Forms (stable in v22, and `@angular/forms` is actually an unused dependency — never imported), `@boundary` (v22.2 dev preview), Angular Aria, the MCP/WebMCP tools. The app never reaches past what its pinned version marks stable.

**Risk picture.** Zero experimental/preview/RC APIs. The two newest APIs (resource, `@Service`) are stable in the pinned version and used exactly per current official guidance. Containment is good: every HTTP concern lives behind one `PokeApi` (poke-api.ts:53), loaders are extracted as plain async functions (home-data.ts:27, pokemon-data.ts:54, moves-data.ts:18, move-page.ts:14) so the `resource()` wiring is a thin, swappable per-page shell. One caveat on how the new API is used: loaders don't forward `resource`'s `abortSignal` into `PokeApi.get` (poke-api.ts:64), so superseded loads aren't cancelled — the official guidance says to always pass it; the URL-keyed request cache partially mitigates this.
