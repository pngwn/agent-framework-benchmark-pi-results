## Review: experimentalness

**What's there.** The app runs on Angular `^22.2.0` (`app/package.json:5-10`), i.e. the current stable release (v22.0 shipped June 2026, minors since). Static analysis found **zero experimental markers** — no `experimental_*`/`unstable_*` names, no preview flags, no zoneless/SSR toggles (`grep` across `app/src` confirms). What the app *does* do is lean on two APIs that only left experimental status in v22 itself:

1. **`resource()`** — experimental since v19, promoted to stable in v22 (June 2026; PR #68253, confirmed by the v22 release announcement and angular.fr/ng-news coverage). It is the app's data backbone: all six pages load through it — `app/src/app/pages/home/home.ts:26`, `app/src/app/pages/pokemon/pokemon-page.ts:29` and `:40`, `app/src/app/pages/type-page.ts:86`, `app/src/app/pages/ability-page.ts:45`, `app/src/app/pages/move-page.ts:77`, `app/src/app/pages/types-page.ts:27`. The cleanest usage is `pokemon-page.ts:40-44`: a second resource keyed on `selectedGame()` re-fetches move tables when the `?game=` query param changes — params-driven reload, dedup and cancel for free.
2. **`@Service()`** — introduced in v22.1 (PR #68195, Apr 2026) and marked stable for v22 (angular/angular #68470). Used once, for the single app-wide service `PokeApi` (`app/src/app/core/poke-api.ts:50`). Pure ergonomics over `@Injectable({providedIn: 'root'})`, but it's now the documented default with an official migration schematic.

The test runner is `@angular/build:unit-test` with Vitest (`app/angular.json:64`), which was experimental in v20 but is the documented default for new CLI projects by v22; only the Karma→Vitest *migration schematic* is still flagged experimental in the docs, so this isn't a risk.

Everything else is long-stable: signals/computed/effect (stable v19), `input.required` (`move-page.ts:70`), `untracked` (`home.ts:100`), `afterNextRender` with explicit injector (`pokemon-page.ts:66`), `takeUntilDestroyed` (`app.ts:33`), `booleanAttribute` input transform (`type-badge.ts:20`), `@let`/`@if`/`@for` control flow, and `provideBrowserGlobalErrorListeners` (`app.config.ts:3`).

**Containment.** `resource()` is not hidden behind a wrapper — it's invoked directly in six page components — but every loader delegates to plain async functions in `core/` and per-page data modules (`loadHomeData`, `loadPokemonView`, `loadMoveTables`…), so the reactive plumbing is a one-line field per page and the data logic is framework-free. If `resource()`'s surface ever shifts, the swap surface is six small declarations, not 100+ lines. That's "partly contained": 3.

**Justification.** The `resource()` usage is genuinely load-bearing, not novelty: route-input-keyed reloading (the `name` input drives `params`, `pokemon-page.ts:30`), query-param re-fetch (`pokemon-page.ts:41-43`), and loading/error state consumed by `LoadState` without a single RxJS subscription. `@Service()` is the one gratuitous-but-harmless choice; `@Injectable` would behave identically.
