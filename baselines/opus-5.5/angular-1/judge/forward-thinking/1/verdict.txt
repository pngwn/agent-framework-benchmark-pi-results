# Review: forward-thinking — Angular Pokédex

## Context

The app targets **Angular 22.2** (released June 2026; current stable as of 2026-10-30) and, per the v22 release notes, v22 made Signal Forms, Angular Aria and the async reactivity APIs (`resource`, `httpResource`, `rxResource`) **stable**, introduced the **`@Service()` decorator**, and made **OnPush + zoneless the defaults**. This codebase leans on those new defaults rather than fighting them (no `zone.js` anywhere, no `ChangeDetectionStrategy` overrides, no `provideZoneChangeDetection`) — a genuinely current posture.

**latest_apis — 4.** This is close to exemplary: `resource({params, loader})` on every page (`app/src/app/pages/home/home.ts:26`, `pokemon-page.ts:29-45`, `move-page.ts:77-80`, `ability-page.ts:45-48`, `type-page.ts:86-89`), signal inputs bound from route params via `withComponentInputBinding` (`app/src/app/app.config.ts:6`), the v22-only `@Service()` decorator (`app/src/app/core/poke-api.ts:52`), `@if/@else/@for/@empty/@let` with `track` throughout, `provideBrowserGlobalErrorListeners` (`app/src/app/app.config.ts:6`), and Vitest via `@angular/build:unit-test` (`app/angular.json` test builder) — all stable, current-generation APIs, several of them post-training-data. What keeps it from a 5: it misses two patterns the v22 resource docs themselves prescribe — the loader ignores the documented `abortSignal` (`app/src/app/core/poke-api.ts:64`), and the dependent moves resource reads `this.data.value()` inside `params` (`app/src/app/pages/pokemon/pokemon-page.ts:41-43`), the exact anti-pattern the v22 guide calls out in favor of the new `chain()` API (angular.dev/guide/signals/resource, "Chaining vs. reading resource values directly").

**platform — 5.** Reaches for the platform first everywhere: plain `fetch` with no HTTP library (`app/src/app/core/poke-api.ts:64`), native form controls with no forms framework (`app/src/app/pages/home/home.html:12-46`), `AbortSignal.timeout` for the server's API probe (`app/server/server.mjs:69`), `new URL()` for request parsing (`app/server/server.mjs:115`), modern image hints (`loading="lazy" decoding="async"` at `app/src/app/shared/pokemon-card-list.ts:15-18`, `fetchpriority="high"` at `pokemon-page.html:5`), and CSS custom properties plus `:has()` (`app/src/styles.css:192`) on top of the design tokens. The static server is hand-rolled `node:http` with zero npm deps and `node:`-prefixed ES modules.

**dependencies — 4.** Runtime deps are 8 packages: the Angular set, `rxjs` (genuinely needed by the router and `takeUntilDestroyed`, `app/src/app/app.ts:2`), and `tslib` — no zone.js, no state library, no CSS framework, no express. Dev deps are modern (`typescript@6.0`, `vitest@5`, `@angular/build@22.2`). One clear blemish: **`@angular/forms` is declared but never imported** (zero references in `src/`), and `jsdom` is likely unnecessary given both spec files are pure-function tests.

**churn_resistance — 4.** Strong bones: all HTTP knowledge lives in one module behind a typed boundary (`app/src/app/core/poke-api.ts` + `models.ts`), each page maps raw API shapes to its own view model (`pokemon-data.ts:16-35`, `moves-data.ts:10-24`, `home-data.ts:8-24`), and the API origin is injected at runtime from a meta tag so one build works against any API (`app/src/app/core/api-config.ts:8-15`, written per-request in `app/server/server.mjs:42`) — config in exactly one place. Deductions: route knowledge is duplicated between `app/src/app/app.routes.ts` and the server's `DETAIL_ROUTES`/`STATIC_ROUTES` (`app/server/server.mjs:45-51`) so adding a route touches both; scroll behavior is hand-rolled in three components (`app/src/app/app.ts:33-39`, `home.ts:66-69`, `pokemon-page.ts:63-67`) where `withInMemoryScrolling` covers part; and the global stylesheet reaches into framework internals via `.site-main > :not(router-outlet)` (`app/src/styles.css:143,149`).

**Overall — 4.** A forward-looking, current-release codebase whose few misses are documented best practices from the same release it otherwise fully embraces.
