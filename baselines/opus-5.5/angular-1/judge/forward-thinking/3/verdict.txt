# Review: forward-thinking

The app targets Angular **22.2** (current stable, v22 released June 2026 — confirmed via angular.dev/events/v22 and the v22 announcement post), TypeScript ~6.0 (the version Angular 22 requires), and is **zoneless** by default (`zone.js` appears only as a peer range in the lockfile, never installed — zoneless is default since v21 per angular.dev/guide/zoneless). Almost every choice is the current generation of the framework.

**What's notably current** — and newer than most training data:
- `@Service()` decorator (`app/src/app/core/poke-api.ts:52`), introduced in v22 as the replacement for `@Injectable({providedIn:'root'})` (confirmed: v22 announcement "The new @Service decorator", skill `references/creating-services.md`).
- `resource()` for all data loading (`app/src/app/pages/home/home.ts:26`, `pokemon-page.ts:29,40`, `move-page.ts:77`, `ability-page.ts:45`, `type-page.ts:86`, `types-page.ts:27`) — the async-signals primitive stabilized in v22, used with the correct `params` + `hasValue()` guard pattern, including the `undefined`-params-to-skip idiom at `pokemon-page.ts:40-47`.
- Signal inputs (`input.required`/`input` with router binding via `withComponentInputBinding` at `app/src/app/app.config.ts:6`), `computed`, `booleanAttribute` transform (`app/src/app/shared/type-badge.ts:17`), native control flow `@if/@for/@let/@empty`, `NgTemplateOutlet` for recursion (the pattern the skill's `queries-and-projection.md:198-210` still recommends), `provideBrowserGlobalErrorListeners` (`app.config.ts:6`), route-level `title` (`app.routes.ts:8`), and the Vitest + `@angular/build:unit-test` builder (`angular.json:49`) that matches Angular 22's default test stack.
- Platform-first: `fetch` with typed JSON, `new URL()` and `AbortSignal.timeout()` in the server (`server/server.mjs:76-78`), native form controls with zero forms library, `:has()` selector (`styles.css:192`), auto-fill grid (`styles.css:240`), `loading=lazy`/`decoding=async`/`fetchpriority`/intrinsic sizes on images (`pokemon-card-list.ts:14-19`, `pokemon-page.html:6`), and a hand-rolled ~140-line static server on `node:http`/streams instead of pulling in express.
- Churn resistance is strong: every API call sits behind the single `PokeApi` service with typed response models (`core/models.ts`) and per-page view models (`pokemon-data.ts`, `home-data.ts`, `moves-data.ts`); pure formatting/filtering helpers are unit-tested; API origin is runtime-injected via `<meta name="api-base-url">` + an `InjectionToken` factory (`core/api-config.ts:9-16`, `server/server.mjs:34`) so one build serves any API — a better fit to the spec than the environment-file default and documented in `environment-configuration.md` as runtime configuration.

**What keeps it from top marks:**
1. `home.ts:59-62` uses `effect()` to copy the `q` route input into the `searchText` signal, with a manual `lastSearchSent` escape hatch — the skill's `linked-signal.md` says "Never use an effect to sync one piece of state to another… use linkedSignal", and `linkedSignal({source: this.q})` is exactly the documented primitive for "user-editable state that resets when a source changes". Also `effect()` writing `.set()` is the anti-pattern called out in `effects.md`.
2. `resource` loaders ignore the `abortSignal` (no `fetch(url, {signal})` anywhere — `core/poke-api.ts:64`); `references/resource.md` is explicit: "Always pass `abortSignal` to your `fetch` calls." The TTL cache mitigates refetches, but stale navigations still burn bandwidth and can't be cancelled.
3. Scroll management is hand-rolled in three places (`app.ts:31-38`, `home.ts:66-69`, `pokemon-page.ts:49-58`) where the router already offers `withInMemoryScrolling`/the `Scroll` event — and v22's platform-navigation integration exists precisely to remove "custom scroll-management logic". The `#moves` case (scroll after async data) genuinely needs custom handling, but the path-change and pagination cases don't.
4. `@angular/forms` is declared in `app/package.json` but never imported; `prettier` is installed with no script that runs it.
5. All styles live in one global stylesheet that keys off component tag names (`app-load-state`, `.site-main > app-home`, `router-outlet` — `styles.css:131-152`), so renaming a component ripples into CSS; component-scoped styles would localize that.
