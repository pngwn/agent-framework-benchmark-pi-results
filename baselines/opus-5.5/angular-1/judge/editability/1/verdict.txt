## Review: editability of the Pokédex Angular app

**Framework currency.** The app targets Angular v22 (`app/package.json:12-17`) and uses current stable idioms, confirmed against the official skill guidance: signal `input()` with `withComponentInputBinding` (`app/src/app/app.config.ts:5`), `resource()` for async data (`app/src/app/pages/move-page.ts:29-32`), the `@Service()` decorator (`app/src/app/core/poke-api.ts:50`), and template control flow (`@if/@for/@let`). Nothing here is stale.

**Scenario walkthrough**

1. **Remove Abilities**: delete the route (`app/src/app/app.routes.ts:7`) and `app/src/app/pages/ability-page.ts`; then scattered edits — the Abilities section that links to it (`app/src/app/pages/pokemon/pokemon-page.html:67-77`), its data mapping (`app/src/app/pages/pokemon/pokemon-data.ts:89-93`), the server's route table (`app/server/server.mjs:48`), and would-be-dead `PokeApi.ability` / `Ability` model. A handful of findable edits, no nav link involved.
2. **Sprite fix**: sprite derivation is centralized in `spriteUrl` (`app/src/app/core/poke-api.ts:158`) with a single card consumer (`app/src/app/shared/pokemon-card-list.ts:18`); card data assembly is in `cardsFor` (`app/src/app/core/poke-api.ts:143`) — but home builds its own cards (`app/src/app/pages/home/home.ts:41-48`), so a data-level card change touches two sites. One fix covers every list, because all four lists render through `PokemonCardList`.
3. **Sort by name**: a sort inside `PokemonCardList` (or in `cardsFor`) covers move/ability/type lists; the home list's global order lives separately in `home-data.ts`/`home.ts`, so full consistency needs a second edit.
4. **Items section shaped like Moves**: `PokeApi` (private `byName` + one-line resource methods), `format.ts` helpers, `LoadState`, `syncPageTitle`, `PokemonCardList`/`TypeBadge` all stretch without changes — but the detail-page scaffolding (resource + loader + `hasValue`/error template + title sync) is repeated per page with no shared abstraction, so a new `item-page.ts` copies ~90 lines of wiring from `move-page.ts`, plus a route line and a `DETAIL_ROUTES` entry.
5. **Data source change**: base URL is known by exactly three config-ish places (`app/src/app/core/api-config.ts:3,9-13`, `app/src/index.html:8-9`, `app/server/server.mjs:27`); every consumer reads the injected token (`app/src/app/core/poke-api.ts:54`). Caching lives in one Map + one TTL constant (`app/src/app/core/poke-api.ts:47,69`). Excellent seam.

**Notable strengths**: pure, unit-tested helpers (`home-data.spec.ts`, `format.spec.ts`) make the trickiest logic safe to refactor; the meta-tag injection means the same build works against any API with zero code edits.

**Notable smells**: `shared/load-state.ts:2` imports from `pages/` (inverted layering); `PokemonCardList` injects the data service just for sprite URLs; loading/error markup is re-hand-rolled in `home.html` and `types-page.ts` instead of extending `LoadState`.
