## Review: test quality — Pokédex Angular app (Angular 22)

The agent wrote its own unit tests (2 files, ~10 cases, 22 assertions) using the current Angular CLI default setup: `@angular/build:unit-test` with Vitest (`app/angular.json:44-46`, `app/tsconfig.spec.json:7-8`, `app/package.json` devDeps `vitest` + `jsdom`) — verified against current Angular docs that Vitest is the default runner for new projects. The design is deliberately test-friendly: the riskiest logic was factored into pure modules (`core/format.ts`, `pages/home/home-data.ts`) that are tested without any TestBed or mocks.

**What's covered well**

- `app/src/app/core/format.spec.ts:6-19` — humanize and dex-number padding, exactly the spec's edge cases (`mr-mime → Mr Mime`, `#0025`).
- `app/src/app/core/format.spec.ts:22-31` — the English-name pick with fallback, and latest-English-flavor-text with whitespace collapse — a genuinely fiddly data transformation (`app/src/app/core/format.ts:26-29`).
- `app/src/app/core/format.spec.ts:33-37` — `idFromUrl`/`isDefaultForm` — this guards the "no alternate forms (ID > 10000) in any list" rule that runs through `app/src/app/core/poke-api.ts:113`, `:147`.
- `app/src/app/core/format.spec.ts:39-41` — `orMissing(0) → '0'` catches the classic falsy-zero bug for move power.
- `app/src/app/pages/home/home-data.spec.ts:28-45` — `filterSpecies` search/type/generation/combination logic (`app/src/app/pages/home/home-data.ts:62-70`), asserted as exact name arrays, no mocks.

Every assertion is input→output on a public function — no private access, no snapshots, no call counts, no framework-behaviour padding. That's the right shape; it's just too little of it.

**What isn't covered (the risk)**

- `app/src/app/pages/pokemon/moves-data.ts:31-78` — the entire moves-table construction: the dedup key at `:38`, method ordering ranks at `:25-27`, default sort at `:74`. A refactor could duplicate or drop move rows silently.
- `app/src/app/pages/pokemon/moves-table.ts:71-90` — the sortable-column comparator: nulls-last in both directions (`:80`), stable ties, the ascending-first flip in `sortBy`. This is the most bug-prone code in the app and has zero tests.
- `app/src/app/pages/home/home.ts:36-38, 89-96` — page clamping (NaN, beyond-last-page) and the query-param serializer's omit-defaults rule; URL-state regressions would slip through.
- `app/src/app/core/poke-api.ts:139-155` — `cardsFor`: deoxys-normal → species mapping, dedup by id, dex ordering.
- `app/src/app/core/poke-api.ts:58-71` — cache TTL, in-flight sharing, failed-promise eviction.
- No rendered-behaviour tests at all: `LoadState`'s NotFoundError-vs-generic-error branch (`app/src/app/shared/load-state.ts:10-17`) is unverified.
