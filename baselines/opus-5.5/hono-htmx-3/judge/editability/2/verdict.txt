## Review: `app/` — Hono + htmx Pokédex

This is a small, cleanly layered codebase: `api.ts` (fetch + cache) → `data.ts` (domain helpers) → `views/*` (loader + view co-located per page) → `index.tsx` (routes) → `layout.tsx` (renderer). Working through the five scenarios:

**1. Remove Abilities.** Delete the route block (`app/src/index.tsx:77-81`) and the `loadAbility`/`AbilityPage` pair (`app/src/views/details.tsx:53-75`), plus the one in-page link site (`app/src/views/pokemon.tsx:284-293`) and the now-dead `.card-note` CSS (`app/public/style.css:275`). Nav has no Abilities link. Three files, each a contiguous block — good, not perfect.

**2. Sprite bug (Deoxys).** The render path is single — every list renders through `CardList` (`app/src/views/components.tsx:20-25`), which calls `spriteUrl(card.id)` (`app/src/data.ts:28`). But the `Card` view-model is built in **two** places: `cardsForPokemon` (`app/src/data.ts:91-100`, which discards the Pokémon ID it had in `ref.url`) and `loadHome` (`app/src/views/home.tsx:44`, which only has species). A correct fix (carry the default Pokémon ID on the card) touches the `Card` type, both builders, and `CardList` — findable, but not one place.

**3. Name sorting on all card lists.** One sort inside `CardList` covers home, move, ability and type lists (all pass `Card[]`); alternatively both builders (`app/src/data.ts:100`, `app/src/views/home.tsx:43-44`). Cheap either way.

**4. Items section.** `loadMove`/`MovePage` (`app/src/views/details.tsx:6-35`) and `TypesPage` (`app/src/views/details.tsx:78-87`) form an obvious template: reuse `api`/`apiList`, `Section`/`Count`/`CardList`, register routes in `index.tsx`. It's copy-adapt of a ~40-line loader/page pair rather than reuse, but a shared generic "resource page" abstraction would be over-engineering here. Note `cardsForPokemon`'s note-callback (`app/src/data.ts:91`) already stretches to the ability page's hidden note, so the seams are real.

**5. Data source change.** Fully centralized: base URL (`app/src/api.ts:4`), cache policy (`app/src/api.ts:6,33-47`), one import of `API_BASE_URL` for sprites (`app/src/data.ts:28`). One file.

Minor smells: the `/moves-table` partial endpoint's URL scheme is known by both the route (`app/src/index.tsx:52-66`) and the component that builds `hx-get` hrefs (`app/src/views/pokemon.tsx:153-159`); `pokemon.tsx` mixes page, moves-loading and sortable-table concerns; `any` in loader signatures (`app/src/views/pokemon.tsx:77,87`) weakens the seams the layering otherwise creates. The `typecheck` script exists (`app/package.json:11`) but nothing runs it, and there are no app-level tests, so edits are verified only by repo acceptance tests.
