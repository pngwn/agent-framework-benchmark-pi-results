# Review: `app/` — Hono + htmx Pokédex (dimension: forward-thinking)

## Version currency (verified, not assumed)

- **hono 4.13.14** is npm `latest` (published 2026-10-25); v5.0.0-rc.1 is a pre-release — so 4.x is the current stable, and this app pins the newest patch of it.
- **@hono/node-server 2.1.5** is the latest (Oct 2026), including the serve-static path-decoding security fix from 2.1.3.
- **htmx.org 2.0.11** is npm `latest`. htmx 4.0.0 shipped 2026-08-28, but the maintainers deliberately did **not** tag it `latest` — 2.x remains the stable line, so 2.0.11 is the correct current choice. However, htmx 4 replaces *implicit attribute inheritance* with explicit `:inherited`, which matters below.
- **typescript 7.0.2** is the current stable native release; **esbuild 0.28.2** is npm `latest`. The hono skill's JSX section confirms the app's tsconfig (`jsx: "react-jsx"`, `jsxImportSource: "hono/jsx"`) and `jsxRenderer` are the current idiom.

## What ages well

- **All APIs current.** `jsxRenderer` with `ContextRenderer` declaration merging (`app/src/views/layout.tsx:3-7`) is the documented typed-renderer pattern; `serve`/`serveStatic` (`app/src/index.tsx:12,14,96`) are the current v2.x node-server APIs; nothing is legacy-era or deprecated. The code is ESM-only with no runtime-path-specific `hono/<runtime>` imports, so the Hono v5 (ESM-only) upgrade is essentially a version bump.
- **Platform-first data layer.** Native `fetch` with explicit stream cleanup on 404 (`app/src/api.ts:12-14`), `URLSearchParams` for all query building (`app/src/views/home.tsx:20`, `app/src/views/pokemon.tsx:153`), ES modules + top-level await in the build (`app/build.mjs:3-5`), native form semantics with a no-JS `action="/"` fallback (`app/src/views/home.tsx:76-78`), CSS custom properties and logical properties throughout (`app/public/style.css:61-63`, `:114`).
- **Churn-limiting structure.** Single HTTP client with SWR caching (`app/src/api.ts:8-57`), single config point for `API_BASE_URL` (`app/src/api.ts:4`), URL state canonicalized in one helper per route (`app/src/views/home.tsx:19-29`), loaders colocated with their views, and correct `Vary: HX-Request, HX-History-Restore-Request` cache hygiene (`app/src/index.tsx:25`) so partial/full responses can't be cross-served by a proxy.
- **Lean dependencies.** Three runtime deps, all needed, all at latest, served locally (htmx copied into `dist/static` at build, no CDN — `app/build.mjs:16`).

## What will cause churn

- **Untyped API boundary.** `api<T = any>` (`app/src/api.ts:35`), `loadMoves(pokemon: any)` (`app/src/views/pokemon.tsx:77`), and `(t: any)` casts in `app/src/data.ts:49,80-84` mean a PokeAPI shape change — which the spec explicitly warns about — surfaces as silent runtime `undefined`/`NaN` rather than a compile error. All access funnels through `api.ts`/`data.ts`, so fixing this is cheap; it just wasn't done.
- **No upstream timeout.** `fetch(API_ROOT + path)` (`app/src/api.ts:12`) has no `AbortSignal.timeout()`; a hung API call stalls a page render indefinitely — the one place a modern platform primitive was skipped.
- **Implicit htmx attribute inheritance.** The filter form carries `hx-target="#results"` / `hx-swap="outerHTML"` that its children consume implicitly (`app/src/views/home.tsx:78-82` consumed by `:94,99,110`). That works on htmx 2 (current stable), but htmx 4's explicit-inheritance change means the eventual upgrade touches these views; per-child explicit attributes would be migration-proof.
- **Sort keys triplicated.** `SortKey` (`app/src/views/pokemon.tsx:29`), `COLUMNS` (`:31`), and `SORT_KEYS` (`app/src/index.tsx:50`) each encode the same set; adding a column requires all three.
- **URL string surgery.** `idFromUrl` regex and `apiUrl`'s `indexOf('/api/v2/')` (`app/src/api.ts:48-59`) instead of `new URL(url).pathname`.
