The app is remarkably conservative API-wise. Everything in `src/` is long-stable Hono: `Hono`, `serve`/`serveStatic`, `jsxRenderer` with the documented `ContextRenderer` module augmentation, `hono/jsx` with the automatic runtime (`app/tsconfig.json:12-13`, `app/build.mjs:13-15`), and htmx 2 attributes (`hx-get`, `hx-sync`, etc. — all stable since htmx 1.9/2.0, 2024). No `unstable_`/`experimental_` names, no config flags, no canary packages.

The only "new-ish" things are toolchain version pins, and both are **stable releases**, not experimental: TypeScript 7.0.2 shipped as stable on 2026-07-08 (devblogs.microsoft.com/typescript/announcing-typescript-7-0), and `@hono/node-server` 2.x shipped as a stable major on 2026-04-21 whose release notes state "the public API stays the same" (github.com/honojs/node-server/releases/tag/v2.0.0). Hono itself is pinned to the mature 4.13 line, not even the newest major. htmx 2.0.11 and esbuild 0.28.2 are likewise stable tooling. Version pins are exact (no `^` on runtime deps), which further reduces drift risk.
