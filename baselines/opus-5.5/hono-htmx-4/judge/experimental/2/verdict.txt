## Review: experimentalness

I've read the whole app (`app/src/index.tsx`, `components.tsx`, `api.ts`, `pages/home.tsx`, `pages/pokemon.tsx`, `pages/details.tsx`, `public/app.js`, `scripts/copy-assets.mjs`, `tsconfig.json`, `package.json`) and verified the status of every framework API and dependency against current release channels.

**What the app actually uses**

- **Hono `^4.13.14`** — `Hono`, `Context`, `app.notFound`/`onError`, `c.html`/`c.redirect` (`app/src/index.tsx:5,15,21,78,84`). v4.13.14 is the current stable line (released 2026‑10‑25); Hono v5 exists only as `v5.0.0-rc.1` (2026‑10‑10) and the app correctly does **not** use it (source: github.com/honojs/hono/releases, releasealert.dev).
- **`hono/html` `raw`** and **`hono/jsx` `FC`/`Child`/`PropsWithChildren` + async server components** (`app/src/index.tsx:6,15-20`; async FCs at `app/src/pages/home.tsx:88`, `app/src/pages/pokemon.tsx:30,115`). Async JSX components are part of the documented, stable hono/jsx rendering pipeline since v4.0 (source: hono.dev/docs/guides/jsx).
- **`@hono/node-server` `^2.1.5`** — `serve` (`app/src/index.tsx:91`) and the `@hono/node-server/serve-static` subpath export with `rewriteRequestPath`/`onFound` (`app/src/index.tsx:26-33`). Both are the exact patterns in the adapter's current README, incl. the `onFound` Cache-Control example (source: github.com/honojs/node-server). The 2.x subpath import (rather than the old root-entry import) is the *current* recommendation.
- **htmx.org `^2.0.11`** — the current stable release (2026‑09‑22; htmx 4.0 is only mentioned in the changelog as the source of a backport, not shipped). All directives used (`hx-get`, `hx-target`, `hx-swap`, `hx-sync`, `hx-trigger`, `app/src/pages/home.tsx:95-99`; `app/src/pages/pokemon.tsx:179-183`) and response headers (`HX-Push-Url`, `app/src/index.tsx:37`; `HX-Request`/`HX-History-Restore-Request`, `app/src/index.tsx:11`) are long-stable, and it correctly uses the 2.x `HX-*` header names rather than the deprecated 1.x `X-*` spellings (source: htmx.org, github.com/bigskysoftware/htmx CHANGELOG).
- **Node platform**: `import.meta.dirname` (`app/src/index.tsx:25`, Node ≥20.11), `fs.cpSync`/`createRequire` (`app/scripts/copy-assets.mjs:3,8-10`) — all stable well over a year; spec pins Node 24.

**The only "new" thing**: TypeScript `^7.0.2` (`app/package.json:12`) — the native Go-port compiler, released 2026‑07‑08 as the official stable `latest` (source: devblogs.microsoft.com/typescript/announcing-typescript-7-0). It's a stable release, not experimental, but it's a ~3-month-old major rewrite powering the entire build (`npm run build` = `tsc`, `app/package.json:6`). No experimental tsconfig flags (`app/tsconfig.json` has none). Notably the measured facts report `experimental: []`, and my reading agrees: no `unstable_*`/`experimental_*` names, no RC/canary deps.

Everything is small, vanilla, and easily swappable: the htmx surface is confined to attributes in two components plus one plain delegated-event listener (`app/public/app.js:1-36`); the API cache is a hand-rolled `Map` with a semaphore (`app/src/api.ts:18-47`) rather than any preview library feature.
