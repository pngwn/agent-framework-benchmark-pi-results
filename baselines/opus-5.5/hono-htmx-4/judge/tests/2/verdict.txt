The app contains no tests of its own: `app/package.json` has only `build`, `start` and `typecheck` scripts (no `test`, no runner devDependency), and the only JavaScript in `app/public/` is the hand-rolled table sorter. Static facts confirm: 0 test files, 0 cases, 0 assertions. All quality therefore rests on the acceptance suite, which exercises rendered pages end-to-end but leaves the pure logic — the parts most tempting to refactor — completely unguarded.

What's untested, and what bugs that invites:

- **`app/src/pages/home.tsx:62-79`** — `loadResults` does substring search, type/generation filtering, `Math.ceil` pagination and `slice((page-1)*48, page*48)` paging. An off-by-one in the slice, a flipped filter predicate, or page clamping (`Math.min(query.page, pages)`) breaking would slip through any data-layer refactor; the acceptance tests only pin a handful of filter combinations.
- **`app/src/pages/home.tsx:26-43`** — `parseHomeQuery`/`homeUrl` are pure functions encoding the whole URL-state contract (omit empty/default params, `page>1` only, garbage `page=abc` → 1). Trivially unit-testable, currently guarded by nothing; a regression here silently breaks deep links and history.
- **`app/src/api.ts:44-89`** — the stale-while-revalidate cache and `withSlot` semaphore are concurrency code: pending-promise dedup, error-path `pending` cleanup, LRU eviction via `cache.delete(cache.keys().next().value!)`. These are exactly the bugs (dropped wake-ups, double fetches, unhandled rejections crashing the server) that only deterministic tests catch.
- **`app/src/api.ts:220-235`** — `speciesForPokemon` implements alternate-form exclusion (`id > 10000`), dedupe, and "first reference wins" for `extra`; the hidden-ability flag (`details.tsx:45-52`) is lost if the duplicate ordering assumption ever breaks.
- **`app/src/index.tsx:56-66, 70-79`** — the htmx contract: `isHtmx` header sniffing, `HX-Push-Url` with a *clamped* page, `Vary: HX-Request`, and the `/pokemon/:name/moves` partial endpoint. No test asserts that a filter change returns a fragment vs. a full document or updates the address bar; a route refactor could return a fragment into a full page with no failing test until a human notices.
- **`app/public/app.js:1-31`** — client-side sorting: missing-values-last in both directions, `aria-sort` flipping, event delegation surviving htmx swaps. The "missing last when descending" behavior is a classic regression spot (`cmp * sign` alone would put missing first on the second click).
- **`app/src/pages/pokemon.tsx:143-176`** — moves-table assembly: method grouping, `(name, level)` dedupe, method ordering (`METHOD_ORDER` rank then `localeCompare`), default sort by level-then-name. Complex, spec-heavy, untested.

On the positive side, the code is structured *for* testability: pure helpers (`humanize`, `latestEnglishFlavor`, `dexNumber`, `dash`, `docTitle`) are exported from `app/src/api.ts:132-158` and `app/src/components.tsx:35-90`, and page data loading is separated from JSX. Writing tests would have been cheap; the agent chose not to, and the cost lands on whoever refactors `api.ts` next.
