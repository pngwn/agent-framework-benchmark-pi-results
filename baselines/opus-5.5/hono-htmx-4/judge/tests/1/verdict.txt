I've reviewed the full app. Confirmed via grep and package inspection: `app/` contains **zero tests** — no test files, no test script in `app/package.json`, no test framework dependency (only `tsc`, `copy-assets`, and `start`/`build`). The measured facts agree (`tests.files: 0`). So this review focuses on what the missing tests would let through.

The riskiest logic, all unguarded:

- **In-memory SWR cache + concurrency semaphore** — `app/src/api.ts:30-68`: stale-while-revalidate, pending-request dedup, LRU-ish eviction (`cache.delete(cache.keys().next().value!)` can evict an entry with a live `pending` promise), and error-path mutation of shared cache entries. This is the most concurrency-subtle code in the app and has nothing pinning it down.
- **Reverse-assembled dex data** — `app/src/api.ts:241-257` (`getDex`) rebuilds each species' type slots by iterating all 18 type endpoints and sorting by slot, plus generation mapping. A slot-sort or id-mapping regression silently mislabels every card's types.
- **Alternate-form exclusion & dedupe** — `app/src/api.ts:225-236` (`speciesForPokemon`): the `id > 10000` filter and "first ref's `extra` wins" rule (which carries the *Hidden ability* marker) would break invisibly under refactor.
- **Filter/pagination/URL state** — `app/src/pages/home.tsx:12-33,52-72`: page clamping, 48-per-page slicing, canonical URL param omission. Classic off-by-one territory.
- **Moves grouping and ordering rules** — `app/src/pages/pokemon.tsx:151-230`: default game = highest `order`, method order `level-up/machine/egg/tutor` then alphabetical, name+level dedupe, default sort. All spec-encoded rules with no regression net.
- **Client-side table sort** — `app/public/app.js:1-32`: missing-values-last in both directions, `aria-sort` bookkeeping, stable tiebreak via index. Untestable from the server side; only a browser test would catch a break, and the `data-sort` contract in `pokemon.tsx:247-263` is its only glue.
- **htmx partial vs full-page paths** — `app/src/index.tsx:29-46` and the `/pokemon/:name/moves` endpoint at `index.tsx:62-68`, which sets `HX-Push-Url` but **not** `Vary: HX-Request` (the `/` route does at `index.tsx:44-45`). A caching proxy in front could serve an htmx fragment to a normal browser with no test noticing. Similarly `app.notFound` (`index.tsx:97`) returns a full document even for `HX-Request` fragment swaps.

Positively: the code is factored so tests would be cheap — `humanize`, `latestEnglishFlavor`, `dexNumber`, `parseHomeQuery`, `homeUrl`, `loadResults`, and `speciesForPokemon` are exported, mostly pure or mockable-with-one-`fetch` functions (`app/src/api.ts:150-176`, `app/src/pages/home.tsx:12-72`). That nobody wrote even ten lines of `node:test` against them is the core gap.
