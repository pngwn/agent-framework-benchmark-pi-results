## Review

**Latest APIs.** The app pins exactly the current stable generation of every library: hono `^4.13.14` (4.13.14 *is* the `latest` dist-tag; Hono 5 exists only as `5.0.0-rc.1` on `next`, so staying on 4.x is correct, not stale), `@hono/node-server` `^2.1.5` (latest), `htmx.org` `^2.0.11` (latest 2.x), TypeScript `^7.0.2` (the current stable native compiler). API usage matches the current docs: `serve({ fetch: app.fetch, port })` and `serveStatic` with `rewriteRequestPath` (`app/src/index.tsx:21`, `app/src/index.tsx:27`) match hono.dev/docs/getting-started/nodejs; `jsx: "react-jsx"` + `jsxImportSource: "hono/jsx"` (`app/tsconfig.json:5-6`) and async server components awaited by `c.html()` (`app/src/pages/home.tsx:104`, `app/src/pages/pokemon.tsx:34`) match hono.dev/docs/guides/jsx; `FC`/`PropsWithChildren`/`Child` are the current type exports. Notably the htmx usage is 2.x-correct where 1.x-era code usually isn't: URL pushing uses the `HX-Push-Url` **response header** (`app/src/index.tsx:40`, `app/src/index.tsx:73`) rather than the `hx-push` attribute that htmx 2 removed, and it guards `HX-History-Restore-Request` so history restore gets a full page (`app/src/index.tsx:13`). It also sets `Vary: HX-Request` on the htmx-varying route (`app/src/index.tsx:41,45`) — cache hygiene most htmx apps skip.

**Platform.** Good reach: `fetch` with `res.body?.cancel()` on the 404 path (`app/src/api.ts:57`), `URLSearchParams` for canonical URLs (`app/src/pages/home.tsx:27`), `import.meta.dirname` for a cwd-independent static root (`app/src/index.tsx:30`) — which also sidesteps the `serveStatic` cwd warning in the docs, event delegation with `closest`/`dataset` instead of a bundler (`app/public/app.js:4-10`), ES modules throughout, lazy images with intrinsic dimensions (`app/src/components.tsx:44`). The one gap: `load()` has no timeout — no `AbortSignal.timeout()` — so a hung upstream pins one of the 16 semaphore slots indefinitely (`app/src/api.ts:49-58`).

**Dependencies.** Three runtime deps, all needed, all latest stable, zero filler; htmx is vendored from `node_modules` into the static dir (`app/scripts/copy-assets.mjs:10`) rather than pulled from a CDN — the approach the htmx docs recommend for production.

**Churn resistance.** All API access and every API shape live behind one module (`app/src/api.ts`); pages consume typed summaries, so an upstream change or a Hono upgrade touches few files. Config (`API_BASE_URL`, freshness, limits) is centralized (`app/src/api.ts:5-10`). Minor coupling: htmx swap-target ids (`#results`, `#search`, `#moves-body`) are string-duplicated across server components, route handlers, and the client script (`app/src/pages/home.tsx:104-108`, `app/src/index.tsx:36`, `app/src/pages/pokemon.tsx:225`, `app/public/app.js:2`), so a rename ripples through three layers. The `/pokemon/:name/moves` route responds differently to htmx vs non-htmx requests (redirect vs partial) but omits the `Vary: HX-Request` header the home route sets (`app/src/index.tsx:72-76`), an inconsistency a proxy cache could expose; its `HX-Push-Url` also drops the `#moves` fragment. A fabricated species `Ref` with `url: ''` is a small wart (`app/src/pages/pokemon.tsx:87`).
