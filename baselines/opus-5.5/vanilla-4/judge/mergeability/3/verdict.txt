## Review

I read `SPEC.md`, all 12 source files in `app/` (router, data layer, DOM helpers, five page modules, production server, index.html, tsconfig, styles) and cross-checked behaviors against the spec. No UI framework is in play, so "idiomatic" here means vanilla platform APIs + standard Vite usage — which this app does straightforwardly.

**What's good**

- `app/src/main.ts:1-78` — a ~70-line hand-rolled router (regex route table, render-token race guard, delegated link interception that correctly falls through to native hash navigation at `main.ts:53`) is the right amount of hand-rolling for framework-free vanilla.
- `app/src/api.ts:71-84` — promise-level cache with eviction of failed fetches (`p.catch(() => cache.delete(url))`), `NotFoundError` classification for clean 404 rendering. All data over HTTP at request time as the spec demands.
- `app/server.mjs:14,37-41` — runtime `API_BASE_URL` injection into an `<!--app-config-->` placeholder with `<` escaped (`server.mjs:20`), path-traversal guard (`server.mjs:41`), method/HEAD handling, and proper 404 status for non-routes. This is exactly why a hand-rolled server beats `vite preview` here.
- No `innerHTML` anywhere; all DOM built via `createElement`/text nodes (`app/src/dom.ts:18-31`), so no XSS surface. Stat-bar widths come from API numbers into a `style` attr — safe.
- `app/src/pages/pokemon.ts:244-263` — moves tables have their own token race guard for the `change` listener, matching the pattern in `main.ts`.

**Problems found**

- Real race: `app/src/pages/home.ts:117-131` — the 150 ms debounce timer is never cancelled when the user navigates away. `apply()` calls `updateUrl(filtersUrl(filters), true)`, and `filtersUrl` (`home.ts:33`) hardcodes `new URL('/', location.href)`, so a timer firing after a click navigates to `/pokemon/x` will `replaceState` the visible Pokémon page's URL to `/?q=…`. Narrow window, but it corrupts history state — the classic leaked-timer bug.
- `app/src/pages/pokemon.ts:264-266` — an invalid `?game=bogus` falls back to the default version group in the select but the stale `game` param stays in the URL; view and URL disagree.
- `app/src/pages/home.ts:94-99` — `?page=999` is clamped for display ("Page 3 of 3") but the URL is never synced, and the param is also not omitted when equal to the clamped default.
- `app/src/pages/pokemon.ts:288-294` — `buildTables` fires one fetch per move with no concurrency limit (~90+ parallel requests for scarlet-violet); saved only by the browser's connection limit and the cache. Acceptable for this API, worth a limiter.
- `app/src/dom.ts:30-40` — `sectionId` is hidden mutable module state generating opaque ids (`section-42`); fine functionally, but per-page prefixes would be more debuggable.
- `app/src/dom.ts:6-8` — the `Attrs` record lumps event listeners in with attributes (`Record<string, string | number | boolean | EventListener>`), so typos in `onclick` silently become attributes; a discriminated key would type-check better.
- `app/server.mjs:15` — `dist/index.html` is read at startup; running `npm start` before `npm run build` fails with a raw ENOENT rather than a helpful message.

The structure is clean: `api.ts` (data) / `dom.ts`+`components.ts` (view primitives) / `pages/*` (one file per route) with clear boundaries, and the shared card logic (`toSpeciesCards`, `api.ts:210-227`) removes what would otherwise be four copies of alternate-form filtering. `nav.ts` is a 7-line module — trivially mergeable into `main.ts`, but harmless.
