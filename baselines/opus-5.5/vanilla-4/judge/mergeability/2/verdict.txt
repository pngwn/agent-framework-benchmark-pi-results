## Review

A clean, deliberately minimal vanilla-TS/Vite app: a hand-rolled `h()` DOM helper, a promise-caching API client, one small router, five page modules, and a hand-written static server. For a framework-less Vite app, hand-rolling the router/render loop *is* the idiomatic choice, and the implementation is careful: stale-render tokens (`main.ts:23`, `pokemon.ts:314`), `NotFoundError` → Not-found handling, `title` from the post-render `h1`, `aria-busy`, `history.scrollRestoration`, XSS-safe DOM construction (text nodes everywhere, escaped config injection in `server.mjs:27`), and path-traversal guarding on the server (`server.mjs:42`).

**Strengths**
- `app/src/api.ts` is a genuinely thin data layer: typed responses, single in-memory promise cache with rejection eviction (`api.ts:108`), and pure text/aggregation helpers (`humanize`, `latestFlavorText`, `toSpeciesCards`) that every page reuses instead of re-implementing.
- `pages/pokemon.ts:157-197` turns the spec's sortable-move-tables requirement into a small table-driven `COLUMNS` model with per-column `value`/`cell` pairs — the right shape for this feature, not premature generality.
- `server.mjs` is production-appropriate: HEAD support, immutable caching for hashed assets, 404 status for unknown routes while the app renders the Not-found page.

**Concerns**
- The route table exists twice: `main.ts:13` and `server.mjs:31`. Adding a route (or changing a URL shape) requires editing both files in two runtimes; this is the one leaky server/client boundary and my top merge-blocking-adjacent nit.
- `pages/pokemon.ts:286` fires one parallel fetch per learn-entry for the selected game with no concurrency limit (Mew in `scarlet-violet` is several hundred requests on first view). Cached afterwards, and the API is local, but it's unbounded fan-out.
- `get()` has no `AbortSignal`; navigating away mid-fetch lets in-flight requests run to completion (only the commit is guarded by `renderToken`).
- `pages/home.ts:94` clamps an out-of-range `page` for display but leaves the bogus `page=999` in the URL; `pokemon.ts:273` similarly leaves an invalid `game=` param. Cosmetic state/URL mismatches.
- `dom.ts:36-40` uses a module-global monotonic `sectionId` counter — hidden global state, harmless but slightly smelly; ids grow forever over a long session.

I found no security or serious correctness problems. I'd approve after a round of nits.
