Confirming the measured facts: `app/package.json` defines only `dev`, `build`, `preview`, `prepare`, `check`, `check:watch`, and `start` — there is no test script, no runner in devDependencies, and zero `*.test.*`/`*.spec.*` files anywhere under `app/`. The app's logic is nonetheless rich in exactly the kind of pure, testable code that a small Vitest suite would have covered cheaply: `app/src/lib/util.ts` (name/dex formatting), the home page's filter/pagination math, the move-table sort state machine, alternate-form exclusion in `pokemonCards`, localized-string selection, and a hand-rolled in-memory HTTP cache.

Notable risk concentration with no guard once the acceptance suite stops pinning it:

- **Home filtering/pagination** — `app/src/routes/+page.server.ts:29-42`: case-insensitive substring match, type/generation membership, page clamping (`Math.min(Math.max(...), pageCount)`), 48-per-page slicing, default-omitted URL params rebuilt in `href()` at `app/src/routes/+page.svelte:20-30`.
- **Move table sorting** — `app/src/lib/components/MoveTable.svelte:45-70`: "missing values last in both directions" (`if (va === null) return 1`), ascending-first toggle with `direction` flip, tie-break by name, default order (level then name vs name only). Sorting bugs here are pure logic and would slip straight through.
- **Alternate-form exclusion** — `app/src/lib/server/api.ts:126-143`: `if (!(id <= MAX_DEFAULT_ID))` boundary, dedup by Pokémon ID, re-sort by dex, and species-name fallback (`byId.get(id)`) for references like `deoxys-normal` → `Deoxys`.
- **Moves assembly** — `app/src/routes/pokemon/[name]/+page.server.ts:88-117`: default game = highest `order` (fallback to ID when `order` is missing, `group?.order ?? idFromUrl(groupUrl)`), method ranking `['level-up','machine','egg','tutor']` then alphabetical, and the dedup key `${method}|${move}|${level}`.
- **Cache semantics** — `app/src/lib/server/api.ts:22-55`: 60s TTL on *promises*, 404s cached as `null` (stale-not-found window after data changes), rejection cleanup.
- **Client URL-state sync** — `app/src/routes/+page.svelte:14-16,36-48`: debounce timer plus `afterNavigate` type check (`navigation.type !== 'goto'`) to avoid clobbering in-flight keystrokes — a race-prone interaction with no test.

The framework's current guidance (svelte.dev/docs/svelte/testing) recommends Vitest for unit/component tests (`sv add vitest`) and Playwright for E2E; the app adopted neither. Only `npm run check` (svelte-check) exists as an automated safety net, which catches type errors but none of the behavioural logic above.
