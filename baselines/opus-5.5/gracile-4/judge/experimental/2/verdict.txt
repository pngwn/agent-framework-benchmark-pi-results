I've reviewed the app, the Gracile docs (gracile.js.org), the official Hono starter, and npm registry metadata for the pinned versions. Here's my assessment for the **experimentalness** dimension.

## What the app actually leans on

- **Framework baseline**: `@gracile/gracile@^0.11.0` is the *current latest stable* release (published ~May 2026 per registry metadata), and every Gracile API the app touches is documented in that release: `defineRoute` with `handler`/`document`/`template` (`app/src/routes/(home).ts:1-6`, `app/src/routes/pokemon/[name].ts:290`), `server-html`'s server-only `html` (`app/src/routes/(home).ts:2` — the docs explicitly recommend this import over client Lit `html` to avoid hydration markers), `output: 'server'` (`app/vite.config.ts:6`), the `route-template-outlet` element (`app/src/document.ts:16`), and the `.client.ts` sibling-script convention (`app/src/routes/(home).client.ts`, `app/src/routes/pokemon/[name].client.ts`). The Hono integration (`app/server.js:14-20`) mirrors the official `minimal-server-hono` starter and the documented Hono adapter almost line-for-line.
- **Deliberate conservatism**: Gracile documents its whole-page hydration, CSR add-on and "page premises" as *"Caution: Experimental. This is not well tested"* (progressive-interactivity docs). The app **avoids all of them**: its client scripts are plain `HTMLElement` custom elements (`app/src/routes/(home).client.ts:3`, `app/src/routes/pokemon/[name].client.ts:7`) doing fetch-and-swap, i.e. documented "layer 3 progressive enhancement" rather than the experimental hydration layers. No `unstable_`/`experimental_` markers, no `@lit-labs` direct imports in app source (grep only hits them as transitive deps of `@gracile/gracile` in `package-lock.json:57`).
- **Recently-stable surface**: `vite@^8.3.5` (`app/package.json:10`) — Vite 8 (Rolldown) went stable 2026-03-12, ~7.5 months before "today", and is explicitly in `@gracile/engine@0.12.0`'s peer range (`^7.0.0 || ^8.0.0`), so this is a supported, officially-declared combination rather than a gamble.
- **The one fragile spot**: `app/src/lib/build.ts:8` detects Gracile's internal build-time render pass via the undocumented `gracile-static` hostname sentinel. It's neatly quarantined in an 8-line module and justified by the spec's "no build-time data fetching" rule, but it's coupling to framework internals I could not find documented anywhere — it would break silently if Gracile changes that sentinel string.

## Risk picture

The only truly experimental foundations are ambient: Gracile self-describes as **alpha** ("This project is in an alpha state", gracile.js.org/docs/) and runs on Lit SSR via the `@lit-labs/ssr` labs package — but that's the mandated framework's architecture, not a choice the app made beyond the spec. Within that constraint, the app picks the most stable path available at every fork (server mode + Hono adapter + non-hydrated custom elements) and pins `^0.11.0` so caret semantics keep it on 0.11.x patches only.
