What follows is the risk map, since the acceptance suite in `tests/` is the only guard.

**Riskiest untested logic (with concrete locations):**

- **Pagination and URL filter state** — `app/src/routes/(home).ts:45-52`: `slice((page-1)*48, page*48)`, the `Number.parseInt`/`Math.max`/`Math.min` clamp chain, and `totalPages = Math.max(1, Math.ceil(...))`. A refactor that drops the upper clamp makes `?page=999` render an empty list; a dropped `Math.max(1, …)` breaks zero-result filtering; `parseInt('2x')` silently yields `2`. Paired with `app/src/lib/home-url.ts:9-12`, which must omit defaults (`page=1`, empty `q`) — a regression that always emits `page=1` violates the spec and nothing in-app would catch it.
- **Alternate-form exclusion and dedup** — `app/src/lib/data.ts:27` (`id < 10000` bound) and `data.ts:35-52` (`seen` set, sort by dex, species-map fallback). Inverting the bound, dropping the dedup, or linking `deoxys-normal` instead of `deoxys` are all one-line regressions with visible consequences on every move/ability/type page.
- **API client cache + concurrency semaphore** — `app/src/lib/api.ts:14-33` (`withSlot` queue, `queue.shift()?.()` in `finally`) and `api.ts:55-70` (TTL, LRU re-insert, `value.catch(() => cache.delete(url))`). This is the most likely place for a refactor to hang every request (missed release, `pop()` instead of `shift()`) — a deadlock that acceptance tests might mask by timing, and that nothing in-app would ever flag.
- **Client-side table sorting** — `app/src/routes/pokemon/[name].client.ts:19-26`: missing values (`data-sort === ''`) are pushed last *regardless of `sign`*. The classic refactor — applying `sign` to that comparison — makes blanks sort first when descending. Same file, lines 23-24: `aria-sort` clearing/toggling.
- **Moves table assembly** — `app/src/routes/pokemon/[name].ts:101` (`game = requestedGame && gameNames.includes(...)` — falls back silently on an invalid `?game=`), `[name].ts:114-117` (dedup key `${method}|${move.name}|${level}`; including `level` unconditionally would drop machine/egg duplicates or keep dupes), `[name].ts:88-95` (default game = highest `order` via `games.at(-1)` with a `MAX_SAFE_INTEGER` fallback in `data.ts:140-147`).
- **Progressive enhancement race handling** — `app/src/routes/(home).client.ts:39-59`: the `AbortController` swap is what prevents a stale slow response from overwriting a newer one; deleting it during a "simplify" pass is invisible until a user on slow network sees wrong results.
- **404 contract** — `app/src/lib/api.ts:52-55` returns `null` on 404; routes like `app/src/routes/moves/[name].ts:47-50` turn that into a 404 page. If `load` ever threw on 404, every bad slug becomes a 500.
- **Pure helpers begging for unit tests** — all of `app/src/lib/format.ts` (`humanize`, `dexNumber` padStart, `latestEnglishFlavorText`'s "last English entry + whitespace collapse", `orDash`, `pageTitle`) and `app/src/lib/home-url.ts` are pure, dependency-free, and cover spec-defined edge cases — the cheapest possible coverage, and it's absent.
- **Build-render guard** — `app/src/lib/build.ts:8`: if the `gracile-static` hostname check were removed, handlers would fetch API data at build time — exactly the violation the spec's live-overlay test exists to catch, but a partial regression (only some routes) could slip through.

Positive note: the app is otherwise cleanly layered (`lib/` pure helpers, route handlers returning plain data, thin templates), so the logic most needing tests is already isolated and easy to test — which makes the absence more glaring, not less.
