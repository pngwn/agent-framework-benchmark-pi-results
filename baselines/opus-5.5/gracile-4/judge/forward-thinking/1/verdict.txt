I've reviewed the app against the framework's current stable release (Gracile 0.11.0, Vite 8.3.5, Lit 3.3.3, Hono 4.13.14 — all latest stable as of today) and its docs (`gracile.js.org` — defining routes, base documents, output modes, Hono server recipe) plus the official Hono starter. Here is my review.

## Review

**Current APIs (verified against docs/npm):** The app is on `@gracile/gracile@^0.11.0` (npm `latest`, published ~6 months ago) and uses exactly the documented shapes: `defineRoute({ handler, document, template })` with typed `props`/`params`/`responseInit` (`app/src/routes/(home).ts:12`, `app/src/routes/moves/[name].ts:59`), `html` from `@gracile/gracile/server-html` (`app/src/document.ts:1`), `<route-template-outlet>` (`app/src/document.ts:30`), the `(home)`/`[name]`/`.client.ts` file-routing conventions, `gracile({ output: 'server' })` (`app/vite.config.ts:5`), and a `server.js` that mirrors the official Hono starter (`honoAdapter`, `getClientBuildPath`, `serveStatic`) plus a sensible `Cache-Control: immutable` header for hashed assets (`app/server.js:8-21`). Interactive bits are vanilla `customElements` — a choice Gracile explicitly documents ("Custom HTML Elements") rather than LitElement islands, which trims Lit churn out of the client bundle.

**Platform-first:** The client enhancement is textbook — native `<form>` + `<noscript>` submit fallback (`app/src/routes/(home).ts:85`), `fetch` + `AbortController` + `DOMParser` + `document.importNode` fragment swapping with a `location.assign` error fallback (`app/src/routes/(home).client.ts:62-72`, `app/src/routes/pokemon/[name].client.ts:59-69`), `URLSearchParams` for filter state (`app/src/lib/home-url.ts:5`), and careful details like `res.body?.cancel()` on 404s (`app/src/lib/api.ts:31`) and `Array.prototype.at(-1)` (`app/src/lib/format.ts:28`). CSS uses custom properties, logical properties, `:focus-visible`, `aspect-ratio`.

**Weak spots (churn):** Two places lean on internals rather than documented APIs: `app/src/lib/build.ts:6` sniffs the undocumented `gracile-static` stub origin to detect build-time renders, and `app/src/document.ts:13` uses `new URL('./document.css', import.meta.url).pathname` — a pattern Vite's docs explicitly say "does not work with SSR" (the documented Gracile convention is a root-relative `/src/...` href). Layering is otherwise good (one API client + one domain module), but `routes/pokemon/[name].ts:90` carries ~100 lines of data loading and its own copy of `type Move` (duplicated with `routes/moves/[name].ts:19`), and there's no `typescript`/typecheck tooling at all, so the app's type annotations are never verified.
