# Review — Pokédex app (forward-thinking)

I read `SPEC.md`, all of `app/` (17 source files), the React Router skill's framework-mode reference, the React Router 8.5.0 docs shipped on unpkg (route-module, error-boundary, error-reporting, meta), and verified version currency against npm and the React Router changelog.

## Version currency (verified)

- `react-router` 8.5.0 is the current generation — npm shows 8.5.1 published 2026-10-27; the changelog's `v8.5.0` (2026-10-19) deprecates the `viewTransition` APIs, which this app correctly doesn't use.
- `vite` 8.3.5, `typescript` 7.0.2 (native port, announced 2026-07-08), `react` 19.3.1, `express` 5.3 — all current stable lines.
- The app uses the *newest* idioms, not just the newest version: React Router's v8 route-module doc explicitly says "Since React 19, using the built-in `<title>` element is recommended over the use of the route module's `meta` export" — the app renders `<title>` inline (`app/app/routes/types.tsx:14`, `home.tsx:96`), which is exactly the recommended move, not an outdated shortcut. Typed `Route.LoaderArgs`/`Route.ComponentProps`/`Route.ErrorBoundaryProps`, `data()`-thrown 404s, the root `Layout` export — all current, all used.

## What ages well

- **Data access is behind one boundary.** Every PokeAPI call funnels through `app/app/lib/api.server.ts:22` (`api`, `apiOr404`, `getIndex`, `pokemonCards`); routes never construct fetch URLs themselves. The `.server.ts` suffix keeps it out of the client bundle — the right convention.
- **Lean dependency set** (7 runtime deps) on a custom Express server rather than a bloated adapter stack; `server.mjs:12` correctly uses the Express 5 wildcard `/{*splat}` and top-level `await import`.
- **Graceful degradation**: the filter form is a real native GET form (`home.tsx:101-106`) whose input names match the URL params, so it works even if JS never attaches.
- **No reliance on framework internals or unstable APIs.** `react-router.config.ts` sets only `ssr: true`; no future flags to chase, no `unstable_*` surface adopted.

## What will churn / hurt later

1. **No error reporting in production.** `root.tsx:53` only logs in `import.meta.env.DEV`, and there is no `handleError` in a revealed `entry.server.tsx` or `onError` on `HydratedRouter` — the current documented API for this (RR 8.5 `docs/how-to/error-reporting.md`). Server failures are silent in prod.
2. **Unbounded fetch fan-out with no timeout.** `pokemon.tsx:112` fires one fetch per unique move URL in a game (often 100–300 requests) with no concurrency cap and no `AbortSignal.timeout`; since the cache TTL is 60 s (`api.server.ts:8`), this repeats. Same for the index build (18 type + 9 generation records).
3. **API response types are duplicated across route modules.** `Move` is defined twice with different shapes (`pokemon.tsx:43`, `move.tsx:8`), and `Species`/`Pokemon`/`TypeRecord` live in the route files or `api.server.ts` piecemeal. An API shape change ripples through every route — the opposite of what the otherwise-clean `lib/api.server.ts` boundary promises.
4. **Hand-rolled hydration-compensation, duplicated.** `home.tsx:78-84` and `pokemon.tsx:206-213` both reimplement "apply the value the user picked before hydration" via refs, `document.activeElement` checks and mount-time `navigate`. It's thoughtful (it solves a real SSR race), but it's imperative, subtle, and copy-pasted between two routes — a candidate for one shared hook or a `useSearchParams`-driven controlled input.

## Minor

- `isbot` (`package.json:18`) and `@react-router/node` (`package.json:16`) are not imported anywhere; `@react-router/dev` and `@react-router/express` already pull them in transitively (package-lock).
- `routes/not-found.tsx` renders `null` and exists only to convert splat matches into 404 throws; unmatched URLs already land in the root `ErrorBoundary` with a 404, so the route is dead weight with a confusing empty component.
- `spriteUrl` (`api.server.ts:39`) hard-codes the media path pattern instead of the sprite URLs the API itself returns — spec-documented, but a silent breakage point if the layout moves.
