I've reviewed the app against the spec and confirmed through search that `app/` contains no test files, no test runner dependency, and no `test` script — the measured facts (`testLoc: 0`, `tests.files: 0`) match the code. The dimension therefore reduces to what the acceptance suite won't catch, so I audited the riskiest logic: the species-index construction, card mapping/form exclusion, pagination and URL filter state, move-table grouping, client-side enhancement scripts, and the runtime API cache.

Notable observations backing the findings:

- `app/src/lib/pokedex.ts:77-114` builds the entire 1025-species index (type slots assembled from 18 type records, generation membership) — pure, easily unit-testable functions, zero coverage.
- `app/src/lib/pokedex.ts:122-144` (`cardsForPokemon`) implements the alternate-form exclusion (`MAX_DEFAULT_ID`) and `deoxys-normal → deoxys` species remap that several pages depend on.
- `app/src/pages/index.astro:14-31` clamps `page`, validates `type`/`generation` params, and `pageHref` (line 34) omits default params; `index.astro:83-127` is the debounced, race-guarded client enhancement.
- `app/src/pages/pokemon/[name].astro:46-89` handles version-group ordering, default game selection (`games.at(-1)`), method grouping and row sorting.
- `app/src/scripts/sortable.ts:8-20` implements missing-values-last sorting plus `aria-sort` toggling.
- `app/src/lib/api.ts:32-70` is a stale-while-revalidate cache with a semaphore and LRU eviction; a regression breaks every page, and it's completely untested.
- A latent bug of exactly the kind a unit test would catch: `app/src/pages/abilities/[name].astro:12` falls back to `record.flavor_text_entries`, but the ability resource exposes `flavor_text_entries` under a different key — the fallback can never fire (dead code today, silently wrong behavior if `effect_entries` is ever missing).
