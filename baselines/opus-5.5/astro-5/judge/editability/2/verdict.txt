# Review — Editability of `app/` (Astro 7.4.2, current stable)

The app is on the current stable stack: `astro@^7.4.2` with `@astrojs/node@^11.1.9` (`app/package.json:11,10`), and the config uses up-to-date Astro 7 idioms — `output: 'server'` with the standalone node adapter, `session: false` (the opt-out added in Astro 7.2), and `security.checkOrigin: false`, all still valid in the current configuration reference (`app/astro.config.mjs:4-9`). There's no legacy or experimental-flag debt. Two small libs (`app/src/lib/api.ts`, `app/src/lib/pokedex.ts`) own all data access; pages are thin; components take narrow props. This is an easy codebase to change, with a few duplicated seams noted below.

**Scenario walkthrough**

1. **Remove Abilities** — delete `app/src/pages/abilities/[name].astro`; then the Abilities section and `page.abilities` on the Pokémon page (`app/src/pages/pokemon/[name].astro:170-180`, `:63`), the `hidden` flag on `Card` (`app/src/lib/pokedex.ts:117`) and its rendering (`app/src/components/PokemonCard.astro:29`). Nav has no Abilities link, so no `Layout` change. A handful of scattered edits — mostly clean, small residue.
2. **Sprite bug (Deoxys)** — one render point, `spriteUrl(card.id)` (`app/src/components/PokemonCard.astro:17`), fed by every list via `CardGrid`; card construction happens in two places though (`cardsForPokemon`, `app/src/lib/pokedex.ts:135`, and the home page's species entries via `getSpeciesIndex`), so an ID-mapping fix could touch both.
3. **Sort cards by name** — `CardGrid.astro:14` is the single render seam, but the home page slices/paginates before it (`app/src/pages/index.astro:25,70`) and default dex ordering lives in `cardsForPokemon` (`pokedex.ts:135`), so a URL-persisted sort control means edits in four pages + the component.
4. **Add Items shaped like Moves** — Layout, Section, NotFound, CardGrid/PokemonCard, `api.ts` helpers and all the text helpers (`englishName`, `englishShortEffect`, `latestFlavorText`, `humanize`) are resource-agnostic and reusable; the new pages would copy the skeleton of `moves/[name].astro` (there's no `/moves` index, so `/items` would be modeled on `types/index.astro`). Mostly reuse, one page-copy.
5. **Change API base URL / caching** — everything lives in `app/src/lib/api.ts:4` (base URL), `:6-8` (freshness/entry caps), `:75` (sprite URL base). One file, period.
