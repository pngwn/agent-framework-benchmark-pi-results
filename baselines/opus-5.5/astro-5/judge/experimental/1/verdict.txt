I've reviewed the whole app. Here's my assessment for the **experimentalness** dimension.

## What the app actually uses

**Dependencies** (`app/package.json:9-12`): exactly two — `astro ^7.4.2` (lockfile resolves 7.4.2, `app/package-lock.json:1637`) and `@astrojs/node ^11.1.9`. I verified against current releases: the latest stable Astro is **7.4.4 (28 Oct 2026)**, so the app is on the *current stable major*, not a canary/RC/beta channel. The only `beta` strings anywhere are transitive deps inside Astro itself (`get-tsconfig@5.0.0-beta.6`, `app/package-lock.json:2255`) — not the app's choice.

**Config** (`app/astro.config.mjs:3-8`): there is no `experimental` block at all, and every key set is long-stable:
- `output: 'server'` — documented top-level option, stable for years (`https://docs.astro.build/en/reference/configuration-reference/#output`)
- `adapter: node({ mode: 'standalone' })` — the adapter's stable mode since v1
- `session: false` — sessions config stabilized in Astro 5.0; present in v7 types
- `devToolbar: { enabled: false }` — stable since Astro 3.x (dev-only)
- `security: { checkOrigin: false }` — stable option added in `astro@4.9.0`, confirmed in the current config reference

**Astro API surface in code** — grep across `app/src` shows only the oldest, most boring primitives: `Astro.props` (`app/src/layouts/Layout.astro:10`), `Astro.params` (`app/src/pages/pokemon/[name].astro:29`), `Astro.url.searchParams` (`app/src/pages/index.astro:9`), `Astro.response.status = 404` (`app/src/pages/moves/[name].astro:20`), and the recursive `Astro.self` (`app/src/components/EvolutionNode.astro:17`). No middleware, no Actions, no server islands, no view transitions, no content layer, no `astro:env`, no `src/fetch.ts` (Astro 7's new advanced-routing entrypoint is a reserved name — the app doesn't have one and doesn't need it). No `is:inline`/`define:vars`/`transition:`/`client:` directives anywhere.

**Astro 7's new stable features**: v7 (2026-06-22) stabilized route caching (`cache`/`routeRules`) and made advanced routing, queued rendering and the Rust compiler defaults. The app opts into none of them — not even the now-free route caching: `app/src/lib/api.ts:25-62` hand-rolls a semaphore + stale-while-revalidate in-memory Map instead. That's a design choice, not an experimental one (using Astro's cache would also *not* be experimental), but it's the only place where the app ignores a newly-stable framework feature.

The only remotely notable flags I found and cleared:
- `security: { checkOrigin: false }` explicitly disables the CSRF origin check that is **on by default in v7**. For this read-only, GET-only, cookie-less app it has no practical impact (checkOrigin only inspects unsafe POST/PATCH/DELETE/PUT), but it's an unnecessary downgrade to write down.
- Riding `astro@7` four months after its release does expose the app to v7's churn (Vite 8, Rust compiler, `compressHTML: 'jsx'` whitespace semantics) — but that's the current stable, and the app passes acceptance on it, so it's the right target, not a risk.
