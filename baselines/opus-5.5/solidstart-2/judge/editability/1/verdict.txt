## Review: `app/` (Pokédex, SolidStart v2)

**Framework currency check:** The app targets `@solidjs/start@^2.1.0` (v2 went stable Aug 2026; 2.1.0 shipped 22 Oct 2026) with Vite 8 + Nitro 3, `vite.config.ts` using the `solidStart()`/`nitro()` plugins — exactly the v2 setup. Its data layer uses `query` from `@solidjs/router` with `"use server"` bodies plus `createAsync` and route `preload` (app/src/lib/queries.ts:3-38, app/src/routes/moves/[name].tsx:11-13), which matches the current v2 data-fetching docs. No deprecated v1 `cache`/`routeData` idioms anywhere. Nothing here is stale.

**What's good for editability:** All PokeAPI knowledge (base URL, cache TTL, media URL pattern, form-ID exclusion, name-mapping) lives in one server-only module, `app/src/lib/server/pokeapi.ts`, reached only through a thin registry of `"use server"` queries (app/src/lib/queries.ts) that return typed DTOs (app/src/lib/types.ts) consumed by dumb presentational components (Section, PokemonCards, MoveTable, TypeBadge). That's a real seam: swapping the data source or changing caching is a one-file job (pokeapi.ts:23, 18, 44-49).

**What costs you:** The sprite URL is built in two places in the same file (pokeapi.ts:113 and :184), so a sprite bug needs a two-site fix or a helper extraction first. The four detail routes each hand-copy the same ~10-line `Switch`/`Match`/`NotFound`/`Title`/`h1` shell (moves/[name].tsx:20-26, abilities/[name].tsx:19-25, types/[name].tsx:20-26, pokemon/[name].tsx:160-165), so a new resource (Items) is mostly copy-paste of boilerplate, not configuration. And the ability-specific `hidden` flag leaks into the shared `Card` type and the shared `PokemonCards` component (app/src/lib/types.ts:9, app/src/components/PokemonCards.tsx:26-28), so deleting the Abilities feature leaves dead markup in a component that four pages share.
