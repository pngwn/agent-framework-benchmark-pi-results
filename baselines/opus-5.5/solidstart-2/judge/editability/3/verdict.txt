## Review

The app is a SolidStart v2 (stable, Vite 8 + Nitro v3) Pokédex with a clean three-layer structure: thin file routes → `query`-wrapped server functions (`app/src/lib/queries.ts`) → a server-only API module (`app/src/lib/server/pokeapi.ts`). I verified the stack matches current guidance (`vite.config.ts` with `solidStart()` + `nitro()`, Vite scripts, Node ≥24 engines) per the SolidStart v2 stable announcement and migration docs.

### Scenario walkthrough

1. **Remove Abilities**: delete `app/src/routes/abilities/`, then pure deletions in `app/src/lib/queries.ts:38` (`getAbility`), `app/src/lib/server/pokeapi.ts:339` (`abilityDetail`), `app/src/lib/types.ts:64` (`AbilityDetail`), and the Abilities section on the Pokémon page (`app/src/routes/pokemon/[name].tsx:133-146`), since its links would dangle. No nav link exists. Five files, all mechanical deletions — difficulty 4.
2. **Sprite bug (Deoxys-style)**: `card()` at `app/src/lib/server/pokeapi.ts:112-113` builds the sprite URL and covers every card list that goes through `cardsFor` (moves, abilities, types). But the home list builds the same URL inline at `app/src/lib/server/pokeapi.ts:184`, so one fix covers 3 of 4 lists — difficulty 4.
3. **Sort cards by name**: `cardsFor`'s single sort at `app/src/lib/server/pokeapi.ts:115` covers moves/abilities/types; home has its own sort at `app/src/lib/server/pokeapi.ts:173`. The component (`PokemonCards.tsx`) renders whatever it's given, so it's untouched — difficulty 4.
4. **Items section**: `listAll`, `api()`, `englishName`, `cardsFor`, `Section`, `CountText`, `NotFound` are all reusable; you'd add a `getItem` query, a server fn, a type, and a route. The catch: the detail-page skeleton (`Switch`/`Match` null + `Title` + `h1` + `preload`) is copy-pasted in four routes (e.g. `app/src/routes/moves/[name].tsx:14-20` vs `app/src/routes/abilities/[name].tsx:14-20`), so the new page clones ~15 lines of boilerplate — difficulty 3.
5. **Change API base/caching**: `apiBase()` (`app/src/lib/server/pokeapi.ts:23`), `TTL_MS`/cache (`:17-19`), and the whole fetch path (`:31-52`) live in one file, and sprite URLs also derive from `apiBase()` — difficulty 5.

### Criteria judgment

- **removability 4** — features are one route directory plus pure deletions in three shared modules; the Pokémon page edit is required by the spec (its Abilities section links to the pages), not entanglement.
- **changeability 4** — nearly all data bugs land in `pokeapi.ts`; the sprite-URL and sort-order duplication are the two spots where a fix needs two edits in one file.
- **coupling 5** — server code is unreachable from the client (only `queries.ts` imports `~/lib/server/...`, per grep), components take narrow typed props (`PokemonCards.tsx:12`, `MoveTable.tsx:28`), shared state is explicit via URL params. Clear seams.
- **abstraction_design 4** — `cardsFor`'s `extra` callback (`pokeapi.ts:103-108`) handles real variation (hidden-ability flag) without flag soup; `Section`, `MoveTable`'s `showLevel`, and `CountText`'s `noun` stretch well. Docked one point for the repeated route skeleton and `Card`'s accumulating single-caller optional fields.
