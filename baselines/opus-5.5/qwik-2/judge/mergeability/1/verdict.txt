I've reviewed the app against Qwik 1.20 (the current stable — `1.20.3` released 2026-10-25, matching the app's pinned version) and current docs. Here's my assessment.

## Review notes

**What's good**

- Structure matches the Qwik City starter conventions exactly: `src/routes/` with `layout.tsx`, `[...rest]` catch-all, `entry.ssr.tsx` setting `lang="en"` via `containerAttributes` (`app/src/entry.ssr.tsx:24-26`), `entry.node-server.tsx` and `adapters/node-server/vite.config.ts` mirroring the official node adapter.
- Data loading is the recommended pattern throughout: `routeLoader$` + `status(404)` for missing resources (`app/src/routes/pokemon/[name]/index.tsx:87-90`) and `resolveValue(useX)` in `head` functions (`app/src/routes/moves/[name]/index.tsx:78-81`) — current, correct API usage.
- `Section`/`TypeBadge`/`CardList` are small, purposeful components; `lib/format.ts` is a clean pure-function module safe to share across server and client.
- Nice touches: rejected promises are evicted from the cache (`app/src/lib/server-api.ts:29`), the search-input sync task refuses to clobber what the user is typing (`app/src/routes/index.tsx:76-80`), and the debounce double-checks the current URL before navigating (`app/src/routes/index.tsx:100-101`).

**Problems**

- **Leaked debounce timer**: the search debounce is a `useSignal<number>`-held `setTimeout` with no cleanup on unmount (`app/src/routes/index.tsx:74,96-106`). Type a query and click a card within the 200 ms window: the timer fires after you've landed on `/pokemon/…` and calls `nav()` back to `/`, yanking the user to the home page. This is exactly the case the documented `useTask$(({ track, cleanup }))` debounce pattern handles (`qwik.dev/docs/core/tasks`, docs demo `demo/tasks/cleanup`). Related: `value={search.value}` + `onInput$` instead of the idiomatic `bind:value`.
- **`any`-typed API layer**: `strict: true` is on, but the load-bearing API shapes are untyped — `app/src/lib/server-api.ts:21,78,94,104` and `app/src/routes/pokemon/[name]/index.tsx:90,105-141` all use `any`/casts. `lib/types.ts` only types the loader→component boundary. A typo in `flavor_text_entries` etc. compiles fine.
- **Derived state computed in the render body**: `app/src/components/moves-table.tsx:76` reads `sortColumn.value`/`sortDirection.value` outside the template, which the Qwik best-practices guide explicitly calls out as causing a whole-template re-render; `useComputed$` is the recommended shape.
- **Cache never evicts expired entries** (`app/src/lib/server-api.ts:18-28`) — bounded by the API's surface (~a few thousand paths), so low risk, but stale entries linger forever.
- **No error path** if the API is down: `api()` throws on non-ok (`app/src/lib/server-api.ts:26-27`), loaders propagate, and the user gets an opaque 500.
- Zero app tests; the sort rules (missing values last, level-up default order), `humanize`, `dexNumber` and pagination clamping are pure and trivially testable.
- Nits: mixed pinning policy (exact `1.20.3` for Qwik, `^` elsewhere in `app/package.json:13-19`); `useHome` re-fetches `allTypes`/`allGenerations` that `speciesIndex()` already gathers internally (harmless via cache, `app/src/routes/index.tsx:34-37`).
