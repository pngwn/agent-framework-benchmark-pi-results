## Review

**Framework currency.** The app pins `@builder.io/qwik` / `@builder.io/qwik-city` at **1.20.3**, which is the current stable release (released 2026-10-25; 2.0 is still at RC and not stable). Judged against 1.20.x docs and starter patterns.

**What's good**

- The Qwik City data-flow is exactly what the docs prescribe: `routeLoader$` for all fetching (`app/src/routes/moves/[name]/index.tsx:17`), URL-as-state for filters (`app/src/routes/index.tsx:41`), `useNavigate` for query updates (`app/src/routes/index.tsx:96`), `DocumentHead` resolved from loader values via `resolveValue` (`app/src/routes/pokemon/[name]/index.tsx:283`), and a `[...rest]` catch-all returning 404 (`app/src/routes/[...rest]/index.tsx:7`). No hand-rolled routing or reactivity anywhere.
- The node adapter setup (`app/adapters/node-server/vite.config.ts`), SSR entry with `containerAttributes: { lang: "en" }` (`app/src/entry.ssr.tsx:22`), and `ssg: null` because all data is request-time — all match the official deployment guidance.
- Server-only API access lives in `app/src/lib/server-api.ts` and is only ever called inside loader closures, so it's stripped from the client bundle — the correct server/client boundary.
- Component-level state is minimal and correct: `useSignal`/`useTask$` for the search box sync (`app/src/routes/index.tsx:77-82`), signals for table sorting (`app/src/components/moves-table.tsx:71-72`). Sorting logic (missing-values-last in both directions) is right (`app/src/components/moves-table.tsx:46-51`).
- The in-memory cache stores promises (no dogpile) and evicts on rejection (`app/src/lib/server-api.ts:26-33`); `speciesIndex()` builds the whole index from cached list endpoints once per TTL — proportionate to a fixed 1,025-species dataset.

**Problems**

- The debounce timer is never cleared on navigation away from `/` (`app/src/routes/index.tsx:114`): if a user types then clicks a card within the debounce window, the pending timeout fires `nav()` to `/?q=…`, hijacking the navigation. Needs cleanup on unmount (Qwik offers task cleanup for exactly this).
- Non-404 API failures throw raw inside `routeLoader$` (`app/src/lib/server-api.ts:29`) — a single 500 from the API becomes an unhandled rejection and a framework error page; no retry or graceful degradation.
- `any` is used pervasively for API records (`app/src/lib/server-api.ts:73,80,87,105,118`) even though `lib/types.ts` shows the author is comfortable with types; PokeAPI responses deserve at least partial interfaces.
- The effect-fallback chain (`short_effect || flavor text || —`) is duplicated verbatim in the moves and abilities routes (`app/src/routes/moves/[name]/index.tsx:39-42`, `app/src/routes/abilities/[name]/index.tsx:20-23`).
- The home loader calls `allTypes()`/`allGenerations()` (`app/src/routes/index.tsx:52-55`) that `speciesIndex()` already fetched internally (`app/src/lib/server-api.ts:141-144`) — the cache dedupes the requests, but the code-level redundancy is confusing.
- Search input is wired manually with `onInput$` + `value=` (`app/src/routes/index.tsx:107-124`) where Qwik's `bind:value` is the idiomatic shorthand; the manual version is defensible because of the focus-guard task, but worth a comment.
