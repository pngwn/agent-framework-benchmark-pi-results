## Review: `app/` (Qwik + Qwik City Pokédex) — forward-thinking

**Framework currency check.** The app pins `@builder.io/qwik` / `@builder.io/qwik-city` at **1.20.3**, which is the current stable (released 2026-10-25; Qwik v2 is still at `2.0.0-rc`/`beta` under the new `@qwik.dev/*` names, so v1 is the correct line to target today). Verified against the deprecated-features table (`useWatch$`/`useMount$`/`useRef`/`useEndpoint`/`loader$` are the legacy ones) and the v2 upgrade guide: none of them appear in this codebase. Every hook used is the current generation — `routeLoader$` (replaces `loader$`/`useEndpoint`), `useTask$` (replaces `useWatch$`), `useSignal` (replaces `useRef`), `status(404)` on the request event, `DocumentHead` with `resolveValue`, `preventdefault:submit`. The server boilerplate (`entry.node-server.tsx:1-59`) is byte-identical to the `create-qwik@1.20.3` starter (I fetched the starter file to compare), and `nodeServerAdapter({ ssg: null })` (`app/adapters/node-server/vite.config.ts:14`) is the documented current way to disable SSG on the node-server adapter. No `useResource$`/`Resource`/`useVisibleTask$` anywhere — the app also deliberately avoids client-side hydration work by doing all filtering server-side in loaders.

**Platform.** Consistently platform-first: native `fetch` with a single in-memory TTL cache (`app/src/lib/server-api.ts:21-31`), `URLSearchParams` for query construction (`app/src/routes/index.tsx:24`), `new URL(...)` manipulation (`app/src/routes/pokemon/[name]/index.tsx:252`), a native `GET` form with `preventdefault:submit` so the filters degrade to a plain form submit without JS (`app/src/routes/index.tsx:90-101`), `type="search"` inputs, `loading="lazy"` plus explicit `width`/`height` on sprites (`app/src/components/cards.tsx:9`), and hand-written modern CSS using custom properties, logical properties (`padding-inline`/`margin-inline`/`padding-block`, `app/src/global.css:59,74`), `aspect-ratio` (`global.css:278`), grid `auto-fill`/`minmax` and CSS multicol (`global.css:526`). No polyfills, no icon fonts, no CSS framework.

**Dependencies.** Zero runtime dependencies; six devDependencies that are all required by the toolchain and match the official starter set (including `vite-tsconfig-paths`, which the 1.20.3 starter also ships). Vite `7.3.1` is the previous-major line that still receives backports and is what Qwik v1 supports (Vite 8/Rolldown arrives with Qwik v2). The `typescript: 5.4.5` pin looks old but is exactly what the Qwik repo itself overrides to across its monorepo, so it's framework-consistent rather than stale. Only gap: `eslint-plugin-qwik` (starter standard, catches Qwik-specific mistakes) is absent, and the type-check script isn't wired into `build`.

**Churn resistance.** All API access is behind one module (`app/src/lib/server-api.ts`) with component-facing shapes in `app/src/lib/types.ts`; `API_BASE_URL` is read in one place; per-page constants are co-located; no framework internals or undocumented behaviour; no copy-pasted starter code that a newer release would generate differently (the copied entry files match the current starter verbatim). A v2 upgrade would touch only the standard files (`package.json`, `root.tsx`, `entry.node-server.tsx`, `vite.config.ts`, `adapter vite.config.ts`) and the CLI migration covers all of them. The main deduction is that the API boundary itself is untyped — `api<T = any>` (`server-api.ts:21`), `allTypes(): Promise<any[]>` (`server-api.ts:78`), and ~20 inline `any` casts in loaders — so changes in the upstream data shape would surface at runtime rather than at compile time, and `tsc --noEmit` never runs as part of `build` (`app/package.json:7`).
