## Review

This is a clean, idiomatic Qwik City 1.20.3 app (the current stable release, published 2026-10-25). The architecture gives editability a strong foundation: all API access, caching and sprite derivation live in `app/src/lib/server-api.ts`; every card list in the app flows through `cardsFor`/`speciesIndex` into the single `CardList`/`PokemonCard` pair; route files own their loaders and heads; components take narrow, typed props from `app/src/lib/types.ts` and never touch server code.

Walking the five scenarios:

1. **Remove Abilities**: delete `app/src/routes/abilities/`, then remove the Abilities section from the Pokémon page (`app/src/routes/pokemon/[name]/index.tsx:225-234`). The nav in `layout.tsx` has no abilities link, so nothing else references the route — but the `hidden` flag machinery (`cards.tsx:19`, `types.ts:26`, `server-api.ts:111`) and `.card-note` CSS (`global.css:204`) would be left dead unless you also clean them.
2. **Sprite fix**: `spriteUrl` (`server-api.ts:67`) is the only sprite derivation, called from `cardsFor` (line 120) and `speciesIndex` (line 163). One fix covers every card list, since the home page and all three detail pages build cards through those two functions. The main caveat: the `Card` object literal is constructed in *two* places, so a fix that changes card shape touches both — same file, though.
3. **Sort by name**: two spots — `cardsFor`'s sort (`server-api.ts:125`) for the detail pages, and the home loader before pagination (`routes/index.tsx:49-56`). Home can't be sorted in `CardList` because pagination happens server-side; both spots are obvious.
4. **Items section**: `Section`, `CardList`, `NotFound`, `orDash`, `pageTitle`, and the `api`/`slug`/`english`/`englishName`/`latestFlavorText` helpers all reuse directly; new files follow the `types/index.tsx` and `moves/[name]/index.tsx` skeletons. But there's no shared detail-page abstraction, so the moves page's ~100-line loader+template gets adapted (not shared) — and the effect-fallback expression is already duplicated between moves and abilities, so a third copy is likely.
5. **API base / caching**: exactly one file. `apiBase()` (`server-api.ts:15`), `CACHE_TTL_MS` (line 7) and the cache Map (line 18) are the only places that know; every fetch goes through `api()` (line 27). The layout's `cacheControl` (`layout.tsx:4-6`) is a separate, correctly-separated browser-cache concern.

Weakest points: the duplicated card construction, the pervasive `any` in loader bodies (the compiler won't catch API-shape changes), the ability-specific `hidden` flag living on the shared `Card` type, and one flat 541-line stylesheet that will silently accumulate dead CSS as features are removed.
