## Review: Pokédex app (Gracile with Lit)

I verified every framework API and dependency version against current sources as of today (2026-10-30):

- `@gracile/gracile` 0.11.0 is the **current latest stable** (npm; `0.11.1-next.*` are prereleases). The app pins it exactly, matching the official starter's own convention.
- `server.js` (`nodeAdapter`, `getClientBuildPath`, `printUrls`) is a near-verbatim, improved copy of the official `minimal-server-express` starter — it adds `immutable`/`1y` caching on `/assets` and disables `x-powered-by`.
- `document.ts:17` uses `new URL('./styles/tokens.css', import.meta.url).pathname`, which the current "Working with assets" doc explicitly presents as the *canonical* alternative to root-absolute strings.
- `defineRoute({ handler, document, template })`, `responseInit.status`, `route-template-outlet`, `.client.ts` sibling scripts, and `Response.json` endpoints all match the current "Defining routes", "Defining the base documents" and "Server Endpoints" docs.
- Deps verified current: `vite ^8.3.5` (latest stable, patched Oct 21 2026), `lit ^3.3.3` (current, May 2026), `typescript ^7.0.2` (the native port, released July 2026), `express ^5.1`, `@types/node ^24` matching the Node 24 runtime.

The architecture is deliberately platform-first and upgrade-tolerant: all PokeAPI access sits behind `lib/api.ts` (fetch + TTL cache + concurrency semaphore) and `lib/data.ts` (typed view models), routes are thin, and `templates/components.ts` renders both server-side (Lit SSR) and in the browser (`lit`'s `render`), so client and server markup cannot drift. Client interactivity is progressive enhancement over native GET forms with a `<noscript>` fallback — no hydration, no experimental add-ons (the official `@gracile-labs/client-router` is flagged "Experimental… not customizable enough"; hand-rolling was the sound call).

The main aging risk is the `POKEDEX_BUILD_STEP` env-var guard (vite.config + per-route checks), which encodes an *undocumented* Gracile behavior (handlers run once during build) — contained, but worth a comment-to-code consolidation and watching for an official flag.
