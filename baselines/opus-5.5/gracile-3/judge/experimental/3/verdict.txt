## Review: experimentalness — Gracile 0.11 + Lit Pokédex

**What the app actually reaches for.** Every API the app's own 19 source files touch is documented, stable-surface API of the framework's current release (0.11.0) or long-stable platform code:

- `defineRoute` with the `handler`/`document`/`template` trio, `context.props`, and `responseInit.status` (`app/src/routes/(home).ts:9`, `app/src/routes/moves/[name].ts:16-19`, `app/src/routes/types/[name].ts:13-16`) — these are exactly the shapes shown in Gracile's own annotated examples on gracile.js.org.
- `html` from `@gracile/gracile/server-html` and `<route-template-outlet>` (`app/src/document.ts:1,31`) — the literal pattern from the framework's documented `src/document.ts` example.
- The Node adapter stack (`app/server.js:10-23`) — `express.static(gracile.getClientBuildPath(...))`, `gracile.nodeAdapter(handler)`, `gracile.printUrls(...)` — is near line-for-line the official `minimal-server-express` starter's `server.js`.
- `.client.ts` route bundles, `@gracile/gracile/ambient` types, and `@gracile/gracile/tsconfigs/strictest` (`app/src/ambient.d.ts:1`, `app/tsconfig.json:2`) — all core, current conventions.
- Client enhancements use only long-stable browser APIs: `history.pushState`/`popstate`, `DOMParser`, `fetch`, `Intl.Collator`, `lit`'s `render` (`app/src/routes/(home).client.ts:3`, `app/src/routes/pokemon/[name].client.ts:2`). No canary web APIs (no Navigation API, View Transitions, signals).
- Zero `unstable_`/`experimental_` names or flags anywhere; the vite config passes only `{ output: 'server' }` (`app/vite.config.ts:6`), and the measured `experimental: []` confirms.

**What is experimental or very new, and whose choice it was:**

1. **`@lit-labs/ssr` / `@lit-labs/ssr-client`** (`app/package.json:13-14`) — Lit Labs packages are formally experimental ("may receive breaking changes or stop being supported", lit.dev/docs/libraries/labs). The app *never imports either* (grep across `app/src`: zero `@lit-labs` references); `@gracile/gracile@0.11.0` ships `@lit-labs/ssr` as a transitive dependency (confirmed via npm registry metadata). The framework was mandated by the spec, so this inheritance is unavoidable — but listing them as *direct* app dependencies is redundant and slightly widens the experimental surface for nothing (`ssr-client` in particular: the app uses no custom elements, so no hydration path exists). Removing both from `app/package.json` is a strict improvement.
2. **TypeScript `^7.0.2`** (`app/package.json:18`) — the Go-native rewrite went stable 2026-07-08, ~3.5 months before today; "recently stable", dev-only (`npm run check`), low risk.
3. **Vite `^8.3.5`** (`app/package.json:19`) — stable since 2026-03-12 (~7.5 months), and the major Gracile 0.11 targets; normal, not experimental.
4. **Gracile `0.11.0` pinned exactly, no caret** (`app/package.json:10`) — on a pre-1.0 framework this is exactly the right containment: deterministic lock against breaking 0.x minors.

**Judgment.** This is a deliberately conservative codebase: the only experimental package in the runtime chain is one the assigned framework itself is built on, and the app keeps even that at arm's length. Scores reflect that app-authored code relies on long-stable APIs, with inherited labs experimentation plus a very fresh (but stable) toolchain.
