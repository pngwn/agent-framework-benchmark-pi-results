I've reviewed the app end-to-end. Here's what I found for the **test quality** dimension.

## The headline: there are no tests at all

Confirmed both by the measured facts (`tests.files: 0, cases: 0, runner: []`) and by inspection: `app/package.json:5-10` defines only `build`, `dev`, `start`, `typecheck` — no test script, and no `vitest`/`playwright`/`jest` anywhere in the dependency tree. There is a `typecheck` script, which is a genuine (small) safety net for the loader/`lib` code, but it asserts nothing about behaviour.

The frustrating part is that the riskiest logic in this app is almost entirely **pure functions and loaders that would be trivially unit-testable**: `humanize`/`dexNumber`/`idFromUrl`/`orDash` (`app/app/lib/format.ts`), the localization and card transforms (`app/app/lib/api.server.ts:201-257`), the home loader's filter+paginate pipeline (`app/app/routes/home.tsx:41-69`), and the move-table comparator (`app/app/components/move-tables.tsx:36-53`). None of it is covered.

## Where bugs will hide once the acceptance suite stops guarding

1. **Home filtering + pagination** (`app/app/routes/home.tsx:41-69`) — combining `q`/`type`/`generation`, the 48-per-page slice, and page clamping (`Math.min(Math.max(1, requested), pageCount)`). Classic off-by-one territory; a data-layer refactor that changes how `typesById` is built would silently break type filtering, and nothing would fail.
2. **URL state serialization** (`app/app/routes/home.tsx:76-86`) — `queryFor` must omit empty/default params and `page<=1`. A regression here breaks deep links like `/?type=fire&generation=generation-i` and the "omit default params" requirement.
3. **Move-table sorting** (`app/app/components/move-tables.tsx:36-53`) — missing-values-last in *both* directions, tie-break by name, default level-up ordering. The null-handling branch (`va === null ? 1 : -1`) is exactly the kind of comparator that inverts under refactor with no test to catch it.
4. **Move grouping on the Pokémon page** (`app/app/routes/pokemon.tsx:55-100`) — method ordering (`METHOD_ORDER` then alphabetical), dedup key `move|method|level`, default game = highest `order`, level column only for level-up, invalid `?game=` fallback. Lots of spec-critical ordering rules, zero coverage.
5. **`cardsFromPokemon`** (`app/app/lib/api.server.ts:237-257`) — alternate-form exclusion (`id > 10000`), dedup, dex-number sort, and the `deoxys-normal → deoxys` mapping via the species index. The hidden-ability `extra` callback (`app/app/routes/ability.tsx:22-29`) is only applied to the *first* ref per id — fine today, but a silent behaviour if the data ever lists a Pokémon twice.
6. **`idFromUrl` returning `NaN`** (`app/app/lib/format.ts:19-22`) — malformed URLs silently drop cards rather than failing loudly; a data change could make entries vanish with no signal.
7. **Localisation helpers** (`app/app/lib/api.server.ts:203-222`) — "latest" English flavor text (last entry) vs. `englishShortEffect` (first entry) and the `\n`/`\f` whitespace collapse. A refactor that flips last→first would pass typecheck and no test would notice.
8. **Debounced search ↔ URL sync** (`app/app/routes/home.tsx:96-124`) — the `lastPushed` ref dance is the most fragile client logic in the app (back/forward, race with debounce timer). Only the acceptance tests touch it.
9. **Error/404 classification** (`app/app/lib/api.server.ts:44-52`, `app/app/root.tsx:50-60`) — `NotFoundError` → `data(null, 404)` → `isRouteErrorResponse` → "Not found" heading. A regression makes missing Pokémon render "Something went wrong" — nothing would catch it.
10. **In-memory cache** (`app/app/lib/api.server.ts:19-39`) — 60 s TTL with failure eviction; the acceptance harness's live-data overlay (extra Pokémon) already skirts staleness. Cache behaviour is entirely unguarded.

The one positive: the risky logic is cleanly factored into `lib/` and loader functions with explicit types, so adding tests later would be cheap — the agent just didn't.
