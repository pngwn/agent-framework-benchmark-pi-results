## Review: Pokédex (React Router 8.5, framework mode)

**What I verified:** React Router's current stable is **8.5.x** (8.5.1 shipped Oct 27, 2026, per reactrouter.com/changelog), so `^8.5.0` in `app/package.json:8` is the latest major, not a training-data version. Vite 8's built-in `resolve.tsconfigPaths` (`app/vite.config.ts:6`) is the native replacement for the `vite-tsconfig-paths` plugin (Vite 8 changelog, vitejs/vite#277) — a genuinely current choice rather than the plugin-era default. The skill's framework-mode reference confirms every convention in use: `app/routes.ts`, `root.tsx` with `Layout`/`ErrorBoundary` exports, loaders parsing `request.url`, `throw data(null, { status: 404 })` for missing records, `+types` typegen.

**Latest APIs (5).** Nothing deprecated is used: v8 removed `react-router-dom` and the deprecated `meta` `data` arg — this app imports only from `react-router` (`app/app/root.tsx:1`) and uses `loaderData` in every `meta` (`app/app/routes/pokemon.tsx:31`). The 8.5.0 view-transition deprecation doesn't apply (no `viewTransition` props anywhere). The 404 path is idiomatic on both ends: a splat route whose loader throws `data(null, {status: 404})` (`app/app/routes/not-found.tsx:3`, `app/app/lib/api.server.ts:51-53`) rendered by a root `ErrorBoundary` typed with `Route.ErrorBoundaryProps` (`app/app/root.tsx:69`) — exactly the documented pattern, and it gets real 404 statuses.

**Platform (4).** `URL`/`URLSearchParams` for query handling (`app/app/routes/home.tsx:30`, `:81`), native form elements with a `<noscript>` submit fallback (`home.tsx:188-190`), `useId`-derived section names (`app/app/components/ui.tsx:32`), custom properties and `aspect-ratio` in the CSS (`app/app/app.css:302`). The one real gap: server fetches pass no `AbortSignal` (`app/app/lib/api.server.ts:26`); loaders already receive `request` (`home.tsx:29`), so `fetch(url, { signal: request.signal })` would make abandoned navigations cancel upstream work.

**Dependencies (4).** Runtime deps are exactly what the framework mandates, at current versions — with one dead weight: `isbot` (`app/package.json:14`) is never imported anywhere in `app/` (it's only used by the generated `entry.server.tsx` this app doesn't have; the framework's internal default doesn't need it). Grep confirms zero usages.

**Churn resistance (4).** This is the strongest structural property: every PokeAPI call, shape type, and localization helper lives behind one server-only module (`app/app/lib/api.server.ts` — the `.server.ts` name means a client import would fail the build), components receive plain derived objects typed by the route's generated types. Small longevity concerns: the TTL cache never evicts entries (`api.server.ts:16`, `:31` — the Map grows forever in a long-lived server), and the search-box/URL sync is a hand-rolled web of refs (`home.tsx:104-124`) that will be the first thing to break when someone touches filtering.
