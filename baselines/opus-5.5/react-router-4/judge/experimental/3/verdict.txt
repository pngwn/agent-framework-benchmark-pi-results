I've reviewed the app against the React Router 8.5.0/8.5.1 changelog (current stable, released 2026-10-19/-27), the official react-router skill references in this repo, and the Vite 8 release notes (stable 2026-03-12). Here's what I found:

**What the app uses** — exclusively long-stable, documented APIs:
- `routes.ts` uses only `RouteConfig`/`index`/`route` (`app/app/routes.ts:1-11`) — no lazy route object API, no `middleware`, no RSC.
- `react-router.config.ts` sets only `ssr: true` (`app/react-router.config.ts:4`) — which is the default; no `future` flags, no `unstable_api-only` mode.
- `root.tsx` uses `Layout`, `Links`, `Meta`, `Scripts`, `ScrollRestoration`, `Outlet`, `isRouteErrorResponse` (`app/app/root.tsx:5-14`), all stable since v7.0. Notably it does **not** use the view-transition APIs that 8.5.0 just deprecated.
- The single "newest" API is `data()` (`app/app/lib/api.server.ts:5,40`), stable since v7.9.0 (Sept 2025, >12 months ago) and the documented replacement for the removed `json()` helper — the skill reference explicitly endorses `throw data("Not Found", { status: 404 })` for missing records, which is exactly what the app does.
- Route types come from `./+types/*` typegen (`app/app/routes/home.tsx:3`), stable since v7.
- React 19's `useId` (`app/app/components/ui.tsx:1`) is stable since React 18.
- Toolchain is current-stable, not canary: React Router 8.5.x, Vite 8.0.3 (stable March 2026, incl. the stable `resolve.tsconfigPaths` option at `app/vite.config.ts:5-7`).

**What it avoids** — every unstable feature in the current release (API-only mode, `unstable_fetch`/`HydratedRouter`, `future.unstable_customRouteDiscovery`/`unstable_useRouteDiscovery`, RSC mode, `Await unstable_promise`) is absent. The one shared 404 helper (`notFound()` in `app/app/lib/api.server.ts:39-41`) wraps `data()` in a single module.
