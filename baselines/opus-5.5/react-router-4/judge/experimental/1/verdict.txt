## Review: experimentalness of `app/`

**Framework version check.** `app/package.json` pins `react-router@^8.5.0` / `@react-router/dev@^8.5.0`. Per the official changelog, 8.5.0 (2026-10-19) and 8.5.1 (2026-10-27) are the current stable releases, so the app targets the current stable major, not a pre-release. Vite is `^8.0.3` (Vite 8.0 stable shipped 2026-03-12; latest is 8.1.0), matching what the framework requires.

**Measured experimental markers:** none. A repo-wide grep for `unstable_`, `experimental_`, `preview`, `canary`, `future`, and `v3_` returns zero hits in `app/`.

**Framework surface audit (all long-stable):**
- Route config via `index`/`route` from `@react-router/dev/routes` (`app/app/routes.ts:1-9`) — the documented, non-flagged convention.
- `react-router.config.ts` sets only `ssr: true` (`app/react-router.config.ts:6`) — no `future.*` flags (v8 adopted all future-flag behavior by default), no `ssr: "unstable_api-only"`, no `unstable_apiServerOrigin`.
- Root `Layout` export (`app/app/root.tsx:27`) — introduced in v7.16.0 (Aug 2025), now the standard root-shell idiom; stable.
- `data()` helper for 404 responses (`app/app/lib/api.server.ts:4`, `app/app/routes/not-found.tsx:3-5`) — stable since v7.
- Typed route modules via `./+types/*` with `Route.MetaFunction`, `Route.LoaderArgs`, `Route.ComponentProps` (e.g. `app/app/routes/pokemon.tsx:29`, `app/app/routes/home.tsx:16`) — stable since 7.9.
- `meta` reads `loaderData`, not the deprecated `data` field (`app/app/routes/move.tsx:11`) — matches v8's removal of deprecated `meta` `data` fields.
- `Link`, `NavLink`, `Form`, `Outlet`, `ScrollRestoration`, `useNavigate`, `useSearchParams`, `isRouteErrorResponse` (`app/app/root.tsx:3-10`, `app/app/routes/home.tsx:2`) — all long-stable. No `viewTransition` props or `useViewTransitionState` (deprecated in 8.5.0) — correctly avoided. No RSC, no middleware, no `@react-router-dom` (removed in v8).
- No `entry.server`/`entry.client` overrides — uses the framework defaults (v8.2 made the web-streams entry the default), which is the low-risk choice.

**Only borderline item.** `app/vite.config.ts:7` uses Vite 8's built-in `resolve.tsconfigPaths: true` to power the `~/*` alias (declared in `app/tsconfig.json:14-16`). This is a Vite 8 feature that shipped in the 8.0.0 stable release (2026-03-12) but kept an `@experimental` JSDoc marker until it was removed on 2026-07-22 (vitejs/vite commit 961643a). So it's "recently-stable" — roughly 3 months by documentation markers — and it replaces the third-party `vite-tsconfig-paths` plugin, which Vite now explicitly warns against (vitejs/vite#21781). It's one line, in the build config, isolated from app code, and is the currently recommended approach. It does not count as experimental/preview/RC/canary.

**Scoring.** Reach: one recently-stable build-tool option in a peripheral, one-line location — better than "recently-stable in central places" but not quite "only long-stable", so 4. Containment: the React Router surface needs no containment and the single recently-stable option is confined to `vite.config.ts` — 5. Justification: the one new-ish use buys real value (drops a third-party plugin, follows Vite's own migration guidance) — 5. Distinct experimental/preview/RC/canary API count: 0.
