## Review — test quality

**The app's own suite is one file, three cases, eight assertions** (`app/src/app/shared/format.spec.ts:1-20`, run via the current vitest-based `@angular/build:unit-test` builder configured in `app/angular.json:33` and `app/package.json:11`). The tests are behavioural and clean — pure functions, no mocks, no snapshots — but they cover ~15 lines of trivial string formatting out of ~876 significant LOC. Every piece of genuinely risky logic is unguarded except by the acceptance Playwright suite.

What's tested and what it would catch:

- `humanize` (spec lines 4-8) — a regression here breaks every list label in the app.
- `dexNumber` padding (lines 10-13) — catches a `padStart` off-by-one.
- `orDash` null-vs-`0` distinction (lines 15-18) — a real edge case (power 0 is not "missing").

What isn't tested — and this is where the money is:

- **View-model construction** (`app/src/server/loaders.ts:116-180, 232-315`): English-name selection, "last English flavor text" (`latestFlavorText`, line 120 — picking the *first* instead of the *last* English entry would still pass for most species and is a classic silent regression), `$effect_chance` substitution (line 134), alternate-form exclusion and dex-sorting in `toCards` (lines 159-169), the move-row dedup key `${method}|move|level` and method-table ordering (lines 281-311, `METHOD_ORDER` line 180), default game selection "highest order" (line 260). All of this is pure-enough logic that would be cheap to unit test once extracted from the loaders, but nothing pins it.
- **URL state / filtering / pagination** (`app/src/app/pages/home/home.ts:62-86`): the filter predicate, `page` clamping, `slice((page-1)*48, page*48)` math, and the "omit defaults from the query" rule in `updateFilters` (lines 88-91). An off-by-one or a lost `page: null` reset would only be caught by the acceptance suite's specific fixtures.
- **Sortable move tables** (`app/src/app/pages/pokemon/move-table.ts:66-79`): spec-mandated "missing values sort last in both directions" and the flip-on-second-click `aria-sort` logic. Refactoring the comparator (e.g. dropping the null short-circuit) would reorder rows with no failing app-owned test.
- **Caching layers** (`app/src/server/api-client.ts:31-71`, `app/src/app/data/page-data.ts:11-26`): TTL expiry, error eviction, 404→`ApiNotFoundError` mapping, TransferState handoff. Stale-data or swallowed-error bugs here are subtle and hard to reproduce.
- **Not-found paths**: `apiFind` → `null` → `NotFound` rendering, the `/ _data` 404 (`app/src/server.ts:18-25`) and malformed-URI handling (`app/src/server/loaders.ts:394-397`).

The acceptance tests currently mask all of this; the moment someone refactors the data layer, there is essentially no safety net in `app/`.
