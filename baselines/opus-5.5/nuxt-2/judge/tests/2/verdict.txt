I've reviewed the full app. `app/` contains no test files, no test runner, and no test script — every score below reflects "no tests," with my effort spent on what the missing coverage lets through.

## Review

### What exists
The app is a competent Nuxt 4 SSR app: server routes under `app/server/api/` do the heavy lifting (index building, card mapping, move-table grouping), pages own URL state, and `app/server/utils/pokeapi.ts` is a caching fetch client. **There is not a single test in `app/`**: no `test` script in `app/package.json:6-11`, no vitest/`@nuxt/test-utils`/Playwright anywhere in the tree (grep confirmed), and the measured facts agree (`tests: { files: 0, cases: 0, runner: [] }`). The only safety net is the acceptance suite in `tests/`, which the agent didn't write and which covers a sample of pages, not the logic.

### Where the risk actually is
The riskiest code is exactly the code with zero coverage:

- **`speciesCards`** (`app/server/utils/data.ts:69-79`) — dedup-by-ID, alternate-form exclusion (`id > MAX_SPECIES_ID`), Pokémon-ID→species-name mapping, hidden-ability flag. A refactor that changes the dedup key or drops the `cards.has(id)` guard would silently produce duplicate cards or lost `Hidden ability` labels; nothing would fail.
- **Moves endpoint** (`app/server/api/pokemon/[name]/moves.get.ts:17-72`) — version-group ordering by `order`, default = highest `order` (`games[games.length-1]`), method ordering (`METHOD_ORDER` then alphabetical), per-method dedup key `${move}:${level}`. Any of these inverted (e.g. defaulting to *lowest* order) only breaks for games the acceptance suite happens to sample.
- **Client sorting** (`app/app/components/MovesTable.vue:42-68`) — missing-values-last in *both* directions, direction flip, `aria-sort`. The null-handling branch is easy to break and no test pins it.
- **URL state machine** (`app/app/pages/index.vue:40-52`) — `buildQuery` omitting defaults, page clamping (`Math.min(Math.max(n,1), totalPages)`), filter-change resetting to page 1, debounced search with timer cleanup (`onBeforeUnmount`). Off-by-one in the `slice` at line 37 would show 47/49 per page; `Number.parseInt('12abc')` → 12 is unpinned behaviour.
- **Cache layer** (`app/server/utils/pokeapi.ts:11-19`) — 60s TTL, promise coalescing, negative caching of 404s, unbounded `Map`. TTL expiry, error eviction and memory growth under a long-running server are all untested behaviours someone will eventually "simplify" incorrectly.
- **Cheap pure helpers** (`app/shared/utils/format.ts`, `englishName`/`latestFlavorText`/`collapse` in `data.ts`) — trivially unit-testable, untested.

### Verdict
The data layer is the part a future refactor will touch first, and it's completely unguarded. Adding vitest + `@nuxt/test-utils` with unit tests on `shared/utils`, `server/utils`, and a component test each for `index.vue` and `MovesTable.vue` would be the highest-value follow-up.
