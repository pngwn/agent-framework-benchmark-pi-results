Everything below is therefore scored on what the acceptance suite will *not* catch once someone starts refactoring.

**Risky, completely untested logic I verified while reading:**

- **Home page filtering/pagination/URL state** — `app/app/pages/index.vue:23` (search/type/generation matching), `:33` (page parse + clamp), `:40` (`buildQuery` omitting empty/default params), `:52` (`setFilter` dropping `page` to reset it), `:56` (debounced search). A refactor that breaks the clamp, the "omit defaults" rule, or the reset-to-page-1-on-filter-change behaviour would pass review unnoticed.
- **Moves endpoint assembly** — `app/server/api/pokemon/[name]/moves.get.ts:23` (version groups ordered by `order`), `:29` (default = highest order, falling back to last), `:45` (dedupe on `move:level`), `:60` (method order `level-up, machine, egg, tutor`, then alphabetical). This is the densest transformation code in the app and the easiest to get subtly wrong.
- **Client-side sorting** — `app/app/components/MovesTable.vue:49` (`sortedRows`: missing-values-last in both directions, `aria-sort` management). Note the tie-breaker `a.label.localeCompare(b.label)` is not multiplied by `sign`, so descending sort keeps an ascending tie-break — exactly the kind of thing a test would pin down.
- **Species-card mapping** — `app/server/utils/data.ts:71` (`speciesCards`: alternate-form exclusion via `MAX_SPECIES_ID`, dedupe by species ID, `hidden` flag). The flag is first-occurrence-wins; if a species appears once hidden and once not, the badge depends on API array order — an untested assumption.
- **API client caching** — `app/server/utils/pokeapi.ts:19` (TTL cache with shared in-flight promises, 404→`null`), `:57` (`mapLimit` concurrency). The live-data overlay acceptance test only covers the happy path; a regression that cached rejected promises or ignored the TTL would slip through.
- **404/status handling** — `app/server/utils/pokeapi.ts:48` (`fetchResource` throwing `createError` 404), `app/app/components/NotFound.vue:5` (`setResponseStatus` only when `useRequestEvent()` exists). Nothing verifies unknown routes/names actually return 404 vs 200.
- **Pure helpers** — `app/shared/utils/format.ts:5` (`humanize`), `:13` (`dexNumber`), `:18` (`display`'s `—` fallback): the cheapest possible unit tests, none written.

The shared `#shared/types/pokedex.ts` types and server handlers are testable with Nitro's `defineEventHandler` mocks or `@nuxt/test-utils` with trivial setup; the app is architected (pure helpers, thin handlers) such that unit tests would have been inexpensive to add.
