## Review summary

This is a well-executed Nuxt 4 app (pinned to the current stable, `nuxt@4.6.2` per `app/package-lock.json:6125`, released three days before "today"). The architecture is textbook Nuxt 4: Nitro server routes as a data layer over the PokeAPI, `shared/` for cross-boundary pure helpers and types (matching the `shared/` docs), small auto-imported components, `useFetch` with reactive URLs, `createError` 404s propagated through `useFetch`, and `setResponseStatus` in the shared `NotFound` component.

What stands out positively:

- Clean layering: `app/server/utils/pokeapi.ts` (transport + TTL cache with request dedup), `app/server/utils/data.ts` (domain mapping), `app/shared/utils/format.ts` (pure display helpers), typed DTOs in `app/shared/types/pokedex.ts`.
- Correctness care: `mapLimit` bounds fetch fan-out (`pokeapi.ts:43`), 404 vs error responses distinguished, debounce with timer cleanup (`app/app/pages/index.vue:58-66`), missing-values-sort-last handled in both directions (`app/app/components/MovesTable.vue:46-55`), `useId` for section headings, no hydration-sensitive client-only sorting.

Nits a reviewer would raise: no timeout/abort on upstream fetches, the in-memory cache never evicts expired entries, `any` throughout the PokeAPI-facing data layer, a `new Map(...)` construction that would fail `vue-tsc` (and no typecheck script exists), `error.vue` duplicating `app.vue`'s chrome, and zero self-written tests for the tricky pure logic. None of these block merge.
