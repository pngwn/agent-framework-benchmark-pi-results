## Scenario walkthrough

**1. Remove the Abilities pages.** Two files: delete `app/src/pages/abilities/[name].astro` and remove the `Abilities` section + `abilities` const in `app/src/pages/pokemon/[name].astro:45,106-115`. No nav link exists to remove (`Layout.astro:20-23` only lists Pokémon/Types). Two CSS rules become dead (`global.css:139 .plain-list`, used only by that section; `global.css:276 .card__note`, used only by the ability page) — optional cleanup. Trivial.

**2. Sprite bug (Deoxys).** Every card list (home `index.astro:82`, moves `:72`, abilities `:36`, types `:63`) renders through `PokemonCard.astro:16`, whose only sprite source is `spriteUrl` at `app/src/lib/api.ts:73`; all ids flow through two central resolvers (`pokemonRefsToSpecies` at `api.ts:92-103`, which resolves a `deoxys-normal` ref to species 386/`deoxys`, and `getPokemonIndex` at `api.ts:151`). One fix in `spriteUrl`/`PokemonCard` covers every list — no per-page edits.

**3. Sort all card lists by name.** Two sort sites in one file: `api.ts:103` (`pokemonRefsToSpecies`, serves moves/abilities/types) and `api.ts:168` (`getPokemonIndex`, serves home). They must be kept consistent with each other, and a user-facing sort control would additionally touch all four pages plus the client re-render path in `index.astro`.

**4. Items section.** Reusable as-is: `getJson`/`englishName`/`latestEnglishFlavorText`/`pokemonRefsToSpecies` (`api.ts`), `Layout`, `Section`, `NotFound`, `PokemonCard`. What gets copied: the ~10-line page scaffolding pattern (fetch → `Astro.response.status = 404` → `NotFound`/`Layout title`) already instantiated 4× (e.g. `moves/[name].astro:14-17`, `types/[name].astro:19-21`), the `effect` fallback chain, and a list layout (types index `types/index.astro` is a 17-line model). Mostly additive, two new files + CSS.

**5. Change API base URL / caching.** Exactly one file knows either: `API_BASE_URL` at `api.ts:5` (shared by `resolve` and `spriteUrl:73`), `CACHE_TTL_MS` at `api.ts:7`, and the in-memory cache entirely inside `getJson` (`api.ts:21-35`). Client scripts only fetch the app's own pages, never the API — clean seam.

## Notes on idiomatic Astro

- Recursive component via `Astro.self` (`EvolutionTree.astro:14`) and inline TS client scripts in `.astro` files (processed by default) are current, idiomatic Astro 7 usage.
- `Astro.response.status = 404` in SSR pages plus a shared `NotFound` component is the idiomatic 404 pattern; a 7.4 `notFound()` entrypoint isn't needed since only the per-route pages need custom status.
- Using one global stylesheet with feature-comment sections instead of Astro scoped styles is a legitimate choice here, but it's the only place feature removal leaves residue.
