## Review summary

**Structure & idiom.** This is a clean, small Astro 7 app: `output: 'server'` with the Node adapter in standalone mode (`app/astro.config.mjs:1-5`), file-based routing with `[name].astro` params, top-level `await` data loading in frontmatter, `Astro.self` recursion for the evolution tree (`app/src/components/EvolutionTree.astro:13-21`), `class:list` in `Section.astro:12`, bundled `<script>` tags, and `astro/tsconfigs/strict` (`app/tsconfig.json:2`). Versions are current (`astro@^7.4.2` matches the latest stable line, 7.4.4, verified 2026-10-28) and `devToolbar: { enabled: false }` is still a valid schema shape in Astro 7 (verified against the defaults schema). The 404 handling via `Astro.response.status = 404` is literally the documented pattern in the Astro render-context reference, so I won't count the inline `<NotFound/>` branches as a framework violation — only as duplication across the four detail pages.

**Correctness.** Real risks I'd ask about before merging: the module-level cache in `app/src/lib/api.ts:14,32` never evicts expired entries (the TTL only marks staleness; failed promises are deleted but successful ones live forever), so a long-lived server process accumulates every distinct API URL ever fetched — with ~1,000 species, ~900 moves, and per-`game` move fetches, that's a genuine slow leak. The MoveTables `popstate` handler desyncs the `<select>` from the displayed tables when the back target has no `?game=` param (`app/src/components/MoveTables.astro:149-156`). The `innerHTML`/`replaceWith` swap helpers silently no-op when the fetched document lacks the expected fragment (e.g., a 500 page while the API is down). No XSS (Astro escaping everywhere, `set:html` never used), abort races are handled correctly with `AbortController`, and there are no SSR/CSR mismatch or leaked-listener issues.

**Abstractions.** `lib/api.ts` is a reasonable single data-access module, but it mixes three concerns — HTTP fetch + cache, formatting helpers, and precomputed shared indexes (`getPokemonIndex` rebuilds a 1,025-species index per home-page request, cached 60s). The nearly identical "fetch → DOMParser → swap" helpers in `index.astro:124-133` and `MoveTables.astro:119-128` are the clearest case of duplication that should become one shared module. `TypeInfo` leaks the raw API record as `data: any` (`app/src/lib/api.ts:106`) — a leaky boundary that forces `any` casts downstream.

**Readability.** Good: consistent page structure, comments explain intent (cache rationale at `api.ts:1-5`, sort rules in `MoveTables.astro:81-82`), small focused components. Rough: pervasive `(x: any)` casts in the pages defeat the strict tsconfig (`app/src/pages/pokemon/[name].astro:33,36,42,108` etc.), and the four page templates wrap their entire body in a `{!x ? <NotFound/> : <Layout>…}` ternary that pushes everything deep. All CSS lives in one global stylesheet (`app/src/styles/global.css`, ~545 lines) rather than Astro's favored colocated scoped styles — allowed by the spec, but component class names live far from their markup.

I'd merge after one focused round; nothing architectural needs rework.
