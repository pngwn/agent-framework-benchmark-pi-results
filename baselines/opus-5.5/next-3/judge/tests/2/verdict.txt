# Test-quality review: `app/`

## What's there

The app is a solid, well-organized Next.js 16 App Router build (18 source files, clean server/client split, `server-only` guards, typed API client). What it has **zero** of is tests: `app/package.json` has no `test` script and no test dependencies (`app/package.json:6-11`), and a repo-wide grep for `describe(`/`it(`/`expect(` finds only incidental regex `.test()` calls (`app/lib/format.ts:9,52`, `app/lib/api.ts:28`). Static analysis agrees (`tests.files: 0`, `testLoc: 0`). Everything that passes today passes because the *acceptance* suite in `tests/` (not the agent's work) happens to cover it — and that suite exercises a happy-path slice only.

## Where the unguarded risk actually lives

Reading the code, the highest-risk untested logic, in order:

1. **Species/pokémon mapping** — `app/lib/data.ts:52-69` (`cardsForPokemon`) maps pokémon refs back to species IDs, drops alternate forms (`id <= MAX_SPECIES_ID`), dedupes via a `Map`, and sorts by dex number. This is exactly the transformation the spec calls tricky (deoxys-normal → Deoxys, ID 386) and exactly what someone refactoring the data layer will break. No test would catch a dropped or duplicated card, or a wrong sort.

2. **The home-page index build** — `app/lib/data.ts:71-99` (`getSpeciesIndex`) cross-joins species names with 18 type records and 9 generation records to build the filter index. Silent failure modes: a species with no type record gets `types: []` (so it renders cardless-type and is invisible to type filters) and `generation: undefined`; `idFromUrl` returning `NaN` flows into `NaN <= MAX_SPECIES_ID` comparisons (`app/lib/data.ts:58` — happens to be false, i.e. safe, but only by luck). The live-data overlay's "one extra Pokémon" is precisely the input that would expose an empty-types or missing-generation bug, and no test pins it.

3. **The moves aggregation** — `app/app/pokemon/[name]/page.tsx:151-241` (`getMoves`, ~90 lines) does version-group ordering, default-to-highest-`order` selection, dedup via a composite `${method}:${move}:${level}` key (line 201), per-method table partitioning with the `level-up → machine → egg → tutor → alphabetical` rank (lines 231-240), and a level-then-name sort. Any of the ordering/dedup decisions could be inverted in a refactor and nothing in `app/` would fail.

4. **Client-side table sorting** — `app/components/MoveTable.tsx:62-78`: missing-values-last in both directions, numeric vs `localeCompare` dispatch, `aria-sort` toggling. The missing-last-in-both-directions branch is a classic silent regression.

5. **Filter URL state** — `app/components/Filters.tsx:27-61`: 200 ms debounce, `router.replace` for typing vs `router.push` for selects, and the `sentQuery` ref that stops a slow navigation from clobbering what the user typed (lines 33-40). This is hand-rolled race handling — the single most fragile client code in the app — and completely untested.

6. **Pagination clamping** — `app/app/page.tsx:38-40`: `parseInt` → NaN guard, clamp to `[1, totalPages]`, and `pageHref`'s "omit defaults" rule (lines 43-52). `?page=9999`, `?page=abc`, `?page=0` all silently normalize; a refactor that drops the clamp or the "no `page=1`" omission would go unnoticed.

7. **The fetch cache** — `app/lib/api.ts:23-58`: promise memoization, 60 s TTL, failed-request eviction, and an LRU-ish sweep whose condition (`entry.expires <= now || cache.size > MAX_ENTRIES`) evicts *fresh* entries once over capacity. Nobody will refactor that safely without tests.

8. **Formatting helpers** — `app/lib/format.ts` is the cheapest, highest-leverage unit-test target imaginable (`humanize`, `dexNumber`'s 4-digit padding, `lastEnglish`/`findLast` for "latest flavor text", `collapseWhitespace`'s `\f` handling, `idFromUrl`). Untested.

Cheap, high-value tests the agent could have written with zero new infra beyond `vitest`: format-helper units, `getSpeciesIndex`/`cardsForPokemon` against a fixture API, a render test of `MoveTable`'s sort, and a `Filters` URL-sync test with a mocked router. Nothing of the sort exists.

## Scores

- **coverage_of_risk: 1** — no tests at all; the riskiest code (species mapping, index build, moves aggregation) is entirely uncovered.
- **behaviour_not_implementation: 1** — no tests, so nothing to classify.
- **regression_power: 1** — every behaviour is currently guarded only by the acceptance suite; any refactor of `lib/` ships unverified.
- **signal_to_noise: 3** — no tests means no noise, per the anchor.
