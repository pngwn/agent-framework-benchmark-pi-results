## Review

This is a Next.js 16 (App Router, Turbopack, React 19) Pokédex with server components for pages and small, well-scoped client components for interactive controls. Structure follows the framework's conventions closely; the main non-native piece is a hand-rolled in-memory fetch cache, which is a deliberate and documented choice given the spec's "live API" requirement.

**Idiom.** Async `params`/`searchParams` (`app/app/pokemon/[name]/page.tsx:14`), `notFound()` + `not-found.tsx`, `generateMetadata` with the title template (`app/app/layout.tsx:11`), `server-only` guards on data modules (`app/lib/api.ts:1`), and a clean server/client split (`format.ts` shared both sides) all read like current docs. Route segment config `dynamic = "force-dynamic"` (`app/app/layout.tsx:6`) is still valid on Next 16 stable (only conflicts with opt-in `cacheComponents`). The custom 60s TTL promise cache (`app/lib/api.ts:29-47`) reimplements what `use cache`/`cacheLife` would do — acceptable since Cache Components is opt-in, but a reviewer could ask. Blanket `prefetch={false}` on every Link (e.g. `app/components/PokemonCards.tsx:15`) deviates from the framework default without a comment. `error.tsx` renders a `<title>` in the tree (`app/app/error.tsx:6`) — works via React 19 hoisting and is a known workaround for client boundaries, fine.

**Correctness.** Genuinely careful: the `sentQuery` guard against a slow navigation clobbering the user's typing (`app/components/Filters.tsx:26-35`), failed-request cache eviction (`app/lib/api.ts:43-45`), missing-values-sorted-last (`app/components/MoveTable.tsx:46-50`), bounded cache with FIFO sweep (`app/lib/api.ts:36-41`), and name validation before fetching (`app/lib/format.ts:44`). Remaining risks are minor: `get<Pokemon>` for the default variety turns a hypothetical 404 into an error-boundary 500 instead of `notFound()` (`app/app/pokemon/[name]/page.tsx:38`); `GameSelect` lacks the same stale-navigation guard `Filters` has (`app/components/GameSelect.tsx:14-18`); `error.tsx` never logs the error. No SSR/CSR mismatches found — client components all derive initial state from props.

**Abstractions.** `lib/api.ts` (transport + types), `lib/data.ts` (domain assembly), `lib/format.ts` (pure helpers) is a clean layering with the server/client boundary drawn explicitly. Duplication exists: two query-string builders for filter state (`app/app/page.tsx:44-51` vs `app/components/Filters.tsx:12-18`) that can drift, `MISSING` redefined (`app/components/MoveTable.tsx:14` vs `app/lib/format.ts:5`), and `/types` re-implements the `--type-color` inline style rather than reusing `TypeBadge` (`app/app/types/page.tsx:14`). All small.

**Readability.** Strong. Comments explain *why* (cache eviction rationale at `app/lib/api.ts:2-3`, sentQuery guard at `app/components/Filters.tsx:24-25`), naming is consistent, files are modest. The Pokémon page is the longest at ~230 lines but stays coherent; `getMoves` could live in `lib/`. `Section.tsx`'s diacritic-stripping slug (`app/components/Section.tsx:4-11`) is over-engineered for a fixed set of ASCII titles.

**Review cost.** I'd approve after one round of nits: dedupe the query builders, reuse the `MISSING` constant, add the missing-value/404 guards, and drop or justify blanket `prefetch={false}`.
